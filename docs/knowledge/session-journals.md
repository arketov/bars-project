# Проверка соглашения о журналах сессий

Соглашение — [журнал сессии](../features/docs-convention/session-log.md); проверку «по самим журналам» обещал [ADR-0001](../adr/0001-docs-by-features.md). Исследование 28-10-2026, шаг 6.4.1. Предложения ниже — не решения автора: они вынесены в OQ-223.

## Вопрос и метод проверки журналов

Три вопроса: сколько и каких записей в `log.md`, помогает ли `handoff.md` следующей сессии, мешает ли модуль `chats` поиску.

Данные:

1. **Папки `docs/chats/`** на 28-10-2026: 188 сессий с 15-10 по 28-10. Скрипт считает записи `log.md` (пункт списка или абзац с датой), их длину в знаках, строки и разделы `handoff.md`, ссылки на прошлые сессии, файлы помимо журнала. Скрипт — [данные замера](session-journals-2026-10-28/Index.md).
2. **Расшифровки Claude Code** этого проекта (`~/.claude/projects/*bars-project*/*.jsonl`, без субагентов): 154 сессии с вызовами инструментов. Чтение handoff — вызов `bars_read`, Read, Bash или PowerShell с путём `chats/<сессия>/handoff.md`. Чтение своего журнала (папки, в которую сессия же пишет) отделено от чтения чужого. Расшифровки Codex по bars-project вызовов инструментов не содержат и не учтены.
3. **Модули индекса** из `bars_projects` и прежний [бенч выбора модулей](module-scope-bench.md).

Ограничения: расшифровки есть не для всех 188 папок; «прочитал» не значит «воспользовался» — пользу handoff показывает только то, что сессия его открыла, а не качество её работы. Скорость роста корпуса и доля `chats` — снимок одного дня.

## Сколько записей в log.md

`log.md` есть в 146 из 188 сессий (78%); 42 сессии без находок журнал не завели, как и требует правило «только по поводу». Пустых журналов нет.

| Мера | Медиана | p90 | Максимум | Всего |
|---|---|---|---|---|
| Записей в журнале | 3 | 6 | 14 | 461 |
| Знаков в журнале | 607 | 1 362 | 3 672 | 111 516 |
| Знаков в самой длинной записи | 254 | 490 | 2 115 | — |

Записи короткие и редкие: журнал в среднем — три находки. Правило «не больше трёх строк» соблюдается формально, но не ограничивает объём: запись пишется одной длинной строкой, 12 записей длиннее 600 знаков, самая длинная — 2 115 знаков в одной строке. Мера в строках для Markdown, где абзац — одна строка, ничего не меряет.

Чужие `log.md` читаются редко: 16 вызовов на 44 тыс. знаков за всё время. Правило «новая сессия читает handoff, а не логи» выполняется.

## Помогает ли handoff следующей сессии

`handoff.md` есть в 187 из 188 сессий; нет только в `2026-10-22-tree-files` (один `log.md`). Медиана — 12 непустых строк и 1 756 знаков, p90 — 2 613 знаков, максимум — 7 739 знаков (`2026-10-18-stage33-implementation`). «Не длиннее экрана» держат почти все.

Разделы: все четыре — в 151 handoff, без «Сложностей» — 27, остальные девять отклоняются. Три handoff (`2026-10-19-plan-backlog-cleanup`, `2026-10-22-link-index`, `2026-10-22-text-search-research`) озаглавлены по-английски `Done / Not done / Difficulties / Next` — так названы разделы в английском тексте skill `bars-session-log`, а журнал по AGENTS.md пишется по-русски.

Как handoff читают (154 сессии с инструментами):

| Мера | Значение |
|---|---|
| Сессий, открывших чужой handoff | 57 (37%) |
| …из них в первых 15 вызовах, то есть при входе в работу | 31 |
| Вызовов чтения чужих handoff | 99, 242 тыс. знаков — около 4 тыс. знаков на сессию |
| Вызовов `bars_rag_search` с `modules: ["chats"]` | 11 из 283 |
| Handoff со ссылкой на прошлую сессию по теме | 3 из 187 |

Вывод: handoff — рабочий вход для продолжения темы. Его открывает больше трети сессий, треть из них — сразу при старте; цена — около тысячи токенов на сессию. Четыре handoff прямо пишут «изучен прошлый handoff» как шаг погружения. Цепочка тем держится на плане и имени папки, а не на ссылках: handoff почти никогда не ссылается на предыдущий по той же теме, и найти его агент может только поиском или по дате.

## Мешает ли модуль chats поиску

Доля истории растёт: `chats` — 325 из 527 документов bars-project (62%; 22-10-2026 было 206 из 372, 55%), в overdrive-bots — 490 из 822 (60%). Сессий — до 41 в день, в среднем 16.

Мешает ли это выдаче, уже измерено бенчем 24-10-2026: с rerank `chats` занимает 5–8% мест в первых пяти, исключение `chats` выигрыша не дало ([бенч выбора модулей](module-scope-bench.md)); решение — оставить `chats` в поиске по умолчанию ([выбор модулей агентом](../features/agent-tools/module-scope.md)). Расшифровки этой проверки не противоречат: из 283 поисков агентов в 67 (24%) хотя бы один из первых пяти результатов — из `chats`, но сюда входят и намеренные поиски истории. Жалоб на засорение выдачи историей в журналах нет.

Мешает другое — вес папок сессий в репозитории. В git под `docs/chats/` 1 507 файлов на 10,3 МБ, из них `.md` — 355. Остальное — сырые данные замеров (`.log`, `.json`, `.txt`, снимки). Среди них 339 файлов профиля WebView2 (`2026-10-25-performance-audit/native-check/fixture-*/webview/EBWebView/`, 9,1 МБ на диске) — служебный профиль браузера, попавший в коммит `a923fc9`. bars их не индексирует (берёт только `.md`), но они раздувают клон и историю git навсегда.

Внутри папок сессий есть и другие `.md`: 25 файлов (`verification.md` — 11, планы этапов, отчёты). Это разрешённые AGENTS.md отчёты о завершённых этапах; они индексируются наравне с handoff.

## Выводы проверки соглашения

- Соглашение работает: журналы короткие, handoff есть почти везде и читается при входе в работу, чужие логи почти не читаются.
- Мера «три строки» ничего не ограничивает: записи длиной до 2 115 знаков проходят как одна строка.
- Английские заголовки разделов skill переходят в русские handoff.
- Модуль `chats` выдаче не мешает; повод вернуться к вопросу — доля `chats` в первых пяти выше 15% на бенче или жалобы в журналах.
- Настоящая цена журналов — не поиск, а файлы замеров в git, в том числе случайный профиль WebView2.

## Предложения автору по журналам сессий

Записаны как OQ-223; ни одно не внедрено.

1. **Мерить запись `log.md` в знаках**: «не больше трёх строк» заменить на «до ~400 знаков» в session-log.md и skill `bars-session-log`.
2. **Названия разделов handoff по-русски** в skill: «Сделано, Не сделано, Сложности, Дальше»; раздел «Сложности» можно опустить, если их не было (так уже делают 27 сессий).
3. **Ссылка на прошлый handoff темы**: строка «Предыдущая сессия: …» в начале handoff, если сессия продолжает тему. Дёшево, а цепочка темы перестаёт зависеть от поиска.
4. **Служебные данные замеров вне git**: удалить из индекса git профиль WebView2 `2026-10-25-performance-audit/native-check/fixture-*` и добавить правило `.gitignore` для `fixture-*/webview/`; в session-log.md — строка «профили браузеров, кэши и выгрузки инструментов не коммитятся; сырые данные замера — в `knowledge/<тема>-<дата>/`». Переписывать историю git не предлагается.
5. **`chats` оставить в поиске по умолчанию** — подтверждение решения выбора модулей; пересмотреть по порогу из выводов.
