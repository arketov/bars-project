# Контекстные меню окна bars — опись объектов и устройство меню образцов

Статус на 24-10-2026: опись объектов сверена с кодом `ui/src/lib` и документами окна; устройство меню Проводника, VS Code и Obsidian взято из первоисточников и помечено проверенным или нет. Меню в приложении не запускались. Выводы — предложения агента для проектирования, а не решения автора; модель меню проектируется отдельным шагом. Основание: [ISS-57 и ISS-47](../backlog/issues.md), [аудит клиента, А-8](../audits/client-2026-10-23.md), [меню документа](../features/window/document-actions.md), [меню проекта](../features/window/project-menu.md), [каталог команд](../features/window/keyboard-design.md).

## Вопрос и метод контекстных меню

Вопрос: какие объекты в окне bars могут иметь контекстное меню, что у каждого есть сегодня и какие действия ему нужны, и как устроены меню у образцов — чтобы одна модель «объект → действия» закрыла все места с одинаковыми группами.

Метод: опись — чтение `ContextMenu.svelte`, `contextmenu.ts`, разметки `data-*` в компонентах и каталога команд `keybindings.ts`; требования — ISS-57, ISS-47, Т-33, Т-38, Т-40. Образцы — официальная документация Microsoft Learn (меню, Shell verbs), справка VS Code и Obsidian; страницы читались 24-10-2026, VS Code и справка Obsidian — через пересказ страницы, поэтому проверяемы по ссылкам внизу. Приложения образцов не запускались: порядок пунктов внутри меню Проводника и Obsidian ниже указан только там, где источник его называет.

## Как было устроено меню bars при описи 24-10-2026

Опись фиксирует исходный код на 24-10-2026, до реализации модели дерева; действующее поведение описывает [модель меню документа](../features/window/document-actions.md). В исходном срезе один компонент `ContextMenu.svelte` слушал `contextmenu` на окне и по ближайшему предку цели определял вид объекта: тема, папка, проект, файл. Пункты собирались склейкой списков через `unshift` и `push` в порядке проверок, у пункта не было ни разделителя, ни признака «опасный», ни сочетания клавиш. Наблюдавшиеся следствия:

- **Порядок случайный.** В меню папки «Удалить…» стоит между «Переместить…» и «Открыть в Проводнике»; в меню файла дерева «Переименовать», «Переместить», «Удалить» идут после «Цвет…» (ISS-57).
- **Операции с файлом только в дереве.** Пункты `entryItems` добавляются при `data-tree-node`, поэтому на вкладке, в шапке, на карточке и в редакторе их нет, как и «Закрыть вкладку».
- **Редактор без правки текста.** CodeMirror не поле ввода для `textField()`, поэтому «Вырезать», «Вставить» и «Отменить» не показываются; вместо них — меню документа.
- **Один жёстко зашитый список — «Открыть в …».** `ArrowRight` всегда открывает подменю редакторов; других подменю модель не знает.
- **Цель определяется по ближайшему `data-document-path`.** Это даёт ошибочную цель во вложенных объектах (см. таблицу).

Сочетания клавиш живут отдельно: реестр `keybindings.ts` содержит `id` и умолчания команд (`tab.close` — Mod+W, `document.newWindow`, `target.rename`, `target.move`, `target.delete` и другие), но меню их не показывает и не вызывает через реестр.

## Опись объектов окна и их меню на 24-10-2026

Колонка «При описи» — состав меню по коду и аудиту А-8 на 24-10-2026; «Нужные действия» — из требований и реестра команд на тот момент, не итоговый состав.

| Объект | Как определяется | При описи | Нужные действия |
|---|---|---|---|
| Файл в дереве | `data-document-path` + `data-tree-node` | Открыть, В новом окне, Открыть в …, Проводник, Скопировать путь, Проверить индекс, Цвет…, Переименовать…, Переместить…, Удалить… | Тот же набор в одном порядке; удаление последним |
| Папка и модуль в дереве | `data-folder-path` | Новый документ…, Новая папка…, Переименовать…, Переместить…, Удалить…, Проводник, Скопировать путь, Проверить индекс проекта, Цвет и иконка… (2-й уровень) | То же в группах |
| Группа «Корневые документы» (`.`) | `data-folder-path="."` | Создание, Проводник, путь, проверка; без переименования, переноса, удаления | Прежнее ограничение |
| Проект | `data-project-path`, три места боковой панели | Удалить проект, Проверить индекс | Удаление последним |
| Карточка результата поиска | `data-document-path` + строка | Меню документа без операций с файлом | Открыть справа, Открыть в новом окне, путь, ссылка, проверка |
| Вкладка документа | `data-document-path` на вкладке Dockview | Меню документа без «Закрыть» | Закрыть, Закрыть другие, Закрыть справа, перенос, операции с файлом |
| Вкладка служебной панели (поиск, граф, настройки, логи, MCP, индексация, новые темы, аудиты) | `data-workspace-panel` | Меню нет | Закрыть, перенос (`tab.close`, `tab.move`) |
| Шапка документа | `data-document-path` на `header` | Меню документа | Как у вкладки документа |
| Редактор исходника | `section[data-document-path]`, CodeMirror | Меню документа, без правки текста | Отменить, Вырезать, Копировать, Вставить, Выделить всё, затем подменю «Документ» |
| Рендер документа | `section[data-document-path]` | Меню документа; при выделении добавляется «Копировать» | Копировать; меню документа |
| Ссылка в тексте (`a[data-doc-link]`, `a[data-wiki-link]`) | не размечена | Меню документа, в котором лежит ссылка — не цель ссылки | Открыть цель, Открыть в новом окне, Копировать ссылку; цель — документ ссылки |
| Строка панели «Ссылки» (входящие, исходящие, битые) | кнопка без `data-document-path` | Меню открытого документа, не документа строки | Открыть, В новом окне; для битой — Создать документ |
| Структура документа | внутри `section[data-document-path]` | Меню открытого документа | Перейти к заголовку, Копировать ссылку на заголовок |
| Строка «Новых тем» | `data-new-topic-id` | Скопировать, Закрыть | Прежнее; «Закрыть» опасное |
| Находка аудита, вхождение «В тексте», «Похожие отрывки» | кнопки без разметки | Меню нет | Открыть, Открыть в новом окне, путь |
| Узел и ребро графа, мини-граф | Canvas, разметки нет | Меню нет, действия в инспекторе | «Открыть», «Локальный граф», «Путь до…» и другие из [дизайна действий графа](../features/graphrag/graph-actions-design.md); вместе с этапом 2.3 |
| Задание индексации, вызов MCP, уведомление, журнал | строки экранов | Меню нет; команды `indexing.details`, `mcp.details`, `notification.details`, `logs.copy` в реестре | Подробности, Повторить, Копировать |
| Поле ввода | `textField()` | Копировать, Вставить, Выделить всё | Прежнее |
| Выделенный текст вне поля | `selectedText()` | Копировать | Прежнее |
| Окно документа (отдельное) | тот же компонент | Наследует меню документа | Как в основном окне; набор вкладки решается моделью меню |

Две вещи из таблицы не исправляются добавлением пунктов, а требуют правила цели. Первая: вложенный объект (ссылка, строка «Ссылки», структура) не должен наследовать документ раздела по `closest("[data-document-path]")`; цель берётся у ближайшего объекта с собственной разметкой. Вторая: у вкладки служебной панели и у узла графа цель не файл, и `documentAt` для них пуст.

## Проводник Windows: порядок, скрытие и подменю

Проверено по [Creating Shortcut Menu Handlers](https://learn.microsoft.com/en-us/windows/win32/shell/context-menu-handlers) и [Menus and context menus](https://learn.microsoft.com/en-us/windows/apps/design/controls/menus-and-context-menus), 24-10-2026.

- **Канонические действия.** Система задаёт набор canonical verbs — Open, Opennew («в новом окне»), Print, Explore, Properties; подпись берётся из системы, а не из приложения, одинаковая во всех местах.
- **Основное действие первым.** Default verb отображается первым и служит действием двойного щелчка. Дальше порядок задаётся списком в значении ключа Shell; атрибут `Position=Top|Bottom` ставит пункт в начало или конец меню.
- **Скрыто, а не серое.** Глагол не показывается, если выбор не подходит его модели (`Single`, `Player`, `Document`: для `Document` лимит 15 объектов) или сработала политика подавления. Состояние объекта (например, «только чтение») может включать и выключать пункт через маску атрибутов; фильтр `AppliesTo` решает, показывать ли пункт.
- **Редкие пункты за Shift.** «Расширенные» глаголы появляются только при правом клике с Shift; их назначение — команды для опытных пользователей. В Windows 11 по сообщениям вторичных источников ([Windows 11 Forum](https://www.elevenforum.com/t/enable-or-disable-show-more-options-context-menu-in-windows-11.1589/), [Winaero](https://winaero.com/windows-11-open-extended-context-menu-in-file-explorer/)) короткое меню дополняет пункт «Показать дополнительные параметры» с Shift+F10; состав строки значков вверху меню этими источниками не подтверждён.
- **Подменю.** Каскадное меню собирается списком `SubCommands` из системных и своих глаголов; разделитель перед пунктом допустим только на верхнем уровне. Подменю применяется для групп, а не для одиночных пунктов.
- **Правила Microsoft для меню приложений.** Контекстное меню несёт вторичные команды объекта, у которого есть главная роль; частые команды стоит выносить на сам элемент. Общие команды (Копировать, Вырезать, Вставить, Удалить) в WinUI группируются в горизонтальный ряд командной панели. Значки — только у частых и узнаваемых пунктов: «Загадочные значки… создают визуальный шум». Разделитель отделяет группы; у разделённого пункта Enter выполняет действие по умолчанию, стрелка вправо переходит к вариантам.

## VS Code: группы с номерами и условия показа

Проверено по [Contribution Points — menus](https://code.visualstudio.com/api/references/contribution-points) и [UX Guidelines — context menus](https://code.visualstudio.com/api/ux-guidelines/context-menus), 24-10-2026, через пересказ страницы.

- **Меню — это каталог мест.** `explorer/context` (дерево), `editor/context` (текст), `editor/title/context` (вкладка). Команда попадает в место объявлением в `contributes.menus`; обработчик получает URI цели и массив выбранных URI.
- **Группы с порядком по имени.** Группы идут по лексикографическому порядку, `navigation` всегда первая. По умолчанию — в дереве: `navigation`, `2_workspace`, `3_compare`, `4_search`, `5_cutcopypaste`, `6_copypath`, `7_modification`; в редакторе: `navigation`, `1_modification`, `9_cutcopypaste`, `z_commands`; во вкладке: `1_close`, `3_preview`. Порядок в группе — суффикс `@число`, без него — по названию.
- **Условие показа и доступность разделены.** `when` решает, есть ли пункт в этом месте; `enablement` относится к команде везде, включая клавиши. Недоступный пункт не обязан быть серым.
- **Подменю.** Объявляется как отдельная сущность с подписью, прикрепляется к месту и само становится местом для команд. Рекомендация гида: большую группу вынести в подменю, показывать действия по контексту, держать группы одинаковыми в разных меню.
- **Сочетание в меню.** На странице интерфейса показан пункт «Открыть сбоку» с Ctrl+Enter; сочетание берётся из привязки команды, а не из меню.

Порядок конкретных пунктов дерева VS Code источники не называют; имена групп, где копирование пути и изменение (переименовать, удалить) стоят в конце, — единственное проверенное.

## Obsidian: состав меню файла, папки и вкладки

Проверено по справке [File explorer](https://obsidian.md/help/plugins/file-explorer) и [Tabs](https://obsidian.md/help/tabs), 24-10-2026, через пересказ страниц.

- **Файл:** Rename…, Delete (может запросить подтверждение), Move file to…, Duplicate, Reveal in system explorer (на macOS «Reveal in Finder»), Copy path (адрес Obsidian, от корня хранилища или от корня диска), Bookmark….
- **Папка:** те же Rename…, Delete, Duplicate, Move folder to…, Bookmark…, Copy path (без адреса Obsidian), Reveal; плюс New note, New folder, New canvas, New base, Search in folder.
- **Вкладка:** Split right, Split down, Pin, Unpin; пункта «Закрыть» страница не называет. Перенос в новое окно — команда палитры и перетаскивание. Меню ⋯ в заголовке заметки содержит «Открыть связанный вид» (локальный граф, обратные ссылки, структура).
- **Меню редактора и порядок пунктов** справка не описывает; не проверено.

## Что следует из образцов для модели меню bars

Это предложения для шага проектирования модели меню. Автор их не принимал.

1. **Одна таблица «объект → действия» и один список групп.** Проводник и VS Code описывают меню как набор объявленных глаголов с заданным порядком и группами, а не как склейку по месту вызова; в VS Code группы одинаковы для всех команд места. Группы из ISS-57: открыть · создать · переименовать и переместить · путь и Проводник · цвет · проверить индекс · удалить.
2. **Опасное — последней отдельной группой.** В VS Code изменение (`7_modification`) завершает меню дерева, в Проводнике Position=Bottom ставит пункт в конец; общее правило «Удалить последним» совпадает с ISS-57.
3. **Скрывать неприменимое, показывать серым применимое, но недоступное сейчас.** Проводник и VS Code скрывают пункты по типу объекта (`when`, `AppliesTo`, `Single/Document`). У bars уже есть второй случай: «Проверить индекс» при `unavailable` или `reindex_required` показывается серым с причиной. Правило разделяет оба случая явно.
4. **Сочетание клавиш показывается из реестра.** Windows и VS Code показывают его справа от пункта; в bars `bindingFor` и `label` уже есть, а обновление подписей после смены карты предусмотрено документом о клавишах.
5. **Подменю — для большой группы, глубина один.** «Открыть в …» и «Документ ▸» в редакторе; в Проводнике подменю тоже строится из списка, а не из одиночных пунктов.
6. **Редактор: правка текста, затем подменю.** У Windows и VS Code общие команды правки (вырезать, копировать, вставить) стоят отдельной группой; это согласуется с ожиданием ISS-57 и с тем, что меню документа в редакторе нужно свернуть в подменю.
7. **Цель берётся у ближайшего размеченного объекта.** Нужны размеченные вложенные объекты (ссылка, строка «Ссылки», структура, находка аудита) и вид цели «вкладка служебной панели» без пути файла.
8. **Закрытие вкладки — в меню вкладки и рядом с ней.** В Obsidian справка закрытия в меню вкладки не называет, поэтому как образец опора — VS Code (`1_close`) и ISS-57.
9. **Скрытое «расширенное» меню не нужно.** Меню bars компактное (ширина от 180 px по замечанию автора 20-10-2026) и содержит только действия объекта; отдельный слой за Shift нужен там, где меню длинное, и здесь решает проблему, которой нет.

## Что не проверено

- Состав и порядок пунктов настоящих меню Проводника Windows 11, VS Code (дерево, вкладка, редактор) и Obsidian (редактор) не наблюдался в приложениях; указаны только факты из документации.
- Строка значков вверху меню Проводника Windows 11 не подтверждена источниками.
- Реестр, ширина и поведение меню на macOS не исследовались; в образцах macOS отличается подписями («Reveal in Finder»).
- Сами меню bars в собранном приложении не запускались: опись основана на коде и аудите А-8, проверенном в браузере 23-10-2026.
