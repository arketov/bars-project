# Спайк локального канала bars

Проверено 15-10-2026 на Windows 11, `interprocess` 2.4.5, `windows-sys` 0.61.2. Устройство канала — [architecture/ipc.md](../architecture/ipc.md), что по нему передаётся — [architecture/protocol.md](../architecture/protocol.md).

## Что проверено в спайке канала

- **Тестовый exe `bars-app` с Tauri запускается.** Опасение было, что у тестового exe нет манифеста comctl32 v6 и он падает при старте; не подтвердилось, `cargo test -p bars-app` работает.
- **SDDL-дескриптор ложится на канал.** `SecurityDescriptor::deserialize` принимает строку `D:P(A;;GA;;;<SID>)`, `ListenerOptions::security_descriptor(..).create_tokio()` создаёт канал. По описателю открытого канала (`GetSecurityInfo`) DACL защищён от наследования и состоит из одной записи «разрешить» с SID текущего пользователя; Everyone и Users в нём нет. Проверка — тест `pipe_dacl_allows_only_the_current_user` в `bars-app`.
- **Занятое имя** при втором `create_tokio` на Windows — `PermissionDenied` (os error 5), а не `AddrInUse`. Воркер считает обе ошибки признаком «воркер уже запущен».
- **Алиасы SDDL `OW` и `CO` не используются:** владельцем объекта канала может оказаться группа администраторов, поэтому в запись подставляется явный SID.

## Что не проверено в спайке канала

- Отказ пользователю с другой учёткой: нужна вторая учётная запись на машине (`runas`); подключение от неё должно дать `ERROR_ACCESS_DENIED`.
- Что `interprocess` отклоняет удалённых клиентов канала (`PIPE_REJECT_REMOTE_CLIENTS`): по исходникам не подтверждено.
- Права `0600` на сокет и удаление мёртвого сокета на macOS: ветка написана, не собиралась.
- Сверка владельца сервера клиентом (OQ-38) проверена только в положительном случае: свой воркер принимается, `process_user_sid` совпадает с `current_user_sid`. Чужой процесс не проверен: нужна вторая учётная запись. Процесс System (pid 4) либо не открывается, либо имеет другой SID: тест принимает оба исхода.
