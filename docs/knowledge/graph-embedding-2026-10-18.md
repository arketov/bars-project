# GraphRAG на существующих embeddings — первый опыт

Статус на 18-10-2026: реализовано и проверено ядро cosine kNN на Rust; выполнен development-опыт на существующих векторах и восьми запросах к установленному MCP. Новая extraction-модель не добавлялась. Это не приёмка S1–S8, не завершение P0 или этапа 33.

## Что проверялось без новой модели

По ответам автора OQ-85…87/91: автоматическое локальное обновление, только чтение/evidence, один выбранный проект; сначала существующие embeddings и явные связи. Дополнительную модель обсуждать только после конкретного показанного недостатка. [ТЗ](../features/graphrag/requirements.md) сохраняет все S1–S8.

Имеющиеся нормализованные векторы достаточно прочитать из SQLite: для построения `similar_to` не требуются повторный embed или новый runtime. Реализация — [similarity.rs](../../crates/bars-core/src/graph/similarity.rs); самостоятельный [Rust-драйвер](../../spikes/graph/knn.rs) использует ровно этот файл. [Стенд](../../scripts/graph-embedding-probe.mjs) экспортирует read-only snapshot и сравнивает контекст. Ни одна из этих частей не меняет работающий поиск, профиль клиента или установленный exe.

## Корпус, метод и происхождение

- Снимок одного SQLite read transaction: 104 документа, 569 чанков, размерность 1024; fingerprint и document hashes — в [manifest](graph-embedding-2026-10-18/manifest.json).
- Исследования графа, документация самой фичи и журналы исключены до построения. Это development-набор; независимый holdout и экспертная разметка ещё не подготовлены.
- Для каждой S-группы сформулирован один вопрос. Обычный поиск вызван через настоящий `bars_rag_search`, только с перечнем файлов снимка: C100, limit20, min_score0; фактически rerank, K30. Это настройки установленного воркера в опыте, а не новые продуктовые умолчания.
- Все 160 результатов MCP сопоставлены со снимком по path, диапазону строк и полному тексту. Несовпадений — 0. Смена текста/выход за область делает вопрос invalid, а не успешным.
- Сетка: k=3/5/10 × min_cosine=0/0,5/0,7. Каждый граф строился из тех же векторов; по 323 192 направленных сравнения, 569 завершённых строк соседей, partial=false. ID в файлах опыта — локальные индексы snapshot, не публичные ObjectRef.
- Baseline набирает исходные результаты по порядку. Expansion ставит первыми три seeds, добавляет соседей по cosine/(rank seed+1), затем оставшихся исходных кандидатов. Оба ограничены 16 КиБ UTF-8 исходного текста; не помещающийся целиком чанк пропускается, включая seed. Это пробный способ отбора, а не реализация продуктового byte/token budget: envelope/справочники в эту метрику не входят.

Снимок, векторы, ответы MCP, все девять графов, анализ и хеши исходников сохранены в [доказательствах](graph-embedding-2026-10-18/Index.md). Обновление рабочего репозитория не подменяет эти входы.

## Полученный результат и конкретный недостаток

Полное построение графа заняло 0,283–0,321 с на i7-11700KF, Windows x64, Rust 1.99.0, `rustc -O`. Девять значений относятся к разным параметрам: это не p50/p95, не время запроса, не чистый ресурсный бенч и не оценка масштабирования на 5000 чанков. Чтение SQLite, MCP и сериализация в это время не входят.

| Проба | Наблюдение на одном бюджете текста |
|---|---|
| S2, fingerprint → состояние → действие | k3/t0 добавил `architecture/protocol.md`, которого не было в упакованном baseline |
| S6, оптимизация моделей | k5/t0,5 добавил `knowledge/inference-speed.md` к исходникам о памяти |
| S1, согласие на перестроение | k10/t0,7 добавил обзоры и воркер, но вытеснил `architecture/protocol.md` и часть исходных описаний |
| S7, длина/пачка и ожидание поиска | k5/t0,5 добавил экран прогресса, но вытеснил `features/models/local-models.md` и внешние модели |

Добавление документа не равнозначно улучшению качества. Удалённый source тоже не обязательно был нужен: для численных precision/recall нужны gold labels. Наблюдение уже достаточно, чтобы **не внедрять наивный expansion как улучшение текущей выдачи**: при фиксированном бюджете метод может вытеснять основания. Выбор соседей и сохранение evidence bundles нужно проверять отдельно.

Результат показывает осуществимость графа близости на нынешней модели. Он **не доказывает необходимость дополнительной модели**. Наличие сходства не даёт предиката, направления факта или polarity: это другой контракт, который предстоит проверить на явных связях и правилах исходного текста. Проверка только kNN не считается сравнением с полноценным rule-based extraction.

## Дальнейший метод без смены модели

1. Структурные связи из Markdown, точный source map и ревизии; не извлекать факты из повторённых служебных заголовков чанка.
2. Отдельные каналы основных результатов и related; расширение кандидатов до окончательного top-K, сравнение с увеличением обычного K и отбором существующим reranker. Сохранять целые evidence bundles и роли, а не только ближайшие chunks.
3. Явные ID/отношения из источников и проверка условий/отрицаний на размеченных примерах всех S1–S8. Similarity/co-occurrence сохраняют свои типы.
4. Если определённый результат остаётся недостижимым, показать вопрос, точный источник, пропущенное/ложное отношение и варианты автору по OQ-91. До этого новую модель не выбирать и S-сценарии не исключать.

## Проверки реализации и пределы

Rust kernel: 7 тестов — нормализация/знак/порядок, self edges, одинаковые оценки/перестановка входа, heap против полной сортировки, invalid vectors/параметры, cancellation и атомарная публикация строки при лимите сравнений. Отдельная сборка модуля и драйвера с `-D warnings` успешна.

Node-стенд: 4 теста — источник SQLite остаётся побайтово неизменным; исключение области и отказ перезаписи; missing vectors; проверка хешей snapshot, stale live hits, partial graph и недопустимые node IDs. Все прошли. Это проверка стенда, не жизни графа в воркере.

Первая попытка интегрированного `cargo test -p bars-core --lib graph:: --locked --offline` остановилась в уже добавленном параллельной работой `llama-cpp-sys-2`: в окружении отсутствовал `VULKAN_SDK`. Через CMake cache найден ранее установленный SDK; повторный `cargo test --release -p bars-core --lib graph:: --locked --offline` с Developer PowerShell/MSVC 17.14, Ninja и `CARGO_TARGET_DIR=C:/bg22` прошёл: 7 тестов, 207 отфильтрованы. Окружение менялось только для команды, SDK/модели не устанавливались. Полный набор core/worker/UI в этой задаче не запускался.

Не выполнены: независимый baseline/holdout и quality floors, resource acceptance, весь P1–P8, миграция/обновление графа, extraction, шесть публичных инструментов и окно. Этап 33 остаётся открытым.
