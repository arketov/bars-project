# Установщик bars: исследование и проверка

Поведение установщика — [features/distribution/installer.md](../features/distribution/installer.md); здесь только исследование (команды и окружение сборки — [build.md](build.md)): почему NSIS, что в шаблоне Tauri пришлось обойти, как и что проверено руками (15-10-2026, Windows 11, Tauri CLI 2.12.3, NSIS 3.13).

## NSIS или MSI

Требования автора (OQ-17): без подписи, без ручных шагов при обновлении, `bars-mcp` и `bars-cli` в составе. Tauri bundler собирает оба формата. NSIS собран и проверен; колонка MSI — по документации Tauri и WiX, MSI не собирался.

| | NSIS | MSI (WiX) |
|---|---|---|
| Установка без прав администратора | да, режим `currentUser` (`%LOCALAPPDATA%`) | нет: только на машину, нужен UAC |
| Обновление поверх | по идентификатору приложения находит прежнюю установку и её папку, сравнивает версии | `UpgradeCode` из идентификатора, мажорное обновление Windows Installer |
| Остановка работающего приложения | хуки `NSIS_HOOK_PREINSTALL` и `PREUNINSTALL`: любой код, например вызов `bars.exe --quit` | только Restart Manager; своего кода в обновлении нет без собственных действий WiX |
| Понижение версии | настройка `allowDowngrades`, в тихом режиме отказ с кодом выхода | запрет по умолчанию |
| Что нужно для сборки | NSIS скачивается автоматически | WiX Toolset скачивается автоматически, но сборка только на Windows |
| Размер | 11 МБ (собран) | не собирался |

Выбран NSIS: bars — пользовательское приложение в трее, ему не нужны права администратора, а главное требование — корректная остановка перед заменой файлов — решается кодом в хуках. MSI не отклонён навсегда: если появится требование корпоративного развёртывания (групповые политики), `bundle.targets` расширяется на `msi`, но хуки пришлось бы переписывать на действия WiX.

Другие варианты отклонены: `zip`/portable — автор отменил (промежуточный ответ по OQ-17 снят); `tauri-plugin-updater` — самообновление с сервера нужно, когда есть подписанные релизы и сервер обновлений; у приватного репозитория без подписи его нет, поэтому обновление идёт запуском новой версии установщика.

## Как устроен шаблон NSIS в Tauri и что из этого следует

Разбор сгенерированного `installer.nsi` (в `<target>/release/nsis/x64/`). Факты, на которых стоит решение:

- **Папка установки.** Для `currentUser` — `$LOCALAPPDATA\<productName>`, прежняя установка запоминается в `HKCU\Software\<издатель>\<productName>` и берётся при обновлении. Поэтому идентификатор приложения и издатель менять нельзя (иначе прежняя установка не находится и ставится вторая).
- **Остановка приложения.** Шаблон проверяет только главный exe через Restart Manager и при согласии (или в тихом режиме) принудительно закрывает его; дополнительные exe (`bars-mcp`, `bars-cli`) не проверяет, замена занятого файла падает, поэтому хук переименовывает их заранее. Шаблон вызывает хук `NSIS_HOOK_PREINSTALL` раньше, чем эту проверку, а записанный в Restart Manager путь `bars.exe` после переименования уже не находит процесс: хук, который переносит `bars.exe` в сторону, обязан сам убедиться, что воркер вышел, иначе его никто не завершит (ISS-107, [установщик](../features/distribution/installer.md#обновление-на-месте)). Принудительное закрытие `bars.exe` обрывает воркер без записи, поэтому хук сначала просит его выйти штатно: `bars.exe --quit` передаётся работающему экземпляру плагином единственного экземпляра ([features/window/implementation.md](../features/window/implementation.md)); без работающего экземпляра процесс сразу завершается, не создавая окна. Порядок обновления для пользователя — [features/distribution/installer.md](../features/distribution/installer.md#обновление-на-месте).
- **Обычное обновление.** Если пользователь соглашается «удалить прежнюю версию перед установкой» (выбор по умолчанию), новый установщик запускает прежний `uninstall.exe` на месте (`_?=<папка>`). Флаг `/UPDATE` туда попадает только когда он передан самому установщику, поэтому такой деинсталлятор считал бы вызов настоящим удалением и стёр бы запись автозапуска (шаблон удаляет значение `Run\<productName>`, и его имя совпадает с нашим). Хук `NSIS_HOOK_PREUNINSTALL` различает случаи: деинсталлятор из папки установки (`$EXEDIR == $INSTDIR`) — вызов из установщика, `$UpdateMode` ставится в 1; настоящий деинсталлятор копирует себя во временную папку и такого равенства не даёт.
- **Деинсталлятор прежней версии выполняет хуки прежней версии.** Поэтому правило обновления нужно закладывать в первую же выпущенную версию: хуки версии A обслужат обновление A→B.
- **Автозапуск.** Шаблон Tauri сам стирает `Run\<productName>` при настоящем удалении и сохраняет при обновлении; значение `bars` в нашей реализации ([features/distribution/autostart.md](../features/distribution/autostart.md)) именно под этим именем, и отдельной чистки в хуке для него не нужно. Хук дополнительно стирает отметку «Диспетчера задач» в `StartupApproved\Run`.
- **Установка в `%LOCALAPPDATA%\bars`.** Каталог установки отличается от каталога сборки ([build.md](build.md#где-хранятся-артефакты-сборки-target)); деинсталлятор стирает только свои файлы и `RMDir` без рекурсии. Если в папку установки вручную помещены чужие файлы, они сохранятся и папка не исчезнет.
- **sidecar-файлы.** `bundle.externalBin` требует файл `<имя>-<triple>.exe` рядом с конфигом уже при сборке `bars-app` (`tauri-build` проверяет). Поэтому конфиг упаковки отдельный (`--config tauri.bundle.conf.json`), а скрипт `scripts/build-installer.ps1` кладёт exe в `crates/bars-app/binaries/` перед сборкой.
- **Экземпляр после установки.** `RunAsUser` из шаблона запускает процесс от имени пользователя через оболочку и не передаёт окружение; хук запускает `bars` обычным `Exec`: установщик `currentUser` не повышен, а окружение наследуется (нужно для проверки на копиях, `BARS_USER_HOME`).

## Что проверено руками

Таблица ниже описывает прежний порядок хуков. Порядок ISS-107 (метка `update.lock`, перенос `bars.exe`, проверки до и после копирования) написан 05-11-2026 и не собирался и не проверялся: сборки на ноутбуке автора запрещены.

Версия A — 0.1.0, версия B — 0.1.1 (поднята временно в `Cargo.toml`, возвращена). Окружение: `BARS_USER_HOME` на временную папку с копиями-имитациями `~/.claude.json`, `~/.claude/settings.json`, `~/.codex/config.toml` (с чужими записями и комментарием), `~/.bars` с ссылкой-junction на настоящие модели (только чтение), тестовый проект с двумя документами, установка в `%TEMP%\bars-e2e\app`. Настоящие `~/.bars`, `~/.claude`, `~/.codex` не затрагивались.

| Шаг | Итог |
|---|---|
| Тихая установка A (`/S /D=…`) | в папке `bars.exe`, `bars-mcp.exe`, `bars-cli.exe`, `uninstall.exe`; запись об установке 0.1.0 |
| Запуск, регистрация проекта, `install` для обоих клиентов, `autostart on`, правка `settings.toml` | проект «готов», поиск работает; значение `bars` в `Run`; чужие записи клиентов целы |
| B поверх запущенных `bars` и `bars-mcp` (тихо, без `/UPDATE`) | код 0; версия 0.1.1; `bars` перезапущен автоматически; живой `bars-mcp` не убит, его файл переименован в `bars-mcp.exe.old`; новый `bars-mcp` отвечает на `initialize` |
| После обновления | снимки хешей `settings.toml`, `projects.toml`, конфигов клиентов и их `.bars-backup` до и после совпали; поиск даёт те же результаты; `autostart` — «включён»; записи клиентов указывают на те же пути |
| A поверх B (понижение, тихо) | код 2, ничего не изменено, `bars` не остановлен |
| B поверх B с `/P` | код 0, `bars` запущен, автозапуск цел |
| Деинсталлятор на месте (`uninstall.exe /S _?=<папка>`, как из установщика) | файлы стёрты, автозапуск и записи клиентов остались, отметка «запустить после установки» поставлена; следующая установка A запустила `bars` |
| Настоящее удаление (`uninstall.exe /S`) | процессы остановлены, папка удалена, запись об установке и автозапуск стёрты, `bars` убран из клиентов (чужие записи, хук и комментарий Codex на месте), `~/.bars` и `.bars` проекта целы |

Остался след `HKCU\Software\<издатель>\bars` (запомненная папка установки): шаблон стирает его только при флажке «удалить данные приложения». Так и задумано: при переустановке путь подставится прежний. Проверочный ключ после опытов удалён вручную.

## Что не проверено

- Обычный режим с окнами: клик по «Установить» и «Запустить bars», выбор «удалить перед установкой» мышью. Его пути (деинсталлятор на месте с `_?=`, `/P`) воспроизведены командной строкой, окна не открывались.
- Вид окна «Запуск» в настройках на собранном приложении и клик по галочке: интерфейс проверен на заглушке, воркер — тестами и `bars-cli autostart`; автозагрузка при реальном входе в систему не проверялась (перелогин).
- Перенос на другую папку установки и чистая установка при уже запущенном `bars` другого пользователя.
- macOS целиком.
