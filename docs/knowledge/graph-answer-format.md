# Формат ответов графа для агента — чужие MCP-серверы и GraphRAG, черновые форматы, прогон агентами Sonnet, стоимость списка инструментов

Статус: исследование шага 4.3.1, 24-10-2026. Проверено:
- объём четырёх форматов на 37 настоящих ответах графа (замороженный корпус 20-10);
- шесть прогонов агентами Sonnet по 13 задачам;
- размер `tools/list` собранного `bars-mcp`.

Не проверено:
- живой граф bars-project — он в состоянии `failed`;
- точный подсчёт токенов: числа даны оценкой;
- клиенты, кроме Claude Code.

Это исследование, а не решение: контракт ответа принят в 4.3.2 — [ответ графа для агента](../features/graphrag/tools.md).

## Вопрос и метод исследования формата ответов графа

Вопрос: в каком виде шесть графовых операций и `bars_rag_search` с `mode=mix` должны отвечать агенту, чтобы он прочитал ответ за один вызов, не тонул в объёме и не делал неверных выводов. Повод — ISS-22: сейчас `txt` графа — это JSON одной строкой, 51–59 тыс. знаков на вопрос (находка А-1 [аудита работы агентов](../audits/agent-usage-2026-10-23.md)). Второй вопрос — во что обходится список инструментов (ISS-23).

Метод:

1. **Чужие форматы.** Документация и исходники Microsoft GraphRAG, LightRAG, официального MCP-сервера memory и Graphiti, спецификация MCP 2025-06-18, рекомендации Anthropic о написании инструментов для агентов, документация Claude Code о пределах вывода MCP.
2. **Черновые форматы.** Скрипт `render.mjs` строит четыре вида из настоящих DTO [независимой оценки GraphRAG](graph-quality-2026-10-20/Index.md): 32 случая S1–S8, 4 точечных контроля и аналог задачи З10 (mix):
   - **J** — текущий вывод `bars-mcp` (`=== GRAPH: Impact ===` и JSON);
   - **A** — строка на факт с основанием `путь:строка «цитата»` прямо под ней, без состояния;
   - **B** — A плюс строка состояния (слои, недостающие роли, усечение и продолжение), пустой ответ со следующим шагом, предел 16 тыс. знаков;
   - **C** — компактный JSON без эха запроса и хешей, основание внутри элемента.
3. **Прогон агентами Sonnet.** 13 задач:
   - 9 случаев S2–S8 с разными операциями;
   - аналоги задач аудита: З11 (`impact` по документу), З10 (mix), З12 (`conflict_candidates`), путь с неразрешённым именем.

   Шесть субагентов Sonnet, по два на формат J, A, B. Каждый видит только папку своего формата и отвечает по-русски со ссылками `путь:строка`, оценкой достаточности, следующим вызовом и трудностью 1–5. Ответы сверены с эталоном `gold-matched.json`.
4. **Список инструментов.** Ответ `initialize` и `tools/list` от `C:\bt\bars\debug\bars-mcp.exe` (сборка 24-10, схемы инструментов совпадают с коммитом `f4ce7a3`); пересчёт для схем по операции и для скрытых графовых инструментов.

Токены оценены как в проекте контракта `context` (`estimate-v1`: байты UTF-8 / 3). Для английского JSON это завышение примерно на четверть, для русского текста — занижение.

## Как отвечают другие MCP-серверы и GraphRAG

| Источник | Как устроен ответ | Что взять для bars |
|---|---|---|
| Microsoft GraphRAG, local search | Контекст — таблицы `-----Entities-----`, `-----Relationships-----` с разделителем `\|` и короткими `id`; строки добавляются, пока помещаются в `max_context_tokens` (8000); строка не режется посередине | Таблица строкой на факт, короткие номера вместо хешей, усечение целыми строками |
| LightRAG | Разделы «Knowledge Graph Data (Entity)», «(Relationship)», «Document Chunks», «Reference Document List»; чанки ссылаются на `reference_id` списка документов; бюджеты отдельно на сущности, отношения и текст (по 4000 токенов) | Справочник документов один раз, в фактах — короткая ссылка; раздельный бюджет фактов и цитат |
| MCP memory (официальный) | `read_graph`/`search_nodes` отдают JSON `entities`(name, entityType, observations) и `relations`(from, to, relationType); имена вместо ID; пределов нет | Имена участников прямо в отношении; без предела такой ответ ломается на больших графах |
| Graphiti MCP | Факт — текст ребра с интервалом `valid_at`/`invalid_at` | Факт формулируется фразой источника, а не парой идентификаторов |
| Спецификация MCP 2025-06-18 | `content` для модели и необязательный `structuredContent` с `outputSchema`; структурный ответ дублируется JSON-текстом для совместимости; ошибка исполнения — результат с `isError` | Текст для модели и JSON — разные каналы; `outputSchema` даёт клиенту структуру, не раздувая текст |
| Anthropic, «Writing tools for agents» | `response_format` concise/detailed (в примере краткий — треть токенов подробного); осмысленные имена вместо UUID снижают ошибки; усечение с подсказкой, как сузить запрос; ошибка с примером правильного ввода | Краткий вид по умолчанию, ref-ы только в подробном; подсказка следующего шага |
| Claude Code | Предупреждение при выводе MCP больше 10 тыс. токенов, предел 25 тыс. (`MAX_MCP_OUTPUT_TOKENS`); текст больше 50 тыс. знаков сохраняется в файл | Текущие ответы графа (до 115 тыс. знаков) упираются в оба порога |

Общее у всех: факт читается без сопоставления идентификаторов, у объёма есть предел, при усечении объясняется, как продолжить. Ни один из просмотренных серверов не отдаёт модели нормализованный граф с хешами, как сейчас bars.

Источники: [Writing tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents), [GraphRAG local search](https://microsoft.github.io/graphrag/query/local_search/) и `graphrag/query/context_builder/local_context.py`, [LightRAG prompt.py](https://github.com/HKUDS/LightRAG/blob/main/lightrag/prompt.py), [MCP memory](https://github.com/modelcontextprotocol/servers/tree/main/src/memory), [MCP tools 2025-06-18](https://modelcontextprotocol.io/specification/2025-06-18/server/tools), [Claude Code MCP](https://code.claude.com/docs/en/mcp).

## Объём черновых форматов на 37 ответах графа

Медиана и максимум, знаков:

| Группа ответов | Случаев | J | A | B | C |
|---|---|---|---|---|---|
| Пустые (`impact`, `paths`, `relations`, `explore`) | 13 | 1 906 / 3 847 | 61 / 132 | 300 / 363 | 223 / 243 |
| `relations` | 4 | 10 259 / 26 481 | 658 / 1 761 | 780 / 1 883 | 1 122 / 2 777 |
| `context` | 12 | 25 576 / 34 930 | 5 061 / 6 837 | 5 281 / 7 020 | 5 644 / 7 543 |
| `explore` | 7 | 52 935 / 115 176 | 2 332 / 10 370 | 2 515 / 10 492 | 3 481 / 13 689 |
| mix (аналог З10) | 1 | 70 395 | 10 353 | 10 554 | 22 427 |

Всего по 37 ответам: J — 920 тыс. знаков, A — 108 тыс., B — 115 тыс., C — 144 тыс. Текст в 8,5 раза (A) и 8,0 раза (B) короче J, компактный JSON — в 6,4 раза. Строка состояния и подсказка B добавляют около 7 %.

Откуда объём J: 64-значные хеши — 41,5 % знаков, массив `nodes` — 14,5 %, эхо `requested` — 3 %. Пустой ответ J — около 1,9 тыс. знаков служебных полей без единого факта. Самый большой ответ — `explore` topics (115 тыс.): он перечисляет узлы и ссылки, хотя агенту нужны темы и их документы.

## Прогон агентами Sonnet: шесть прогонов по 13 задачам

| Прогон | Токены субагента | Вызовов инструментов | Время, с | Да / частично / нет | Средняя трудность |
|---|---|---|---|---|---|
| J1 | 134 790 | 14 | 180 | 4 / 3 / 6 | 3,08 |
| J2 | 151 312 | 16 | 175 | 4 / 4 / 5 | 3,08 |
| A1 | 119 622 | 6 | 83 | 4 / 2 / 7 | 3,00 |
| A2 | 122 933 | 6 | 83 | 4 / 2 / 7 | 2,85 |
| B1 | 116 536 | 7 | 75 | 4 / 2 / 7 | 2,23 |
| B2 | 123 603 | 6 | 70 | 4 / 2 / 7 | 2,38 |

Как читать:
- **Токены и время.** На JSON агенты тратили в 2,3 раза больше вызовов и времени: большие однострочные файлы приходилось разбирать node и grep. Токенов уходило на 15–30 тыс. больше. Разница в токенах меньше разницы в объёме, потому что агент читал JSON выборочно; это работа самого агента, а не экономия.
- **Верность.** Неверных утверждений о проекте не сделал ни один агент. Это заслуга не формата, а содержимого: в ответах графа было лишь 4 из 25 нужных фрагментов эталона, и на T01–T03, T05, T07, T10, T11, T13 все шесть честно ответили «недостаточно».
- **Где формат изменил вывод:**
  - **T08 (`explore` connectivity, 50 из большего числа ссылок).** В A не было признака усечения, и A1 написал «полный список в ответе» — ложная полнота. B и J увидели усечение и курсор.
  - **T10, T13 (пустой ответ).** В B подсказка «Next…» дала следующий вызов (трудность 1). В A «No results.» без причины получило трудность 3; агенты гадали, «нет связей или корень задан неверно».
  - **T12 (mix).** В A и B связанные пути остались сырым JSON: в черновике не отрисован тип элемента `path`, это дефект `render.mjs`. Агенты J нашли в связанных пакетах ещё `settings.md:120` и `indexing-progress.md:16`. Вывод: формат должен покрывать все типы элементов, иначе текст теряет то, что было в JSON.
  - **T07 (`explore` topics).** В A и B темы шли списками путей без названия: черновик отбросил `label`. Агенты J назвали темы по заголовкам документов.
- **Трудность.** B оценён легче всех (2,2–2,4 против 3,1 у J). У A и J одинаково (2,9–3,1), но причины разные: у J — разбор идентификаторов, у A — отсутствие состояния и причин.

## Что мешало агентам в ответах графа

Повторяющиеся замечания самих агентов, по всем форматам:

- **Смысловая выдача нерелевантна вопросу.** `relations` на T01–T03 вернул отношения по глаголу «заменяет» и слову «модель»: это качество извлечения и сопоставления, его исправляют 4.3.6–4.3.8, а не формат. Формат только не должен делать нерелевантный ответ убедительнее.
- **Повторы цитат в `context`.** Одно место приходит несколько раз: диапазон `MAIN_IDEA.md:368-374` и вложенные в него строки 368, 370, 372, 374. Склейка вложенных диапазонов документа сократила бы `context` заметно и убрала бы шум.
- **Цитата, обрезанная на 300 знаках,** иногда отрезала нужное место (T05). Цитату лучше резать по границе предложения и давать `путь:строки` для дочитывания.
- **Кандидат имени без ссылки** нельзя подставить в следующий вызов (T11). Кандидату нужен ref или точная подпись, которую принимает `from`/`to`.
- **Корень `impact` только как ObjectRef.** Агент знает путь, а не ref (T10, З11 аудита) — подтверждает пункт «вход по пути документа» в 4.3.2.
- **Тема `explore` без имени и строк.** Агенту нужны название темы и документы-представители со строками, а не только пути.
- **Строка состояния полезна, когда в ней событие.** Агенты цитировали «semantic partial» и «truncated by limit; continue with cursor». Постоянная оговорка о неполноте в конце каждого ответа повторяется и не мешала, но и нового не сообщала.

## Стоимость списка инструментов bars-mcp

| Вариант | Инструментов | Байт JSON | Оценка токенов |
|---|---|---|---|
| Сейчас | 16 | 52 699 | ≈ 13–18 тыс. |
| из них шесть графовых | 6 | 32 059 | ≈ 8–11 тыс. |
| Схема у каждой операции своя | 16 | 34 840 | ≈ 9–12 тыс. |
| из них шесть графовых | 6 | 14 199 | ≈ 3,5–4,7 тыс. |
| Графовые скрыты (OQ-162) | 10 | 20 641 | ≈ 5–7 тыс. |

Сейчас у каждой графовой операции 32 поля, 4 807 знаков схемы, ровно одинаковой у всех шести. Своя схема оставляет 8–13 полей (общие `project`, `format`, `modules`, `files`, `limit`, `cursor` и поля операции по фактическому контракту v1 [инструментов GraphRAG](../features/graphrag/tools.md)) и 1,7–3,2 КБ на операцию. Графовые инструменты — 61 % списка; их схемы по операции сокращают весь список на треть, скрытие — на 61 %. Стартовая инструкция `initialize` — 1 952 знака, отдельно от списка.

Где это платится. В Claude Code с поиском инструментов по умолчанию описания MCP могут откладываться до поиска. Но в сессии этого исследования схемы bars были загружены сразу целиком. Клиенты без отложенной загрузки платят за весь список в каждой сессии; поведение Codex здесь не проверялось. Оценка: 13–18 тыс. токенов на bars, из них 8–11 тыс. — графовые инструменты, которыми агенты по журналу MCP не пользуются (5 вызовов на 628).

## Предложения для проектирования контракта 4.3.2

Предложения исследования, не решения автора:

1. **Текст по умолчанию — вид B:** строка на факт с основанием `путь:строки «цитата»` под ней; строка состояния только при событии (частичный слой, недостающие роли, усечение с курсором или подсказкой сузить область); пустой ответ — причина и следующий шаг по операции. JSON остаётся за `format=json`; возможный канал — `structuredContent` с `outputSchema`.
2. **Покрыть все типы элементов** (`relation`, `path`, `role_group`, `topic`, `audit`, кандидаты); неизвестный тип — понятная строка, а не JSON. Проверка: на каждом типе текст не теряет источников, которые есть в JSON.
3. **Справочник документов один раз** (как Reference Document List у LightRAG), в фактах — путь от корня документации; никаких 64-значных хешей в тексте. Ref-ы для следующего вызова — только там, где они нужны: у кандидатов имён и у корней.
4. **Склеивать вложенные диапазоны одного документа** в `context` и не повторять цитату в нескольких ролях.
5. **Предел текста** порядка 16 тыс. знаков (≈ 5 тыс. токенов), ниже порога предупреждения Claude Code. Усечение — целыми фактами, с числом скрытых и способом продолжить.
6. **Тема `explore`** — имя, число документов, представители со строками.
7. **Список инструментов:** своя схема у каждой операции и скрытие графовых по умолчанию дают вместе около 30 тыс. байт экономии на сессию; описания «когда звать» — в той же правке (ISS-27).

## Ограничения исследования формата

- Ответы графа взяты из замороженного корпуса 20-10 и метода `explicit-markdown-v4`; нынешний метод v6 и живой корпус не проверены. Живой граф bars-project сейчас `failed` («ссылка на объект устарела: editor-design.md»).
- В эталоне 4 из 25 нужных фрагментов есть в ответах графа, поэтому прогон проверяет честность и удобство формата, а не способность формата донести правильный ответ. Повторить после 4.3.6–4.3.8.
- По два прогона на формат и одна модель (Sonnet); вердикты выставил один агент, знавший форматы. Разброс внутри формата мал, но статистической значимости нет.
- В черновиках A и B не отрисован тип `path` (mix) и отброшено имя темы; оба дефекта повлияли на T07 и T12 и описаны выше.
- Токены оценены `estimate-v1`, не токенизатором клиента. Полные тексты ответов агентов не сохранились; в данных — их оценки и вердикт.
