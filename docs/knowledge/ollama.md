# Ollama — API, модели и границы подключения

Статус 23-10-2026: официальные API, нативный embed и полный индекс/поиск через bars проверены на RTX 3090. Сравнительное качество Ollama на корпусе и установленное окно не проверены. [Предыдущее исследование встроенных GGUF](gguf-models.md) проверило Qwen 0.6B/4B на RTX 3090 и 100 вопросах, но не показало устойчивого преимущества над bge-m3; оно не доказывает качество внешнего сервера Ollama.

## API Ollama и выбор транспорта

[Нативный embed API](https://docs.ollama.com/api/embed) принимает пачку и позволяет запретить обрезание через `truncate: false`. Поэтому отдельный источник предпочтительнее существующего OpenAI-совместимого транспорта. Поля ответа `embeddings`; размерность определяется первым ответом. В [маршрутах upstream](https://github.com/ollama/ollama/blob/main/server/routes.go) rerank отсутствует; [запрос #3368](https://github.com/ollama/ollama/issues/3368) открыт. Загрузка GGUF с названием reranker сама по себе не создаёт API и корректного cross-encoder scoring. Реализация контракта — [внешние модели](../features/models/external-models.md).

## Кандидаты embedding для RTX 3090

[Официальная библиотека Qwen3](https://ollama.com/library/qwen3-embedding) предлагает `qwen3-embedding:0.6b` (около 639 МБ), `:4b` (2,5 ГБ), `:8b` (4,7 ГБ). Это объём весов, не VRAM процесса. Для ограниченного первого прогона — 0.6b; 4b/8b — кандидаты на качество, без заявления о преимуществе на корпусе bars. [Авторы Qwen](https://github.com/QwenLM/Qwen3-Embedding) рекомендуют instruction к запросу; bars использует существующий QWEN3_QUERY_PREFIX. Библиотека Ollama также содержит bge-m3 и nomic, но здесь их качество и рецепты префиксов не проверены.

## Метод проверки Ollama

Проверки транспорта: пачки, порядок, ключ, ошибка контекста без повторов, плохой ответ и изменение размерности; настройки и отдельный rerank; полный путь индекс → поиск через ConfiguredProvider. Настоящий сервер — отдельный процесс, тестовый профиль/индекс, запись версии, digest модели, GPU через `/api/ps`, размерности и поиска. По указанию автора тестовые модели хранятся исключительно в `D:\text-generation-webui-1.16\models` через `OLLAMA_MODELS` процесса; рабочий bars и его настройки не меняются. Малый smoke-прогон не подтверждает сравнительное качество, p95 большого корпуса или установленное окно.

ISS-18 остаётся отдельной задачей: внешний процесс переносит размещение весов под управление Ollama, но не доказывает снижения суммарной памяти или доступности поиска во время большой индексации. Причины и исходные числа — в [исследовании памяти](memory.md). Устройство embed и rerank остаётся независимым (IDEA-01); привычные параметры CPU/GPU встроенной модели не должны выдавать внешнюю модель за DirectML.

## Аппаратная проба 23-10-2026

Официальный portable Ollama 0.40.9, архив проверен по опубликованному SHA-256. Сервер на `127.0.0.1:11435` обнаружил RTX 3090, CUDA compute 8.6, драйвер API 13.4. `qwen3-embedding:0.6b` — Q8_0, 639 150 858 байт, digest `ac6da0dfba84a81fdbfbaf330198c33cd77c4cdfc53e8bc50eb581914a15621d`. Два текста дали по 1024 координаты. После инференса `/api/ps` показал `size_vram=size=4 634 632 519` байт при контексте 32768. Это выделение памяти по API сервера, не пик и не профилирование каждого оператора. Профиль изолирован; manifest и blobs лежат в указанном автором каталоге на D:.

Та же сборка вернула HTTP 404 на `POST /rerank`, `/v1/rerank`, `/api/rerank`: отсутствие маршрута подтверждено на тестовом сервере, а не только по upstream.

Стенд `crates/bars-worker/examples/verify_ollama.rs` прошёл на release: временный проект из трёх документов, индекс `ollama:qwen3-embedding:0.6b`, состояние `Ready`, без ошибки; настоящая запись размера пачки через `SettingsSave` и чтение `SettingsGet`; два русскоязычных запроса вернули ожидаемый раздел первым. Профиль и индекс удалены штатно после `shutdown`; модель выгружена, отдельный сервер остановлен. Веса остаются на D:. Временная portable-сборка осталась в `%TEMP%/bars-ollama-5-1`: автоматическая проверка отклонила удаление. Установленный bars не менялся.

Рецепт отличается от прежней встроенной Q4_K_M с контекстом 8192: сравнивать их качество и расход по этим двум пробам нельзя. Холодная загрузка и два поиска выполнялись на машине с параллельными сборками; времена 824/353 мс — отдельные наблюдения, не бенчмарк или p95. Воспроизведение при заранее запущенном сервере и скачанной модели: `cargo run --release -p bars-worker --example verify_ollama -- http://127.0.0.1:11435 qwen3-embedding:0.6b <evidence.json>`.
