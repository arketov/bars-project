# Повторный счёт modules и bars_projects в журнале MCP — 01-11-2026

Статус: исследование 4.4.4 завершено по решению автора 01-11-2026 на доступной части журнала 25-10—01-11-2026; 1 201 поиск, 274 соединения с поиском. Неделя после подтверждённой доставки новых правил не установлена; закрытие пункта не означает проверку этого условия.

## Метод повторного счёта MCP

Основание — [приёмка выбора модулей](../features/agent-tools/module-scope.md): доля поисков с непустым `modules` и доля соединений с поиском, вызвавших `bars_projects`. Это наблюдение, а не норма частоты и не оценка качества поиска.

Источник — `~/.bars/mcp-statistics.sqlite3`, таблица `attempts` версии 2. Чтение через SQLite read-only внутри одной транзакции. Верхняя граница — 01-11-2026 13:40:00 Asia/Yekaterinburg, до первого вызова этой сессии; нижняя — ровно семь суток назад. Интервал полуоткрытый. История ограничена сроком, числом строк и байтами: отсутствие записи не доказывает отсутствие вызова. Состав и ограничения данных задаёт [контракт истории MCP](../features/window/mcp-statistics.md).

Сохраняется только проекция для пересчёта: время, локальный номер попытки, псевдоним соединения, условное имя проекта, инструмент, исход и категория области с учётом полноты, номер повтора. Нет запросов, содержимого документов, исходных идентификаторов, путей и текстов ошибок. [Сводка счётчика](agent-module-usage-2026-11-01/snapshot/summary.json) получена из зафиксированного `records.jsonl`; SHA-256 файла и границы находятся в соседнем `snapshot.json`.

Считаются и успешные, и ошибочные поиски. `modules` и `files` — непустые массивы; совместное использование выделяется отдельно. При отсутствии исходного MCP-входа область считается неизвестной. Первым поиском считается самый ранний наблюдаемый в интервале, с порядком по ID при равном времени.

`bars_projects` соединяется с поиском по паре эпоха воркера + ID соединения, независимо от проекта попытки: у общего списка проект пустой. Переподключения одного чата могут давать несколько соединений. Доли по проектам не складываются: одно соединение может искать в нескольких проектах.

Основной счёт — попытки, как в прежнем аудите. Дополнительный исключает только явно помеченные повторы `applied.proxy_attempt > 1`; отсутствие метки не позволяет угадать повторы старого прокси. Прогон Sonnet 24 октября исключён датой; принадлежность остальных вызовов экспериментам в журнале не записана.

Самая ранняя сохранённая попытка — 25-10-2026 13:50:03: первые 10 минут 3 секунды запрошенной недели уже вне сохранённой истории. Неизвестно, были ли в потерянном начале поиски. Это доступная часть семи суток, а не доказанно полный недельный журнал. Отсутствие записей за 27 октября означает только отсутствие наблюдений в снимке.

Дата и версия установленного файла не дают дату получения конкретного текста каждым агентом. История не содержит клиента, модели, задания или признака контролируемого эксперимента; исключить все такие эксперименты, разделить Claude/Codex и доказать изменение поведения одной модели нельзя. Отдельные чаты могут открывать много соединений. Первое событие в интервале может быть продолжением старого соединения; `bars_projects` до нижней границы не учитывается.

Правильность выбранного модуля, релевантность выдачи и полезность ответа не размечались. Высокая частота фильтра сама по себе не доказывает улучшение поиска. Счёт частот не заменяет [бенч качества выбора модулей](module-scope-bench.md).

## Воспроизведение и стоимость счётчика

Команды из корня репозитория, Node.js с `node:sqlite`, без пакетов и инференса:

```powershell
node --test docs/knowledge/agent-module-usage-2026-11-01/analyze.test.mjs
node docs/knowledge/agent-module-usage-2026-11-01/analyze.mjs report docs/knowledge/agent-module-usage-2026-11-01/snapshot
# Новый замер — в новую папку; исходная база открывается только на чтение.
node --no-warnings docs/knowledge/agent-module-usage-2026-11-01/analyze.mjs capture "$env:USERPROFILE/.bars/mcp-statistics.sqlite3" 2026-11-01T08:40:00Z docs/knowledge/agent-module-usage-2026-11-01/new-snapshot
```

Повторное чтение живой базы спустя время не обязано дать прежние числа: её обслуживает воркер. Для точного пересчёта используется сохранённая проекция с проверкой SHA-256. Начальная транзакция и подготовка проекции заняли 70 мс на 6 012 исходных попытках; два пересчёта 1 333 записей — 14 и 61 мс на занятой машине. Это локальная стоимость исследовательского скрипта, не SLA продукта. Он не пишет в рабочую базу, не вызывает MCP, не запускает модель и не меняет установленное приложение.

## Проверки исследования и граница проектных проверок

Четыре теста счётчика прошли; независимый SQL по сохранённой проекции подтвердил оба знаменателя и числителя. SHA-256 проверен также после помещения данных в Git. Два прохода Sol-ревью не оставили замечаний; отдельно проверялись логика, полнота, приватность, производительность и отсутствие лишнего усложнения. В сравнении с прежним аудитом число первых поисков с `modules` не выводится из числа поисков без фильтра: остальные могли использовать `files`.

Полный `scripts/check.ps1` на снимке исходной базы `b777200` прошёл fmt, clippy и build; в существующем воркере четыре теста исчерпали ожидание: `shutdown_joins_in_flight_blocking_drop`, `full_rebuild_keeps_status_window_controls_and_full_ipc_search_responsive`, `scan_exposes_explicit_documents_while_indexing_is_paused`, `hundreds_of_files_at_once_reach_the_index`. Причина падений не установлена; зелёный полный прогон не заявляется. Повтор с двумя потоками тестов остановлен после указания автора завершать работу и отправить коммит при мешающих соседних правках. Это разрешение относится к завершению данной сессии, а не меняет общее правило проверок проекта.
