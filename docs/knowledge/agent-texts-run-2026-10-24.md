# Прогон 14 задач аудита агентами Sonnet со старыми и новыми текстами bars 24-10-2026

Статус: исследование 24-10-2026, правок кода, инструкции, skills и описаний инструментов нет. Проверено 28 запусками агентов Sonnet в Claude Code на установленной сборке (14 инструментов MCP, без `bars_text_search` и `bars_links`). Каждая задача прогнана один раз в каждой группе, без повтора, поэтому разница в одну задачу может быть случайной. Задачи и их прежний разбор — [аудит работы агентов](../audits/agent-usage-2026-10-23.md). Новые тексты — кандидат для свода правил агента в [инструкции bars](../features/docs-convention/bars-instruction.md), а не принятое решение.

## Вопрос и условия прогона текстов агента

Вопрос: меняют ли предложенные аудитом тексты для агента выбор инструментов, объём ответов и правильность на тех же 14 задачах.

Условия согласованы с автором 24-10-2026 (OQ-175, OQ-176, OQ-177):

- **Новые тексты** собраны из предложений аудита. Взяты только правила, которые выполнимы на 14 установленных инструментах. Правила для `bars_text_search`, `bars_links`, чтения части документа и списка документов не проверялись. Правило номеров переписано на чтение реестра, потому что `bars_text_search` не установлен.
- **Доставка.** Обе группы получили в задании блок «правила bars» одинакового строения: стартовая инструкция `initialize`, выбор инструмента из skill `bars-docs`, выдержки описаний. Старая группа получила нынешние тексты установленной сборки, новая — те же места в новой редакции. Описания в схеме инструментов, `initialize` сервера и skills в контексте клиента у обеих групп остались старыми.
- **Объём.** 28 агентов Sonnet, по одному на задачу и группу, у каждого свежий контекст. Обе группы одной задачи шли в одной пачке: задачи 1–7, затем 8–14.
- **Счёт.** Вызовы, их аргументы и объём ответов взяты из журналов агентов Claude Code, а не со слов агентов. Правильность сверена с ключом, составленным до прогона по текущим документам. Оценивал тот же агент, который собрал новые тексты.

Отличия новых текстов от старых:

| Правило | Старые тексты | Новые тексты |
|---|---|---|
| Область поиска | «Для межслойной задачи ищи по всему проекту», «Filtering is optional» | Модуль по виду знания с назначением каждого модуля, список модулей bars-project с числом документов; неясно — весь проект, потом сузить |
| Вложенная папка | Не модуль, имена даёт `bars_projects` | То же и пример `features/models` → `files` или `features` |
| Путь из выдачи в `files` | Пути от docs-root | Убрать префикс `docs/` из поля `path` выдачи |
| Номер Т-N, ISS-N, OQ-N | Нет правила | Определение в реестре: `bars_outline`, затем `bars_read` |
| Последний handoff | Поиск с `modules:["chats"]` | Перечислить `chats/` и взять самую новую папку темы; поиск не знает дат |
| Граф и `mode=mix` | Шесть графовых инструментов, mix «добавляет связанные источники» | Графовые операции экспериментальные, пустой ответ ничего не доказывает; mix — десятки килобайт |
| Перед правкой документа | `bars_impact`, затем `bars_get_similar` | Поиск по предмету, текстовый поиск имени файла, similar; impact без гиперссылок |
| `bars_reindex` | При устаревшем индексе или внешней правке | Только при `reindex_required`, не при `model_loading` и `graph_not_ready` |

## Выводы о текстах для агента

- **Последний handoff по имени папки — единственное правило, исправившее ошибку.** В З4 старая группа поиском по `chats` взяла этап 29, новая перечислила папки и нашла этап 30. Правило стоит брать в свод.
- **Предупреждение о mix работает.** Старая группа трижды вызвала mix (З2, З10, З11), один ответ не поместился в контекст. Новая не вызвала ни разу; объём ответов bars меньше на 23%.
- **Правило номеров в нынешнем виде вредно.** «Outline, затем read» без чтения части документа привело к чтению MAIN_IDEA.md целиком (68 тыс. знаков) и отказу клиента. Обе группы в итоге нашли Т-25 через Grep. До чтения по строкам (OQ-158) или `bars_text_search` правило должно звать поиск с `files:["MAIN_IDEA.md"]` или чтение по найденным строкам, а не `bars_read` целого реестра.
- **Список модулей не изменил выбор области.** Доля поисков с `modules` и первых поисков с `modules` одинакова. Обе группы выбирали верный модуль первого уровня там, где вид знания очевиден (`chats`, `features`, `backlog`), и ни одна не угадала вложенный `models` в З7, где задание прямо звало к `features/models`. На этих задачах нейтральный текст OQ-161 не дал выигрыша и не навредил.
- **Слова «экспериментальные» не остановили граф, когда задача просит связанные источники.** В З10 новая группа вызвала `bars_context`; ошибку `graph_not_ready` агент обработал сам и ответил по поиску. `bars_reindex` не вызывала ни одна группа.
- **Обход bars через Grep остаётся в обеих группах** для задач «шаг плана», «номер», «где ещё упоминается», «кто ссылается на файл». Это место для `bars_text_search` и `bars_links` из новой сборки; на установленной сборке агент прав, что идёт в Grep.

## Ограничения прогона текстов агента

- Один прогон на задачу и группу: разница в одну задачу (З2, З4) не доказана статистически.
- Тексты доставлены в задании, а не через `initialize`, описания и skills. Описания в схеме инструментов у обеих групп старые, и старые тексты в контексте клиента присутствовали у обеих групп одновременно с блоком задания.
- Задачи З7 и З8 переформулированы под текущее состояние: шаг 3.3.1 уже выполнен, поэтому взят 3.3.4; в З7 задание само называет папку `features/models`, чтобы проверить угадывание модуля.
- Во время прогона индекс обновлялся (`pending` до 5), граф был в состоянии `stale`.
- Одна модель (Sonnet), один клиент (Claude Code), один проект. Codex не проверялся.
- Ключ ответов и оценку делал агент, который собрал новые тексты; независимой разметки нет.
- В журнал MCP 24-10-2026 попали вызовы прогона. Повторный счёт по журналу берут за неделю после установки новой сборки, и вызовы прогона в него не входят.

## Новые тексты прогона — кандидат для свода правил

Текст блока, который получила новая группа. Правило номеров здесь в проверенной, неудачной редакции.

```text
[A. Инструкции сервера bars (initialize)]
- Контекст неизвестен: bars_rag_search, предметный вопрос на языке пользователя. Если ясно, какой вид знания нужен, передай modules: поведение и контракты — features, устройство — architecture, решения — adr, исследования — knowledge, баги и идеи — backlog, руководство пользователя — manual, аудиты — audits, история сессий — chats. Неясно или нужны несколько видов — весь проект; потом сузь по модулям, из которых пришли результаты.
- Модули проекта bars-project: features (78), architecture (11), adr (6), knowledge (67), backlog (3), manual (15), audits (4), chats (264), «.» — корень (4). Вложенная папка (например features/models) — не модуль: для неё используй files или modules:["features"].
- files — выбранные индексируемые документы, пути от docs-root. Путь из поля path выдачи начинается с docs/ — для files убери этот префикс.
- Номер (Т-N, ISS-N, IDEA-N, OQ-N): поиск по смыслу возвращает документы, которые на номер ссылаются, а не его определение. Определение — в реестре: Т-N — MAIN_IDEA.md, ISS-N — backlog/issues.md, IDEA-N — backlog/ideas.md, OQ-N — QUESTIONS.md в корне проекта. bars_outline реестра, затем bars_read; строку реестра можно искать и поиском с modules:["backlog"].
- Последний handoff по теме: папки сессий называются chats/<YYYY-MM-DD>-<тема>, поиск ранжирует по смыслу, а не по дате. Перечисли папку docs/chats своими средствами (список каталога) и возьми самую новую по теме, затем bars_read её handoff.md.
- bars_reindex — только когда bars_status показывает reindex_required; не при model_loading (прокси ждёт сам) и не при graph_not_ready (граф строится сам после обновления индекса).
Граф: шесть read-only инструментов (relations, paths, impact, context, explore, graph) — экспериментальные. Смысловой слой частичный: пустой ответ ничего не доказывает; ответы бывают десятки килобайт. Для обычной задачи начинай с bars_rag_search и bars_read.

[B. Skill bars-docs, выбор инструмента — изменённые шаги]
2. Pick `modules` by the kind of knowledge when it is clear: features for behaviour and contracts, architecture for structure, adr for decisions, knowledge for research, backlog for bugs and ideas, chats for session history. Search the whole project when the kind is unclear or several kinds are needed, then narrow by the modules the results came from. Never guess a nested folder as a module.
3. Need an ID (Т-N, ISS-N, OQ-N) → read its register (outline, then read); semantic search returns documents that mention the ID, not its definition.
4. About to change a document → `bars_rag_search` for the descriptions of its subject, then find the documents that link to its file name (a text search for the file name in the documentation), then `bars_get_similar` on the section you will edit. `bars_impact` adds typed dependencies when the graph has them; an empty impact proves nothing, and hyperlinks are not in it.
5. Need a session result → list `chats/` and read the newest matching `handoff.md`.
- `bars_rag_search`: `mode=mix` adds graph sources and can return tens of kilobytes; set a small `related_budget` or do not use it.
- `bars_reindex`: only when `bars_status` shows `reindex_required`, or a file changed while bars was not running and stays missing after the normal pause.
- `bars_get_similar` also returns sections of the same document; to find other places with the same text, pass `modules` and skip hits from the source document.

[C. Описания инструментов — новые редакции]
- bars_rag_search, mode: «hybrid — обычный поиск, тот же ответ, что без поля; mix — плюс связанные источники графа (объёмно, задай related_budget); graph — отношения вместо фрагментов.» include_related: «Только для mix: false — без связанных источников; по умолчанию true.»
- bars_impact: «… Смысловой слой частичный: пустой ответ не значит, что зависимостей нет; гиперссылки сюда не входят.»
- bars_context: «Первичные источники для задачи по ролям. Не ответ, а список для чтения; смотри missing_roles. По умолчанию прерывается через 1 с — задай budgets.timeout_ms до 5000.»
- bars_explore: «… Кандидат — повод прочитать, не вывод. Пустой ответ при частичном слое ничего не доказывает.»
```

Старые тексты — нынешние `initialize` установленного `bars-mcp`, раздел «Choosing a tool» и «Choose the subject and sources» установленного skill `bars-docs` и описания инструментов установленной сборки. Сырые вызовы всех 28 агентов — `runs.json` в журнале сессии `chats/2026-10-24-agent-texts-run`.
