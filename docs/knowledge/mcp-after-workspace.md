# Изменения MCP после рабочего окна и редактора

Статус на 23-10-2026: исследование и согласование 4.4.1 завершены. OQ-146: автор выбрал инструкции и два инструмента чтения; инженерный выбор по разрешению автора — без счётчиков статуса. Выполнена статическая сверка требований, прежних исследований, MCP, протокола и окна, привлечён архитектор с доступом bars. В 4.4.2 добавлены API и assets, пройдены проверки общего движка, MCP/IPC, настоящего stdio и доставки в изолированные профили; текущий контракт принадлежит документу MCP. Установленная версия и нативная приёмка не подтверждены.

## Задача и источники исследования MCP

Основано на: [требованиях проекта](../MAIN_IDEA.md) (Т-8, Т-19, Т-25, Т-27, Т-28, Т-37, Т-39, Т-41…Т-47), [границах базы знаний](../features/knowledge-base/requirements.md), [контракте MCP](../features/agent-tools/mcp-tools.md), [контракте GraphRAG](../features/graphrag/tools.md).

Вопрос исследования: какие изменения агентского интерфейса нужны после новых панелей, редактора, ссылок, поиска и аудитов, без копирования каждого действия окна в отдельный инструмент. Т-37 требует доступности функций MCP человеку; обратное правило «каждая кнопка окна обязана иметь MCP» автором не принято. Автор исключил MCP-запись файлов: агенты редактируют их напрямую.

Метод: чтение текущего checkout, инвентаризация `#[tool(name)]`, сопоставление с таблицей допуска `methods!`, DTO, обработчиками и компонентами окна. Факты и пути воспроизводятся в `crates/bars-mcp/src/{lib,instructions,render}.rs`, `crates/bars-protocol/src/{methods,links}.rs`, `crates/bars-worker/src/handler/links.rs`, `ui/src/lib/{GraphTab,WorkspaceDocument,AuditsPage}.svelte` и `ui/src/lib/graph/{PhysicalGraph.svelte,semantic.ts}`. Это проверка маршрутов и контрактов; она не заменяет запуск сценариев.

## Что уже исследовано и повторять не требуется

[Разбор вызовов агентами 18-10-2026](agent-tool-usage-2026-10-18.md) проверил 14 цепочек и три сравнения областей. Сначала определить предмет через известный план, потом искать; `files` полезен для выбранных источников, ранний guessed scope теряет ответ; частота `modules` не метрика качества. Эти правила уже включены в исходные инструкции. Исследование не даёт основания удалять фильтры или делать их обязательными.

[Обзор локальных инструментов](local-documentation-tools.md) предложил обратные ссылки, целостность, связанные разделы и контекст. Часть уже покрывают индекс ссылок, similar, аудиты и GraphRAG. Это идеи, а не разрешение добавлять ещё 14 MCP-имён. Чтение раздела по диапазону ранее отклонено OQ-26; не возвращать его под видом экономии контекста.

Пять решений OQ-142 уже приняты в контракте GraphRAG: словарь зависимостей, estimate-v1, отказ от edge_types, ранжирование change_description, бюджеты по операциям. Их реализация принадлежит 4.1; 4.4 не вводит второй DTO или альтернативные правила.

## Фактические разрывы после блоков 1–3

| Область | Срез исследования 4.4.1 от 23-10-2026, до реализации 4.4.2 | Следствие для реализации |
|---|---|---|
| Состав MCP | 14 имён: 8 базовых и 6 GraphRAG | Перестановка панелей не требует переименования инструментов |
| Сохранение и embed | `StatusOutput` содержит общий `pending`, без waiting/queued/indexing/error | Агент не различает паузу после правки и ошибку документа; `state=ready` не доказывает свежесть каждого файла |
| Поиск по диску | Параллельно реализуется 3.6.2; `text_search` уже добавлен в протокол с допуском Window | В MCP его нет; не обещать поиск только что записанного слова через rag_search |
| Ссылки | `links_of` доступен только окну; перед чтением обновляет отдельную `links.sqlite3` по диску | `bars_relations links_to` и панель ссылок имеют разную свежесть; готовый GraphRAG нельзя выдавать за свежую проверку всех ссылок |
| Физический граф | `graph_physical` только для окна; `GraphTab` показывает единую физическую панель с действиями анализа | Координаты/физика не нужны MCP; `bars_graph` читает GraphRAG, не снимок видимой физической карты |
| Структура | `WorkspaceDocument` показывает заголовки текущего буфера | Диск и несохранённый буфер различаются; Т-37 требует функцию, а не копию фильтров MCP |
| Similar | Параллельно создаются `SimilarSections` и отдельная таблица Т-37 в 3.7.1 | Не дублировать таблицу и реализацию; результаты приёмки читать у владельца этапа |
| Противоречия | Аудит окна и GraphRAG `conflict_candidates` — разные пути выполнения; в текущем query.rs уже есть обработчик конфликтующих рёбер | Не называть GraphRAG-операцию пустой заглушкой по старой документации и не считать числовой аудит её эквивалентом; нулевая выдача не доказывает отсутствие противоречий |
| История MCP | Ошибки до допуска/доставка клиенту не наблюдаются; экран уже реализован | Устаревшее «экран ещё не реализован» исправляется в контракте, ISS-14 не закрывается без нативной приёмки |

В текущем исследовании `bars_relations` вернул `graph_not_ready: stale`; impact-анализ недоступен. Граф не перестраивался. Зависимости сверены чтением исходных документов и кода. Это факт одного вызова, не диагноз дефекта графа.

## Выбранный состав изменений MCP

**Выбрано B + инструменты чтения из C.** Обновить описания и доставляемые инструкции, спроектировать `bars_text_search` и `bars_links` поверх общего поиска и индекса ссылок. Счётчики `bars_status` не меняются: для выбранных сценариев чтения они не нужны. Действующие 14 имён сохраняются; целевой состав — 16 после реализации. Не менять поведение rag_search без mode и не добавлять к нему неявно поиск по диску.

Рассмотренное дополнение `StatusOutput.documents` с количествами waiting/queued/indexing/error оставлено вне объёма. Нельзя получать эти числа из одного `pending`: ошибки в него не входят, а фоновый проход может ещё не перечислить документы. Если такая диагностика понадобится отдельно, нужен один снимок очереди и самостоятельная проверка семантики. Это не обязательство 4.4.2.

Объяснение свежести в инструкции: `read/outline` читают диск; rag_search/similar/duplicates используют индекс; GraphRAG проверяет свои поколения и может быть stale/partial. Сохранённая правка ждёт паузы; агент не запускает reindex для обхода обычного ожидания. При необходимости срочно проверить точную строку — доступное агенту чтение/поиск файлов. Несохранённый буфер окна внешнему агенту недоступен; обещать его чтение нельзя.

Цена отказа от счётчиков: причина ненулевого pending остаётся неразличимой; подробная диагностика документов доступна пользователю в окне. Это ограничение честно описывается инструкцией.

Польза двух новых операций: единая область зарегистрированного проекта и те же исключения/ошибки, точные вхождения и свежие ссылки без embed. Цена: новые схемы, допуск MCP, renderer, история, тесты, обновление skills. Состав принят автором; [контракт расширения MCP](../features/agent-tools/mcp-tools.md) определяет ограничения и проверки до кода. Window-only методы не открываются простым изменением флага допуска: параметры отмены окна и неограниченный ответ links_of непригодны как публичный агентский API.

Не добавлять MCP-команды сохранения/перемещения, управления раскладкой/физикой, настройки цветов, запуска/игнорирования аудитов, согласия на смену модели. Отдельный инструмент чтения последнего аудита может обсуждаться при установленной потребности; существующий duplicates продолжает отвечать на синхронный запрос, не притворяется результатом фонового аудита.

## Доставка инструкций MCP

Действующая [доставка](../features/docs-convention/delivery.md) имеет несколько независимых источников. В реализации синхронно обновить:

| Источник | Содержание правки |
|---|---|
| `bars-mcp/src/instructions.rs` | Краткое различие диск/индекс/GraphRAG, ожидание embed, без перечня кнопок; общий предел 2000 знаков |
| Описания инструментов и схемы `lib.rs`, `graph.rs` | Фактические возможности 4.1; предупреждения о свежести и partial; сохранение пути/области и ошибок |
| `bars-core/assets/BARS_INSTRUCTION.md` | Совет по оформлению ссылок и документации, краткая граница свежести; не инструкция по управлению окном |
| `bars-worker/assets/skills/bars-docs/SKILL.md` | Выбор операций с учётом свежести, разграничение физического графа и GraphRAG, очередь и ошибки |
| `bars-worker/assets/skills/bars-session-log/SKILL.md` | Сохранить правила журнала; изменения только если меняются используемые инструменты |
| Документы фич и руководство | Пользовательское описание состояния, реальные действия из таблицы Т-37 и ограничения |

Репозиторные assets первичны; установленная копия skill и файл в docs-root не подтверждают версию бинарника. Не редактировать настоящие профили клиентов для проверки доставки. Правила «ссылка — утверждение о связи» уже внесены 22-10; повторно не проектировать.

## Ошибки, таймаут и диагностика MCP

ISS-18: не приписывать новый отказ загрузке без проверки состояния слота. Текущий прокси повторяет только model_loading в пределах MODEL_WAIT=60 с; таймаут отдельной попытки CALL_TIMEOUT=120 с. Это не общий потолок 60 с: вызов после ожидания сам может ждать ответа. При ошибке транспорта предусмотрено одно переподключение. Увеличение чисел без воспроизведения не предлагается.

Проверка реального таймаута Codex принадлежит 4.4.2: сопоставить настроенный предел клиента, время MCP/IPC, stderr процесса, состояние модели и историю попыток. Различать скачивание, загрузку, занятость модели, долгий обработчик и закрытие транспорта. Пока нет воспроизведения, причина прежнего Transport closed неизвестна. Не добавлять новые циклы повторов или выдачу пустого результата вместо ошибки.

Срез 23-10-2026: установлен `codex-cli 0.163.0-alpha.11.1`; `codex mcp get bars --json` показывает подключение к установленному `bars-mcp.exe`, без явных `startup_timeout_sec` и `tool_timeout_sec`. [Официальный контракт MCP Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) указывает умолчание вызова 60 секунд. Однако изолированная настоящая сессия CLI (`--ignore-user-config`, без переопределения таймаута) дождалась одного ответа тестового stdio-MCP через 65 005 мс. Промежуточный `cell_id` продолжен через wait; повторного вызова MCP не было. Это нижняя граница ожидания данной сборки/сценария, не измерение максимального таймаута и не воспроизведение старого Transport closed. Первая проба закончилась на промежуточном cell_id и доказательством таймаута не считается. Конфигурация bars и лимиты прокси не менялись. [Контракт хука Codex](https://learn.chatgpt.com/docs/hooks) требует доверия точному определению через `/hooks`; доставка файла не является одобрением.

ISS-14: сохранить исходные/применённые параметры и исход новых вызовов, без содержимого документов и ссылок. ISS-20 о новых темах и ISS-18 о памяти не закрываются обновлением инструкций. Поиск во время индексации, отказ IPC другому пользователю, настоящие клиентские сессии и установка остаются отдельными проверками реализации; рабочий bars не останавливается.

## Порядок реализации после решения OQ-146

1. Сверить завершённый общий поиск 3.6.2 и индекс ссылок 3.5; использовать контракт новых операций из MCP-документа. Не менять очередь 3.2 и семантику статуса.
2. Реализовать ограниченные агентские DTO и методы, допуск и изоляцию отмены, TXT/JSON и историю. Общий движок и индекс переиспользовать; две версии поиска/разбора ссылок не создавать.
3. Сверить фактическую реализацию 4.1 и таблицу Т-37 после 3.7, добавить два соответствия: «В тексте» и панель ссылок. Обновить описания и инструкции. Не объявлять проектный контракт уже реализованным.
4. Пройти stdio initialize/tools/list/call, guard лёгкости прокси, предел 2000 знаков, schema/renderer, ограничения ответа/продолжения, stale/partial/error и consent. Доставку проверять штатными скриптами с изолированными профилями по delivery.md.
5. В собранном окне проверить доступность действий таблицы Т-37; затем согласованные реальные Claude/Codex, hook и установленную сборку. Записать доказательства; незавершённые нативные проверки оставить открытыми.

## Критерии завершения исследования MCP

Исходный инвентарь 14 инструментов расширяется двумя чтениями по OQ-146; соответствия находятся в [таблице функций окна](../features/agent-tools/window-parity.md). Предыдущие исследования учтены без повторных замеров, ограничения и порядок реализации определены. Исследование и согласование завершены; готовность API и доставки оценивается отдельно в 4.4.2.
