# LM Studio — API моделей и проверка подключения

Статус 23-10-2026: официальный API исследован; LM Studio 0.4.26+4/Qwen3 0.6B Q8_0 прошёл реальный индекс → сохранение настройки → два поиска. Установленное окно и сравнительное качество не проверены. 28-10-2026 пробой на LM Studio 0.4.26 исследованы logprobs для rerank без штатного API; способ согласован с автором ([ADR-0006](../adr/0006-rerank-yes-no-logprobs.md)), reranker-модель не проверялась. Реализация подключения описана во [внешних моделях](../features/models/external-models.md).

## Возможности LM Studio

[Официальный embedding API](https://lmstudio.ai/docs/developer/openai-compat/embeddings) совместим с OpenAI: массив `input`, имя `model`, ответ `data[].embedding/index`. [CLI](https://lmstudio.ai/docs/cli) позволяет выбрать GPU, контекст и отдельный идентификатор загруженной модели. Штатного rerank среди опубликованных endpoints нет; [upstream #521](https://github.com/lmstudio-ai/lms/issues/521) открыт на 28-10-2026. GGUF reranker сам по себе не создаёт поддерживаемый API scoring. В [списке OpenAI-совместимых маршрутов](https://lmstudio.ai/docs/developer/openai-compat) есть `/v1/decisions`, но он требует особой «decision model», и формат ответа не документирован. Для rerank он не рассматривается.

## Rerank в LM Studio через logprobs

Согласованный способ — тот же, что для Ollama: Qwen3-Reranker, один токен на пару, `p = e^yes / (e^yes + e^no)`. Промпт, правило отсутствующего токена, пул из 4 запросов и сбой без частичного rerank описаны в [исследовании Ollama](ollama.md). Отличается только транспорт.

Проба 28-10-2026: LM Studio 0.4.26, `google/gemma-4-e4b`, RTX 3090, отдельный порт. Модель загружена из имеющихся, ничего не скачивалось.
- `/v1/completions` (сырой промпт без шаблона) с `logprobs`/`top_logprobs`: `"logprobs": null`.
- `/v1/chat/completions` с `logprobs: true`: тоже `null`.
- [`/v1/responses`](https://lmstudio.ai/blog/lmstudio-v0.3.39) с `include: ["message.output_text.logprobs"]`, `top_logprobs: 5`, `reasoning: {effort: "none"}` вернул градуированные значения. Релевантная пара: `yes` −0,0002, `no` −8,49. Нерелевантная: `no` −3·10⁻⁶, `yes` −16,7.
- Без `effort: none` первый токен уходит в `reasoning` и `output_text` пуст.
- Прогретый вызов занял 0,5–1,1 с.

Получается, оценки в LM Studio даёт только `/v1/responses`, а шаблон чата накладывает сервер. Поэтому system и user передаются обычными сообщениями. При этом нужно проверить, что отрендеренный промпт оканчивается пустым блоком `<think>` формата Qwen3-Reranker. Ответ эхом показал `frequency_penalty: 1.1`, хотя в запросе был 0. Если штраф действует на logprobs, оценка смещается для документа с «yes»/«no» в тексте. Первый вывод типа `reasoning` считается сбоем, а не оценкой. Модель после пробы выгружена, сервер остановлен.

Обычная чат-модель на пробе даёт почти бинарные оценки. Поэтому она допускается только с пометкой «качество не проверено», основная модель — Qwen3-Reranker.

## Модели и границы проверки

На машине обнаружены Qwen3-Embedding-0.6B Q8_0 (1024 измерения по архитектуре) и Nomic Embed Text v1.5 Q4_K_M. Для русскоязычной аппаратной пробы выбрана имеющаяся Qwen3; Nomic v1.5 не заменяет встроенную multilingual Nomic v2. Qwen3 4B/8B — кандидаты для отдельного сравнения качества, без обещания преимущества на корпусе bars. Веса не скачиваются и не перемещаются; путь тестовой Qwen — `D:\text-generation-webui-1.16\models\Qwen\Qwen3-Embedding-0.6B-GGUF\Qwen3-Embedding-0.6B-Q8_0.gguf`.

Прежнее [исследование встроенных GGUF](gguf-models.md) уже сравнило Qwen3 0.6B/4B Q4_K_M и bge-m3 на 100 вопросах: устойчивого преимущества Qwen не обнаружено. Текущая Q8_0, другой runtime и короткая smoke-проба не переопределяют тот вывод; повтор прежнего бенчмарка в задачу подключения не включён.

Т-25 и независимый rerank сохраняются. Внешний процесс не доказывает решения ISS-18 или уменьшения суммарной памяти. Smoke-тест не заменяет качество на естественном корпусе и приёмку установленного окна.

## Причина потери конца длинного входа

Прямой запрос к локальному LM Studio: общий префикс 156000 символов и два разных окончания; сервер сообщил 24009 и 24010 токенов при контексте 8192. Ответы HTTP 200 содержали побитно одинаковые векторы. `truncate:false` и `truncate:true` результат не изменили. Серверный журнал явно содержит `Truncating to 8192 tokens`: причина — усечение сервером до embedding, а не HTTP-транспорт или нарезка bars. В OpenAI-контракте нет проверенного переключателя отказа вместо усечения; добавлять неподдерживаемое поле бессмысленно. Поддержка ограничена входами, помещающимися в контекст; в окне и руководстве это явно обозначено.

## Аппаратная проба LM Studio

LM Studio 0.4.26+4, CLI commit `dcefd5a`, выбранный runtime `llama.cpp-win-x86_64-nvidia-cuda12-avx2@2.63.0`. Существующая Qwen3-Embedding-0.6B Q8_0 — 639150592 байта, модель загружена `lms load ... --gpu max --context-length 8192`, endpoint `127.0.0.1:12345`. Прямая пачка из двух текстов вернула 2×1024 координаты. Системные GPU-счётчики процесса LM Studio при загруженной модели: 2454020096 байт dedicated и 507510784 shared; после выгрузки строка этого процесса исчезла, UI-процесс остался с 9306112 байт dedicated. На машине одна RTX 3090. Это подтверждает размещение модели на GPU, но не долю каждого оператора или пик VRAM; WDDM не отдаёт per-process memory в `nvidia-smi`.

Настоящий `ConfiguredProvider` с отдельным временным профилем построил индекс трёх документов; `model_index=model_settings=lmstudio:text-embedding-qwen3-embedding-0.6b`, `Ready`, ошибки нет. `SettingsSave` и `SettingsGet` подтвердили запись/чтение пачки. Оба русскоязычных запроса дали ожидаемый документ первым; 103/51 мс — отдельные наблюдения при параллельных процессах, не бенчмарк. Стенд — `crates/bars-worker/examples/verify_lmstudio.rs`; повтор: `cargo run --release -p bars-worker --example verify_lmstudio -- <base-url> <model-id> <evidence.json>` при заранее запущенном сервере.

`POST /rerank` и `/v1/rerank` вернули HTTP 200 с `error: Unexpected endpoint or method`, `/api/v1/rerank` — HTTP 404. Успешный HTTP-код сам по себе не доказывает поддержку rerank. Модель выгружена, тестовый сервер остановлен, исходный порт 1234 восстановлен; профиль/индекс стенда удалены через `TempDir`, веса и рабочий bars сохранены.
