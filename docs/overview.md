# Что такое bars — назначение и возможности проекта

Статус: описание текущей реализации на 18-10-2026; сверено с кодом и документами фич. Ограничения проверки — в [состоянии проекта](project-status.md).

## Для чего нужен bars

bars — локальное приложение для поиска по Markdown-документации проектов. Человек ищет через окно или терминал, агент — через MCP. Все три интерфейса обращаются к одному воркеру и одному индексу выбранного проекта. bars помогает найти описание фичи, принятое решение, ограничение или инструкцию, даже если запрос сформулирован другими словами.

В bars реализован поисковый этап RAG: выдача содержит фрагменты исходных документов, пути, заголовки, строки и оценки. Ответ по найденным материалам составляет человек или подключённый агент. Сам bars ответ LLM не генерирует. Требования и границы продукта — [MAIN_IDEA.md](MAIN_IDEA.md), Т-1, Т-2, Т-13, Т-19, Т-20.

## Какие документы ищет bars

bars индексирует `.md` внутри корня документации зарегистрированного проекта; по умолчанию это `docs/`. Подпапки первого уровня образуют модули, например `features`, `architecture`, `knowledge`. Файлы прямо в `docs/` относятся к модулю `.`. Поиск ограничен одним проектом; внутри проекта можно выбирать модули и файлы.

Документ режется по заголовкам на chunks — фрагменты, пригодные для отдельной выдачи. Для поиска важны `title` во frontmatter, содержательные заголовки и понятный без соседей раздел. Правила нарезки — [chunking.md](features/indexing/chunking.md), исключения обхода — [updates.md](features/indexing/updates.md), оформление — [соглашение о документации](features/docs-convention/Index.md).

## Как bars находит нужный фрагмент

В рабочей копии дополнительно реализован частичный [GraphRAG](features/graphrag/Index.md): чтение отношений/путей, контекст по ролям и просмотр графа. Используются существующие embeddings, ссылки и явные правила; сходство не считается зависимостью. Полная смысловая и нативная приёмка остаётся открытой; базовый поиск без новых параметров сохраняет прежний контракт.

bars совмещает полнотекстовый поиск FTS5 и поиск по смыслу через embed-модель. Кандидаты объединяются, а включённый rerank дополнительно оценивает их соответствие запросу. Путь от запроса до результата описан в [hybrid-search.md](features/search/hybrid-search.md); числовые параметры и умолчания — в [settings.md](features/settings/settings.md).

Индекс обновляется по изменениям документов и фоновым проверкам. Неизменившиеся фрагменты используют ранее рассчитанные векторы; полное перестроение нужно при смене embed-модели и некоторых изменениях формата индекса. Подробности — [обновление индекса](features/indexing/updates.md).

## Из каких частей состоит bars

| Часть | Назначение |
|---|---|
| `bars` | Общий воркер, окно и трей; индексация, модели, поиск |
| `bars-cli` | Команды терминала: регистрация, поиск, чтение, состояние, подключение клиентов |
| `bars-mcp` | stdio-прокси для агентских MCP-клиентов |
| `.bars/` проекта | Настройки проекта и SQLite-индекс |
| `~/.bars/` пользователя | Общие настройки, реестр проектов и скачанные модели |

Реализация — Rust, Tauri, fastembed-rs; окно — Svelte и TypeScript. Карта исходников — [components.md](architecture/components.md), расположение данных — [files.md](architecture/files.md), актуальный выбор библиотек — [stack.md](architecture/stack.md).

## Локальные и внешние модели bars

Встроенные модели скачиваются на машину пользователя и выполняются локально. Первое скачивание требует сети. Модели и индексы не дублируются на каждую агентскую сессию: ими управляет общий воркер.

Можно подключить внешний embed-провайдер или локальный OpenAI-совместимый сервер, а для rerank — совместимый API. При внешнем подключении тексты, необходимые модели, передаются указанному провайдеру. Ключи хранятся отдельно от проекта. Подключение — [models/](features/models/Index.md), хранение ключей — [secrets.md](architecture/secrets.md).

## Локальная история обращений MCP

Общий worker сохраняет разрешённые параметры и краткие итоги MCP-вызовов, включая поисковые запросы и пути, в локальную историю пользователя. Содержимое документов и полные ответы туда не копируются. Политика хранения, границы наблюдения и состояние интерфейса анализа — [история MCP](features/window/mcp-statistics.md).
