# Компоненты bars

Решение агента: автор делегировал его 14-10-2026 (OQ-02, OQ-04, OQ-15).

## Исполняемые файлы bars

| Файл | Что делает | Требования |
|---|---|---|
| `bars` | Воркер с окном и треем. Единственный процесс, который читает и пишет индексы и загружает модели | Т-1, НФТ-3 |
| `bars-mcp` | stdio-MCP для агентских клиентов. Пересылает вызовы воркеру и запускает его, если тот не работает | Т-2, Т-19 |
| `bars-cli` | CLI для людей, хуков и агентов, которые тестируют приложение. Пересылает команды воркеру | Т-20 |

`bars-mcp` и `bars-cli` — тонкие клиенты: в них нет SQLite, ONNX Runtime и Tauri. Поэтому они быстро стартуют, а это важно для хука начала сессии.

## Cargo workspace bars

```text
crates/
├── bars-core/      индекс (SQLite, FTS5, векторы), нарезка, индексация, поиск, модели
├── bars-protocol/  сообщения локального канала, кодек строк, клиент к воркеру, цикл соединения
├── bars-app/       воркер, слушатель канала, трей, окно (Tauri); собирается в `bars`
├── bars-mcp/       stdio-MCP; зависит только от bars-protocol
└── bars-cli/       CLI; зависит только от bars-protocol
ui/                 интерфейс окна (Svelte), встраивается в `bars`
```

Правило зависимостей: `bars-mcp` и `bars-cli` не зависят от `bars-core`. Если клиенту нужна новая операция, она добавляется в `bars-protocol`, а выполняет её воркер.

## Интерфейс окна bars

Svelte 5 + TypeScript + Vite, без SvelteKit. Интерфейс собирается в статические файлы и встраивается в `bars`. Почему Svelte:

- маленький бандл и нет виртуального DOM — подходит для лёгкого окна в трее;
- дерево с галочками (Т-14) и формы настроек (Т-16…Т-18) удобно делать на реактивных состояниях Svelte;
- у Tauri есть официальный шаблон Svelte.

Отклонено: React — тяжелее при той же пользе; vanilla TS — дерево и формы пришлось бы писать вручную; Leptos — меньше готовых компонентов, и интерфейс пришлось бы собирать в WASM.
