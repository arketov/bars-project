# Протокол канала bars

Контракт крейта `bars-protocol`: что `bars-mcp` и `bars-cli` отправляют воркеру по локальному каналу ([ipc.md](ipc.md)) и что получают в ответ. Решение агента, 14-10-2026.

## Кто пользуется протоколом bars

- **`bars-mcp`** превращает каждый MCP-инструмент в один вызов метода ([agent-tools/mcp-tools.md](../agent-tools/mcp-tools.md)).
- **`bars-cli`** превращает каждую команду в один вызов метода ([agent-tools/cli.md](../agent-tools/cli.md)). Флаг `--json` печатает ответ метода как есть.
- **Окно** живёт в том же процессе, что и воркер, и канал не использует. Его команды Tauri вызывают те же обработчики, что и методы протокола, поэтому окно, MCP и CLI получают одинаковые ответы (Т-20).

## Формат сообщений канала

JSON-RPC 2.0, одно сообщение на строку, UTF-8. На одном соединении можно делать несколько вызовов по очереди. `bars-mcp` держит соединение всю сессию, `bars-cli` открывает его на одну команду.

Первый вызов на соединении — `hello`. Без него воркер отвечает на любой метод ошибкой `protocol_mismatch`.

## Как метод находит проект

У методов, которые работают с проектом, есть два параметра:

- `cwd` — рабочая папка клиента. `bars-mcp` передаёт свою cwd, то есть папку сессии агента; `bars-cli` — папку, из которой его запустили;
- `project` — необязательный явный проект: абсолютный путь к корню или имя проекта, если оно однозначно.

Если `project` не задан, проект — ближайшая к `cwd` зарегистрированная папка вверх по дереву (Т-15). Не нашлось — ошибка `project_not_found`. Как проекты регистрируются и как называются — [projects.md](projects.md).

## Методы протокола bars

| Метод | Параметры | Ответ | Кто вызывает |
|---|---|---|---|
| `hello` | `protocol`, `client` (`mcp` / `cli`), `client_version` | `protocol`, `worker_version` | все |
| `search` | `cwd`, `project`, `query`, `modules`, `files`, `limit`, `candidates`, `min_score` | результаты и применённые параметры ([search/hybrid-search.md](../search/hybrid-search.md)) | MCP, CLI |
| `outline` | `cwd`, `project`, `path`, `levels`, `under` (цепочка заголовков) или `under_line` | заголовки с номерами строк (Т-26) | MCP, CLI |
| `read` | `cwd`, `project`, `path` | текст с номерами строк, `title` | MCP, CLI |
| `projects` | — | проекты: путь, имя, корень документации, состояние, модули с числом документов | MCP, CLI |
| `status` | `cwd`, `project` | состояние индекса проекта ([worker.md](worker.md)) | MCP, CLI |
| `reindex` | `cwd`, `project`, `full`, `accept_model_change` | `accepted: true`; ход виден в `status` | MCP, CLI |
| `register` | `path` | проект после регистрации | CLI |
| `unregister` | `cwd`, `project` | `removed: true` | CLI |
| `session_start` | `cwd`, `source` | `accepted: true`; ответ сразу, проверка идёт в очереди | CLI (хук) |
| `install` | `client` (`claude-code` / `codex`) | какие файлы изменены, нужно ли одобрить хук в Codex | CLI |
| `uninstall` | `client` | какие файлы изменены | CLI |

Методы, у которых в колонке «Кто вызывает» нет MCP, для `bars-mcp` не существуют: воркер отвечает на них `-32601`. Первым вызовом на соединении должен быть `hello`; до него любой метод, даже неизвестный, получает `protocol_mismatch`.

## Ответы методов bars

- `search` — `results` (путь от корня проекта, `module`, `title`, `heading_chain` строкой `Заголовок 1/Заголовок 2`, `first_line`, `last_line`, `text`, `score`, `score_kind`), `applied` (число результатов, кандидатов, кандидатов реранка, порог, вид оценки, `clamped`), `indexing`, `pending` и, если rerank не отработал, `rerank_error`.
- `outline` — `headings`: номер строки, уровень, текст. Строку `7 ## Стадия` из заголовка собирает функция крейта `bars-protocol`, общая для MCP и CLI.
- `read` — `title` и `text` как есть. Номера строк ставит функция `number_lines` крейта `bars-protocol`: у MCP и CLI вывод одинаковый (Т-20).
- `status` — поля из таблицы в [worker.md](worker.md) и `path` проекта; время — RFC 3339.
- `projects` и `register` — описание проекта: путь, имя, корень документации, состояние, модули с числом документов.

Установкой в клиенты занимается воркер, а не `bars-cli`: так у окна и CLI одна реализация (Т-21), а пути к `bars-mcp` и `bars-cli` воркер знает от своего exe ([integrations/clients.md](../integrations/clients.md)).

## Что воркер реализует из методов протокола

Работают десять методов; `install` и `uninstall` до среза 4 отвечают `-32603`. Подробности — [worker.md](worker.md), «Обработчики методов воркера bars». `model_loading` пока не возвращается: ошибка загрузки модели приходит как `provider_error` (OQ-43).

## Версия протокола bars

`protocol` — целое число (сейчас 1), его увеличивает любое несовместимое изменение методов. `bars`, `bars-mcp` и `bars-cli` поставляются вместе, поэтому воркер принимает только свою версию. Чужая версия — ошибка `protocol_mismatch` с текстом «обновите bars»: значит, установлены exe из разных сборок.

## Ошибки протокола bars

Стандартные коды JSON-RPC (`-32700`…`-32603`) — для битых сообщений. Ошибки bars несут код, машинное имя в `data.kind` и понятный человеку текст:

| Код | `kind` | Когда |
|---|---|---|
| -32001 | `protocol_mismatch` | нет `hello` или чужая версия протокола |
| -32002 | `project_not_found` | проект не найден по `cwd` или `project`; текст подсказывает `bars-cli register` |
| -32003 | `project_unavailable` | папки проекта нет на диске ([projects.md](projects.md)) |
| -32004 | `reindex_required` | индекс построен другой моделью или старой схемой; поиск не работает до согласия пользователя (Т-25) |
| -32005 | `reindex_needs_consent` | `reindex` по проекту в состоянии `reindex_required` без согласия пользователя (Т-25) |
| -32006 | `file_not_found` | нет файла для `read` или `outline` |
| -32007 | `invalid_params` | параметр вне допустимого: неизвестный модуль, `limit` меньше 1 |
| -32008 | `provider_error` | внешняя модель не ответила; текст без ключей ([secrets.md](secrets.md)) |
| -32009 | `model_loading` | встроенная модель ещё скачивается или загружается; в `data` — ход загрузки |

Коды выхода `bars-cli` по ошибкам: `reindex_required` и `reindex_needs_consent` — `3`, недоступный воркер — `2`, остальные — `1`.

## Согласие на переиндексацию после смены модели

Переиндексацию проекта в состоянии `reindex_required` запускает только пользователь (Т-25): кнопкой в окне или командой `bars-cli reindex --accept-model-change`, которая передаёт `accept_model_change: true`. От `bars-mcp` воркер этот параметр не принимает: в вызове от MCP он сбрасывается в `false`, и агент получает `reindex_needs_consent`. Флаг CLI — согласие человека; текстовая инструкция по установке для агентов ([integrations/clients.md](../integrations/clients.md)) запрещает агенту передавать его самому.

## Порог агента вне пределов

Порог агента вне пределов из настроек — не ошибка: он прижимается к границе, и в ответе указан применённый порог (Т-24).
