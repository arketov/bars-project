# Векторный поиск bars

Решение агента. Точный перебор выбран 14-10-2026 по OQ-11: автор не знал разницы между вариантами и выбор не задал. Реализация своим кодом вместо sqlite-vec выбрана тогда же, по исследованию стека ([knowledge/stack-research.md](../knowledge/stack-research.md)).

## Точный перебор и ANN — в чём разница

- **Точный перебор** сравнивает вектор запроса с каждым вектором индекса и возвращает действительно ближайшие. Время растёт линейно с числом чанков.
- **ANN** (approximate nearest neighbours: HNSW, IVF) строит дополнительную структуру и проверяет только часть векторов. Это быстро на миллионах векторов, но иногда пропускает настоящих соседей, требует памяти и перестройки при изменениях.

## Почему bars использует точный перебор

Индекс bars — один проект, тысячи чанков, а не миллионы. Для сравнения: образец перебирал 3 897 векторов размерности 4096 за 70–76 мс в pgvector, а у bge-m3 (Т-17) размерность 1024 — вчетверо меньше данных на вектор.

Точный перебор ничего не теряет и не требует обслуживать индекс при инкрементальной индексации (Т-9). Урок 7 образца (размерность исключила ANN) здесь не мешает.

## Как устроен перебор в bars

- Векторы хранятся в таблице `vectors` индекса проекта как BLOB из `float32` ([storage/schema.md](../storage/schema.md)). При записи вектор нормализуется до длины 1.
- Для нормализованных векторов косинусная близость — это скалярное произведение. Воркер считает его в Rust для каждого вектора области поиска и держит 30 лучших.
- Область поиска (модули и файлы, Т-14) отбирается обычным SQL-запросом по `chunks` до перебора.

## Почему не расширение sqlite-vec

sqlite-vec на таком объёме тоже делает точный перебор, поэтому быстрее не будет. При этом:

- версия 0.1.x;
- сборка под Windows MSVC не подтверждена: issue #21 открыт;
- синтаксис косинусной метрики в `vec0` не задокументирован.

Свой перебор — около десятка строк кода и ни одной C-зависимости.

## Скорость перебора на прототипе

Замер на синтетике, размерность 1024 ([knowledge/spike-search.md](../knowledge/spike-search.md)): 5 000 векторов — 22 мс при чтении из SQLite и 3 мс в памяти; 50 000 — 221 мс и 33 мс. НФТ-2 выполняется с большим запасом.

## Когда пересматривать векторный поиск

Векторы читаются из SQLite на каждый запрос. Если в проекте больше ~20 000 чанков, воркер держит векторы этого проекта в памяти, пока по нему ищут: 20 000 векторов размерности 1024 — 80 МБ. ANN понадобится только на сотнях тысяч чанков.
