# Файлы bars на диске — папка проекта и папка пользователя

bars хранит данные в двух местах: в `.bars` проекта и в `.bars` домашней папки пользователя.

## Папка .bars проекта

`<проект>/.bars/` — локальные рабочие файлы, как `.serena` или `.claude`. Уходит ли она в git, решает пользователь; bars `.gitignore` проекта не трогает (Т-5).

| Файл | Что в нём |
|---|---|
| `config.toml` | настройки проекта: корень документации (по умолчанию `docs`), переопределения числовых параметров поиска и нарезки ([settings.md](../features/settings/settings.md)) |
| `index.sqlite` | индекс проекта ([schema.md](schema.md)) |
| `index.sqlite.new` | временный файл полной переиндексации; после неё исчезает |
| `new-topics.sqlite3` (и `-wal`, `-shm`) | очередь «Новых тем»: вопросы, для которых поиск окна и MCP не нашёл материалов, их варианты, наблюдения и векторы вопросов ([new-topics](../features/new-topics/Index.md)); не переживает только удаление проекта — полная переиндексация, смена модели и очистка MCP-истории её не трогают |

Ключей в `.bars` проекта нет. Исключение — тексты вопросов в `new-topics.sqlite3`: они могут быть чувствительными, а `.bars` может попасть в git, поэтому пользователь видит место хранения (NT-12).

## Папка .bars пользователя

`<домашняя папка>/.bars/` — общие файлы bars на этой машине.

| Путь | Что в нём |
|---|---|
| `settings.toml` | настройки приложения: embed и rerank модели, включён ли rerank, числовые параметры по умолчанию, порог и его пределы (Т-16…Т-18, Т-24), провайдеры без ключей ([settings.md](../features/settings/settings.md)) |
| `projects.toml` | реестр зарегистрированных проектов: путь и время регистрации |
| `keybindings.json` | общий профиль сочетаний окна: версия, ревизия, переопределения Windows/macOS; воркер — единственный писатель, конфликт ревизии и повреждение не перезаписываются молча ([keyboard-design.md](../features/window/keyboard-design.md#настройки-сочетаний-и-сохранение)) |
| `mcp-statistics.sqlite3` | история отдельных MCP-попыток и настройки её сбора (schema v2), отдельно — агрегаты прежней версии; может содержать поисковые запросы и пути. Политика хранения и очистки — [mcp-statistics.md](../features/window/mcp-statistics.md#контракт-этапа-26-хранение-аргументов-и-срок-mcp-истории) |
| `models/` | скачанные встроенные модели (Т-17) |
| `run/bars.sock` | Unix-сокет воркера на macOS ([architecture/ipc.md](ipc.md)) |

## Артефакты разработки и временные файлы тестов

`target` сборки и временные тестовые проекты не относятся к `.bars` проекта или пользователя. Пути Cargo, выход установщика, системный `%TEMP%`, изолированный `BARS_USER_HOME` и правила уборки описаны в [сборке bars](../knowledge/build.md#где-хранятся-артефакты-сборки-target). Постоянный кэш моделей — строка `models/` в таблице пользователя и [контракт встроенных моделей](../features/models/local-models.md#где-лежат-скачанные-модели).

## Порядок настроек bars

Файловые логи находятся в `~/.bars/logs/`: текущий `worker.jsonl` и три архива. Формат, пределы и просмотр — [logs.md](../features/window/logs.md).

Значение параметра берётся по первому найденному: вызов агента (в пределах Т-24 для порога) → `config.toml` проекта → `settings.toml` пользователя → заводское значение (Т-18).

## Регистрация проекта

Проект регистрируется хуком, в окне или через CLI (Т-6); как хук находит корень проекта и что бывает с пропавшими и перенесёнными проектами — [features/projects/projects.md](../features/projects/projects.md). При регистрации bars создаёт `.bars/config.toml`, если его нет, кладёт `BARS_INSTRUCTION.md` в корень документации (Т-8) и добавляет проект в `projects.toml`. Если `.bars/` уже есть (проект скопирован вместе с ней), используются её настройки. Если индекс в ней построен другой моделью, срабатывает Т-25.
