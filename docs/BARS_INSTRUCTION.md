# BARS_INSTRUCTION.md

Этот файл кладёт в корень документации программа bars (локальный поиск по Markdown). Он адресован моделям, которые пишут документы. Файл перезаписывается при каждой новой версии bars: правки в нём не сохраняются.

## Как писать документы, чтобы bars хорошо их находил

- **Модуль — подпапка первого уровня** под корнем документации; всё глубже принадлежит модулю. Документы одной темы кладите в один модуль.
- **`title` во frontmatter** каждого документа: он показывается в выдаче.
- **Только ATX-заголовки** `#`…`######`. Подчёркнутые заголовки (`===`, `---`) bars не видит.
- **Раздел понятен сам по себе.** Каждый раздел попадает в выдачу без соседей, только с цепочкой заголовков. Не пишите «см. выше», «как сказано ранее»; называйте предмет в заголовке.
- **Заголовки говорят, о чём раздел.** Цепочка заголовков входит в текст для эмбеддинга: «Настройка порта воркера» найдётся, «Настройка» — хуже.
- **Разумный размер разделов.** Очень длинный раздел режется на несколько чанков с одной цепочкой заголовков, совсем короткий склеивается с соседом. Лучше несколько средних разделов, чем один огромный.
- **Документ описывает текущее состояние.** Устаревшее правьте или удаляйте: bars ищет по всему, что лежит в документации.
- **Никаких секретов** в документации: ключей, токенов, паролей.

## Совет о раскладке документации

Это совет, а не правило: bars индексирует любую структуру.

```text
docs/
  Index.md                     оглавление
  knowledge/                   база знаний: исследования, замеры, соглашения по коду
  adr/                         принятые решения, один файл NNNN-<тема>.md
  features/<name>/             фича: Index.md, requirements.md, plan.md, любые документы
  chats/<YYYY-MM-DD>-<тема>/   журнал одной сессии: log.md, handoff.md
```

- Устройство, общее для многих фич, удобно держать отдельной папкой рядом, например `architecture/`.
- ADR не переписывается под текущее состояние: новое решение — новый ADR, у старого меняется только статус.
- В каждой папке, кроме папок сессий в `chats/`, лежит `Index.md` с оглавлением.

## Журнал сессии

Сессия, с которой говорит пользователь, ведёт папку `docs/chats/<YYYY-MM-DD>-<тема>/`.

- `log.md` — только по поводу: неочевидная находка, подход не сработал, план меняется, перед рискованным шагом. До трёх строк, дописывать в конец без чтения файла.
- `handoff.md` — в конце сессии: сделано, не сделано, сложности, дальше. Новая сессия читает последний handoff по своей теме, а не все логи.
- Ключей, токенов и личных данных в журнале нет.
