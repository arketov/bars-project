## Вопрос и метод исследования работы агентов с bars

Вопрос: что мешает агенту получить нужное знание из bars за малое число вызовов и без лишнего текста в контексте.

Метод:

1. **14 настоящих задач** в bars-project, решённых этой сессией через MCP bars (Claude Code, установленный `bars-mcp`). Для каждой записаны вызовы, ошибки выбора и что в ответе мешало.

3. **Журналы `docs/chats/`**: поиск жалоб на bars (пустые выдачи, обрывы, неработающие операции).
4. **Чтение каналов доставки**: описания и схемы инструментов, ответ `initialize`, `BARS_INSTRUCTION.md`, skills `bars-docs` и `bars-session-log`, хук начала сессии, гейт чтения документации и собственный хук проекта `.claude/hooks/require_tools.py`.

## Находки: что мешает агентам и что предложить

Серьёзность: **высокая** — инструмент не даёт ответа или ломает контекст; **средняя** — лишние вызовы или риск неверного вывода; **низкая** — шум и неточности.

### А-1. Графовые операции и mix отвечают сырым JSON на десятки килобайт — высокая

**Что.** В формате `txt` графовые инструменты и `bars_rag_search` с `mode=mix` печатают JSON воркера одной строкой внутри `=== GRAPH … ===`. В каждом ответе — эхо `requested` с ~35 полями, большинство `null`; доказательства — 64-значные хеши, которые агент сам сопоставляет с массивом `evidence`. **Чем подтверждено:** З10 — 58,8 тыс. знаков на `limit:3`, `related` 54 тыс. на два документа, клиент Claude Code отказался вставить ответ в контекст; З2 — 51 тыс., из них 39 тыс. `evidence`; предупреждение «Граф близости частичный: Some(ComparisonLimit)» показывает отладочный вид Rust. В skill `bars-docs` `mode=mix` предлагается без оговорок.

**Предложение.** Настоящий текстовый рендер графа: по строке на факт — вид, `docs_path:строки`, заголовок, короткая цитата evidence прямо в строке; эхо `requested` только для полей, отличных от умолчаний; бюджет txt-ответа MCP по умолчанию порядка 16 тыс. знаков с явным `truncated` и курсором; `related_budget` в mix по умолчанию малым. Текст предупреждений — без `Some(…)`.

### А-2. Одна общая схема на шесть графовых операций — высокая

**Что.** `bars_relations`, `bars_paths`, `bars_impact`, `bars_context`, `bars_explore`, `bars_graph` принимают один `GraphArgs` (`crates/bars-mcp/src/lib.rs:218-268`): у каждого около 35 параметров, включая чужие (`analysis` и `grouping` у relations, `from`/`to` у context). `change_description` описан в схеме, но не поддержан (журнал `2026-10-20-window-foundation`). Шесть копий схемы — порядка 30 тыс. знаков в каждой сессии, даже если граф не нужен.

**Предложение.** Своя структура аргументов на операцию, только используемые поля с описанием умолчаний; убрать `change_description` до реализации. Если операция не готова к работе агента (А-3), не публиковать её в `list_tools`, пока нет качества по этапу 3.1.

### А-3. Графовые операции молча возвращают пустоту и не подсказывают следующий шаг — высокая

**Что.** З2, З11, З12: `items: []` при `resolution: resolved`; единственная подсказка — общие предупреждения о частичном слое. `bars_context` по умолчанию прерывается по `timeout_ms` 1000 мс и отдаёт все роли в `missing_roles`; с явным 15 000 воркер прижимает до 5000 и тогда отвечает. `bars_impact` требует `roots` — объектные ссылки с двумя хешами, которые есть только в ответах других графовых операций; ошибка «impact: нужны roots» не говорит, где их взять. На документе с входящими ссылками impact пуст, потому что гиперссылки не считаются зависимостью, — для вопроса агента «что поправить вместе с Y» это главный источник.

**Предложение.** `bars_impact` и `bars_context` принимают путь документа (`path` от docs-root или из выдачи) и сами разрешают его в ссылку; таймаут MCP по умолчанию — допустимый максимум 5000 мс; пустой ответ дополняется строкой «смысловой слой частичный (566/1766); для этой задачи попробуйте bars_rag_search или входящие ссылки bars_links». Пока качество не принято (этап 3.1), в описаниях прямо писать «экспериментально, может вернуть пусто».

### А-4. Четыре правила путей, и путь из выдачи нельзя передать в files — средняя

**Что.** Выдача поиска печатает `path: docs/features/…` (от корня проекта); `files` принимает только путь от docs-root; `bars_read`/`bars_outline` — оба вида; `bars_links` и продолжение `bars_text_search` — от корня проекта. Скопированный из выдачи путь даёт «неизвестный файл `docs/features/agent-tools/mcp-tools.md`» без подсказки (З7; так же в случае C09 исследования 18-10). Модуль `models` — «неизвестный модуль» без списка (З7; в журнале дважды). Список модулей в ошибке уже предложен в module-scope.md; для файлов — нет.

**Предложение.** `files` принимает путь с префиксом docs-root, если с префиксом его в индексе нет, а без префикса — есть. Если решено не принимать — ошибка с исправленным вариантом: «неизвестный файл `docs/features/x.md`; пути files — от корня документации `docs`: `features/x.md`». В выдаче поиска печатать и `docs_path`, как это уже делает граф.

### А-5. В выдаче не видно, что документ — проект без реализации — средняя

**Что.** З3: на вопрос «как устроен формат ответа» первым пришёл module-scope.md о будущих строках `scope` и `by_module`; строка «Статус: проект…, реализации нет» стоит в первом разделе документа, а найденный чанк — другой раздел. Агент, читающий только найденный раздел, примет план за действующий контракт. BARS_INSTRUCTION требует статус в начале файла, но поиск этот статус не показывает.

**Предложение.** Соглашение: краткий статус во frontmatter (`status: проект, реализации нет` / `действует` / `исследование`), bars печатает его строкой `status:` в каждом результате рядом с `title`. Альтернатива без нового поля — показывать первую строку «Статус:» документа; она хуже, потому что зависит от слов.

### А-6. Нет способа найти последний документ и перечислить документы — средняя

**Что.** З4: поиск не знает дат, «последний handoff по теме» не находится, а `chats` — 248 из 428 документов. В MCP нет списка документов: окно показывает дерево (Т-33), агент — нет; skill `bars-session-log` велит «найти последний handoff.md», не давая средства. Агенты идут в `ls`/Glob (гейт пропускает `chats`). `bars_projects` показывает только число документов в модуле.

**Предложение.** Инструмент списка документов: путь, `title`, модуль, дата изменения; фильтр по модулю или префиксу пути, сортировка по пути или дате, ограниченная страница. Это также функция окна (дерево), то есть закрывает соответствие Т-37. Новое имя инструмента — решение автора.

### А-7. Чтение только целого документа — средняя

**Что.** `bars_read` не принимает диапазон: план, реестры и mcp-tools.md (≈ 25 тыс. знаков) читаются целиком ради одной строки. В журнале `bars_read` — 38% вызовов, план — 13 чтений; З8 и З9 упёрлись в это. `bars_outline` уже даёт номера строк и `under`, но передать их в чтение нельзя.

**Предложение.** `bars_read` с `lines: "98-104"` или `under: "Заголовок/Подзаголовок"` (как у outline), ответ с теми же номерами строк и признаком части документа.

### А-8. Поиск по номеру и строки реестров — средняя

**Что.** З9: запрос «Т-25» возвращает документы, ссылающиеся на Т-25, а не определение; со списком `files` нужный чанк — 6 тыс. знаков других требований с обрывом. З14: строка таблицы реестра проходит порог с 0,121 при пороге 0,1; журнал 18-10 — IDEA-03 потерян на пороге 0,1. Таблицы реестров rerank оценивает низко.

**Предложение.** В инструкции и skills: номер (Т-N, OQ-N, ISS-N) или точная фраза — `bars_text_search`, затем `bars_read` найденного места; `bars_rag_search` — для смысла. В новой сборке `bars_text_search` уже есть, не хватает этого правила. Отдельно — на бенче проверить, не нужен ли реестрам меньший порог; это вопрос качества поиска, не этого исследования.

### А-9. bars_get_similar отвечает соседями из того же документа — средняя

**Что.** З6: 5 из 5 результатов — разделы того же mcp-tools.md; раздел delivery.md с тем же правилом, найденный поиском вторым, не попал. Для задачи «где ещё описано, прежде чем править» ответ бесполезен. `bars_get_duplicates` не принимает тему, и для смысловых пар не показывает отрывков (З5).

**Предложение.** `bars_get_similar` по умолчанию исключает исходный документ (параметр `same_document: true` возвращает прежнее поведение). Для дублей по теме — в skill явный путь: «найди раздел поиском, затем similar без своего документа»; отрывки смысловых пар в `get_duplicates` — по одной строке.

### А-10. Ошибки описаний инструментов — низкая

**Что.** Описание `bars_get_similar` содержит серии по 24 пробела (`lib.rs:507`: перенос строки без `\`), они видны модели. `mode`: «Без поля — прежний поиск и прежняя форма ответа» — «прежний» понятен только автору истории. `include_related`: «отключить расширение…; без поля включено» — у булева поля с именем include направление неочевидно. Описания графа объясняют устройство («поколения и scope фиксированы; курсор только того же запроса»), но не когда операцию звать.

**Предложение** — раздел с текстами описаний ниже.

### А-11. Выдача поиска: лишний хвост и сбивающие поля — низкая

**Что.** З1: без `limit` 7 результатов ≈ 12 тыс. знаков, два с оценкой ниже 0,25; агенты в 220 из 240 вызовов задают `limit` сами. Заголовок `SEARCH: results 7` и `APPLIED PARAMETERS results: 8` — разные смыслы одного слова (предел и число найденного). Поле `heading` показывает только H1, а текст чанка включает приклеенный H2 (З1).

**Предложение.** В `APPLIED PARAMETERS` назвать предел `limit:` и добавить `returned:`; `heading` — цепочка последнего заголовка внутри чанка, либо строка `sections:` со всеми заголовками чанка (как уже делает `other headers` у similar).

### А-12. Хуки: двойной гейт, ложная подсказка, лишний отказ — низкая

**Что.** В bars-project одновременно работают собственный хук проекта (`.claude/settings.json` → `require_tools.py`) и гейт bars (`.claude/settings.local.json` → `bars-cli hook pre-tool-use`). Отказ показывает текст проектного хука: «The bars tool schemas are deferred: load them with ToolSearch» — неверно, когда схемы уже загружены (в этой сессии). Гейт bars (`gate.rs`, `reads_docs`) отклоняет Glob/Grep с шаблоном `*.md` в любой папке, даже вне `docs` (`norm(glob).ends_with(".md")` без проверки пути), а Grep по всему репозиторию без шаблона пропускает. Блок снимает любой вызов bars, включая `bars_status`. Хук начала сессии ничего не сообщает агенту.

**Предложение.** В гейте отклонять Glob/Grep с шаблоном `*.md`, только если `path` лежит в папке документации или не задан (поиск от корня проекта заходит в неё); с `path` вне документации — пропускать. В проектном хуке bars-project убрать проверку docs (её делает гейт bars) и оставить только правило кода, текст — «may be deferred». Хук начала сессии остаётся молчаливым: модули проекта доставляет `initialize` по module-scope.md.

### А-14. Журнал MCP не позволяет разобрать графовые вызовы и повторы прокси — низкая

**Что.** У графовых операций `requested` пуст; попытки прокси при `model_loading` неотличимы от повторов агента. Для разбора поведения агентов это потеря данных. Корректность истории — область аудита внутренней части; здесь отмечено только как препятствие исследованию.

**Предложение.** Allowlist графовых аргументов (query, roots, topic, analysis, budgets) и признак «повтор прокси, номер попытки».
