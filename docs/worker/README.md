# worker

Статус: требования · Спека: нет

## Назначение

Единственный на машине процесс bars. Держит индексы всех зарегистрированных проектов; с ним работают окно, CLI и все сессии агентов. Воркер и окно — один exe: воркер живёт в трее и сам не завершается.

## Требования

- Один процесс на машину, один exe с окном, трей — `[требование Т-1]`.
- Стек — `[требование Т-3]`, платформы — `[требование Т-4]`.
- Реестр проектов, три пути регистрации — `[требование Т-6]`.
- Четыре источника проверки актуальности: слежение за файлами, старт воркера, хук, раз в час — `[требование Т-10]`.
- Вся тяжёлая работа идёт здесь, а не в прокси — НФТ-3.

## Границы

Входит: жизненный цикл процесса, защита от второго экземпляра, реестр проектов, планировщик проверок, приём вызовов по локальному каналу, очередь индексации.

Не входит: нарезка и эмбеддинг ([indexer](../indexer/README.md)), ранжирование ([search](../search/README.md)), интерфейс ([ui](../ui/README.md)).

## Уроки образца

- 11: индекс обновлялся вручную и незаметно устаревал. Здесь актуальность держит воркер.

## Вопросы

OQ-03 (канал), OQ-16 (автозапуск). Ещё нужно решить, где хранить реестр проектов и как идут одновременные индексации нескольких проектов.
