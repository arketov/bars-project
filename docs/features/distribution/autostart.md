# Автозапуск bars при входе в систему

Решение автора, 15-10-2026 (OQ-16): автозапуск **выключен по умолчанию**, включается галочкой «Запускать при входе в систему» в окне настроек. Воркер и без него поднимается по требованию из `bars-mcp` и `bars-cli` (Т-2), поэтому автозапуск — удобство, а не необходимость: индекс обновляется и до первого обращения агента (Т-10).

## Что записывается в ОС для автозапуска

На Windows — строковое значение `bars` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` со значением `"<папка установки>\bars.exe" --background`. Прав администратора не нужно. Ключ `--background` запускает `bars` без окна: иконка появляется в трее, окно открывается по клику ([window/implementation.md](../window/implementation.md)). Если `bars` уже работает, второй запуск ничего не делает — он передаётся работающему экземпляру (Т-1).

macOS: автозапуск пока не сделан (LaunchAgent, когда появится Mac, [installer.md](installer.md)). Там методы отвечают «не поддерживается», а окно прячет галочку.

## Где живёт состояние автозапуска

Это состояние ОС, а не ключ `settings.toml`: пользователь может отключить запись в «Диспетчер задач → Автозагрузка», и второй источник правды в файле разошёлся бы с первым. Поэтому окно и CLI спрашивают воркер, а воркер читает реестр.

Автозапуск **включён**, если значение `bars` есть и «Диспетчер задач» его не отключил (значение `bars` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\Run` с нечётным первым байтом). Включение из bars убирает это отключение, иначе галочка стояла бы, а запуска не было.

## Методы и команда автозапуска

| Что | Как |
|---|---|
| Метод `autostart_get` | `supported`, `enabled`, `stale`, `command` ([architecture/protocol.md](../../architecture/protocol.md)) |
| Метод `autostart_set` | `enabled: true\|false`; возвращает новое состояние; повтор безвреден. На ОС без автозапуска — `invalid_params` |
| `bars-cli autostart [status\|on\|off]` | то же из терминала; без аргумента — `status` ([agent-tools/cli.md](../agent-tools/cli.md)) |
| Окно | вкладка «Запуск» в настройках: галочка, применяется сразу, без «Сохранить» ([window/settings-window.md](../window/settings-window.md)) |

Методы доступны окну и `bars-cli`, но не `bars-mcp`: включать автозапуск агенту по MCP незачем (Т-20).

Решение агента: свой небольшой модуль в `bars-worker` вместо `tauri-plugin-autostart`. Воркер собирается и тестируется без Tauri ([architecture/components.md](../../architecture/components.md)), а плагин доступен только из процесса Tauri; своя запись пишет то же значение реестра. Тесты работают с подделкой в памяти и реестр не трогают.

## Автозапуск при обновлении, переезде и удалении

- **Обновление на месте** ([installer.md](installer.md)): папка установки не меняется, значение остаётся верным. Установщик запись не трогает.
- **Переезд.** Если приложение установлено в другую папку (чистая установка в новое место), значение указывает на старый `bars.exe`. При старте воркер сверяет запись с расположением своего exe: если запись есть и отличается, он переписывает её на текущий exe (`stale`, исправление в `serve`). Выключенный автозапуск при этом не включается. Окно до исправления показывает предупреждение.
- **Удаление.** Деинсталлятор удаляет значение `bars` и его отметку в `StartupApproved`. При обновлении запись сохраняется: обновление — это замена файлов, а не удаление.
