# Проверки автообновления интеграций

18-10-2026, Windows. Проверен код рабочей копии. При приёмке IDEA-10 профиль пользователя не менялся; при исправлении ISS-12 восстановлены пути установленного bars в Codex MCP и хуке. Установленное приложение не заменялось. Контракт — [clients.md](clients.md).

Новые регрессии: отсутствие интеграции и одни skills; восстановление из одного MCP или хука в обоих клиентах; сохранение байтов/mtime/backup; смешанные группы и дубли; изменение лишь MCP/skill/чужого хука без `/hooks`; preflight невалидного синтаксиса и структуры; ошибка после успешных записей и повтор; конфликт внешней правки с ограниченными повторами; оба порядка uninstall/refresh. Отдельный тест удерживает настоящий замок файлов: CLI/MCP handshake и projects работают, второй воркер уступает, shutdown ждёт прохода.

Старый CLI-тест требовал `/hooks` даже при повторной неизменной установке. Он обновлён до OQ-75: no-op без напоминания, реальная правка matcher — с напоминанием. Первоначальное падение исправлено, повторный набор целиком зелёный.

## Шесть отдельных процессных сессий

Повторяемый стенд — `scripts/test-client-refresh.ps1`; отдельный воркер без окна — `crates/bars-worker/examples/client_refresh_session.rs`. Пример требует явный `BARS_USER_HOME`, использует настоящий `serve_with` и останавливается сигнальным файлом `stop` с ожиданием `Worker::shutdown`. Нет подмены файловых операций или MCP.

```powershell
cargo build -p bars-worker --example client_refresh_session --locked
cargo build -p bars-cli -p bars-mcp --bins --locked
./scripts/test-client-refresh.ps1
```

Если cargo отсутствует в PATH, используется полный путь к пользовательскому `.cargo/bin/cargo.exe`. Скрипт сохраняет отчёт и stderr в `target/client-refresh-<uuid>/`; профиль, junction и сигнальные файлы принадлежат только стенду. Пароли и конфиги настоящих клиентов не копируются. Дочерние процессы закрываются в finally, таймаут завершает только созданный стендом процесс.

| Сессия | Проверенный результат |
|---|---|
| 01-update | Старые пути и дубли обоих клиентов обновились; чужие MCP/хуки сохранены; оба skills совпадают со встроенными; ровно одно напоминание `/hooks` |
| 02-noop | Повторный запуск не изменил SHA-256, mtime и backup восьми файлов; нет сообщений об обновлении |
| 03-uninstall | Настоящий CLI удалил обе интеграции во временном home; чужой skill сохранился |
| 04-after-uninstall | Новая сессия не восстановила удалённые интеграции; снимок файлов прежний |
| 05-error-isolation | Невалидный Claude JSON дал диагностику; его MCP остался байт-в-байт прежним; Codex обновился |
| 06-empty | Чистый профиль не получил папок клиентов и интеграций |

Итог последнего прогона: `sessions=6`, `passed=true`, `codex_config_read=true`, `mcp_stdio=true`, `skills_junction=true`. Skills Codex обновлены через NTFS junction на отдельную папку внутри стенда (OQ-54).

Установленный Codex CLI `0.163.0-alpha.10.2` с отдельным `CODEX_HOME` успешно прочитал обновлённую запись командой `codex mcp get bars --json`: transport `stdio`, enabled `true`, команда текущего `bars-mcp.exe`. Настоящий `bars-mcp.exe` прошёл stdio initialize и вызов `bars_projects` до одобрения хука; результат без `isError`. Это проверка MCP, а не выполнения хука.

## Проверка изоляции профиля (ISS-12)

`scripts/test-client-profile-isolation.ps1` запускается без `BARS_USER_HOME`: сначала безопасная регрессия конструктора (проверка до запуска serve), затем worker/CLI/MCP. Снимок настоящего профиля до/после включает SHA-256, mtime и наличие файлов Codex/Claude, их bars-backup и обоих skills bars. Содержимое конфигов и секреты в отчёт не выводятся. При любой параллельной записи скрипт сообщает об изменении, даже если оно не связано с bars.

Первый проход: worker 131/131, CLI 8/8, MCP 9/9; контроль всего профиля обнаружил параллельную правку Codex config.toml. Хук и запись MCP bars остались установленными. Повторный проход: worker 132/132, CLI 8/8, MCP 9/9; SHA-256, mtime и наличие всех отслеживаемых файлов профиля совпали. Дополнительная регрессия конструктора также прошла. `cargo check -p bars-app --bin bars`, rustfmt изменённых самостоятельных файлов, PowerShell parser, ссылки и diff whitespace прошли; изменённые участки просмотрены вручную.

Стенд явной установки повторно прошёл шесть сессий: `target/client-refresh-53ef35d93f084fd9bf5b22ccd9c8d853/summary.json`, `passed=true`, `codex_config_read=true`, `mcp_stdio=true`, `skills_junction=true`. Конфиги настоящего пользователя содержат пути установленного bars; исполняемые файлы установки не заменялись.

Восстановление файлов на диске не подтверждает обновление открытого окна Codex. После восстановления пользователь прислал окно со старой debug-командой; повторная проверка диска показала установленные пути. Одобрение хука и обновление уже открытого окна этой проверкой не подтверждены.

## Оставшиеся ручные проверки интеграций

- Интерактивное одобрение и запуск хука в Codex `/hooks` не проверены; `mcp get` не подтверждает hook trust.
- Claude Code не найден в PATH и стандартных пользовательских местах установки; настоящий клиент не запускался. Его файлы проверены на копиях, без AI-сессии.
- macOS не проверена. Актуальность внешнего формата хуков и доставка контекста в AI-сессию требуют отдельной проверки при ISS-08. События startup/resume и stdout хука этим изменением не расширены.
