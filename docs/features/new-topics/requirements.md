# Новые темы — сценарии и требования

Статус: проект контракта IDEA-14 от 18-10-2026; требования NT-N — предложения реализации, кроме явно отмеченных решений автора. Код и физическая приёмка отсутствуют. [Устройство и UX](design.md), [этапы](plan.md).

## Потребность и решения автора

Пользователю нужен перечень того, каких знаний не хватило при обращениях к документации, чтобы целенаправленно её пополнять. Автор предложил собирать запросы из общего чата и MCP, дедуплицировать по уже вычисленному вектору с порогом, хранить в `.bars`, показывать результат только пользователю; разрешить удаление и проверку появления знаний.

Уточнение автора по скриншоту дерева, 18-10-2026: «просто как типо файл в самом верху и с иконкой чтоб было понятно что это другое». Название — «Новые темы», первая строка дерева выше «(корень)», файловая строка с отдельной иконкой. Конкретный рисунок иконки автором не выбран.

Поручение автора: проработать фичу в `docs/features/`. Внедрение в приложение пока не поручено. Предложения ниже не записываются как уже принятые автором решения.

## Границы фичи

Один список на проект; пользователь видит и обрабатывает потребности, возникшие при поиске в этом проекте. Сбор не требует открытого окна. Список не является документом, поисковым корпусом или историей всего разговора. Ответ LLM и автоматическое написание документации не добавляются; действуют Т-13 и существующая граница поиска.

Слово «чат» не меняет текущую архитектуру: у bars нет LLM-чата, MCP передаёт отдельные вызовы. Источник «общего чата» остаётся OQ-94. Поиск окна и MCP проектируются полностью; внешний чат — явный вход интеграции, не молчаливо отброшенный сценарий. Произвольные архивы клиентов не читаются.

## Сценарии пользователя

| ID | Сценарий | Видимый результат |
|---|---|---|
| S1 | Агент через MCP ищет отсутствующую инструкцию | Тема появляется у пользователя, даже если окно закрыто; исходный MCP-ответ сохраняется |
| S2 | В окне искали тот же вопрос другими словами | Одна тема с сохранёнными формулировками и частотой; спорные совпадения не скрывают отдельную потребность |
| S3 | Пользователь открывает строку над «(корень)» | Список текущего проекта, без смены галочек документов |
| S4 | Документация дополнена, пользователь проверяет тему | Актуальные материалы с путями/строками; можно открыть документ и подтвердить достаточность |
| S5 | Поиск дал фрагменты, но ответа в них нет | Пользователь вручную отмечает «Не хватило знаний»; тема получает соответствующее основание |
| S6 | Вопрос больше не нужен | Запись удаляется; запоздавшая проверка её не восстанавливает |
| S7 | Индексация/модель недоступны | Честное состояние проверки; ошибка не выдаётся за отсутствие знаний |
| S8 | Сменили модель, перестроили индекс или очистили MCP-историю | Вопросы и решения пользователя сохраняются; несовместимые векторы не сравниваются |

## Требования к сбору новых тем

- **NT-01. Источники.** Worker собирает события поисковых обращений окна и MCP; в записи сохраняется источник. Подключение общего чата по OQ-94 использует тот же вход наблюдений. Просмотр, изменение и выгрузка очереди агентам через публичный MCP не предоставляются.
- **NT-02. Основания.** Успешный поиск с нулём результатов создаёт кандидата при готовом индексе без известной ошибки обновления; сохраняются реальная область и применённые параметры. Ручная отметка пользователя создаёт тему и при непустой выдаче. Индексация, техническая ошибка, неизвестный итог и проверка самой темы не считаются отсутствием знаний. Непустая выдача сама по себе не закрывает тему.
- **NT-03. Самостоятельное обращение.** Диагностический запрос окна, загрузочные повторы и повторная проверка темы не увеличивают спрос. Одно самостоятельное обращение может увеличить его один раз. Несколько отдельных вызовов агента — отдельные наблюдаемые обращения, а не доказанное число пользовательских задач или людей.
- **NT-04. Дедупликация.** Сначала точный текст с осторожной нормализацией и контекстом области, затем косинус готового вектора в совместимом пространстве. Порог вопрос–вопрос выбирается отдельно от порога поиска. Варианты вопроса сохраняются; отрицания, числа, версии и идентификаторы не удаляются. При отсутствии готового вектора сохраняется текст, семантическая обработка отложена.

## Требования к пользовательскому экрану

- **NT-05. Строка дерева.** «Новые темы» стоит первой выше «(корень)»; своя иконка, размеры и отступы файловой строки. Без галочки, раскрывающей стрелки и числа чанков. Нажатие открывает экран, не меняет область поиска. Строка доступна и при пустом корпусе проекта. Предложение: справа — число активных тем, включая найденные материалы, ожидающие решения.
- **NT-06. Список и карточка.** Видны вопрос, частота, последнее обращение, источник, причина и статус. Карточка показывает варианты и области, результат последней проверки. Основные действия — «Проверить знания» и «Удалить»; после нахождения материалов — «Знаний достаточно» и «Всё ещё не хватает». Закрытые доступны отдельным фильтром.
- **NT-07. Повторная проверка.** Проверка использует текущий индекс и исходную область каждого варианта. Расширение на весь проект — явное действие. Найденные фрагменты показываются с путём, заголовком и строками, но не считаются доказательством достаточности. При нескольких вариантах виден итог каждого. Пустой или неполный результат не затирает сохранённую предыдущую проверку без объяснения.
- **NT-08. Жизненный цикл.** Материалы переводят тему в «Есть материалы», подтверждение пользователя — в «Закрыта». Удаление убирает тему и её варианты. Предложение OQ-96: новое самостоятельное неудачное обращение может создать тему заново; существующая закрытая тема при совпадении снова открывается. Поздние записи, начатые до удаления/очистки, ничего не восстанавливают.

## Требования к данным и надёжности

- **NT-09. Хранение.** Отдельная БД в `.bars` проекта, по предложению OQ-96. Полная переиндексация, смена embedding-модели и очистка истории MCP её не удаляют. Активные темы не получают автоматически семидневный срок MCP-истории. Удаление проекта учитывает БД и её SQLite sidecar-файлы в перечне рабочих данных.
- **NT-10. Граница знания.** Вопросы и результаты их проверки не индексируются как документы и не подмешиваются в ответы поисковых инструментов. Окно читает их через внутренний API. «Только пользователю» означает продуктовую границу доступа; защита от процессов с доступом к диску не обещается.
- **NT-11. Достоверность и сбои.** Отказ записи не ломает поиск. Потери сбора видны пользователю без текстов запросов в техническом логе. Ошибка БД не выглядит пустым списком. Повреждённая/более новая схема не заменяется пустой. Смена проекта и устаревшие ответы не показывают чужой список.
- **NT-12. Управление.** В экране доступны включение/выключение сбора для проекта и очистка списка с подтверждением. Выключение останавливает новые записи, сохраняя существующие; очистка не отключает будущий сбор. Запросы могут содержать чувствительные сведения; пользователь видит место хранения. Технические логи не дублируют тексты запросов и векторы.

## Сквозная приёмка новой темы

| ID | Проверка | Ожидаемое |
|---|---|---|
| A1 | По одному независимому пустому поиску из окна и MCP при закрытом окне | Два наблюдения правильных источников; семантически одинаковые вопросы группируются по проверенному правилу |
| A2 | Пустая выдача запускает диагностику; загрузка модели вызывает повторы | Диагностика и технические попытки не становятся новым спросом |
| A3 | Найденные фрагменты не отвечают на вопрос; ручная отметка | Тема появляется с основанием пользователя |
| A4 | Запрос с modules/files; затем проверка по всему проекту | Исходная область сохранена; расширение явно подписано, не выдаётся за исходный результат |
| A5 | Корпус пуст, вектора нет | Текст сохранён; поиск не делает дополнительный обязательный embed только для списка |
| A6 | Перефразирование, отрицания, разные числа/версии/идентификаторы | Размеченные пары и отдельная оценка ложных слияний; нет выбранного «на глаз» порога |
| A7 | После добавления документа — проверка и подтверждение пользователя | Видны новые источники; закрытие только по действию пользователя |
| A8 | Проверка во время индексации / ошибка модели / пропавшая область | Неполнота либо точная ошибка; тема не закрывается и область молча не расширяется |
| A9 | Полная переиндексация, новая модель, очистка истории MCP, рестарт | Тексты и статусы остаются; несовместимые векторы не сравниваются |
| A10 | Удаление/очистка/выключение сбора при активном поиске или проверке | Поздние операции не воскрешают данные |
| A11 | Нет проекта, пустой список, ошибка чтения, переключение проекта | Разные состояния; первая строка дерева не меняет выбор документов |
| A12 | Поиск самой сохранённой темы и попытка доступа через MCP/CLI | Служебная очередь не становится поисковым источником; внутренние методы недоступны агенту |
| A13 | Удаление проекта, повторная регистрация | Рабочая БД удалена по контракту удаления; документация сохранена; новый список пуст |
| A14 | БД недоступна или достигнут предел хранения | Поиск работает; потеря сбора видна; существующие темы не вытесняются молча |

## Незакрытые продуктовые решения

- OQ-94 — конкретный источник «общего чата»; поле поиска окна и внешняя беседа технически различны.
- OQ-95 — предложена автоматическая очередь кандидатов плюс ручная отметка; это не подтверждение отсутствия знания.
- OQ-96 — предложены проектная БД, хранение до решения пользователя и повторное появление после нового обращения. Постоянное подавление темы — отдельное возможное развитие, не подменяет удаление.

Эти вопросы не мешают подготовить полный проект фичи и макет. Ответы автора должны быть отражены здесь перед окончательным закреплением поведения в реализации.
