# Новые темы — план реализации и проверки

Статус: проект фичи готов к рассмотрению, реализация не начата. Основание — [NT-01…NT-12](requirements.md); [устройство](design.md). Каждый этап оставляет проверяемый результат, завершение компонента не заменяет сквозную приёмку.

## P0. Продуктовый контракт и макет

- [x] Описать исходную потребность, решения автора и предлагаемые умолчания раздельно.
- [x] Разместить фичу в `features/new-topics/`, убрать прежний документ из knowledge и исправить ссылки.
- [x] Проработать сбор, отсутствие вектора, фильтры/пороги, жизненный цикл, повторную проверку, хранение и гонки.
- [x] Подготовить интерактивный макет первой строки дерева и рабочего экрана; разместить в `design/` по уточнению автора.
- [ ] Закрепить ответы OQ-94…96: источник общего чата, политика автоматического сбора, жизненный цикл. Не подменять отсутствие ответа разрешением.

## P1. Контекст поискового обращения и калибровка

- [ ] Проверить актуальные symbols/references через Serena; сохранить параллельную работу.
- [ ] Ввести внутренний request/parent ID и назначение для окна/MCP/диагностики/проверки; без новых обязательных аргументов MCP.
- [ ] Снять готовый вектор на общем пути ядра без добавления его в публичную выдачу и без удержания index gate на запись темы.
- [ ] Разметить пары реальных запросов: перефразы, разные области, отрицания, числа/версии/идентификаторы; development и отложенная проверка отдельно.
- [ ] Выбрать порог по ложным слияниям/разделениям; зафиксировать результаты и ограничения, не переносить порог поиска документов.
- [ ] Замерить добавленную задержку поиска, очередь записи, потребление/размер БД; установить численные бюджеты и пределы до нагрузочной приёмки.

## P2. Хранение и сбор

- [ ] Версионированная отдельная SQLite БД, settings/generation, topics/variants/observations/checks; миграции и ошибки без автосброса.
- [ ] Идемпотентный сбор и транзакционная дедупликация; отсутствие вектора, несовместимая модель, закрытое окно.
- [ ] Отказы записи/лимиты не ломают поиск; безопасная диагностика потерь.
- [ ] Очистка/выключение/удаление и поздние операции; удаление проекта включает известные рабочие файлы фичи.
- [ ] Тесты NT-01…04, NT-09…12 и A1…6/A9…10/A12…14 во временных проектах и профиле.

## P3. Проверка знаний и внутренний API

- [ ] UI-only методы с проверкой origin, точного проекта и revision; отказ MCP/CLI.
- [ ] Поиск по сохранённым вариантам/областям, явное расширение; model_loading, индекс изменился, область исчезла.
- [ ] Token ревизии индекса, ссылки на источники и прежний результат; отсутствие самоиндексации.
- [ ] Переходы open/materials_found/resolved, возврат спроса, удаление при проверке, cancel массовой очереди.
- [ ] Тесты A4/A7…10/A12; повторная проверка не создаёт спрос.

## P4. Окно и сквозная приёмка

- [ ] Первая файловая строка со своей иконкой; нет галочки/стрелки/чанков, фильтр документов не скрывает вход.
- [ ] Список/карточка/фильтры/счётчики, ручная отметка из выдачи, источники, закрытие/удаление, управление сбором.
- [ ] Пусто/загрузка/ошибка/выключено/потери; клавиатура, узкое окно, смена проекта и запоздавшие ответы.
- [ ] Ручные merge/split с сохранением формулировок; интерфейс не превращает сходство в доказанную эквивалентность.
- [ ] Проверить весь сценарий в собранном Tauri на временном проекте: MCP → тема → новый документ → обновлённый индекс → проверка → решение пользователя. Отдельно поиск окна при непустой нерелевантной выдаче.
- [ ] Проверить сохранность после полного reindex/смены модели/очистки MCP-истории и отсутствие публичного доступа.
- [ ] Обновить текущие документы окна/файлов/поиска/удаления и changelog, зафиксировать реальный результат и оставшиеся ограничения.

## Подключение общего чата

После OQ-94 — конкретный адаптер, стабильный ID обращения, доступный сигнал отсутствия ответа, определение наличия вектора и проверка доставки. Если автор имеет в виду поиск окна, отдельного адаптера не нужно. Если внешний чат — полный исходный сценарий S1…S8 проверяется также для этого источника до заявления о выполнении общего охвата. Чтение всего разговора не подразумевается MCP-подключением.
