# Цвета и иконки bars — хранение, выбор и показ (Т-38)

Статус: проект 22-10-2026. Решения автора ([раунд 26](../../MAIN_IDEA.md)): документ без своего цвета наследует цвет папки, цвет и иконка выбираются в контекстном меню дерева, сначала документы, затем код. Палитра, набор иконок, файл, ключи и команды — предложения агента (OQ-128…131). Реализовано: хранение и проверка значений в `crates/bars-app/src/appearance.rs`; окна и показа ещё нет. Основано на [требовании Т-38](../../MAIN_IDEA.md), [файлах bars](../../architecture/files.md) и [физическом графе](../graphrag/physical-graph.md).

## Что настраивается

Глубина считается от корня документации: модуль — первый уровень, его подпапка — второй.

| Объект | Цвет | Иконка |
|---|---|---|
| Документ | свой, по выбору | нет |
| Модуль (1-й уровень) и подпапка (2-й) | свой, по выбору | своя, по выбору |
| Папка 3-го уровня и глубже | не выбирается; показывает цвет ближайшей папки выше | не выбирается; обычная папка |
| Корневой модуль «Корневые документы» | нет | нет |

Документы корня могут иметь собственный цвет. Markdown-файлы не меняются: значения лежат только в `.bars/`.

## Какой цвет виден

Цвет документа: свой цвет → цвет ближайшей папки выше, у которой он есть → цвета нет. Так цвет модуля «Features» окрашивает все его документы в дереве и в графе, пока у документа нет своего. Папка 3-го уровня и глубже берёт цвет по той же цепочке и показывает обычную иконку; иконку подпапка у модуля не наследует. Чанк в графе берёт цвет своего документа (OQ-130).

## Палитра и иконки

Цвет хранится именем из закрытого набора, а не шестнадцатеричным кодом: окно подбирает значение под светлую и тёмную тему по контрасту (значок и текст на фоне панели не ниже 3:1). Девять цветов: `red`, `orange`, `amber`, `green`, `teal`, `blue`, `violet`, `pink`, `gray`; токены `--pal-<имя>` для обеих тем добавляются в `ui/src/theme.css`. Цвет акцента окна и цвета видов связей графа в набор не входят: цвет документа не должен читаться как тип ребра, а тип ребра по-прежнему передаёт штрих, стрелка и подпись.

Иконка — имя из встроенного линейного набора (стиль `Icon.svelte`), двадцать: `folder` (по умолчанию), `book`, `gear`, `code`, `flask`, `chat`, `star`, `bolt`, `shield`, `chart`, `database`, `globe`, `users`, `bug`, `target`, `rocket`, `puzzle`, `archive`, `pencil`, `magnifier`. Своих картинок загрузить нельзя. Неизвестное имя показывается как отсутствие значения, остальное применяется. Цвет не единственный признак: у документов он дублируется подсказкой, у папок — иконкой.

## Хранение

Файл `.bars/appearance.toml` проекта, отдельный от `config.toml`: тот воркер перечитывает при каждом задании, а цвета меняются часто и из окна, и не должны вызывать пересчёта настроек и проверки индекса (OQ-129). Ключ — путь от корня документации с прямыми слешами, регистр как на диске; пустые значения не пишутся.

```toml
[folders]
"architecture" = { color = "teal", icon = "gear" }
"features/search" = { color = "violet", icon = "magnifier" }

[documents]
"MAIN_IDEA.md" = { color = "red" }
"features/search/text-search.md" = { color = "blue" }
```

Файл может попасть в git вместе с `.bars/`: оформление тогда общее для команды, это решает пользователь, как и для остальной папки.

## Команды Tauri

Команды лежат в `bars-app`, как команды редактора, протокол воркера не меняется. Допустимость пути и значений проверяется при записи.

- `appearance_read(project)` → `{ status: "ok", folders, documents }`; нет файла — пустые таблицы.
- `appearance_set(project, kind, path, color, icon)`: `kind` — `folder` или `document`; `null` сбрасывает поле, пустая запись удаляется. Файл читается и пишется целиком вокруг одной записи, под замком, атомарно (временный файл и переименование).
- Отказы приходят как `status: "error"` с `kind`: `not_allowed` — иконка у документа, папка глубже второго уровня, плохой путь (`..`, пустые части, обратные слеши, документ не `.md`); `invalid_value` — цвета или иконки нет в наборах; `broken` — файл не разбирается; `io` — запись не удалась.
- Файл, который не разбирается, окно показывает с цветами по умолчанию и уведомлением; запись отклоняется, файл не перезаписывается: ошибка, а не молчаливая подмена умолчанием.
- После записи окно шлёт остальным окнам проекта событие `bars://appearance-changed`, и они перечитывают файл (Т-40, отдельные окна этапа 3.4.2).

## Выбор в окне

Пункт «Цвет и иконка…» стоит в контекстном меню модуля и подпапки второго уровня, пункт «Цвет…» — в меню документа; в меню папки 3-го уровня и глубже их нет. Пункт открывает небольшую панель у строки: девять цветов и «Без цвета», для папки ещё сетка иконок (иконка в цветной плашке, как у проектов в ChatGPT). Выбор применяется сразу, без кнопки «Сохранить»; `Esc` закрывает панель, стрелки и `Enter` работают. Ошибка записи показывается уведомлением, прежнее значение остаётся.

## Где виден

Один источник правды в окне — хранилище `appearance` по проекту: оно отдаёт цвет и иконку по пути с учётом наследования.

| Место | Что показывается |
|---|---|
| Дерево | иконка папки в её цвете вместо общей `folder`; у документа — цветная точка слева от имени |
| Вкладки | цветная точка документа; у вкладки папки — её иконка в цвете |
| Карточки поиска | цветная точка документа и иконка модуля у пути |
| Граф и мини-граф | заливка круга документа; иконка в графе не рисуется; выбор, закрепление и затемнение рисуются поверх цвета |
| Выбор документа (`Ctrl+O`, `[[`) | как в дереве |

Поле `color` у узла графа ([модель графа](../graphrag/physical-graph-design.md)) заполняется из этого хранилища.

## Переименование и перемещение

Переименование и перемещение через bars ([дерево и файлы](tree-and-files.md)) переносят ключи записи папки и вложенных документов вместе с узлом, удаление убирает записи, чтобы значение не осталось у чужого файла. Запись, чей путь не найден в дереве, не показывается и не мешает. Переименование вне bars сбрасывает оформление пути так же, как ломает ссылки.
