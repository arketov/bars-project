# Редактор документа bars — устройство чтения, записи и конфликтов

[← База знаний](Index.md)

Проект этапа 3.4.1 по требованиям Т-29, Т-40 и НФТ-5 ([MAIN_IDEA.md](../../MAIN_IDEA.md)). Устройство — инженерное предложение агента; спорные места автор закрыл 22-10-2026 принятием рекомендаций OQ-122…OQ-126 ([QUESTIONS.md](../../../QUESTIONS.md)). Команды записи реализованы в `crates/bars-app/src/document_io.rs`; хранилище буферов `ui/src/lib/editors.svelte.ts` и редактор `ui/src/lib/Editor.svelte` — шаг 4 (состояния, автосохранение, подсветка, структура, глаз); помощники разметки — шаг 5; выбор версии при конфликте, проверка диска и закрытие — шаг 6 (диалог `UnsavedDialog.svelte`, `unsaved.svelte.ts`). Вкладки, `Ctrl+O` и отдельные окна — этап 3.4.2; ссылки `[[` — 3.5.2; очередь документов и отложенный embed — 3.2. Выбор CodeMirror 6 и замеры — [исследование редактора](../../knowledge/editor-spike.md) и [ADR-0005](../../adr/0005-editor-codemirror.md).

## Состояние реализации

Документ открывается в редакторе CodeMirror 6 в [WorkspaceDocument.svelte](../../../ui/src/lib/WorkspaceDocument.svelte) (первичное содержимое — внутренний вызов воркера `read`, затем буфер читает файл командой `document_read`); запись, конфликты и закрытие описаны ниже и реализованы в этапе 3.4.1; нативная приёмка не проведена. Основа для путей: проверка путей есть в `crates/bars-app/src/folders.rs` (`checked_location`: корень внутри проекта, предок существует, каноническая цель внутри корня — junction и symlink наружу не проходят) и в `documents.rs` (`indexed_path`: только компоненты `Normal` и расширение `.md`). `document_action` требует, чтобы документ был в индексе; для записи это условие не годится — новый файл виден в дереве до индексации (Т-33).

## Команды Tauri

Команды работают от зарегистрированного проекта. Путь задаётся от корня проекта, как у `read` и `document_action` (`docs/a/x.md`), и должен лежать внутри корня документации. Ожидаемые исходы приходят успешным ответом с полем `status` (`ok`, `saved`, `conflict`, `error` с `kind` и `message`); ошибкой Tauri остаются только сбои вроде «воркер ещё запускается».

| Команда | Вход | Выход |
|---|---|---|
| `document_read` | `project`, `path` | `text` (UTF-8, перевод строк приведён к `\n`), `revision`, `eol` (`lf`/`crlf`), `bom`, `size`, `read_only` (`null`, `not_utf8`, `too_large`, `file`); файла нет — пустой документ с `revision = null`; ошибки `invalid_path`, `outside_root`, `parent_missing`, `too_large` |
| `document_write` | `project`, `path`, `text`, `base_revision` (`null` — файла не должно быть), `eol`, `bom` | `revision` записанного; `status: conflict` (с текущей `revision` на диске, `null` — файла нет), ошибки `parent_missing`, `read_only`, `locked`, `invalid_path`, `outside_root`, `io` |
| `document_revision` | `project`, `path` | текущая `revision` или `null`; проверка без передачи текста в окно (файл всё равно читается и хешируется) |

Правила пути: расширение `.md` (регистр не важен); файл внутри корня документации после канонизации; существующий файл не может быть папкой; новый файл создаётся, только если родительская папка существует (папки создаёт 3.3). Документ не обязан быть в индексе (OQ-123, принято). `index.md` папки (Т-32): если файла нет, окно открывает пустой документ с `revision = absent`, на диске файл появляется при первой правке — это запись с `base_revision = null`.

`revision` — хеш содержимого байтов файла вместе с размером (не mtime: mtime у OneDrive и копирования ненадёжен). Вид — `размер-хеш blake3` (первые 32 знака); окно хранит её как непрозрачную строку.

## Запись

- **Атомарность.** Запись идёт во временный файл в той же папке (`.<имя>.bars-tmp`), затем переименование поверх оригинала; обрыв не оставляет половинный файл. Временные файлы при старте не сканируются (индекс берёт только `.md`).
- **Сравнить и записать.** Перед переименованием команда пересчитывает `revision` файла на диске и сравнивает с `base_revision`. Несовпадение — `conflict`, файл не тронут. Новый файл создаётся жёсткой ссылкой на временный файл, которая не заменяет чужой файл, появившийся после проверки. Окно между проверкой и переименованием у существующего файла остаётся (блокировки файла нет): это известное ограничение, оно не превращает конфликт в потерю, потому что внешняя запись в эти миллисекунды тоже даёт полный файл одной из сторон. Граница фиксируется честно, не как «невозможно».
- **Перевод строк, BOM.** Окно держит `\n`; при записи возвращается исходный `eol` и `bom` файла; у нового файла — `\n` без BOM. Файл со смешанными переводами строк записывается с преобладающим: смесь нормализуется. Файл, не являющийся UTF-8, открывается только для чтения с пояснением (правка может испортить его); размер больше 5 МБ тоже открывается только для чтения (замер выдержал 5,1 МБ, выше не проверялось).
- **Ошибки.** Файл только для чтения, занят другой программой, нет места — ошибка с понятным текстом; черновик остаётся в памяти редактора, успех не изображается.
- **Индекс.** Запись не запускает embed и не вызывает проверку на каждое сохранение (Т-41). До этапа 3.2 состояние показывает «записано, индекс обновится при проверке проекта»; состояние индекса не выдаётся за сохранение текста.

## Состояния документа в окне

Хранятся на документ в общем хранилище `editors` (ключ — проект и путь), а не в компоненте: несколько видов одного документа (3.4.2: две панели, отдельное окно) получают один буфер.

| Состояние | Когда | Что видит пользователь |
|---|---|---|
| чисто | текст совпадает с диском | нет отметки |
| изменено | есть правка, запись ещё не началась | точка у названия вкладки, «Изменено» |
| запись | идёт `document_write` | «Запись…»; правки в это время копятся и пишутся следующим шагом |
| записано | запись успешна | «Записано в ЧЧ:ММ:СС» без уведомления |
| ошибка записи | команда вернула ошибку | постоянная полоса с причиной и «Повторить»; черновик не теряется |
| конфликт | `conflict` или диск изменился при изменённом буфере | полоса «Файл изменён на диске» с выбором (ниже) |
| только чтение | не UTF-8, слишком большой, файл только для чтения | поле неактивно, причина в полосе |

## Автосохранение

Запись начинается через 1 с после последней правки (Т-29); одновременно идёт не больше одной записи на документ; правки во время записи ставят следующую. Максимального ожидания при непрерывном наборе нет: Т-29 говорит о 1 с «после последнего изменения» (OQ-124 принят). Переключение «исходник / рендер», потеря фокуса окна и закрытие вкладки сбрасывают таймер и пишут сразу.

## Конфликт версий

Диск проверяется (`document_revision`): при возвращении фокуса окну, при выходе окна из скрытого состояния, при открытии уже открытого документа и перед каждой записью (запись сама сравнивает ревизию и возвращает `conflict`). Фоновый опрос по таймеру не вводится; слежение за файлами при массовых изменениях — этап 3.2.1. Реализовано в `EditorBuffer.checkDisk` и `Editors.checkAll` (`ui/src/lib/editors.svelte.ts`).

- Буфер чистый, диск изменился — текст молча перечитывается, курсор остаётся на прежнем смещении; полоса «Обновлено с диска» закрывается крестиком.
- Буфер изменён, диск изменился — ничего не перезаписывается, автосохранение останавливается. Полоса предлагает: **«Оставить мою версию»** (запись поверх ревизии, которую увидел конфликт), **«Взять версию с диска»** (черновик заменяется) и **«Сохранить мою рядом»** (буфер пишется в `<имя> (конфликт ЧЧММСС).md` в той же папке, при занятом имени добавляется `-2`, `-3`…; затем берётся диск; файл попадает в дерево как обычный документ). OQ-122 принят.
- Файл удалён с диска при изменённом буфере — «Файл удалён с диска»: **«Записать заново»** (создаст файл с `base_revision = null`) или **«Отбросить правки»**.

## Закрытие (НФТ-5)

- **Вкладка.** Закрытие вкладки (крестик, `Ctrl+W`) сначала записывает правки. Если запись не удалась (конфликт, ошибка), открывается диалог со списком документов и причиной: **«Вернуться»** (по умолчанию, `Escape`) или **«Закрыть без записи»**. Если тот же буфер открыт в другом виде, закрытие этого вида ничего не спрашивает. Закрытие последнего вида с правками, записанных не до конца, не теряет их: буфер остаётся и дописывается в фоне. OQ-125 принят.
- **Окно.** Закрытие окна прячет его в трей (процесс живёт). При потере фокуса и сворачивании окна все несохранённые правки пишутся сразу (`Editors.flush`).
- **Выход из процесса** (пункт «Выход» трея, перезапуск из настроек, просьба установщика `--quit`). Процесс отправляет окну событие `bars://flush-request` и ждёт ответа командой `flush_reply` (`crates/bars-app/src/flush.rs`): `clean` — записано или писать нечего; `asking` — есть документы, которые не записались, окно показывается и спрашивает пользователя тем же диалогом; `proceed` / `cancel` — решение пользователя. Нет ответа за 3 с — выход продолжается (окно не загружено или нечего сбрасывать); нет решения пользователя за час — выход отменяется. Отказ пользователя оставляет процесс работать, перезапуск из настроек возвращает ошибку «Перезапуск отменён».
- **Не входит в 3.4.1.** Резервная копия несохранённого черновика на случай аварии процесса (OQ-126 принят: не делать); при аварии теряется не больше последней секунды набора и документы, записанные с ошибкой. Команда «Сохранить сейчас» (`Mod+S`, `document.save`) остаётся будущей: запись и так идёт через секунду, при переключении «исходник / рендер», потере фокуса и закрытии.

## Редактор

CodeMirror 6, версии закреплены в `ui/package.json`. Состав: `@codemirror/state`, `view`, `commands` (история, штатные клавиши), `language` и `lang-markdown` с GFM (`markdownLanguage`), `autocomplete` (`closeBrackets` для `**`, `` ` ``, `(`, `[`), `markdownKeymap` (`Enter` продолжает список и задачу). Подсветка блоков кода по языку — `@codemirror/language-data` с ленивой загрузкой языка на первое появление блока; без него блоки кода подсвечиваются одним стилем (стоимость — в исследовании). Ввод по-русски идёт через штатный `contenteditable` CodeMirror с IME; вручную события клавиатуры не перехватываются, кроме сочетаний ниже.

- **Тема.** Цвета и шрифт берутся из CSS-переменных окна (`--panel`, `--accent-soft`, `--mono`); светлая и тёмная темы без пересоздания редактора (`Compartment`).
- **Подсветка найденного отрывка.** Строки `first_line…last_line` выделяются декорацией; панель прокручивается к ним; выделение пропадает при первой правке.
- **Структура.** Список заголовков строится из синтаксического дерева (ATX и setext, без заголовков внутри кода); переход ставит курсор и прокручивает.
- **Помощники разметки.** Команды `editor.*` из [keyboard-design.md](../window/keyboard-design.md) — функции над `EditorView` в `ui/src/lib/editor-commands.ts`: заголовки 1–3, жирный, курсив, строчный код, блок кода, маркированный и нумерованный список, задача, цитата, таблица, ссылка. Повторная команда снимает разметку; пробелы и конец строки на краях выделения в пару не входят. Сочетания приходят из реестра клавиатуры (Т-45) через адаптер команд редактора (`commandAdapter`): оконный обработчик ловит физическую клавишу, поэтому `Ctrl+B`, `Ctrl+I`, `Ctrl+K` работают и в русской раскладке; `Mod-i` CodeMirror («выбрать родителя») отключён. Панель кнопок над редактором скрыта по умолчанию (плотность окна) и включается кнопкой «Aa» в шапке документа; выбор запоминается. Кнопки сохраняют выделение. Шпаргалка по синтаксису — кнопка «?» в панели (OQ-127). Команда «Ссылка» вставляет `[текст]()`; выбор документа через `[[` — этап 3.5.2.
- **Таблица.** `Tab` / `Shift+Tab` в таблице GFM (подряд идущие строки с `|`, вторая — разделитель) переходят между ячейками и выравнивают столбцы по самой длинной ячейке; `Tab` в последней ячейке добавляет строку; одиночная строка с `|` таблицей не считается, `Tab` в ней и вне таблицы не перехватывается. Ввод `*`: пара вокруг выделения, `**` из `*|*`, шаг за закрывающую `*`; в начале строки (маркер списка), в слове и в «2 * 3» не вмешивается; `Backspace` между `*` и `*` убирает обе.
- **Глаз.** Переключает тот же буфер между редактором и рендером; рендер строится из текущего буфера, а не из диска, поэтому несохранённые правки видны.
- **Не входит:** Live Preview, `[[`, проверка орфографии.
