## Состояние реализации

Документ открывается в редакторе CodeMirror 6 в [WorkspaceDocument.svelte](../../../ui/src/lib/WorkspaceDocument.svelte) (первичное содержимое — внутренний вызов воркера `read`, затем буфер читает файл командой `document_read`); запись, конфликты и закрытие описаны ниже и реализованы в этапе 3.4.1; физическая приёмка установленной версии не проведена; история отмены проверена программно в собранном WebView2. Основа для путей: проверка путей есть в `crates/bars-app/src/folders.rs` (`checked_location`: корень внутри проекта, предок существует, каноническая цель внутри корня — junction и symlink наружу не проходят) и в `documents.rs` (`indexed_path`: только компоненты `Normal` и расширение `.md`). `document_action` требует, чтобы документ был в индексе; для записи это условие не годится — новый файл виден в дереве до индексации (Т-33).

## Команды Tauri

Команды работают от зарегистрированного проекта. Путь задаётся от корня проекта, как у `read` и `document_action` (`docs/a/x.md`), и должен лежать внутри корня документации. Ожидаемые исходы приходят успешным ответом с полем `status` (`ok`, `saved`, `conflict`, `error` с `kind` и `message`); ошибкой Tauri остаются только сбои вроде «воркер ещё запускается».

| Команда | Вход | Выход |
|---|---|---|
| `document_read` | `project`, `path` | `text` (UTF-8, перевод строк приведён к `\n`), `revision`, `eol` (`lf`/`crlf`), `bom`, `size`, `read_only` (`null`, `not_utf8`, `too_large`, `file`); файла нет — пустой документ с `revision = null`; ошибки `invalid_path`, `outside_root`, `parent_missing`, `too_large` |
| `document_write` | `project`, `path`, `text`, `base_revision` (`null` — файла не должно быть), `eol`, `bom` | `revision` записанного; `status: conflict` (с текущей `revision` на диске, `null` — файла нет), ошибки `parent_missing`, `read_only`, `locked`, `invalid_path`, `outside_root`, `io` |
| `document_revision` | `project`, `path` | текущая `revision` или `null`; проверка без передачи текста в окно (файл всё равно читается и хешируется) |

Правила пути: расширение `.md` (регистр не важен); файл внутри корня документации после канонизации; существующий файл не может быть папкой; новый файл создаётся, только если родительская папка существует (папки создаёт 3.3). Документ не обязан быть в индексе (OQ-123, принято). `index.md` папки (Т-32): если файла нет, окно открывает пустой документ с `revision = absent`, на диске файл появляется при первой правке — это запись с `base_revision = null`.

`revision` — хеш содержимого байтов файла вместе с размером (не mtime: mtime у OneDrive и копирования ненадёжен). Вид — `размер-хеш blake3` (первые 32 знака); окно хранит её как непрозрачную строку.

## Запись

- **Атомарность.** Запись идёт во временный файл в той же папке (`.<имя>.bars-tmp`), затем переименование поверх оригинала; обрыв не оставляет половинный файл. Временные файлы при старте не сканируются (индекс берёт только `.md`).
- **Сравнить и записать.** Перед переименованием команда пересчитывает `revision` файла на диске и сравнивает с `base_revision`. Несовпадение — `conflict`, файл не тронут. Новый файл создаётся жёсткой ссылкой на временный файл, которая не заменяет чужой файл, появившийся после проверки. Окно между проверкой и переименованием у существующего файла остаётся (блокировки файла нет): это известное ограничение, оно не превращает конфликт в потерю, потому что внешняя запись в эти миллисекунды тоже даёт полный файл одной из сторон. Граница фиксируется честно, не как «невозможно».
- **Перевод строк, BOM.** Окно держит `\n`; при записи возвращается исходный `eol` и `bom` файла; у нового файла — `\n` без BOM. Файл со смешанными переводами строк записывается с преобладающим: смесь нормализуется. Файл, не являющийся UTF-8, открывается только для чтения с пояснением (правка может испортить его); размер больше 5 МБ тоже открывается только для чтения (замер выдержал 5,1 МБ, выше не проверялось).
- **Ошибки.** Файл только для чтения, занят другой программой, нет места — ошибка с понятным текстом; черновик остаётся в памяти редактора, успех не изображается.
- **Индекс.** Запись не запускает embed и не вызывает проверку на каждое сохранение (Т-41). До этапа 3.2 состояние показывает «записано, индекс обновится при проверке проекта»; состояние индекса не выдаётся за сохранение текста.

## Состояния документа в окне

Хранятся на документ в общем хранилище `editors` (ключ — проект и путь), а не в компоненте: несколько видов одного документа в одном окне (две панели) получают один буфер; у каждого окна, в том числе отдельного, свой набор буферов, согласованный через диск (раздел про отдельные окна ниже).

| Состояние | Когда | Что видит пользователь |
|---|---|---|
| чисто | текст совпадает с диском | нет отметки |
| изменено | есть правка, запись ещё не началась | точка у названия вкладки, «Изменено» |
| запись | идёт `document_write` | «Запись…»; правки в это время копятся и пишутся следующим шагом |
| записано | запись успешна | «Записано в ЧЧ:ММ:СС» без уведомления |
| ошибка записи | команда вернула ошибку | постоянная полоса с причиной и «Повторить»; черновик не теряется |
| конфликт | `conflict` или диск изменился при изменённом буфере | полоса «Файл изменён на диске» с выбором (ниже) |
| только чтение | не UTF-8, слишком большой, файл только для чтения | поле неактивно, причина в полосе |
| файл удалён | при открытом документе файла больше нет (проект: раздел «Файл документа удалён») | текст остаётся, полоса «Файл удалён с диска» с «Записать заново» и «Закрыть вкладку»; автосохранение стоит |

## Автосохранение

Запись начинается через 1 с после последней правки (Т-29); одновременно идёт не больше одной записи на документ; правки во время записи ставят следующую. Максимального ожидания при непрерывном наборе нет: Т-29 говорит о 1 с «после последнего изменения» (OQ-124 принят). Переключение «исходник / рендер», потеря фокуса окна и закрытие вкладки сбрасывают таймер и пишут сразу.

## Конфликт версий

Диск проверяется (`document_revision`): при возвращении фокуса окну, при выходе окна из скрытого состояния, при открытии уже открытого документа и перед каждой записью (запись сама сравнивает ревизию и возвращает `conflict`). Фоновый опрос по таймеру не вводится; слежение за файлами при массовых изменениях — этап 3.2.1. Реализовано в `EditorBuffer.checkDisk` и `Editors.checkAll` (`ui/src/lib/editors.svelte.ts`).

- Буфер чистый, диск изменился — текст молча перечитывается, курсор остаётся на прежнем смещении; полоса «Обновлено с диска» закрывается крестиком. Исчезновение файла перечитыванием не считается: это состояние «файл удалён» (проект ниже).
- Буфер изменён, диск изменился — ничего не перезаписывается, автосохранение останавливается. Полоса предлагает: **«Оставить мою версию»** (запись поверх ревизии, которую увидел конфликт), **«Взять версию с диска»** (черновик заменяется) и **«Сохранить мою рядом»** (буфер пишется в `<имя> (конфликт ЧЧММСС).md` в той же папке, при занятом имени добавляется `-2`, `-3`…; затем берётся диск; файл попадает в дерево как обычный документ). OQ-122 принят.
- Файл удалён с диска при изменённом буфере — «Файл удалён с диска»: **«Записать заново»** (создаст файл с `base_revision = null`) или **«Отбросить правки»**.

## Закрытие (НФТ-5)

- **Вкладка.** Закрытие вкладки (крестик, средняя кнопка мыши, `Ctrl+W`) сначала записывает правки. Если запись не удалась (конфликт, ошибка), открывается диалог со списком документов и причиной: **«Вернуться»** (по умолчанию, `Escape`) или **«Закрыть без записи»**. Если тот же буфер открыт в другом виде, закрытие этого вида ничего не спрашивает. Закрытие последнего вида с правками, записанных не до конца, не теряет их: буфер остаётся и дописывается в фоне. OQ-125 принят.
- **Окно.** Закрытие окна прячет его в трей (процесс живёт). При потере фокуса и сворачивании окна все несохранённые правки пишутся сразу (`Editors.flush`).
- **Выход из процесса** (пункт «Выход» трея, перезапуск из настроек, просьба установщика `--quit`). Процесс отправляет окну событие `bars://flush-request` и ждёт ответа командой `flush_reply` (`crates/bars-app/src/flush.rs`): `clean` — записано или писать нечего; `writing` — у окна есть изменённый или записывающийся документ, запись идёт (процесс ждёт её окончания до 60 с, раздел «Выход из процесса, пока идёт запись»); `asking` — есть документы, которые не записались, окно показывается и спрашивает пользователя тем же диалогом; `proceed` / `cancel` — решение пользователя. Нет ни одного слова окна за 3 с — выход продолжается (окно не загружено или нечего сбрасывать); нет решения пользователя за час — выход отменяется. Отказ пользователя оставляет процесс работать, перезапуск из настроек возвращает ошибку «Перезапуск отменён».
- **Не входит в 3.4.1.** Резервная копия несохранённого черновика на случай аварии процесса (OQ-126 принят: не делать); при аварии теряется не больше последней секунды набора и документы, записанные с ошибкой. Команда «Сохранить сейчас» (`Mod+S`, `document.save`) остаётся будущей: запись и так идёт через секунду, при переключении «исходник / рендер», потере фокуса и закрытии.

Нынешнее поведение и дефекты, на которых стоит модель, — в [матрице сохранности](../../knowledge/data-safety-matrix-2026-10-24.md) (номера M-NN). Настройки подчиняются тому же принципу, но у них своя сверка версии — [settings.md](../settings/settings.md), раздел «Сохранение настроек из окна».

**Принцип.** Правка пользователя, чужая версия файла и исчезнувший документ не пропадают молча. У каждого буфера один из трёх исходов: записан на диск, ждёт решения пользователя на экране или закрыт самим пользователем «без записи». Буфера без вкладки с неясной судьбой не бывает.

### Файл документа удалён

Решение OQ-171, вариант A (M-05, M-06, M-15; ISS-92). Проверка диска отличает «файла нет» от «файл изменился»: если у буфера есть прежняя ревизия, а на диске файла нет, буфер переходит в состояние «файл удалён». Текст не стирается и не перечитывается пустым.

- **Что видит пользователь.** Полоса «Файл удалён с диска» с кнопками «Записать заново» (запись с `base_revision = null`, после успеха буфер чистый) и «Закрыть вкладку». Правка в поле разрешена, но автосохранение стоит, пока пользователь не нажал «Записать заново»: файл не воскресает молча под набранным символом. У буфера с несохранёнными правками те же две кнопки, вторая называется «Отбросить правки» (так сегодня, M-06).
- **Документ, удалённый самим bars** (корзина из дерева, команда удаления). Окно, выполнившее удаление, закрывает чистые вкладки удалённых документов сами, а изменённые переводит в «файл удалён». Другие окна узнают при проверке диска (фокус, `bars://document-saved` для этого не используется) и показывают ту же полосу. Удаление не опрашивает другие окна и не отказывает из-за их правок: правка другого окна не теряется, а получает полосу (M-14, асимметрия с переносом принята).
- **Не затрагивает** открытие документа, которого не было: пустой `index.md` папки и новый файл открываются с `revision = null` с самого начала (E-10); отсутствие у них файла — не удаление.

### Диалог несохранённого

Решение OQ-172, пункт 1. Диалог «Есть несохранённые правки» открывается при закрытии вкладки и отдельного окна, при выходе из процесса, при смене проекта и при уходе проекта из bars (ниже). Список документов с причиной: конфликт, ошибка записи, файл удалён, запись не завершена. Выборы:

- **«Вернуться»** — по умолчанию, `Escape`: действие отменяется, всё остаётся на экране.
- **«Сохранить рядом и закрыть»** — показывается, только если каждый документ списка в конфликте с диском. Каждый буфер пишется в `<имя> (конфликт ЧЧММСС).md` в своей папке, как «Сохранить мою рядом» в полосе конфликта, после чего действие идёт дальше. Если запись рядом не удалась, диалог остаётся, ничего не отброшено. У документа в ошибке записи или «файл удалён» этого выбора нет: рядом писать нечего или некуда.
- **«Закрыть без записи»** — правки отбрасываются, действие продолжается.

### Смена проекта и уход проекта из bars

Решение OQ-172, пункт 2 (M-10…M-12, M-16; ISS-40). Смена проекта сначала записывает правки буферов прежнего проекта в этом окне и только потом пересобирает раскладку. Если запись не удалась, показывается диалог выше: «Вернуться» отменяет смену, прежний проект остаётся на экране с теми же вкладками; «Закрыть без записи» и «Сохранить рядом и закрыть» отпускают смену. То же — перед «Убрать из bars» и перед удалением проекта; у проекта, папки которого нет, запись даёт ошибку «Папки документа нет», и диалог предлагает только «Вернуться» и «Закрыть без записи».

Раскладка пересобирается и вид отцепляется (`detach`) только после решения, поэтому буфера без вкладки с ошибкой или конфликтом не появляется. Остаётся один случай: последний вид закрыт, пока шла запись (`saving`), и запись затем не удалась. Окно сразу показывает тот же диалог с этим документом; «Вернуться» открывает его вкладку, при необходимости через смену проекта по тому же правилу.

### Поиск и перенос при несохранённых правках

Решения ISS-40 и M-12. Буферы считаются по проекту: проверка перед поиском и ответ на `bars://move-flush-request` учитывают только документы проекта, для которого идёт поиск или перенос.

- **Поиск не блокируется.** Окно пробует записать правки проекта и в любом случае выполняет поиск по записанной версии. Над обоими разделами выдачи — «В тексте» и «По смыслу» — строка «Не записано: <документ> — <причина>. Результаты по записанной версии» со ссылкой на вкладку документа. Ошибка видна, даже когда раздел «По смыслу» пуст.
- **Перенос и переименование.** Просьба `bars://move-flush-request` несёт имя проекта; окно отвечает «cancel» только если не записался документ этого проекта. Буфер другого проекта перенос не отменяет.

### История отмены

Решение шага 3.1.1 (M-03, M-04, M-09; ISS-41). Любая замена текста версией с диска — первое чтение, «Обновлено с диска», «Взять версию с диска», «Сохранить мою рядом», приём правки из соседней панели того же документа — идёт транзакцией `Transaction.addToHistory.of(false)`. Кроме того, при смене версии файла история отмены и повтора обнуляется: `Ctrl+Z` не переходит границу между версиями. Буфер передаёт редактору отдельный счётчик успешных чтений: даже совпадающий текст новой версии сбрасывает историю. Внешний текст соседней панели также начинает новую историю этой панели. Правка, набранная пользователем после обновления, отменяется как обычно; собственное автосохранение историю не сбрасывает. Курсор остаётся на прежнем смещении, ограниченном длиной нового текста.

### Выход из процесса, пока идёт запись

Решение автора 24-10-2026, OQ-174 (M-20, ISS-93). Получив `bars://flush-request`, окно, у которого есть изменённый или записывающийся буфер, сразу отвечает «writing» и только потом — «clean» или «asking». Процесс ждёт первого слова окна 3 с, как сегодня: молчание за этот срок означает, что окна нет или оно не загружено. Пока окно ответило «writing», процесс ждёт окончания записи до 60 с; по истечении выход отменяется сообщением «Документ ещё записывается», правка остаётся на экране. Ответ «clean» окно по-прежнему шлёт только после записи.

## Вкладки, `Ctrl+O` и отдельные окна

Решения автора 22-10-2026: рекомендации OQ-138…OQ-140 приняты (Т-40). Реализовано 22-10-2026.

- **Вкладки и панели.** Вкладки, две и больше панелей с разными документами и перенос вкладок даёт каркас этапа 1.1 (Dockview); документ открывается в редакторе, один буфер на документ в окне. Повторное открытие открытого документа показывает его вкладку.
- **`Ctrl+O` (`document.open`).** Список поверх окна: все документы проекта, включая `Index.md` папок (`documentTargets` в `link-picker.ts`), отбор по названию и пути (палитра команд); после паузы 250 мс и от трёх знаков ниже добавляются документы из поиска по смыслу (`search` воркера, лимит 10, без повторов, ответ дописывается в открытый список; поздний ответ устаревшего запроса отбрасывается). `Enter` открывает вкладку в активной группе (`app.openDocument`), `Alt+Enter` — отдельное окно. Область — текущий проект; работает и в русской раскладке (физическая клавиша).
- **Отдельное окно документа (`document.newWindow`).** Пункт «Открыть в новом окне» в контекстном меню файла в дереве, карточки результата и вкладки документа (меню берёт ближайший `data-document-path`) и команда списка действий для документа в фокусе. Команда Tauri `document_window_open(project, path)` (`crates/bars-app/src/doc_window.rs`) проверяет путь теми же правилами, что чтение документа, и создаёт окно `doc-<хеш проекта и пути>` на том же `index.html`: окно спрашивает у процесса свой документ (`document_window_target`) и показывает компонент `DocumentWindow.svelte` — один документ с редактором, глазом, структурой и строкой состояния, без дерева, поиска, графа и вкладок. Воркер и модели общие. Подпись окна одинакова для одного документа, поэтому повторная команда выводит открытое окно вперёд. Права окна (`capabilities/default.json`) выданы по маске `doc-*`.
- **Ссылка внутри отдельного окна** (`[[…]]`, относительная, входящие) открывается в основном окне вкладкой: окно просит процесс командой `open_in_main_window`, основное окно показывается и получает событие `bars://open-document`. Выбор проекта в основном окне отдельное окно не меняет и не запоминает.
- **Согласованность правок между окнами (OQ-138, вариант А).** У каждого окна свой буфер. После успешной записи окно рассылает событие `bars://document-saved` (проект, путь, новая ревизия, подпись отправившего). Окно с буфером того же документа и другой ревизией выполняет обычную проверку диска (`EditorBuffer.checkDisk`): чистый буфер молча перечитывается («Обновлено с диска»), буфер с правками переходит в конфликт с тремя выборами (раздел «Конфликт версий»); автосохранение останавливается, ничего не перезаписывается молча. Свои сообщения окно игнорирует. Если событие потерялось, остаётся проверка при фокусе и перед каждой записью с контролем ревизий. Живой совместной правки одного буфера нет и не планируется в Т-40. Отдельное окно документа по записи (своей и чужой) и по `entry-moved` перечитывает дерево для `[[`, см. [опрос и нагрузку окон](../window/main-window.md).
- **Закрытие отдельного окна.** Закрытие окна документа не прячет его в трей: процесс отменяет закрытие и шлёт окну `bars://document-close-request`; окно закрывается командой `document_window_close` после записи правок (`confirmClose`). Если запись не удалась, тот же диалог «Вернуться / Закрыть без записи»; «Закрыть без записи» отбрасывает правки. Остальные окна и воркер продолжают работу. Главное окно командой не закрывается.
- **Выход из процесса.** `bars://flush-request` идёт всем окнам; `flush_reply` называет окно подписью. Выход разрешён, когда все окна ответили «чисто» или «закрыть без записи» (или молчат 3 с и ни одно не задало вопрос); любой отказ отменяет выход, спрашивающее окно показывается (`crates/bars-app/src/flush.rs`).
- **Не входит.** Перенос вкладки из основного окна в отдельное и обратно, сохранение раскладки отдельных окон (они не восстанавливаются после перезапуска bars), восстановление положения и размера окна, общий буфер между окнами.

## Редактор

CodeMirror 6, версии закреплены в `ui/package.json`. Состав: `@codemirror/state`, `view`, `commands` (история, штатные клавиши), `language` и `lang-markdown` с GFM (`markdownLanguage`), `autocomplete` (`closeBrackets` для `**`, `` ` ``, `(`, `[`), `markdownKeymap` (`Enter` продолжает список и задачу). Подсветка блоков кода по языку — `@codemirror/language-data` с ленивой загрузкой языка на первое появление блока; без него блоки кода подсвечиваются одним стилем (стоимость — в исследовании). Ввод по-русски идёт через штатный `contenteditable` CodeMirror с IME; вручную события клавиатуры не перехватываются, кроме сочетаний ниже.

- **Тема.** Цвета и шрифт берутся из CSS-переменных окна (`--panel`, `--accent-soft`, `--mono`); светлая и тёмная темы без пересоздания редактора (`Compartment`).
- **Подсветка найденного отрывка.** Строки `first_line…last_line` выделяются декорацией; панель прокручивается к ним; выделение пропадает при первой правке.
- **Структура.** Список заголовков строится из синтаксического дерева (ATX и setext, без заголовков внутри кода); переход ставит курсор и прокручивает.
- **Помощники разметки.** Команды `editor.*` из [keyboard-design.md](../window/keyboard-design.md) — функции над `EditorView` в `ui/src/lib/editor-commands.ts`: заголовки 1–3, жирный, курсив, строчный код, блок кода, маркированный и нумерованный список, задача, цитата, таблица, ссылка. Повторная команда снимает разметку; пробелы и конец строки на краях выделения в пару не входят. Сочетания приходят из реестра клавиатуры (Т-45) через адаптер команд редактора (`commandAdapter`): оконный обработчик ловит физическую клавишу, поэтому `Ctrl+B`, `Ctrl+I`, `Ctrl+K` работают и в русской раскладке; `Mod-i` CodeMirror («выбрать родителя») отключён. Панель кнопок над редактором скрыта по умолчанию (плотность окна) и включается кнопкой «Aa» в шапке документа; выбор запоминается. Кнопки сохраняют выделение. Шпаргалка по синтаксису — кнопка «?» в панели (OQ-127). **Ссылка на документ (Т-30).** Ввод `[[` и команда «Ссылка» без выделения (`Ctrl+K`) открывают выбор документа (`link-picker.ts`, `autocompletion` CodeMirror): список строится по мере набора: сначала документы проекта из дерева, чьи заголовок, имя файла или путь совпадают (мгновенно, без `Index.md`), ниже — документы из поиска по смыслу (`search` воркера, лимит 10, после паузы 250 мс и от трёх знаков, без повторов; ответ дописывается в открытый список), в конце «Создать ссылку»; Enter вставляет в файл `[[имя файла]]` без `.md` (как в Obsidian; если у другого файла то же имя — `[[папка/имя]]` с путём от корня документации) и убирает набранное `[[…` вместе с закрывающими `]]` автопары. Если точного совпадения названия нет, последним пунктом идёт «Создать ссылку на «название»»: вставляется `[[название]]`, файл не создаётся, ссылка остаётся битой до создания документа. Из названия убираются знаки `[ ] | # ^`. С выделением команда «Ссылка» по-прежнему оборачивает его в `[…]()`. Имя из `[[…]]` разбирают одинаково окно (`resolveWikilink`, рендер и переход по клику) и граф (`bars-graph`, `resolve_wikilink`, входящие ссылки и аудит битых ссылок): регистр не важен, `Название|текст` и `Название#раздел` ведут на документ, имя с `/` сверяется с путём от корня документации, при нескольких кандидатах выбирается файл в папке источника, затем самый короткий путь, затем по алфавиту; ссылка в коде ссылкой не считается. Переход в рендере или из панели «Ссылки» предлагает создать отсутствующий документ; пути, допуск и перенос ссылок описаны в [индексе ссылок](link-index.md).
- **Таблица.** `Tab` / `Shift+Tab` в таблице GFM (подряд идущие строки с `|`, вторая — разделитель) переходят между ячейками и выравнивают столбцы по самой длинной ячейке; `Tab` в последней ячейке добавляет строку; одиночная строка с `|` таблицей не считается, `Tab` в ней и вне таблицы не перехватывается. Ввод `*`: пара вокруг выделения, `**` из `*|*`, шаг за закрывающую `*`; в начале строки (маркер списка), в слове и в «2 * 3» не вмешивается; `Backspace` между `*` и `*` убирает обе.
- **Глаз.** Переключает тот же буфер между редактором и рендером; рендер строится из текущего буфера, а не из диска, поэтому несохранённые правки видны.
- **Не входит:** Live Preview и проверка орфографии.
