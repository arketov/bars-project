# Внешние модели bars — HTTP и локальные серверы

Кроме встроенных моделей, embed и rerank подключаются по HTTP (Т-17). OpenAI-совместимый embed и Cohere-совместимый rerank используют отдельные настройки. Ollama и LM Studio поддерживают embed; штатного rerank API у них нет.

Статус 23-10-2026: источник Ollama реализован; транспорт, сохранение настроек и независимый rerank проверены тестами. Настоящий Ollama 0.40.9 с Qwen3 0.6B на RTX 3090 прошёл индекс → запись настройки → два поиска. Нативное/установленное окно и сравнительное качество на корпусе не проверены; штатный rerank Ollama недоступен.

## Подключение Ollama

В настройках embed источник `ollama`, адрес корня сервера (например, `http://127.0.0.1:11434`) и точное имя установленной модели. В окне — отдельный переключатель «Ollama», исходный адрес и пример `qwen3-embedding:0.6b`; модель пользователь устанавливает в Ollama самостоятельно. bars не запускает сервер и не скачивает его модели. Выбор CPU/GPU и выгрузку определяет Ollama; параметры встроенных моделей bars к нему не применяются.

Запрос `POST <base_url>/api/embed`: `model`, массив `input`, `truncate: false`; ответ `embeddings` в исходном порядке. Размер пачки и таймаут прежние. bars проверяет число, конечность координат, ненулевую длину и одинаковую размерность векторов. Превышение контекста — ошибка, а не тихая потеря конца документа. Для семейства `qwen3-embedding` к поисковому запросу добавляется та же инструкция, что у встроенной Qwen; документ отправляется без неё. Отпечаток содержит отдельный источник `ollama` и точное имя модели; смена источника/модели требует согласия по Т-25. Изменяемые теги и замена модели на сервере при прежнем имени автоматически не обнаруживаются: после замены нужна полная переиндексация.

У Ollama нет штатного API rerank: сейчас источник `ollama` для включённого rerank отклоняется при сохранении, в переключателе rerank его нет. Можно независимо оставить встроенный rerank либо совместимый HTTP-сервер. Согласован, но не реализован rerank по logprobs yes/no через `POST /api/generate` с `raw: true` и промптом Qwen3-Reranker ([ADR-0006](../../adr/0006-rerank-yes-no-logprobs.md)). Запрос, оценка и обработка сбоев описаны в [исследовании Ollama](../../knowledge/ollama.md).

## Подключение LM Studio

Статус 23-10-2026: источник реализован, настройки и транспорт проверены тестами, настоящий LM Studio 0.4.26+4/Qwen3 Q8_0 на RTX 3090 прошёл индекс → сохранение → два поиска. Production UI и release WebView2 собраны; 13 программных проверок настоящего окна/IPC с FakeProvider подтвердили выбор, запись/чтение настроек, независимый rerank и предупреждение об усечении, обе темы на 1440/1024/760 px. Аппаратный backend проверен отдельно настоящим ConfiguredProvider. Установленное окно, физические жесты и сравнительное качество не проверены.

Подключение по Т-17 и Т-25: отдельный источник `lmstudio` для embed, адрес `http://127.0.0.1:1234` (допускается окончание `/v1`), точный идентификатор модели из LM Studio. Транспорт общий OpenAI `POST /v1/embeddings`; источник входит в отпечаток. Для стандартных имён Qwen3-Embedding инструкция добавляется только к запросу; произвольный алиас должен сохранять имя семейства. Документы идут без инструкции. bars не запускает LM Studio, не скачивает веса, не меняет GPU/context/выгрузку сервера. При замене весов под прежним ID нужна полная переиндексация.

У LM Studio не заявлен штатный rerank API: сейчас включённый rerank с источником `lmstudio` отклоняется, в окне такой выбор отсутствует. Rerank настраивается независимо — встроенный или совместимый HTTP. Согласован, но не реализован rerank по logprobs yes/no через `POST /v1/responses` ([ADR-0006](../../adr/0006-rerank-yes-no-logprobs.md)): другие маршруты LM Studio logprobs не отдают. Основания и ограничения — в [исследовании LM Studio](../../knowledge/lmstudio.md).

LM Studio на проверенной сборке обрезает длинный вход до контекста с HTTP 200, даже при `truncate:false`; предупреждение остаётся только в серверном журнале. bars отправляет полный текст, но этот API не гарантирует сохранность его конца. Окно явно предупреждает об ограничении. Размер `max_chars` задаётся в символах, а контекст сервера — в токенах: прямое сравнение некорректно. В тесте на 8192 токенах разные окончания входа по 24009/24010 токенов дали одинаковые 1024 координаты, журнал подтвердил усечение. Для входа неизвестной длины выбирать провайдер с явным отказом вместо усечения.

## Embed через OpenAI-совместимый API

Запрос `POST <base_url>/v1/embeddings` с телом `{"model": "...", "input": [...]}`. Чанки отправляются пачками; размер пачки задаётся в настройках провайдера. Размерность bars узнаёт по первому ответу и записывает в отпечаток модели.

## Подключение TEI

Источник `tei` для embed и rerank: корень отдельного сервера Hugging Face Text Embeddings Inference без `/v1`. Embed: `POST /embed`, `inputs` массивом, `truncate: false`, `normalize: true`; ответ — массив векторов в исходном порядке. Rerank: `POST /rerank`, `query`, `texts`, `truncate: false`, `raw_scores: false`, `return_text: false`; ответ — массив `{index, score}`. Все оценки возвращаются в порядке исходных документов; дубли, пропуски, неконечные значения и выход за диапазон отклоняются. Пустой или нулевой вектор, неверное количество/размерность — ошибка.

В TEI модель выбирается при запуске сервера: имя в настройках bars должно соответствовать загруженной модели и служит идентичностью индекса. bars не проверяет замену весов под тем же именем; после неё нужна полная переиндексация. Embed и rerank обычно обслуживают два экземпляра на разных портах. Ключ при необходимости указывается через `api_key_name`/`api_key_env`, передаётся Bearer; устройство и выгрузка определяются сервером. Для Qwen3-Embedding с сохранённым именем семейства bars добавляет стандартную инструкцию только к запросу; серверный default prompt нужно отключить. Для других моделей, требующих собственных префиксов, нужна отдельная согласованная настройка сервера, их универсальная поддержка не заявляется.

Выбор серверов и границы — [исследование внешнего инференса](../../knowledge/external-inference.md). Источник TEI проверен фикстурами и настоящим TEI 1.9.4/CUDA в WSL2 на RTX 3090: multilingual MiniLM embed/rerank, индекс, сохранение настроек и поиск через воркер. Оба адаптера отклоняют длинный вход по ответу 422: `truncate:false` действует даже при серверном `auto_truncate:true`. Собранный WebView2 проверил выбор обоих источников, адреса и сохранение через настоящий IPC. Это проверка подключения; превосходство качества моделей не установлено.

## llama.cpp и Infinity

Источник «Локальный адрес» (`local-openai`) использует совместимые API. llama-server: отдельный процесс embedding с `--embedding`, для rerank — другой процесс с поддерживаемой reranker-моделью и `--reranking`; pooling и контекст выбираются под модель. Не включайте reranking у embedding-модели. У Infinity настройте префикс маршрутов `/v1`. Точное имя модели/alias и адрес каждого сервера указываются независимо; bars сам процессы не запускает и веса не скачивает.

Для локального Qwen3-Embedding имя `Qwen/Qwen3-Embedding-…` либо `Qwen3-Embedding-…` включает стандартную инструкцию только к запросу; alias без семейства автоматически не распознаётся. На сервере не добавляйте ту же инструкцию повторно. Полный путь bars с llama.cpp b11669/Vulkan, Qwen3 embed/rerank 0.6B Q8_0 и RTX 3090 проверен на трёх документах и двух вопросах; Infinity и сравнительное качество не проверены. Совместимый HTTP не гарантирует отказ вместо усечения длинного входа: контекст и поведение конкретной сборки сервера необходимо проверить отдельно.

## Rerank через API в формате Cohere

Запрос `POST <base_url>/rerank` (или `/v1/rerank`) с телом `{"model": "...", "query": "...", "documents": [...], "top_n": N}`. Так отвечают routerai, Cohere, llama-server с `--reranking`.

## Адреса запросов

Решение агента (OQ-59):

- Embed: `<base_url>/v1/embeddings`. Если `base_url` уже заканчивается на `/v1`, вторая `v1` не дописывается.
- Rerank: сначала `<base_url>/rerank`, при ответе 404 — `<base_url>/v1/rerank`. Рабочий адрес запоминается до смены настроек.
- Ключ уходит заголовком `Authorization: Bearer <ключ>`. Ответы провайдера разбираются так: embed — `data[].embedding` (по `index`, если он есть); rerank — `results[].index` и `relevance_score` (или `score`).
- Оценки rerank в диапазоне 0…1 берутся как есть. Если хоть одна вне диапазона (сервер отдаёт сырой логит, например llama-server), все оценки пропускаются через сигмоиду.

## Размерность внешней модели

Размерность в настройках не задаётся. Отпечаток внешней модели по настройкам имеет размерность `0` («ещё не известна»); проверка Т-25 сравнивает остальные поля: источник, имя модели, префикс. Размерность воркер узнаёт из первого ответа провайдера: при создании индекса — одним пробным запросом, при поиске и обычной индексации — из ответов, которые всё равно нужны. Узнанная размерность записывается в индекс. Если позже тот же адрес вернёт вектор другого размера, индексация и поиск останавливаются ошибкой о размерности: переиндексация нужна, но bars сам её не начинает.

## Ключи внешних провайдеров

Ключ хранится в хранилище ОС, а не в настройках: см. [architecture/secrets.md](../../architecture/secrets.md). Для локального адреса ключ не нужен; удалённому провайдеру нужен `api_key_name` или `api_key_env` (проверяется при чтении настроек). Ключ читается при каждом запросе, поэтому исправленный ключ действует без перезапуска воркера. Если ответ провайдера повторяет ключ, bars заменяет его на `***` до записи в ошибку.

## Длина входа внешних моделей

bars не обрезает текст для внешнего провайдера: предел знает только он. Если провайдер отвечает ошибкой о слишком длинном входе, документ остаётся в очереди с этой ошибкой в состоянии индекса. Пользователь уменьшает `max_chars` ([features/settings/settings.md](../settings/settings.md)) или выбирает другую модель.

## Ошибки внешнего провайдера

- Индексация: единый бюджет индексатора — первая попытка и до трёх повторов документа с паузами 1/2/4 с. HTTP-транспорт не добавляет своих повторов; 4xx, кроме 429, не повторяется. После отказа документ пропускается, его прежняя версия сохраняется; следующая проверка попробует снова. Три неудачных документа подряд останавливают проверку ([updates.md](../indexing/updates.md)). Таймаут отдельного запроса embed — 120 с. Подготовка неизвестной размерности и embed поискового запроса сохраняют собственный прежний HTTP-бюджет; на повторы документа он не накладывается.
- Поиск: если embed недоступен, поиск возвращает ошибку с причиной. Если недоступен только rerank (таймаут 60 с, повторов нет), выдача возвращается без реранка и с пометкой об этом; число результатов тогда берётся как без реранка.
