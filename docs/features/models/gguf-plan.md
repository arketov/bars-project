# Этап 22 — встроенные GGUF-модели

Статус: проектирование и спайк. Основание — OQ-60, Т-3, Т-17, Т-25. Решение автора: Qwen3-Embedding 0.6B/4B в Q4_K_M через встроенный `llama-cpp-2`; сначала Windows/ORT/Vulkan, скорость, память и качество, затем ADR и продуктовая замена candle.

## Контракт GGUF

Инженерный проект: отдельный backend с прежним trait `Embedder`; ONNX bge и rerank сохраняются. GGUF содержит tokenizer. Для Qwen — last-token pooling, инструкция только к запросу, нормализованный конечный вектор ожидаемой размерности. Ограничение входа явно 8192 токена; обработка длинного входа должна сохранять последний токен при усечении. Индекс candle нельзя считать совместимым с квантованным backend: новый fingerprint требует согласия на переиндексацию по Т-25.

Артефакты закрепляются repo/revision/file/размером и хешем; скачивание в пользовательский кэш, готовность только после полной проверки. `Cpu` запрещает offload; `Gpu` требует реально доступного Vulkan; `Auto` допускает CPU с причиной fallback. Существующие настройки отдельных устройств, очередь модели, прогресс скачивания и ошибки окна должны работать с GGUF. Жизненный цикл backend общий на процесс; контекст не хранит ссылку на перемещаемую модель.

## Порядок внедрения GGUF

- [ ] Изолированный Rust-спайк, закреплённая версия wrapper/backend, сборка рядом с bars-core/ORT.
- [ ] CPU и Vulkan, проверка размерности, нормы, повторяемости и независимости текстов.
- [ ] Замороженный корпус этапа 9: отдельный индекс Qwen, полный retrieval, MRR/Hit и задержка против bge-m3; память отдельного процесса. Не сравнивать чужие векторы в одном индексе.
- [ ] Проверить Nomic v2 MoE на llama.cpp; сохранить поддержку Т-17, пока замена не доказана.
- [ ] После успешного спайка: ADR, каталог/скачивание, loader, fingerprint, устройства, регрессии и документация.

## Критерии приёмки GGUF

Обе Qwen загружаются из проверенного кэша и скачиваются штатным путём окна; CPU/Vulkan подтверждены исполнением. Ошибки/неполные файлы не становятся готовой моделью. Старый индекс требует согласия, bge не переиндексируется. Поиск/индексация и rerank ORT сосуществуют в одном процессе. Качество и расход памяти описываются измерениями с границами; неподтверждённые модели и платформы не объявляются принятыми.
