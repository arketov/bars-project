# Этап 22 — встроенные GGUF-модели

Статус: реализовано 18-10-2026 по [ADR-0002](../../adr/0002-qwen-gguf.md); CPU/Vulkan обеих Qwen, полный retrieval и ORT проверены. [Результаты](../../knowledge/gguf-models.md). Основание — OQ-60, Т-3, Т-17, Т-25. Установленный bars не менялся; OQ-90 запрещает закрывать его ради опытов.

## Контракт GGUF

Инженерный проект: отдельный backend с прежним trait `Embedder`; ONNX bge и rerank сохраняются. GGUF содержит tokenizer. Для Qwen — last-token pooling, инструкция только к запросу, нормализованный конечный вектор ожидаемой размерности. Контекст создаётся лениво по фактическому числу токенов (степень двойки, минимум 256), растёт до 8192; старый контекст освобождается до создания нового. Это ограничивает предварительный KV-cache для коротких текстов. Microbatch не больше 512. Ограничение входа явно 8192 токена; обработка длинного входа должна сохранять последний токен при усечении. Индекс candle нельзя считать совместимым с квантованным backend: новый fingerprint требует согласия на переиндексацию по Т-25.

Артефакты закрепляются repo/revision/file/размером и хешем; скачивание в пользовательский кэш, готовность только после полной проверки. Существующее `Cpu` запрещает offload; `Auto` предпочитает реально доступный Vulkan и допускает CPU с причиной fallback. Новый режим настройки устройства не вводится. Существующие настройки отдельных устройств, очередь модели, прогресс скачивания и ошибки окна должны работать с GGUF. Жизненный цикл backend общий на процесс; контекст не хранит ссылку на перемещаемую модель.

## Порядок внедрения GGUF

- [x] Изолированный Rust-спайк, закреплённая версия wrapper/backend, сборка рядом с bars-core/ORT.
- [x] CPU и Vulkan, проверка размерности, нормы, повторяемости и независимости текстов.
- [x] Замороженный корпус этапа 9: отдельный индекс Qwen, полный retrieval, MRR/Hit и задержка против bge-m3; память отдельного процесса. Не сравнивать чужие векторы в одном индексе.
- [x] Решить судьбу Nomic v2 MoE: сохранить candle по ADR-0002; GGUF-перенос без отдельной проверки не выполняется.
- [x] После успешного спайка: ADR, каталог/скачивание, loader, fingerprint, устройства, регрессии и документация.

## Критерии приёмки GGUF

Обе Qwen загружаются из проверенного кэша и скачиваются штатным путём окна; CPU/Vulkan подтверждены исполнением. Ошибки/неполные файлы не становятся готовой моделью. Старый индекс требует согласия, bge не переиндексируется. Поиск/индексация и rerank ORT сосуществуют в одном процессе. Качество и расход памяти описываются измерениями с границами; неподтверждённые модели и платформы не объявляются принятыми.

## Ручные хвосты GGUF

- Нажатие скачивания и выбор/поиск Qwen в настоящем Tauri; сейчас проверены общий worker-путь и библиотечный loader на отдельном кэше.
- Полный NSIS и запуск на Windows без установленного Vulkan runtime/драйвера; DLL/лицензия подготовлены и запуск с упаковываемой DLL на этой машине прошёл.
- macOS/Metal и другие GPU; нагрузочный CPU-корпус. Три GPU-прохода не заменяют эти проверки.
