# Похожие чанки и дубликаты для поддержки документации

Статус: назначение и входные параметры согласованы автором 18-10-2026; реализация и проверки не выполнены. Пожелания — IDEA-12 и IDEA-13 в [реестре](../../backlog/ideas.md).

## Общая область поиска

Оба инструмента работают внутри одного проекта и принимают необязательный список `modules` с той же семантикой, что [область rag_search](hybrid-search.md#область-поиска): перечисленные модули объединяются, `.` обозначает корневой модуль; отсутствие или пустой список означает весь проект, неизвестный модуль — `invalid_params`. Фильтр применяется до отбора результатов; пары дублей целиком принадлежат выбранной области.

## get_similar: похожие чанки по ID

Назначение: перед правкой найти похожие описания и разделы для проверки; перед добавлением текста — найти уже существующее описание.

Вход: ID индексированного чанка, проект и необязательный список `modules`. Проект можно определить из сессии, как у `rag_search`. Фильтр модулей ограничивает область кандидатов, исходный чанк может находиться в другом модуле того же проекта.

Результат: несколько наиболее похожих чанков из выбранной области, исключая исходный. Каждый результат содержит ID, путь, модуль, заголовки, строки, текст и оценку близости. Готовый вектор исходного чанка позволяет обойтись без нового embed. Смысловая близость сама по себе не доказывает дублирование, согласие или зависимость документов.

При реализации определить и проверить доступность ID в выдаче поиска, срок действия ID после переиндексации и явную ошибку для неизвестного или устаревшего ID. Лимит результатов и порог подобрать на реальных разделах; не заимствовать порог поиска «вопрос → документ» без проверки.

## get_duplicates: аудит дублей проекта

Назначение: ревизия повторяющихся описаний и разошедшихся копий для выбора основного источника и замены повторов ссылками.

Вход: обязательный явный `project`, необязательный список `modules`. Исходный чанк не нужен; без модулей проверяется весь указанный проект.

Результат: список пар или групп сильно повторяющихся чанков, наиболее явные совпадения первыми. Для каждого совпадения — ID чанков, пути, модули, заголовки, строки, совпавшие фрагменты и различия. Точные повторы, почти одинаковые копии и возможное смысловое дублирование различаются явно; одна высокая векторная близость не считается доказанным дублем. Изменённые числа, условия и отрицания сохраняются в сравнении. Автоматическое удаление или объединение документов не входит в инструмент.

При реализации определить группировку и порядок выдачи, ограничения объёма, обработку повторяющихся шаблонов и границ нарезки. Проверить полные и частичные копии, перефразирование, разные инструкции на одну тему и копии с изменённым числом или отрицанием.

## Реализация и приёмка

Два отдельных результата: `get_similar` и `get_duplicates`. Для каждого — ядро, вызов через воркер/MCP, описание инструмента и проверки фактической выдачи на временном проекте. Проверить фильтры модулей, отсутствие результатов, ошибки параметров и изменение индекса; замерить задержку на зафиксированном корпусе. До реализации уточнить технические контракты ID, лимитов и состояния индекса в этом документе.

Основание для выбора алгоритмов — [исследование локальных инструментов](../../knowledge/local-documentation-tools.md) (включает перепроверку источников); конкретные алгоритмы и зависимости этим решением не утверждены.
