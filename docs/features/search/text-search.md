# Поиск «В тексте» bars — вхождения строки в документах на диске

[← Поиск](Index.md)

Статус: проект этапов 3.6.1 и 3.6.2 от 22-10-2026, инженерное предложение агента; рекомендации OQ-136 приняты автором 22-10-2026. Кода нет, замера нет: НФТ-6 (p95 меньше 300 мс на проекте размером с bars) остаётся непроверенным. Размер корпуса bars-project на 22-10-2026: 334 документа, 2,6 МБ.

Основано на: [требования Т-39 и НФТ-6](../knowledge-base/requirements.md), [гибридный поиск](hybrid-search.md), [обновление индекса](../indexing/updates.md).

## Чем «В тексте» отличается от «По смыслу»

Нынешний поиск — ранжирование по чанкам: полнотекстовый FTS5 со стеммингом и слиянием слов через `OR` плюс векторный и реранк ([гибридный поиск](hybrid-search.md)). Он отвечает на вопрос «что об этом сказано», а не «где встречается эта строка», и видит правку только после embed (пауза Т-41). «В тексте» отвечает на второй вопрос: **все вхождения строки в файлах на диске**, без индекса, моделей и очереди. Одно поле запроса запускает оба поиска; разделы выдачи независимы, «В тексте» приходит первым.

## Что ищется

- **Строка запроса** — подстрока в тексте документа, не «слова независимо» (в отличие от Obsidian, где каждое слово ищется отдельно в файле); так «В тексте» не дублирует ранжирование и находит точные идентификаторы, куски кода и опечатки. Несколько слов с пробелом — подстрока с пробелом.
- **Регистр.** По умолчанию без учёта регистра по простому правилу Unicode (кириллица и латиница работают); переключатель «Aa» — с учётом регистра.
- **Регулярное выражение.** Переключатель `.*`: синтаксис крейта `regex` (без просмотра вперёд и назад, линейное время); построчный режим, `^` и `$` — границы строки, точка не пересекает строку. Ошибка выражения возвращается как `invalid_regex` с текстом и позицией, а не как пустая выдача.
- **Фильтр по пути.** Строка относительно корня документации: подстрока без учёта регистра; если содержит `*` или `?` — маска по компонентам пути. Без фильтра — весь проект.
- **Область.** Те же галочки дерева (Т-14, Т-34): модули, папки, файлы; пустой выбор — весь проект, как у «По смыслу».
- **Что читается.** Те же файлы, что видит индексатор ([правила обхода](../indexing/updates.md): `.md`, без папок с точки, без symlink и junction, без `BARS_INSTRUCTION.md`), UTF-8 с отбрасыванием BOM; не-UTF-8 файл пропускается и учитывается в `skipped`. Frontmatter ищется как обычный текст.

Поиск по именам файлов не входит: имена и пути ищет выбор документа (`Ctrl+O`, Т-40) и ссылка (`[[`, Т-30).

## Вызов воркера

Метод `text_search` (аудитория `Window`, как `new_topics_*`; MCP и CLI его не получают: Т-37 требует от окна функции агента, обратного требования нет, у агента есть чтение файлов).

| Поле | Значение |
|---|---|
| вход | `project`, `query`, `case_sensitive`, `regex`, `path_filter`, `scope` (модули и файлы), `limit_hits` (умолчание 500), `limit_docs` (умолчание 100), `request_id` |
| выход: документы | `path`, `module`, `title`, `hits_total` документа, `hits` (до 5 на документ в первом ответе) |
| выход: вхождение | `line`, `column`, `length`, `text` — строка, обрезанная до 240 знаков с сохранением вхождения, `ranges` — сдвиги совпадения в `text` |
| выход: итоги | `docs_total`, `hits_total`, `truncated` (какой предел сработал), `skipped` (не прочитанные файлы с причиной), `elapsed_ms` |
| порядок | по пути; документы, у которых совпало название файла или `title`, — первыми |

Новый запрос того же окна отменяет предыдущий (`request_id`); поздний ответ не показывается. «Показать ещё» у документа добавляет вхождения этого документа отдельным вызовом с `path`, а не пересчитывает всё. Опрос идёт по Enter, как у нынешнего поиска; поиск при наборе — улучшение, которое можно включить, если замер покажет запас.

## Свежесть

Метод читает диск. Правка в редакторе пишется через 1 с после последнего изменения ([редактор](../knowledge-base/editor-design.md), «Автосохранение»); перед отправкой запроса окно сбрасывает несохранённые буферы (`Editors.flush`), поэтому слово, только что набранное в документе, находится «В тексте» до индексации (критерий Т-39). Внешняя правка видна сразу: никакого кэша между диском и ответом нет.

## Устройство и бюджет

Первая версия — обход и чтение файлов в блокирующем пуле потоков воркера, построчный поиск `memchr`-подстрокой или `regex`, без кэша и без индекса. На корпусе bars (2,6 МБ) это ожидаемо десятки миллисекунд при тёплом кэше ОС; бюджет НФТ-6 и пределы нужно **измерить**, а не предполагать. Замер 3.6.1:

| Что | Как |
|---|---|
| Корпуса | bars-project (334 документа); снимок overdrive-bots; синтетические 2 000, 10 000 и 50 000 документов по 8 КБ |
| Режимы | подстрока без регистра, с регистром, регулярное выражение, редкое слово, частое слово (предел вхождений срабатывает) |
| Кэш | тёплый и холодный (первое чтение после перезагрузки или освобождения кэша) |
| Меры | p50, p95 и максимум на 30 прогонах; время до первого документа; память воркера |
| Варианты | один поток; пул потоков по числу ядер; кэш текстов документов в памяти по ключу (путь, размер, время), ограниченный по объёму и обновляемый слежением |
| Критерий | p95 меньше 300 мс на bars-project (НФТ-6); для 10 000 документов — вывод о том, нужен ли кэш или индекс триграмм |

Если одним потоком или пулом бюджет на большом корпусе не выполняется, следующий шаг — кэш текстов; индекс триграмм — только если кэш не помогает. Решение принимается по замеру и записывается в `knowledge/`, а не по предположению. Зависимости: `regex`, `memchr` (лицензии MIT или Apache-2.0, проверить при подключении); `globset` для маски пути можно заменить собственным сопоставлением двух знаков.

## Переход к найденному

Вхождение открывает документ в редакторе на строке; подсветка найденного отрывка редактора сейчас подсвечивает строки `first_line…last_line` ([редактор](../knowledge-base/editor-design.md), «Редактор»), для вхождения нужна подсветка диапазона `column…column+length` — малое расширение. Переход из раздела «В тексте» и «По смыслу» использует один механизм открытия.

## Проверка

| № | Сценарий |
|---|---|
| X-01 | Слово, набранное в редакторе секунду назад, находится «В тексте» до индексации и до паузы Т-41 |
| X-02 | Регистр: «Aa» отличает `Bars` от `bars`; кириллица работает без учёта регистра |
| X-03 | Регулярное выражение с классом символов находит вхождение; ошибочное выражение — `invalid_regex` с позицией, не пустой результат |
| X-04 | Фильтр по пути и область из галочек ограничивают документы; пустая область — весь проект |
| X-05 | Те же исключения, что у индексатора: папка с точки, symlink, junction, `BARS_INSTRUCTION.md` |
| X-06 | Не-UTF-8 файл пропущен и виден в `skipped`; BOM не мешает искать первую строку |
| X-07 | Пределы: частое слово даёт `truncated`, число вхождений ограничено |
| X-08 | Быстрый ввод двух запросов подряд: ответ прежнего запроса не показан |
| X-09 | Замер НФТ-6 на bars-project: p95 меньше 300 мс (3.6.1) |
