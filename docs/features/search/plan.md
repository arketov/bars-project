# ISS-02 — порядок и шкала без rerank

Статус: решение автора OQ-77 реализовано 18-10-2026; автоматические проверки и визуальная проверка во встроенном браузере пройдены. Текущее поведение — [hybrid-search.md](hybrid-search.md).

## Задача автора и границы ISS-02

Автор видит растущие вниз проценты и воспринимает порядок как случайный: [ISS-02](../../backlog/issues.md#iss-02-без-rerank-результаты-идут-не-по-убыванию-шкалы-релевантности). Основание — Т-12, Т-13, Т-18, Т-24. Изменение касается обычного поиска и возврата без rerank при его ошибке; окно, MCP и CLI должны передавать один порядок.

Ускорение моделей, умолчания C/K, ISS-03 и перевод интерфейса ISS-11 — отдельные задачи. Подписи, добавленные исправлением, учитывать в работе над ISS-11.

## Что установлено по коду и материалам этапа 9

- `bars-core/src/search/hybrid.rs::search`: FTS и векторы → `fuse` (RRF) → `exact_first` → фильтр по косинусу → лимит → `SearchHit.score = cosine`. Порядок и оценка имеют разный смысл уже в ядре.
- `exact_first` реализует критерий Т-12: точный идентификатор первым. Глобальная сортировка по косинусу может нарушить этот критерий, даже если сортировать полный пул до лимита.
- `ui/src/lib/ResultCard.svelte` вызывает `fit(hit.score)` без учёта `score_kind`. `format.ts::fit` превращает обе оценки в проценты, цвет и словесные метки по одним границам 0,5/0,75. Замер не калибровал эти метки как вероятность правильного ответа.
- `SearchHit` проходит через `bars-worker/src/handler/mod.rs::hit`; MCP и CLI печатают оценку с видом `cosine`/`rerank`. Исправление только сортировкой карточек создало бы разные выдачи клиентов.
- Успешный rerank уже сортирует по своей оценке. Ошибка rerank возвращает обычный гибридный порядок и косинус; эта ветка входит в приёмку.

Serena: Rust LSP проверен реальными запросами символов `search`, `exact_first`, `threshold_and_cut` и ссылок на `SearchHit`; доступен. Новый инференс для установления причины не нужен.

## Принятое решение OQ-77 — гибридный порядок и честная полоска

Автор выбрал А с поправкой: «Вариант, а Но процентную полоску не убирай - она красивая, просто надо чтоб она показывала реальность.» Ответ сохранён в [QUESTIONS.md](../../../QUESTIONS.md), OQ-77.

Реализация: сохранить RRF и приоритет идентификаторов. Полоска и проценты остаются шкалой фактической оценки: `Cosine similarity` без rerank, `Rerank score` с ним. Над карточками видны вид порядка и пояснение: близость может возрастать вниз, поскольку гибридный порядок учитывает также слова и точные идентификаторы. Числа не изображают вероятность правильности. Не нормировать RRF и не вычислять процент из места результата.

Убрать неподтверждённые категории «хорошо подходит/частично/слабо». Для косинуса использовать акцентный цвет без цветовых категорий; для rerank сохранить цвета числовых диапазонов с явной подписью вида оценки. Доступное имя полоски и подсказка называют измеряемую величину.

Ядро, IPC, JSON, типы `SearchHit`, `min_score_vector`, порядок и оценки MCP/CLI сохраняются. Ошибка rerank получает представление косинуса по фактическому `score_kind`. Успешный rerank сохраняет свою оценку и порядок.

Глобальная сортировка по косинусу и отдельные группы точных совпадений отклонены выбором А; дополнительных замеров нового алгоритма не требуется. Исходный бенч этапа 9 остаётся действующим: ранжирование не меняется.
