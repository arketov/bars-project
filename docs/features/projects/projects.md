# Реестр проектов bars

Какие папки bars считает проектами и что происходит с проектом на протяжении его жизни (Т-5, Т-6, Т-15). Решение агента, 14-10-2026.

## Что хранит реестр проектов

`~/.bars/projects.toml` — список проектов: абсолютный путь к корню проекта и время регистрации. Всё остальное о проекте лежит в его `.bars/` ([architecture/files.md](../../architecture/files.md)). Проект однозначно определяется путём к корню.

Имя проекта по умолчанию — имя папки корня. По запросу автора от 31-10-2026 пользователь может задать своё отображаемое имя через «Переименовать…» в меню проекта. Оно хранится в необязательном поле `name` записи реестра, используется в окне, MCP и CLI, включая выбор параметром `project`. Папка, путь, индекс и открытые документы сохраняются. Старое имя папки после переименования не служит псевдонимом; абсолютный путь продолжает работать. Имя обрезается по краям; пустое имя и управляющие символы запрещены. Ошибка записи оставляет прежнее имя и видна в диалоге. Отмена ничего не меняет.

Если у двух проектов одинаковые отображаемые имена, окно и `projects` показывают их с путём, а параметр `project` с таким именем требует путь ([protocol.md](../../architecture/protocol.md)).

Проверка переименования: задать русское имя с пробелами, проверить список проектов в окне и инструментах, перезапустить bars и найти проект по новому имени и прежнему абсолютному пути. Убедиться, что папка не переименована и поиск по индексу работает. Проверить отмену, пустое имя, совпадающие имена и ошибку сохранения. Статус 31-10-2026: реализовано; 12 целевых UI-тестов и проверка Svelte прошли. Полный гейт остановлен по указанию автора «Без тестов комит и пуш». Нативная проверка и установленная версия не проверены.

## Корень проекта при регистрации

Окно и `bars-cli register <путь>` регистрируют ровно ту папку, которую указал пользователь.

Хук начала сессии получает только `cwd` агента, а это может быть подпапка проекта или вообще не проект. Поэтому корень ищется по порядку:

1. ближайшая вверх от `cwd` папка, которая уже зарегистрирована или содержит `.bars/` проекта — тогда это она. `.bars/` проекта — та, где есть `config.toml` или `index.sqlite`; домашняя `.bars/` пользователя папку проектом не делает (решение агента, OQ-45). Незарегистрированная папка с `.bars/` проверяется и регистрируется так же, как найденная по шагам 2 и 3;
2. иначе — корень git-репозитория, в котором лежит `cwd`;
3. иначе — сама `cwd`.

Хук регистрирует найденную и ещё не зарегистрированную папку, только если в ней есть корень документации (по умолчанию `docs/`) хотя бы с одним `.md`. Иначе хук ничего не делает. Так сессия, открытая в домашней папке или в репозитории без документации, не засоряет реестр.

Первый шаг решает и вопрос worktree: worktree в `.worktree/<имя>` или `.claude/worktrees/<имя>` лежит внутри зарегистрированного проекта, поэтому сессия в нём ищет по основному проекту (OQ-28).

## Вложенные проекты

Проект может лежать внутри другого. Для `cwd` действует ближайший зарегистрированный проект вверх по дереву (Т-15). Индексы у проектов свои; если вложенный проект лежит внутри корня документации внешнего, его `.md` попадают и в индекс внешнего — отдельного исключения bars не делает.

## Пропавший проект

Если отсутствие папки обнаружено при старте, часовой проверке, начале активности MCP или событии слежения активного проекта, проект получает состояние `unavailable` ([worker.md](../../architecture/worker.md)):

- из реестра он не удаляется: папка может быть на отключённом диске или в выгруженной папке OneDrive;
- индексация и слежение для него останавливаются;
- поиск и другие методы по нему возвращают `project_unavailable`;
- окно показывает его с пометкой и кнопкой «Убрать из bars».

Папка снова появилась — проект возвращается в работу при ближайшей проверке. Только найденные расхождения создают задание обновления; слежение поднимается при наличии открытого окна или действующего часа MCP-активности. Регистрация сама по себе постоянное слежение не включает; правила активности — [обновление индекса](../indexing/updates.md).

## Перенесённый проект

Индекс хранит пути документов относительно корня проекта, а `.bars/` переезжает вместе с папкой. Поэтому перенос — это регистрация на новом месте: bars подхватывает существующую `.bars/` без переэмбеддинга (Т-6), если модель индекса совпадает с настройками (иначе Т-25). Старая запись в реестре становится `unavailable`, и пользователь убирает её.

## Снятие проекта с регистрации

Команда `bars-cli unregister [--project <путь>]` и кнопка «Убрать из bars» в окне:

- удаляют проект из `projects.toml`;
- останавливают слежение и снимают проект с очереди.

Папку `.bars/` и `BARS_INSTRUCTION.md` в проекте bars не удаляет: это файлы пользователя (Т-5). Если `.bars/` осталась, следующая регистрация подхватит её как есть.

Агенту снятие с регистрации через MCP недоступно: в списке инструментов агента его нет (Т-19).

## Полное удаление данных проекта

Пункт «Удалить проект» в контекстном меню окна — отдельная операция с подтверждением. Очищает регистрацию, индекс, локальные настройки и задания, сохраняя документацию по OQ-83. Состав файлов, ожидание индексации и ошибки — [deletion.md](deletion.md). Семантика CLI `unregister` не меняется.
