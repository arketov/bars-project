# Соглашение о документации — фича bars

bars советует проектам, как раскладывать `docs/`, и доносит этот совет до агентов (Т-8, Т-27, Т-28). Совет необязателен: bars индексирует любую структуру, модуль — по-прежнему подпапка первого уровня (Т-7). На оформление файлов bars влияет только просьбой в инструкции.

Зачем: агенты пишут в документацию разное — устройство, решения, находки, ход работы. Если всё лежит вперемешку, поиск возвращает старый ход работы рядом с текущим устройством. Раскладка по папкам делает каждый вид записей отдельным модулем, и агент сам выбирает, где искать (Т-14).

| Файл | Когда читать |
|---|---|
| `layout.md` | Рекомендуемая раскладка `docs/`: база знаний, решения, фичи, журнал сессий |
| `session-log.md` | Журнал сессии: как вести `handoff.md` (`log.md` не ведётся), что в него писать по ходу работы |
| `session-end.md` | Завершение сессии skill `bars-end`: что агент переносит в документацию, что только предлагает |
| `delivery.md` | Как совет доходит до агента: стартовая инструкция MCP, skills, `BARS_INSTRUCTION.md`; как проверить доставку |
| `bars-instruction.md` | Что такое `BARS_INSTRUCTION.md`, как он обновляется и о чём говорит; свод правил для агента по каналам доставки и место в `initialize` |
