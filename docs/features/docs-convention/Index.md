# Соглашение о документации — фича bars

bars советует проектам, как раскладывать `docs/`, и доносит этот совет до агентов (Т-8, Т-27, Т-28). Совет необязателен: bars индексирует любую структуру, модуль — по-прежнему подпапка первого уровня (Т-7). На оформление файлов bars влияет только просьбой в инструкции.

Зачем: агенты пишут в документацию разное — устройство, решения, находки, ход работы. Если всё лежит вперемешку, поиск возвращает старый ход работы рядом с текущим устройством. Раскладка по папкам делает каждый вид записей отдельным модулем, и агент сам выбирает, где искать (Т-14).

- [layout.md](layout.md) — рекомендуемая раскладка `docs/`: база знаний, решения, фичи, журнал сессий.
- [session-log.md](session-log.md) — журнал сессии: когда писать `log.md` и `handoff.md`, как не тратить на них лишние токены.
- [delivery.md](delivery.md) — как совет доходит до агента: стартовая инструкция MCP, skills, `BARS_INSTRUCTION.md`.
- [bars-instruction.md](bars-instruction.md) — что такое `BARS_INSTRUCTION.md`, как он обновляется и о чём говорит.
- [plan.md](plan.md) — IDEA-08: итог реализации таблиц размещения, переноса реестров и проверок.
- [verification.md](verification.md) — IDEA-08: воспроизведение проверок, тестовые AI-сессии и границы подтверждения.
