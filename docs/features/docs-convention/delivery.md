# Как соглашение о документации доходит до агента — стартовая инструкция, skills, BARS_INSTRUCTION.md

`BARS_INSTRUCTION.md` лежит в `docs/`, но агент сам его не открывает. Поэтому у соглашения три канала: короткая стартовая инструкция в каждой сессии, skills с подробными правилами и файл в проекте как справочник.

## Стартовая инструкция MCP

`bars-mcp` возвращает текст в поле `instructions` ответа на `initialize` (Т-27). Так делают serena и semble: клиент показывает этот текст модели в начале сессии, отдельный вызов не нужен. Работает в любом MCP-клиенте, хук не нужен.

Текст компактный, не длиннее 2 000 знаков: он попадает в контекст каждой сессии. В нём только то, что нужно каждой сессии:

- bars — поиск по документации проекта; модули — папки `docs/`, выбирай нужные;
- сначала определить предмет задачи; для известного документа выбрать `read`/`outline`, для неизвестного контекста — предметный поиск с подходящей областью;
- отсылка к skills для оформления документов и журнала, приоритет правил проекта;
- доступ к аудитам окна и новым темам, явный абсолютный проект и отличие вопроса от источника знания;
- свежесть: чтение/точный поиск/ссылки с диска, индекс после паузы и очереди, GraphRAG отдельно от физической карты; несохранённый буфер недоступен;
- два ограниченных инструмента чтения: `bars_text_search` и `bars_links`, продолжение по revision/cursor и явный перезапуск при устаревании.

Постоянная часть зашита в `bars-mcp`; список модулей проекта добавляется из реестра и индекса при подключении, в пределах трёх секунд и общего лимита 2 000 знаков. При сбое остаётся инструкция без списка; `list_tools` повторяет запрос один раз. Назначения модулей берутся из `title` их `Index.md`, без загрузки моделей ([модули проекта](../agent-tools/module-scope.md)).

## Выбор операции и области агентом

Уточнение автора 18-10-2026 по [разбору вызовов](../../knowledge/agent-tool-usage-2026-10-18.md): сначала определить предмет задачи, затем выбрать операцию. Номер этапа разрешается через известный проектный план или реестр; универсальная добавка «требования ошибки пожелания пользователя» не заменяет предмет запроса. Известный документ можно читать напрямую через `bars_read`, заголовки — через `bars_outline`, без обязательного предварительного поиска.

Неизвестный контекст ищется предметным вопросом. Модуль выбирается по виду знания: `features` — контракты, `architecture` — устройство, `adr` — решения, `knowledge` — исследования, `backlog` — баги и идеи, `chats` — история. Несколько видов или неясное место допускают весь проект; слабая или пустая выдача — повод расширить область. Имена первого уровня берутся из инструкции и описания `modules`, для другого проекта — из `bars_projects`; примеры не заменяют реальные имена. `files` выбирает известные индексируемые документы, принимая обе формы пути, в том числе путь из выдачи. Наличие файла на диске не доказывает наличие в индексе.

Примеры для проекта с рекомендуемой раскладкой; реальные имена модулей и файлы проверяются в целевом проекте:

- Найти пожелания по индексации: `bars_rag_search({query:"Какие пожелания есть к обновлению индекса?",modules:["backlog"]})`.
- Найти контракт поиска: `bars_rag_search({query:"Как работает поиск?",modules:["features"]})`.
- Найти устройство воркера: `bars_rag_search({query:"Как устроен воркер?",modules:["architecture"]})`.
- Найти обоснование решения: `bars_rag_search({query:"Почему выбран SQLite?",modules:["adr"]})`.
- Восстановить итоги прошлой сессии: `bars_rag_search({query:"Последние результаты проверки устройств моделей",modules:["chats"]})`.
- Сверить два выбранных источника: `bars_rag_search({query:"Как выбирается устройство rerank?",files:["features/models/local-models.md","features/settings/settings.md"]})`.
- Прочитать известный контракт: `bars_read({path:"features/settings/settings.md"})`; получить структуру: `bars_outline({path:"features/settings/settings.md"})`.

При пустой выдаче проверить предмет, проект и фильтры; после поиска в модулях попробовать весь проект. Ноль не доказывает отсутствие требования и не оправдывает переиндексацию. `scope` показывает область, `by_module` — состав кандидатов и результатов; подсказка широкого поиска не выбирает модуль за агента. Обязательной частоты фильтрации нет. Правило доставляется стартовой инструкцией, описаниями MCP/аргументов, skills `bars-docs` и `bars-session-log`, гейтом и обеими копиями BARS_INSTRUCTION.

## Skills bars

Установка в Claude Code и Codex (Т-21) ставит skills, удаление их убирает (Т-28). Skill загружается в контекст только когда нужен, поэтому подробные правила живут здесь, а не в стартовой инструкции.

- `bars-docs` — перечень 22 инструментов bars, включая чтение с диска, аудиты и новые темы, с таблицей «когда что вызывать», свежестью и порядком выбора; самодостаточные таблицы выбора документа с содержанием и примерами ([layout.md](layout.md)), оформление для индексации ([bars-instruction.md](bars-instruction.md)), ADR, жизненный цикл фичи. Полная инструкция остаётся справочником; доступ к репозиторию bars не требуется.
- `bars-session-log` — журнал сессии ([session-log.md](session-log.md)): когда и как писать `log.md`, как писать `handoff.md`, как начать с последнего handoff. Таблица отделяет журнал от знаний, ADR, багов и пожеланий; полная карта видов — в `bars-docs`.
- `bars-end` — завершение сессии по команде пользователя ([session-end.md](session-end.md)): опись того, что было в сессии, перенос фактов в документы-владельцы, правка устаревших повторов, `handoff.md`, отчёт. Агент сам его не вызывает.

Skills ставятся в пользовательскую папку клиента, а не в проект: bars не пишет в репозиторий ничего, кроме `.bars` и `BARS_INSTRUCTION.md` (Т-5, Т-8). Установка и удаление трогают только папки skills с именами bars. Папка skills: Claude Code — `~/.claude/skills`, Codex — `~/.agents/skills` ([clients.md](../clients/clients.md)). Тексты skills лежат в `bars-worker/assets/skills/` и зашиты в bars.

Новый skill добавляется в четырёх местах: папка с `SKILL.md` в `assets/skills/`, строка в списке `SKILLS` (`bars-worker/src/clients/mod.rs`), ожидаемое число файлов в тестах установки, удаления и частичного обновления (`clients/tests.rs`, `clients/refresh_tests.rs`), списки skills в `scripts/test-client-refresh.ps1`, `test-client-profile-isolation.ps1`, `test-docs-convention.ps1` и `test-mcp-disk-read.mjs`. Тесты считают файлы, поэтому без правки чисел они падают.

## BARS_INSTRUCTION.md

Полный текст правил в проекте, для людей и для агентов без MCP и skills ([bars-instruction.md](bars-instruction.md)). Он перезаписывается при каждой новой версии bars, поэтому правки проекта в нём не сохраняются (Т-8).

Обновление исходного asset не меняет установленный бинарник. В новой сборке инструкция синхронизируется при проверке проекта, а skills существующих интеграций обновляются [фоновым проходом](../clients/clients.md#автообновление-существующих-интеграций). Старая работающая сборка может вернуть старую инструкцию. Доставка файлов и соблюдение советов моделью проверяются отдельно.

## Как проверить доставку

Проверки собраны в скрипты; Cargo-группы запускать только через `scripts/test-docs-convention.ps1`: он выполняет их с временными `BARS_USER_HOME` и `CODEX_HOME` и сравнивает хеши, mtime и наличие настоящих конфигов, резервных копий и skills до и после.

| Проверка | Команда | Что проверяет |
|---|---|---|
| Три группы Cargo | `pwsh -File scripts/test-docs-convention.ps1 -EvidenceDir <папка>` | `cargo test -p bars-core instruction::tests` (создание и восстановление инструкции, нестандартный корень), `cargo test -p bars-worker clients::` (установка, обновление, удаление, идемпотентность), `cargo test -p bars-mcp` (initialize с инструкцией до 2000 знаков, вызовы, транспорт). |
| Шесть запусков воркера | `pwsh -File scripts/test-client-refresh.ps1 -EvidenceDir <папка>` | Старые тексты skills у обоих клиентов заменяются актуальными; no-op, uninstall, изоляция ошибки, пустой профиль, junction, stdio-MCP ([clients.md](../clients/clients.md)). |
| Нестандартный корень | `pwsh -File scripts/test-docs-delivery.ps1 -BinDir <каталог exe> -EvidenceDir <папка>` | Настоящие IPC, очередь и синхронизация, восстановление испорченной инструкции. Модель подменена FakeProvider за `test-support`, качество инференса не проверяется. |
| Два чтения MCP | `node scripts/test-mcp-disk-read.mjs <каталог exe> <новая папка evidence>` | Настоящие stdio/IPC, 22 схем, свежие текст и ссылки, UTF-16 и хеши/mtime настоящих профилей. Только изолированный воркер с FakeProvider. |
| Чистые AI-сессии | `node scripts/test-docs-agent-sessions.mjs <папка>` | Четыре независимых Codex exec: instruction и skills, стандартная раскладка и своя. Нужен вход в CLI; используется модель Codex по умолчанию. |

Повторный прогон — в новой папке evidence. Стандартные сессии записывают баг, неутверждённую идею, замер, решение, требования фичи, `log.md` и `handoff.md`; проверяются пути, ссылки, frontmatter, оглавления и то, что общий SPEC не расширен деталями фичи. Сессии со своей раскладкой обновляют только собственные документы и не создают `docs/`, `backlog/`, `knowledge/`, `chats/`: так проверяется рекомендательность таблицы.

## Границы проверки доставки

Проверяются содержание и доставка рекомендаций и четыре ограниченные сессии Codex; это не гарантия соблюдения правил всеми моделями. Поведение Claude Code и macOS не проверялись, доставка файлов Claude проверена процессно. Установленная старая сборка bars может перезаписать `docs/BARS_INSTRUCTION.md` старым текстом; источник поставки — `crates/bars-core/assets/BARS_INSTRUCTION.md`. Результаты приёмки IDEA-08 — в журнале сессии 2026-10-18-docs-layout-design (`chats/2026-10-18-docs-layout-design`).
