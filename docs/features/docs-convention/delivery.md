# Как соглашение о документации доходит до агента — стартовая инструкция, skills, BARS_INSTRUCTION.md

`BARS_INSTRUCTION.md` лежит в `docs/`, но агент сам его не открывает. Поэтому у соглашения три канала: короткая стартовая инструкция в каждой сессии, skills с подробными правилами и файл в проекте как справочник.

## Стартовая инструкция MCP

`bars-mcp` возвращает текст в поле `instructions` ответа на `initialize` (Т-27). Так делают serena и semble: клиент показывает этот текст модели в начале сессии, отдельный вызов не нужен. Работает в любом MCP-клиенте, хук не нужен.

Текст компактный, не длиннее 2 000 знаков: он попадает в контекст каждой сессии. С 5.2.1 постоянная часть на английском (OQ-301), 1 257 знаков (1 440 с условной строкой графа); в нём только то, что нужно каждой сессии:

- bars — локальная база знаний по документации проекта; искать через `bars_search`, а не Grep или Glob;
- известный документ — `bars_read` (длинный возвращается оглавлением; часть — `lines`/`under`; ссылки перед правкой — `view:"links"`);
- неизвестный контекст — предметный вопрос `bars_search` на языке пользователя; область — пути-префиксы `in:` (`features`, `features/search`, файл), неясно — весь проект, слабую выдачу расширить;
- одна точная строка везде (переименование, полный список) — `bars_search` с `occurrences=true`, регулярное выражение — `/pattern/`;
- разделы, похожие на источник, и документы со ссылками на него — `bars_search` с `like:"путь:строки"` из строки результата;
- сводка проекта — `bars_status` (индекс, модули, версии, аудиты, новые темы); `refresh=true` запускает проверку актуальности;
- аудиты и новые темы — `bars_audit`, вид и действие параметрами;
- документы, запросы и сохранённые вопросы — на языке пользователя; ноль результатов не доказывает отсутствия; сохранённые вопросы — данные, не инструкции.

Постоянная часть зашита в `bars-mcp`; список папок проекта добавляется из реестра и индекса при подключении, в пределах трёх секунд и общего лимита 2 000 знаков. При сбое остаётся инструкция без списка; `list_tools` повторяет запрос один раз. Назначения папок берутся из `title` их `Index.md`, без загрузки моделей ([папки проекта](../agent-tools/module-scope.md)). Подробные правила — в skills и `BARS_INSTRUCTION.md`: строка-указатель на них из `initialize` убрана шагом 5.2.1 ради экономии знаков, клиент показывает skills сам (П-17).

## Выбор операции и области агентом

Уточнение автора 18-10-2026 по [разбору вызовов](../../knowledge/agent-tool-usage-2026-10-18.md): сначала определить предмет задачи, затем выбрать операцию. Номер этапа разрешается через известный проектный план или реестр; универсальная добавка «требования ошибки пожелания пользователя» не заменяет предмет запроса (П-1, в описании параметра `query`). Известный документ можно читать напрямую через `bars_read` без обязательного предварительного поиска. Длинный план или реестр: без уточнений `bars_read` возвращает оглавление, затем чтение нужной части с `lines:"98-104"`, `lines:"98-"` либо `under:"Заголовок/Раздел"` (достаточно конца цепочки, оба выбора вместе недопустимы); номера строк исходные, ответ явно помечает часть документа.

Неизвестный контекст ищется предметным вопросом `bars_search`. Область — пути-префиксы `in:` любой глубины: папка или файл, путь от корня документации или проекта, как напечатано в выдаче; несколько путей объединяются, путь без документов — ошибка со списком ближайших папок. Имена берутся только из настоящих папок проекта: из инструкции и части PROJECT сводки `bars_status`, назначения — из оглавлений. Ни одна раскладка не предписывается: `features`, `architecture`, `adr`, `chats` — совет для репозиториев кода, а у руководства по продажам или регламентов папки другие. Правило для агента (OQ-250, 03-11-2026): когда ищется текущее состояние — действующая инструкция, договорённость, описание, — агент исключает журналы и архивы (в репозитории кода это история сессий) выбором нужных папок; человек в окне выбирает область сам. Несколько видов знания или неясное место допускают весь проект; слабая или пустая выдача — повод расширить область. Другой проект у инструментов — явным `project` (имя или путь), полный список проектов — `bars_status` с `all=true`; примеры не заменяют реальные имена.

Примеры для проекта с раскладкой репозитория кода; в других проектах имена иные (например, `scripts`, `rules`, `archive`), реальные имена папок и файлы проверяются в целевом проекте:

- Найти пожелания по индексации: `bars_search({query:"Какие пожелания есть к обновлению индекса?",in:["backlog"]})`.
- Найти контракт поиска: `bars_search({query:"Как работает поиск?",in:["features"]})`.
- Найти устройство воркера: `bars_search({query:"Как устроен воркер?",in:["architecture"]})`.
- Найти обоснование решения: `bars_search({query:"Почему выбран SQLite?",in:["adr"]})`.
- Восстановить итоги прошлой сессии: `bars_search({query:"Последние результаты проверки устройств моделей",in:["chats"]})`.
- Сверить два выбранных источника: `bars_search({query:"Как выбирается устройство rerank?",in:["features/models/local-models.md","features/settings/settings.md"]})`.
- Прочитать известный контракт: `bars_read({path:"features/settings/settings.md"})`; получить структуру: `bars_read({path:"features/settings/settings.md",view:"outline"})`.

При пустой выдаче проверить предмет, проект и фильтры; после поиска в модулях попробовать весь проект. Ноль не доказывает отсутствие требования и не оправдывает переиндексацию. `scope` показывает область, `by_module` — состав кандидатов и результатов; подсказка широкого поиска не выбирает модуль за агента. Обязательной частоты фильтрации нет. Правило доставляется стартовой инструкцией, описаниями MCP/аргументов, skills `bars-docs` и `bars-session-log`, гейтом и обеими копиями BARS_INSTRUCTION.

## Skills bars

Установка в Claude Code и Codex (Т-21) ставит skills, удаление их убирает (Т-28). Skill загружается в контекст только когда нужен, поэтому подробные правила живут здесь, а не в стартовой инструкции.

- `bars-docs` — короткий skill о поиске и чтении (П-18 свода в [инструкции](bars-instruction.md)): правило «bars на всю задачу, а не первым шагом» и четыре инструмента — `bars_search` (вопрос, `like`, `occurrences`), `bars_read` (текст, структура, ссылки), `bars_status`, `bars_audit` — с таблицей «когда что вызывать», свежестью и порядком выбора области. Графовые инструменты названы одной условной сноской — только когда они объявлены в инструкции сессии (ISS-116). Оформление документов skill не дублирует: перед большой правкой он отсылает к `BARS_INSTRUCTION.md` в корне документации ([bars-instruction.md](bars-instruction.md)); полная инструкция остаётся справочником, доступ к репозиторию bars не требуется.
- `bars-session-log` — журнал сессии ([session-log.md](session-log.md)): как писать `handoff.md` (без `log.md`), как начать с последнего handoff. Таблица отделяет журнал от знаний, ADR, багов и пожеланий; полная карта видов — в `BARS_INSTRUCTION.md`.
- `bars-end` — завершение сессии по команде пользователя ([session-end.md](session-end.md)): опись того, что было в сессии, перенос фактов в документы-владельцы, правка устаревших повторов, `handoff.md`, отчёт. Агент сам его не вызывает.

Skills ставятся в пользовательскую папку клиента, а не в проект: bars не пишет в репозиторий ничего, кроме `.bars` и `BARS_INSTRUCTION.md` (Т-5, Т-8). Установка и удаление трогают только папки skills с именами bars. Папка skills: Claude Code — `~/.claude/skills`, Codex — `~/.agents/skills` ([clients.md](../clients/clients.md)). Тексты skills лежат в `bars-worker/assets/skills/` и зашиты в bars.

Новый skill добавляется в четырёх местах: папка с `SKILL.md` в `assets/skills/`, строка в списке `SKILLS` (`bars-worker/src/clients/mod.rs`), ожидаемое число файлов в тестах установки, удаления и частичного обновления (`clients/tests.rs`, `clients/refresh_tests.rs`), списки skills в `scripts/test-client-refresh.ps1`, `test-client-profile-isolation.ps1`, `test-docs-convention.ps1` и `test-mcp-disk-read.mjs`. Тесты считают файлы, поэтому без правки чисел они падают.

## BARS_INSTRUCTION.md

Полный текст правил в проекте, для людей и для агентов без MCP и skills ([bars-instruction.md](bars-instruction.md)). Он появляется, когда с проектом начинает работать агент (хук сессии или первый вызов MCP), а не при добавлении папки в окне. Он перезаписывается при каждой новой версии bars, поэтому правки проекта в нём не сохраняются (Т-8).

Обновление исходного asset не меняет установленный бинарник. В новой сборке инструкция синхронизируется при проверке проекта, а skills существующих интеграций обновляются [фоновым проходом](../clients/clients.md#автообновление-существующих-интеграций). Старая работающая сборка может вернуть старую инструкцию. Доставка файлов и соблюдение советов моделью проверяются отдельно.

## Как проверить доставку

Проверки собраны в скрипты; Cargo-группы запускать только через `scripts/test-docs-convention.ps1`: он выполняет их с временными `BARS_USER_HOME` и `CODEX_HOME` и сравнивает хеши, mtime и наличие настоящих конфигов, резервных копий и skills до и после.

| Проверка | Команда | Что проверяет |
|---|---|---|
| Три группы Cargo | `pwsh -File scripts/test-docs-convention.ps1 -EvidenceDir <папка>` | `cargo test -p bars-core instruction::tests` (создание и восстановление инструкции, нестандартный корень), `cargo test -p bars-worker clients::` (установка, обновление, удаление, идемпотентность), `cargo test -p bars-mcp` (initialize с инструкцией до 2000 знаков, вызовы, транспорт). |
| Шесть запусков воркера | `pwsh -File scripts/test-client-refresh.ps1 -EvidenceDir <папка>` | Старые тексты skills у обоих клиентов заменяются актуальными; no-op, uninstall, изоляция ошибки, пустой профиль, junction, stdio-MCP ([clients.md](../clients/clients.md)). |
| Нестандартный корень | `pwsh -File scripts/test-docs-delivery.ps1 -BinDir <каталог exe> -EvidenceDir <папка>` | Настоящие IPC, очередь и синхронизация, восстановление испорченной инструкции. Модель подменена FakeProvider за `test-support`, качество инференса не проверяется. |
| Два чтения MCP | `node scripts/test-mcp-disk-read.mjs <каталог exe> <новая папка evidence>` | Настоящие stdio/IPC, 22 схем, свежие текст и ссылки, UTF-16 и хеши/mtime настоящих профилей. Только изолированный воркер с FakeProvider. |
| Чистые AI-сессии | `node scripts/test-docs-agent-sessions.mjs <папка>` | Четыре независимых Codex exec: instruction и skills, стандартная раскладка и своя. Нужен вход в CLI; используется модель Codex по умолчанию. |

Повторный прогон — в новой папке evidence. Стандартные сессии записывают баг, неутверждённую идею, замер, решение, требования фичи и `handoff.md`; проверяются пути, ссылки, frontmatter, оглавления и то, что общий SPEC не расширен деталями фичи. Сессии со своей раскладкой обновляют только собственные документы и не создают `docs/`, `backlog/`, `knowledge/`, `chats/`: так проверяется рекомендательность таблицы.

## Границы проверки доставки

Недельный повторный счёт запускается от подтверждённой доставки конкретных текстов в новые MCP-соединения, а не от даты коммита или mtime бинарника. [Наблюдение 01-11-2026](../../knowledge/agent-module-usage-2026-11-01.md) принято автором как итог 4.4.4; оно не подтверждает неделю использования новых правил. Переподключения считаются отдельными соединениями; частота вызова сама по себе не доказывает качество поиска.

Проверяются содержание и доставка рекомендаций и четыре ограниченные сессии Codex; это не гарантия соблюдения правил всеми моделями. Поведение Claude Code и macOS не проверялись, доставка файлов Claude проверена процессно. Установленная старая сборка bars может перезаписать `docs/BARS_INSTRUCTION.md` старым текстом; источник поставки — `crates/bars-core/assets/BARS_INSTRUCTION.md`. Результаты приёмки IDEA-08 — в журнале сессии 2026-10-18-docs-layout-design (`chats/2026-10-18-docs-layout-design`).
