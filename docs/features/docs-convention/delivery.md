# Как соглашение о документации доходит до агента — стартовая инструкция, skills, BARS_INSTRUCTION.md

`BARS_INSTRUCTION.md` лежит в `docs/`, но агент сам его не открывает. Поэтому у соглашения три канала: короткая стартовая инструкция в каждой сессии, skills с подробными правилами и файл в проекте как справочник.

## Стартовая инструкция MCP

`bars-mcp` возвращает текст в поле `instructions` ответа на `initialize` (Т-27). Так делают serena и semble: клиент показывает этот текст модели в начале сессии, отдельный вызов не нужен. Работает в любом MCP-клиенте, хук не нужен.

Текст компактный, не длиннее 2 000 знаков: он попадает в контекст каждой сессии. В нём только то, что нужно каждой сессии:

- bars — поиск по документации проекта; модули — папки `docs/`, выбирай нужные;
- сначала определить предмет задачи; для известного документа выбрать `read`/`outline`, для неизвестного контекста — предметный поиск с подходящей областью;
- раскладка `docs/` в одну строку, включая `backlog/`, её рекомендательный характер и приоритет правил проекта; где лежат подробные правила (skills);
- журнал сессии: писать `log.md` только по поводу, `handoff.md` в конце.

Текст зашит в `bars-mcp` и меняется вместе с версией bars.

## Выбор операции и области агентом

Уточнение автора 18-10-2026 по [разбору вызовов](../../knowledge/agent-tool-usage-2026-10-18.md): сначала определить предмет задачи, затем выбрать операцию. Номер этапа разрешается через известный проектный план или реестр; универсальная добавка «требования ошибки пожелания пользователя» не заменяет предмет запроса. Известный документ можно читать напрямую через `bars_read`, заголовки — через `bars_outline`, без обязательного предварительного поиска.

Неизвестный контекст ищется предметным вопросом. Для межслойной задачи допустим весь проект. `modules` выбирает существующие папки первого уровня docs-root, а не произвольную вложенную тему; список можно получить через `bars_projects`. `files` выбирает уже известные индексируемые документы, пути только от docs-root. Путь чтения с префиксом docs-root нельзя автоматически копировать в `files`; существование файла на диске не означает наличие в индексе.

Примеры для проекта с рекомендуемой раскладкой; реальные имена модулей и файлы проверяются в целевом проекте:

- Найти пожелания по индексации: `bars_rag_search({query:"Какие пожелания есть к обновлению индекса?",modules:["backlog"]})`.
- Восстановить итоги прошлой сессии: `bars_rag_search({query:"Последние результаты проверки устройств моделей",modules:["chats"]})`.
- Сверить два выбранных источника: `bars_rag_search({query:"Как выбирается устройство rerank?",files:["features/models/local-models.md","features/settings/settings.md"]})`.
- Прочитать известный контракт: `bars_read({path:"features/settings/settings.md"})`; получить структуру: `bars_outline({path:"features/settings/settings.md"})`.

При пустой выдаче проверить предмет, проект и фильтры; не считать ноль отсутствием требования и не запускать из-за него переиндексацию. Не вводится обязательная частота фильтрации. Правило и примеры доставляются стартовой инструкцией, описаниями MCP/аргументов, обоими skills и полным BARS_INSTRUCTION.

## Skills bars

Установка в Claude Code и Codex (Т-21) ставит skills, удаление их убирает (Т-28). Skill загружается в контекст только когда нужен, поэтому подробные правила живут здесь, а не в стартовой инструкции.

- `bars-docs` — самодостаточные таблицы выбора документа с содержанием и примерами ([layout.md](layout.md)), оформление для индексации ([bars-instruction.md](bars-instruction.md)), ADR, жизненный цикл фичи. Полная инструкция остаётся справочником; доступ к репозиторию bars не требуется.
- `bars-session-log` — журнал сессии ([session-log.md](session-log.md)): когда и как писать `log.md`, как писать `handoff.md`, как начать с последнего handoff. Таблица отделяет журнал от знаний, ADR, багов и пожеланий; полная карта видов — в `bars-docs`.

Skills ставятся в пользовательскую папку клиента, а не в проект: bars не пишет в репозиторий ничего, кроме `.bars` и `BARS_INSTRUCTION.md` (Т-5, Т-8). Установка и удаление трогают только папки skills с именами bars. Папка skills: Claude Code — `~/.claude/skills`, Codex — `~/.agents/skills` ([clients.md](../clients/clients.md)). Тексты skills лежат в `bars-worker/assets/skills/` и зашиты в bars.

## BARS_INSTRUCTION.md

Полный текст правил в проекте, для людей и для агентов без MCP и skills ([bars-instruction.md](bars-instruction.md)). Он перезаписывается при каждой новой версии bars, поэтому правки проекта в нём не сохраняются (Т-8).

Обновление исходного asset не меняет установленный бинарник. В новой сборке инструкция синхронизируется при проверке проекта, а skills существующих интеграций обновляются [фоновым проходом](../clients/clients.md#автообновление-существующих-интеграций). Старая работающая сборка может вернуть старую инструкцию. Доставка файлов и соблюдение советов моделью проверяются отдельно.
