# BARS_INSTRUCTION.md — инструкция bars для моделей, которые пишут документацию

Файл, который bars кладёт в корень документации проекта (Т-8). Он адресован моделям, которые пишут документы, и объясняет, как писать, чтобы bars хорошо их индексировал.

## Как файл живёт в проекте

Формат ссылок, который инструкция объясняет агентам, включает обычные относительные Markdown-ссылки и `[[имя]]` / `[[папка/имя|подпись]]`. Переименование через bars сохраняет ссылки; после внешнего перемещения агент исправляет их сам. Правила и границы правок задаёт [индекс ссылок](../knowledge-base/link-index.md).

- Текст зашит в bars (`bars-core/assets/BARS_INSTRUCTION.md`) и меняется вместе с версией bars.
- При регистрации и при каждой проверке актуальности bars сравнивает хеш файла с хешем своей версии; если не совпадает или файла нет — записывает свою версию (Т-8). Правки пользователя в этом файле не сохраняются.
- Сверка идёт после каждой успешной проверки актуальности проекта (воркер, `bars_core::instruction::sync`). Если корня документации нет, файл не создаётся и сам корень тоже. Ошибка записи индексацию не ломает: файл поправится при следующей проверке.
- Сам файл в индекс не попадает ([features/indexing/updates.md](../indexing/updates.md)).

## О чём инструкция

Текст инструкции на английском (решение автора 16.10.2026); язык документов и поисковых запросов определяется НФТ-4. Английский текст инструкции не разрешает переводить интерфейс, сообщения поиска или документы пользователя на английский. Правила следуют из того, как bars режет документы ([features/indexing/chunking.md](../indexing/chunking.md)):

- **Формат файла:** `title` во frontmatter (Т-11), один `#` равный `title`, только ATX-заголовки, относительные ссылки, никаких секретов.
- **Выбор чтения и поиска:** определить предмет задачи; известный документ читать через read/outline без предварительного поиска, неизвестный контекст искать с подходящей областью. Примеры modules для типа источника и files для выбранного набора, границы docs-root и действия после пустой выдачи — [правило выбора](delivery.md#выбор-операции-и-области-агентом).
- **Разделы:** раздел понятен сам по себе, заголовки называют предмет, средний размер, одна тема — один файл, статус проверки в начале файла темы, ссылка вместо копии.
- **Ссылки в тексте** (решение автора 22-10-2026, заменило правило 21-10-2026 «каждое упоминание — ссылка»): ссылка — утверждение о связи, по ссылкам bars строит граф документов, а читатель идёт за подробностями. Ссылка без связи — шум в обоих, поэтому:
  - ссылка ставится, когда текст называет отношение к документу: утверждение опирается на него (требование, решение, исследование), заменяет, реализует, проверяет или исправляет его, подробности живут там. Упоминание мимоходом — словами;
  - в разделе один документ получает одну ссылку, при первом значимом упоминании; следующий раздел может сослаться снова, потому что раздел читается отдельно;
  - больше трёх источников у одного места — одна строка «Опирается на: …» в начале раздела, а не россыпь ссылок по абзацу;
  - не ссылаются: на `Index.md` папок (связь «папка — файл» у них своя, обратные ссылки «← родитель» не нужны), на перечни изменённых в сессии файлов, на сессии `chats/` из документов текущего состояния, на файлы вне корня документации (реестр вопросов, план) — их называют именем или номером, `OQ-12`;
  - понятное имя и относительный путь `[понятное имя](путь.md)`; ссылка ведёт на документ, раздел называется словами рядом, потому что индекс ссылок якоря не учитывает ([требования базы знаний](../knowledge-base/requirements.md));
  - реестры и таблицы трассировки — исключение: строка ссылается на то, что связывает. Пути кода и файлов вне документации остаются в обратных кавычках.

  Правило в BARS_INSTRUCTION.md и обоих skills.
- **Оглавление `Index.md`** (решение автора 22-10-2026): каждый файл и подпапка — именем в обратных кавычках с одной строкой «когда читать», без ссылок и без ссылки на родителя. Папка и так связывает свои файлы; ссылки из оглавления привязывали бы к нему в графе каждый документ.
- **Текущее состояние, а не история:** устаревшее правится или удаляется; история живёт только в `adr/` и `chats/`.
- **Раскладка:** таблицы «вид → папка → содержание и пример»: общие требования, требования/описание/план фичи, архитектура, ADR, исследование, баг, пожелание, журнал, handoff и оглавление. Баги и пожелания — `backlog/issues.md` и `backlog/ideas.md`; собственные правила и существующие документы проекта важнее совета bars. Пути считаются от настроенного корня документации. Содержание таблиц — [layout.md](layout.md).
- **Чек-лист** перед завершением правки документации.

Это просьба, а не правило: bars индексирует любую структуру (Т-7, Т-8). Подробности раскладки — `layout.md`, журнал — [session-log.md](session-log.md).
