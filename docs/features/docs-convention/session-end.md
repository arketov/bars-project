# Завершение сессии — skill bars-end

Статус: текст skill написан и встроен в установку 24-10-2026; проверены автотесты установки. Один настоящий прогон — 24-10-2026 в Claude Code, в той сессии, где skill создан: ручная копия в `~/.claude/skills/bars-end/` подхватилась без перезапуска клиента. В Codex и на других сессиях не проверялся. Решения — OQ-184…OQ-189 (24-10-2026, приняты рекомендации агента).

В конце сессии пользователь вызывает `/bars-end` (в Codex — `$bars-end`). Агент переносит всё, что узнал и сделал, в документацию проекта и пишет `handoff.md`. Без этого шага знания остаются в разговоре и в handoff, а описания фич, исследования и руководство устаревают.

## Когда вызывается bars-end

Только по команде пользователя. В Claude Code это закреплено полем `disable-model-invocation: true` во frontmatter skill: модель не запускает его сама по описанию. В Codex такого поля в `SKILL.md` нет, поэтому описание прямо говорит «только по явному вызову». Аудит всей документации проекта в `bars-end` не входит: он долгий и не связан с сессией.

## Что агент собирает о сессии

Источники: разговор, `git status`, `git diff` и `git log` за сессию, уже написанный `handoff.md` сессии, если он есть. Из них агент составляет опись:

- что изменилось в поведении, контрактах, настройках, командах;
- решения пользователя — дословно и с датой;
- находки, замеры, причины ошибок;
- что не сработало и как в итоге решили;
- найденные баги и высказанные пожелания;
- открытые вопросы и непроверенное;
- знание о самом проекте и его инструментах: сборка, хуки, ловушки окружения.

## Куда агент записывает факты

Каждый факт идёт в документ, который им владеет, по раскладке из [layout.md](layout.md); правила проекта важнее. Сначала агент ищет существующий документ темы и правит его, новый файл — только для новой темы. После правки он ищет старые имена и значения по всей документации и правит или удаляет устаревшие повторы.

Агент сам правит документы текущего состояния: описания фич, устройство, исследования, руководство пользователя, баги и пожелания, оглавления `Index.md`, журнал сессии. Требования, ADR, план и правила для агентов (`AGENTS.md`, `CLAUDE.md`) он только предлагает списком в отчёте и правит после «да» пользователя (OQ-187). Знание о проекте и его инструментах идёт в `knowledge/`; память клиента агента skill не трогает (OQ-189).

## Итог bars-end

- `handoff.md` по [журналу сессии](session-log.md): в «Сложностях» — нюансы и как их решили, со ссылками на записанные знания.
- Отчёт пользователю: таблица «факт → куда записан», список предложенных правок, которые ждут «да», что осталось непроверенным.
- Код не меняется. Коммита нет: агент перечисляет файлы и предлагает коммит; пользователь может попросить коммит в том же вызове (OQ-188).

`bars-worker/assets/skills/bars-end/SKILL.md`, зашит в bars и ставится третьим skill рядом с `bars-docs` и `bars-session-log` ([доставка](delivery.md)). Текст на английском и общий для любого проекта.
