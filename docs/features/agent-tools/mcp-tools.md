# Инструменты bars для агентов — MCP

Что агент получает через `bars-mcp` (Т-19). Все вызовы выполняет воркер; прокси только пересылает их ([architecture/ipc.md](../../architecture/ipc.md)).

## Проект вызова

Параметр `project` необязателен во всех инструментах. Без него проект — ближайшая к рабочей папке сессии зарегистрированная папка (Т-15). Рабочая папка — cwd процесса `bars-mcp`: клиент запускает его в папке сессии. Если проект не найден, инструмент возвращает ошибку с подсказкой зарегистрировать проект.

## bars_rag_search — поиск

Без `mode` сохраняет прежний ответ. Явный `mode=hybrid|mix|graph` включает расширенную форму с requested/applied mode, fallback и отдельными `related/graph_results`. В mix можно отключить связанные источники `include_related=false`, ограничить пакет `related_budget` в байтах и задать `graph_budgets`. Подробности и ограничения — в [фактическом контракте GraphRAG v1](../graphrag/tools.md#фактический-контракт-v1).

## Шесть операций чтения GraphRAG

`bars_relations`, `bars_paths`, `bars_impact`, `bars_context`, `bars_explore`, `bars_graph` читают готовый граф выбранного проекта. Область применяется до разрешения имён и обхода. Каждый факт/переход содержит evidence с исходными диапазонами; stale refs не заменяются похожими объектами. Структура и similarity различаются от типизированного отношения. Смысловой слой partial: отсутствие извлечённой зависимости не доказывает её отсутствия. MCP не получает write-tools построения/отмены.

Профили контекста: implementation/investigation/decision, сужающие roles и token/byte budget; точный tokenizer пока недоступен. Полный вход/выход, ошибки и ограничения — [GraphRAG v1](../graphrag/tools.md#фактический-контракт-v1). Тесты транспорта не заменяют открытую приёмку качества S1–S8.

## Базовые параметры поиска

Параметры: `query`; `project`; `modules` и `files` — область поиска (Т-14); `limit`, `candidates`, `min_score` — переопределения (Т-18, Т-24). Ответ — по [features/search/hybrid-search.md](../search/hybrid-search.md).

Сначала агент определяет предмет задачи. Если нужный документ известен, можно сразу вызвать `bars_read` или `bars_outline`; предварительный поиск не требуется. Для неизвестного контекста задаётся предметный вопрос: весь проект для межслойной задачи, `modules:["backlog"]` для пожеланий или `modules:["chats"]` для итогов сессий. Модули — только существующие папки первого уровня docs-root; вложенный `models` не становится отдельным модулем внутри `features`.

`files` — уже выбранные индексируемые источники: например, `files:["features/models/local-models.md","features/settings/settings.md"]` для сверки выбора устройства rerank. Пути от docs-root, без префикса `docs/` при docs-root=`docs`; правила разрешения `path` у read/outline шире и не переносятся на `files`. Не угадывать имена файлов и не считать существование файла доказательством его индексации. Полные примеры и восстановление после пустой выдачи — [выбор операции и области](../docs-convention/delivery.md#выбор-операции-и-области-агентом).

## bars_get_similar — похожие чанки

Параметры: `chunk_id` — ID из поля `id` результата `bars_rag_search` или `bars_get_similar`; `project`; `modules` — область кандидатов (исходный чанк может быть вне её); `limit`. Возвращает исходный чанк и ближайшие чанки области без него, оценка — косинусная близость к исходному чанку. Близость не доказывает дублирование. ID действует, пока не изменился документ чанка; иначе ошибка `chunk_not_found` — найди чанк поиском заново. Контракт — [maintenance-tools.md](../search/maintenance-tools.md#get_similar-похожие-чанки-по-id).

## bars_projects — проекты и модули

Без параметров. Возвращает зарегистрированные проекты: путь, корень документации, список модулей с числом документов.

## bars_status — состояние индекса

Параметр `project`. Возвращает: время последнего обновления, идёт ли индексация, сколько документов ждёт, модель индекса и нужна ли переиндексация (Т-19, Т-25), последнюю ошибку провайдера.

## bars_reindex — переиндексация

Параметры `project`, `full`. Без `full` — проверка актуальности с инкрементальной индексацией; с `full` — полная переиндексация. Возвращается сразу, ход видно в `bars_status`. Переиндексацию после смены модели агент запустить не может: на неё нужно согласие пользователя (Т-25), и инструмент возвращает ошибку `reindex_needs_consent` ([architecture/protocol.md](../../architecture/protocol.md)).

## bars_read — документ целиком

Параметры `path`, `project`. Возвращает текст документа с номерами строк и `title`. Путь разрешается как у `bars_outline` (см. ниже): от корня документации, затем от корня проекта; явный `./README.md` и абсолютный путь тоже допустимы. Читаются только файлы `.md`: другой файл — ошибка `invalid_params`.

## bars_outline — структура документа

Т-26. Параметры:

- `path`, `project` — как у `bars_read`; работает с любым `.md`;
- `levels` — какие уровни заголовков вернуть, например `[2, 3]`; по умолчанию все; уровень вне 1…6 — `invalid_params`;
- `under` — только заголовки внутри заданного: цепочка заголовков `Заголовок 1/Заголовок 2` или номер строки заголовка (`under_line` в протоколе и CLI). Цепочка полная, от верхнего заголовка документа, в том же виде, что `heading_chain` в выдаче поиска. Сам заголовок в ответ не входит, вложенные идут на любую глубину и фильтруются по `levels`. Если цепочке отвечают несколько заголовков, возвращаются вложенные заголовки всех, в порядке документа. Заголовок не найден или по номеру строки заголовка нет — `invalid_params`.

Путь разрешается так: сначала от корня документации; если такого файла нет — от корня проекта, поэтому путь из выдачи поиска (`docs/a/x.md`) работает как есть. Явный `./x.md` отсчитывается только от корня проекта.

Ответ — по строке на заголовок: номер строки, решётки уровня, текст.

```text
1 # bars
7 ## Стадия
11 ## С чего читать
```

Структура читается прямо с файла, а не из индекса, поэтому номера строк всегда совпадают с диском. Заголовки распознаются по тем же правилам, что при нарезке ([features/indexing/chunking.md](../indexing/chunking.md)): ATX, без строк внутри блоков кода.

## Как bars-mcp отвечает и ошибается

### Локальная история MCP-вызовов

Допущенные worker вызовы учитываются в локальной [истории MCP](../window/mcp-statistics.md): исходные разрешённые аргументы (включая поисковый запрос/пути), применённые значения и краткий итог, без содержимого документов и полных ответов. Исходный вход передаётся во внутреннем `_mcp`-контексте IPC; это не новый параметр, который агент должен заполнять, и не новый MCP-инструмент. Ошибки до допуска и получение ответа клиентом не наблюдаются. Политика хранения и API просмотра принадлежат описанию истории; экран отдельных попыток ещё не реализован.

### Формат ответа, ошибки и соединение MCP

Решение агента, 15-10-2026 (OQ-52). Уточнение автора 18-10-2026: служебное оформление текстовых ответов MCP — на английском (`SEARCH: results N`, `RESULT n of N`, `END RESULT`, `APPLIED PARAMETERS`, `DOCUMENT`, `OUTLINE`, `PROJECT`, `INDEX STATUS`, `REINDEX`). Содержимое документов, заголовки и сообщения воркера сохраняют исходный язык; интерфейс окна, CLI и поисковые запросы — на языке пользователя (НФТ-4).

- **Ответ.** У каждого инструмента необязательный параметр `format`: `txt` (по умолчанию) или `json`. `json` — ответ метода воркера одной строкой, тот же, что печатает `bars-cli --json`. `txt` — блоки с явными границами и полями `ключ: значение`: `=== RESULT 1 of 3 === … === END RESULT 1 ===` у поиска (поля `path`, `lines`, `module`, `title`, `heading`, `score`, затем `--- text ---` и сам фрагмент, в конце `=== APPLIED PARAMETERS ===`), `=== DOCUMENT <путь> ===` с `title` и текстом с номерами строк у `bars_read`, `=== OUTLINE <путь> … ===` со строками `7 ## Стадия` у `bars_outline`, блоки `=== PROJECT n of N ===` и `=== INDEX STATUS ===`. Номера строк и заголовки собирают функции `bars-protocol`, общие с CLI.
- **Ошибки.** Ошибка воркера или канала — ответ инструмента с признаком ошибки, а не ошибка протокола MCP: клиент показывает модели только первый вид. Текст начинается с `Ошибка bars (<kind>):` и несёт сообщение воркера. При `reindex_required` и `reindex_needs_consent` добавлено: переиндексацию запускает пользователь, агенту не повторять вызов. При недоступном воркере — повторить позже.
- **Загрузка модели.** На `model_loading` прокси сам повторяет вызов раз в секунду до 60 с (`MODEL_WAIT`): загрузка скачанной модели в память занимает секунды, а ждать агенту нечем (ISS-18). Каждая попытка — отдельный вызов воркера и отдельная запись в истории. Если модель так и не готова (обычно она ещё скачивается), агент получает `model_loading` с пояснением повторить вызов позже.
- **Согласие.** У `bars_reindex` нет параметра согласия; `accept_model_change` прокси всегда шлёт `false`, а воркер сбрасывает его от `mcp` в любом случае (`Session::admit`).
- **Соединение.** Первый вызов инструмента подключается к воркеру и при необходимости запускает его (`connect_or_launch_with`); соединение живёт всю сессию. Оборванное соединение открывается заново, вызов повторяется один раз. Ответ ждётся не дольше 120 с, после таймаута соединение сбрасывается.
- **Параметр `project`.** Значение с `/` или `\` либо начинающееся с точки — путь, относительный считается от cwd сессии (как в `bars-cli`, OQ-50); остальное — имя проекта для воркера.
- **Стартовая инструкция** — константа `INSTRUCTIONS` в `bars-mcp/src/instructions.rs`, в ответе на `initialize`; длину не больше 2 000 знаков проверяет тест ([delivery.md](../docs-convention/delivery.md)).
- **Лёгкость прокси (НФТ-3).** В `[dependencies]` `bars-mcp` нет `bars-core` и `bars-worker`; тест следит за этим, а `initialize` и список инструментов отвечают без воркера (тест на настоящем exe).
