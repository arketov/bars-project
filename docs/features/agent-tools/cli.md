# Команды bars-cli

`bars-cli` — отдельный exe для людей, хуков и агентов, которые тестируют приложение (Т-20). Каждая команда — то же действие, что в окне или в MCP-инструменте, и даёт тот же результат.

## Общие правила bars-cli

- Проект по умолчанию — ближайшая к текущей папке зарегистрированная папка; `--project <путь>` задаёт его явно.
- Вывод по умолчанию — для человека; `--json` — тот же ответ, что у MCP-инструмента.
- Код выхода: `0` — успех, `1` — ошибка в запросе, `2` — воркер недоступен, `3` — нужна переиндексация (Т-25). Соответствие ошибкам канала — [architecture/protocol.md](../../architecture/protocol.md).

## Список команд bars-cli

| Команда | Что делает | Соответствие |
|---|---|---|
| `bars-cli search <запрос> [--module M]… [--file F]… [--limit N] [--min-score S]` | поиск | `bars_rag_search` |
| `bars-cli outline <путь> [--levels 2,3] [--under "A/B" \| --under-line N]` | структура документа | `bars_outline` (Т-26) |
| `bars-cli read <путь>` | документ целиком | `bars_read` |
| `bars-cli projects` | проекты и модули | `bars_projects` |
| `bars-cli status` | состояние индекса | `bars_status` |
| `bars-cli reindex [--full] [--accept-model-change]` | переиндексация; `--accept-model-change` — согласие пользователя после смены модели (Т-25, [architecture/protocol.md](../../architecture/protocol.md)) | `bars_reindex` |
| `bars-cli register [путь]` | регистрация проекта (Т-6) | пункт «Добавить проект» в окне |
| `bars-cli unregister` | снять проект с регистрации ([features/projects/projects.md](../projects/projects.md)) | кнопка «Убрать из bars» в окне |
| `bars-cli install --client claude-code\|codex` | подключить bars к клиенту (Т-21) | пункт «Установить» в окне |
| `bars-cli uninstall --client claude-code\|codex` | убрать bars из клиента | пункт «Удалить» в окне |
| `bars-cli hook session-start` | команда для хука начала сессии | — |

## Как bars-cli вызывает воркер

Решения агента, 15-10-2026.

- **Одна команда — одно соединение.** `bars-cli` подключается к воркеру, делает `hello` как `cli`, вызывает один метод и выходит. Если воркер не запущен, клиент сам запускает `bars --background` и ждёт его до 15 с ([architecture/ipc.md](../../architecture/ipc.md)). Не дождался или запустить не смог — код `2`. Таймаута на сам вызов нет: первый поиск может ждать загрузки модели.
- **Вывод.** Успех идёт в stdout, ошибка — в stderr. `outline` печатает строки `7 ## Стадия`, `read` — заголовок документа, пустую строку и текст с номерами строк с единицы; обе функции общие с `bars-mcp` (`bars-protocol`). `search` печатает по результату: номер, `путь:первая-последняя строка`, модуль, вид и значение оценки, затем `title — цепочка заголовков` и текст чанка; в конце — применённые параметры, пометка «идёт индексация» и причина, если rerank не отработал.
- **`--json`.** В stdout попадает ответ метода как есть (отступы по два пробела), без обёртки. Ошибка в режиме `--json` идёт в stderr одним объектом `{"error": {"code", "kind", "message"}}`; код выхода тот же (OQ-49).
- **`--project`.** Значение с разделителем пути или начинающееся с точки считается путём и приводится к абсолютному от текущей папки; остальное — имя проекта, его разбирает воркер (OQ-50).
- **`register`.** Без пути регистрирует `--project`, а без него — текущую папку. Относительный путь клиент делает абсолютным от текущей папки (`.` и `..` убираются без обращения к диску); существование папки и наличие документации проверяет воркер.
- **`unregister`** находит проект так же, как поиск: по `--project` или вверх от текущей папки.
- **Несколько слов запроса.** `bars-cli search как работает поиск` склеивается в один запрос; запрос с флагами лучше брать в кавычки.
- **Ошибки смены модели.** При коде `3` к тексту ошибки добавляется подсказка `bars-cli reindex --accept-model-change`. Флаг — согласие человека; агенту его передавать запрещено ([architecture/protocol.md](../../architecture/protocol.md)).

## Хук начала сессии

`bars-cli hook session-start` читает из stdin JSON, который передаёт клиент, и берёт из него рабочую папку сессии — поле `cwd`; у Claude Code и Codex формат входа одинаковый. Затем находит корень проекта, регистрирует его, если он ещё не зарегистрирован и в нём есть документация ([features/projects/projects.md](../projects/projects.md)), и ставит проект в очередь проверки актуальности (Т-6, Т-10). Команда не ждёт индексации и завершается сразу, чтобы не задерживать старт сессии. Ошибки она пишет в лог воркера и всегда выходит с кодом `0`: сбой bars не должен ломать сессию агента.
