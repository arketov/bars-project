# Команды bars-cli

`bars-cli` — отдельный exe для людей, хуков и агентов, которые тестируют приложение (Т-20). Каждая команда — то же действие, что в окне или в MCP-инструменте, и даёт тот же результат.

## Общие правила bars-cli

В исходниках 4.3.5 (`e633ba4`) `impact`, `context` и `graph show --local` принимают повторяемый `--document <путь.md>`: до 20 путей; воркер объединяет `documents` с `roots`. Явный CLI-флаг заменяет соответствующее поле JSON `--input`, а не дописывает его. Например: `bars-cli impact --document features/search/hybrid-search.md`. Параметры `--from`/`--to` также принимают JSON `{"document":"<путь.md>"}`. Финальные тесты, сборка и доставка установленной версии этого среза не проверены по указанию автора 01-11-2026.

GraphRAG: `relations`, `paths`, `impact`, `context`, `explore`, `graph show/status/build/cancel`; чтение использует общий DTO, `--input` — GraphRequest JSON с переопределением явными флагами. Примеры: `paths --from Т-1 --to Т-3`, `context "устройство индекса" --task-profile investigation`, `explore --whole-scope`. `graph build` не переиндексирует embeddings; accepted/job ID не означает завершения, отмена подтверждается статусом. Search: `--mode hybrid|mix|graph`, в mix — `--no-related` и `--related-budget N`. Без mode прежний поиск/ответ. Точные поля/открытая приёмка — [GraphRAG v1](../graphrag/tools.md#фактический-контракт-v1).

- Проект по умолчанию — ближайшая к текущей папке зарегистрированная папка; `--project <путь>` задаёт его явно.
- Вывод по умолчанию — для человека; `--json` — тот же ответ, что у MCP-инструмента.
- Граф и поиск с `--mode`: общий с MCP текстовый рендер, факты с путём и строками основания, цитаты до 300 знаков, ответ до 16 000 знаков. При ограничении — `truncated:` и продолжение курсором либо совет сузить область; в `mix` основные блоки `RESULT` отделены от `RELATED`. `--json` сохраняет полный DTO в прежних байтовых пределах.
- Код выхода: `0` — успех, `1` — ошибка в запросе, `2` — воркер недоступен, `3` — нужна переиндексация (Т-25). Соответствие ошибкам канала — [architecture/protocol.md](../../architecture/protocol.md).

## Как bars-cli вызывает воркер

Решения агента, 15-10-2026.

- **Одна команда — одно соединение.** `bars-cli` подключается к воркеру, делает `hello` как `cli`, вызывает один метод и выходит. Если воркер не запущен, клиент сам запускает `bars --background` и ждёт его до 15 с ([architecture/ipc.md](../../architecture/ipc.md)). Не дождался или запустить не смог — код `2`. Таймаута на сам вызов нет: первый поиск может ждать загрузки модели.
- **Вывод.** Успех идёт в stdout, ошибка — в stderr. `outline` печатает строки `7 ## Стадия`, `read` — заголовок документа, пустую строку и текст с номерами строк с единицы; обе функции общие с `bars-mcp` (`bars-protocol`). `search` печатает по результату: номер, `путь:первая-последняя строка`, модуль, вид и значение оценки, затем `title — цепочка заголовков` и текст чанка; в конце — применённые параметры, пометка «идёт индексация» и причина, если rerank не отработал; строка «Внимание», если embed-модель не успела загрузиться и выдача идёт только по словам ([ожидание моделей](../search/hybrid-search.md#ожидание-моделей)).
- **`--json`.** В stdout попадает ответ воркера как есть (отступы по два пробела), без обёртки: клиент не разбирает его в свои типы и не сериализует заново, поэтому поля, которых он не знает (например у более новой сборки воркера), не пропадают (ISS-91). Человеческий вывод берёт разобранный ответ.
- **Разные сборки.** Если `bars-cli` и воркер собраны из разных коммитов, в stderr до ответа печатается «bars-cli: предупреждение: клиент и воркер bars собраны из разных сборок …»; код выхода и stdout не меняются ([сверка сборок в hello](../../architecture/protocol.md)). Ошибка в режиме `--json` идёт в stderr одним объектом `{"error": {"code", "kind", "message"}}`; код выхода тот же (OQ-49).
- **`--project`.** Значение с разделителем пути или начинающееся с точки считается путём и приводится к абсолютному от текущей папки; остальное — имя проекта, его разбирает воркер (OQ-50).
- **`register`.** Без пути регистрирует `--project`, а без него — текущую папку. Относительный путь клиент делает абсолютным от текущей папки (`.` и `..` убираются без обращения к диску); существование папки и наличие документации проверяет воркер.
- **`unregister`** находит проект так же, как поиск: по `--project` или вверх от текущей папки.
- **Несколько слов запроса.** `bars-cli search как работает поиск` склеивается в один запрос; запрос с флагами лучше брать в кавычки.
- **Ошибки смены модели.** При коде `3` к тексту ошибки добавляется подсказка `bars-cli reindex --accept-model-change`. Флаг — согласие человека; агенту его передавать запрещено ([architecture/protocol.md](../../architecture/protocol.md)).

## Хук начала сессии

`bars-cli hook session-start` читает из stdin JSON, который передаёт клиент, и берёт из него рабочую папку сессии — поле `cwd`; у Claude Code и Codex формат входа одинаковый. Затем находит корень проекта, регистрирует его, если он ещё не зарегистрирован и в ней есть `docs/` или `.bars/` проекта с хотя бы одним `.md` в корне документации ([features/projects/projects.md](../projects/projects.md)), и ставит проект в очередь проверки актуальности (Т-6, Т-10). Если `cwd` нет во входе, берётся текущая папка, если нет `source` — `startup`. Корень ищет и регистрирует воркер (метод `session_start`, `projects.md`), а не CLI. Команда не ждёт индексации и завершается сразу, чтобы не задерживать старт сессии. Ошибки она пишет в лог воркера и всегда выходит с кодом `0`: сбой bars не должен ломать сессию агента.

## Хук перед вызовом инструмента

Решение агента, 19-10-2026 (OQ-99). `bars-cli hook pre-tool-use` читает из stdin JSON Claude Code (`tool_name`, `tool_input`, `session_id`) и до первого вызова bars в сессии отклоняет чтение документации; запись хука в проект ставит bars сам ([clients.md](../clients/clients.md#гейт-чтения-документации)). К воркеру команда не обращается: папка документации приходит флагом `--docs-root` (по умолчанию `docs`).

- **Что считается чтением документации.** `Read` файла `.md` в папке документации; `Grep` и `Glob` по этой папке, а также с маской `*.md` без пути и без другой папки в шаблоне (поиск от корня проекта заходит в документацию); маска с путём вне документации (`path` или `crates/**/*.md`) не считается; в `Bash` и `PowerShell` — звено конвейера, которое начинается с `cat`, `head`, `tail`, `grep`, `rg`, `sed`, `awk`, `Get-Content`, `Select-String` или `type` и называет такой файл. Журнал сессий `chats/` не считается: он вне поиска. `| head` в конце команды и путь в тексте коммита чтением не считаются.
- **Что снимает блок.** Любой вызов инструмента с префиксом `mcp__bars__`. Отметка — файл `bars-gate-<session_id>.flag` во временной папке; блок не возвращается до конца сессии.
- **Ответ.** Отказ — JSON `hookSpecificOutput` с `permissionDecision: "deny"` и причиной в stdout; пропуск — пустой вывод. Выход всегда `0`: сбой гейта не должен ломать сессию. Непонятный вход пишет причину в stderr и пропускает вызов.
- **Язык.** Причина отказа и сообщения хуков написаны по-английски: их читает агент. Ответы воркера, которые хук `session-start` пересылает в stderr, остаются на языке воркера.
- **Что решено изменить.** Автор 10-11-2026 выбрал вместо разовой разблокировки мягкое напоминание по счётчику: отказ на каждый шестой обход и на широкую рекурсию, повтор вызова проходит (OQ-295). Правила — [проект агентского слоя](agent-layer-project.md), раздел «Гейт чтения документации по счётчику»; реализации нет.

## Установка и удаление

Решения агента, 15-10-2026.

- `bars-cli install --client claude-code|codex|kimi-code|ouroboros|iterion` и `bars-cli uninstall --client …` — один вызов `install` / `uninstall` воркера ([clients.md](../clients/clients.md)). Вывод — список изменённых файлов, напоминание про `/hooks` для Codex и про перезапуск клиента; `--json` — ответ метода. Ouroboros получает только локальный MCP, iterion — плагин с MCP и `bars-docs`.
- `bars-cli install --print-instruction` печатает текст для агента и не обращается к воркеру. Пути к `bars-cli` и `bars-mcp` берутся от расположения exe самого `bars-cli`. В тексте — команды установки, шаг одобрения хука в Codex, ручное подключение другим MCP-клиентам и запрет на `--accept-model-change`.
- `--client` и `--print-instruction` взаимоисключающие; без обоих команда — ошибка аргументов.
