## Назначение и границы вида запроса

Вид запроса — состояние панели графа после завершённого поиска: запрос точкой, найденные документы и их окружение по ссылкам и по смыслу. Это временное представление: в Markdown и индекс ничего не записывается, ранжирование, пороги и результаты поиска он не меняет и поиск повторно не запускает. Область поиска (проект, модули, файлы) вид только наследует; камера, фильтры и выбор узла её не меняют. Четвёртый вид связи между документами (решение автора OQ-110) не вводится: связь запроса с результатом — часть Т-47, а не вид из Т-46 и не связь между источниками.

Граф при построении не вызывает embedding и rerank: используются оценки готового ответа поиска и готовые векторы документов и чанков. Правила узлов, трёх видов связей, силы и физики — [проект физического графа](physical-graph.md); здесь только то, что добавляет запрос.

## Вход: завершённый поиск и что берётся из выдачи

Вход строится из ответа главного или глобального поиска (одна сессия, [глобальный поиск](../window/global-search-design.md)). Интерфейс передаёт воркеру компактный список результатов (не более числа результатов выдачи) вместе с запросом, областью и применёнными параметрами, воркер проверяет их по текущему снимку. Отдельного хранения ответов поиска в воркере не требуется. Инженерное решение, не требование автора.

| Поле результата | Смысл |
|---|---|
| `chunk_ref`, `document_ref` | Чанк из ответа и его документ-владелец той же ревизии |
| `rank` | Место в выдаче |
| `score`, `score_kind` | Оценка ответа и её вид: `rerank` или `cosine`; без реранка и при ошибке реранка — косинус по фактическому виду ([оценка и порог](../search/hybrid-search.md)) |
| `channel` | `primary` — основной результат; `related` — связанный источник режима «Со связями» с причиной включения; `graph` — источник из режима «Отношения и пути», оценки нет |

Результаты нескольких чанков одного документа дают один узел документа: число совпавших фрагментов, их строки и оценки видны в инспекторе. Основной режим узла — документ (по умолчанию уровень «Документы», Т-46); совпавшие чанки появляются раскрытием владельца или в режиме «по смыслу · чанки».

## Узлы вида запроса

| Узел | Представление |
|---|---|
| Запрос | Один временный узел-квадрат с текстом запроса. Тождество — идентификатор завершённого поиска; в хранилище знаний он не существует. Не закрепляется сам и не участвует в «общем притяжении» |
| Результат | Документ из выдачи, `channel` и `rank` в инспекторе. Все результаты входят в вид раньше любого окружения, пока не исчерпан предел узлов |
| Окружение | Документы, связанные с результатом включёнными видами связей; на глубине 2 — окружение окружения |
| Совпавший чанк | Ромб около владельца, только в режиме чанков или после раскрытия; связь запроса с ним — по оценке самого чанка |

Результат, у которого нет объекта в снимке графа, остаётся видимым узлом с причиной: «слой связей не построен», «документ изменён после поиска», «документ удалён». Такой результат не исчезает из выдачи, а панель помечает вид неполным. Причины и состояния слоёв — как в разделе «Жизненный цикл физики и состояния окна» [проекта физического графа](physical-graph.md).

## Сила связи запроса с результатом

`s_q = clamp(score, 0, 1)` для основного результата; у документа с несколькими чанками берётся наибольшая оценка его основных чанков того же `score_kind`. Это абсолютная оценка ответа поиска: без min/max по текущему списку, без перцентилей и без превращения места в выдаче в силу. Результат, прошедший порог поиска, не отсекается графом: ползунок «Сила от» режима «по смыслу» связи запроса не затрагивает.

- Толщина, яркость и притяжение считаются теми же функциями `w(s)`, `b(s)`, `q(s)`, что у остальных рёбер ([раздел «Сила, видимость и физика»](physical-graph.md)). Оранжевый цвет и квадрат запроса отличают связь от трёх видов Т-46; тип кодируется и вне цвета.
- `rerank` и `cosine` — разные величины. Вид оценки подписан в инспекторе и легенде; числа разных видов не складываются и не сравниваются как одна мера. Вес рисунка для `cosine` берётся той же шкалой «окно модели» 0,60–0,95, что для близости документов (принята автором 22-10-2026, OQ-118); пригодность этой шкалы для оценки «запрос↔чанк» не доказана и проверяется в 2.2.3 на настоящих запросах.
- `related` (связанный источник режима «Со связями») не имеет оценки запроса и не получает связи запроса: «основание включения» — путь или причина из ответа, показанные в инспекторе. Подделывать оценку нельзя.
- `graph` (режим «Отношения и пути») не имеет оценки: связь запроса рисуется нейтральной, без толщины по оценке, инспектор говорит «оценки нет». Типизированные предикаты GR-02 в физическом виде не рисуются; пути подсвечиваются только по существующим физическим рёбрам, остальные шаги — в списке (аналитическая проекция — этап 2.3).

## Построение: от запроса к результатам, от результатов к связям

1. Запрос → результаты. Узел запроса и по одному ребру `query_result` к каждому результату; направления нет.
2. Результаты → окружение. Для каждого результата и каждого включённого вида связей берутся `fanout` ближайших; число — инженерное умолчание 4 (значение стенда 2.1.4). Ссылки: входящие и исходящие реальные Markdown-ссылки с направлением. Близость документов: документы области с `s ≥ tau` по документным представлениям ([раздел «Документная близость без новой модели»](physical-graph.md)) и порогом режима «по смыслу».
3. Окружение → окружение. Глубина `depth` — число шагов от результатов: 0 (запрос и результаты), 1 по умолчанию, 2 — максимум; больший обход — «локальный граф» этапа 2.3. На втором шаге те же `fanout` и порядок.
4. Рёбра внутри набора. После отбора узлов добавляются все рёбра включённых видов между любыми двумя включёнными узлами, а не только от результатов к их соседям: связи результатов друг с другом показываются всегда, звезды вокруг запроса нет.

**Порядок соседей.** Внутри вида: сначала другие результаты, затем взаимные ссылки, затем сила по убыванию, затем идентификатор. Число ссылок и степень узла приоритета не дают (требование GR-04 к хабам); отбор по смыслу ближайших к результату, а не к запросу — граф не знает смысла запроса, он показывает окружение результатов.

**Расчёт близости для результатов.** Для результата считается cosine с готовыми векторами документов области точно, а не читается из общего частичного kNN, у которого фильтр области не гарантирует полный top-k. Стоимость порядка `R·D·d` (для 20 результатов, 3000 документов и размерности 1024 — около 61 млн умножений-сложений); время не измерялось, измеряется в 2.2.3. Отсутствие готовых представлений документов — состояние слоя («строится», «недоступен»), не пустая близость; ссылки и результаты работают независимо.

**Область.** Окружение берётся только из документов области поиска. Окружение за её пределами не отображается и не пересчитывается в число: так вид не раскрывает исключённые источники (GR-07).

**Режимы связей.** Срез несёт соседей ссылок и близости документов вместе; режим «ссылки / по смыслу / все связи» выбирается в панели без запроса к воркеру и перекладывает раскладку с нуля, как в общем виде. Узел окружения виден, если в включённом режиме у него есть видимое ребро. Связь запроса видна в любом режиме. Режим «по смыслу · чанки» запрашивает отдельный расчёт: результаты-чанки и `fanout` ближайших чанков области.

## Пределы и усечение

Начальные инженерные пределы вида запроса: 200 узлов, 800 рёбер, 256 КиБ ответа. Максимум — начальные пределы физического графа: 500 узлов, 2000 рёбер, 512 КиБ ([раздел «Срез, бюджеты и договор данных»](physical-graph.md)). Это не новые общепродуктовые требования и не изменение лимитов поиска; пределы запроса поиска — `max_results` и `max_candidates` в [настройках](../settings/settings.md).

На сохранённом снимке (200 случайных наборов результатов на строку, `fanout` 4, порог близости 0,82; узлы включают узел запроса):

| Результатов | Режим | Глубина | Узлов: медиана / 95-й / максимум | Рёбер: медиана / 95-й / максимум |
|---|---|---|---|---|
| 5 | все связи | 1 | 20 / 26 / 30 | 48 / 90 / 111 |
| 10 | все связи | 1 | 35 / 44 / 47 | 109 / 180 / 229 |
| 20 | все связи | 1 | 63 / 74 / 78 | 249 / 350 / 399 |
| 10 | все связи | 2 | 79 / 96 / 105 | 425 / 577 / 644 |
| 20 | все связи | 2 | 113 / 129 / 134 | 653 / 769 / 794 |
| 20 | ссылки | 2 | 82 / 95 / 99 | 357 / 454 / 515 |

Переход от глубины 1 к 2 увеличивает число рёбер примерно в 2,6 раза (20 результатов, все связи: медиана 249 → 653), а при 20 результатах максимум 794 рёбер уже у границы предела 800; глубина 3 не измерялась и не предлагается, поэтому максимум 2. Реальные результаты сгруппированы по темам, и размеры могут отличаться; настоящие запросы — проверка 2.2.3.

**Порядок включения при нехватке места:** запрос; результаты по месту в выдаче; рёбра запроса; соседи по кругу (сначала по одному у каждого результата, затем по второму и так далее), внутри результата — ссылки, затем близость; рёбра — только между включёнными узлами. Результаты не вытесняются окружением. Показ: «Показано X из Y», причина усечения (число узлов, рёбер или байт), «Показать ещё» в том же снимке без дубликатов и без сброса камеры и позиций; число Y показывается, только если оно известно. Пустой отрисованный слой не называется отсутствующим.

## Режимы поиска: обычный, со связями, отношения и пути

| Режим поиска | Результаты вида | Особенности |
|---|---|---|
| «Обычный» (`hybrid`) | `primary` с оценкой | Окружение строит граф независимо от ранжирования поиска и не меняет его |
| «Со связями» (`mix`) | `primary` с оценкой и `related` с причиной | `related` — узлы окружения, если у них есть физическое ребро с результатами; иначе в списке и инспекторе с пометкой «без физической связи», рёбер для них не выдумывается. При откате `mix` на `hybrid` вид строится по применённому режиму, причина видна |
| «Отношения и пути» (`graph`) | `graph`, оценки нет | Связь запроса нейтральна; пути подсвечены по физическим рёбрам; при `graph_not_ready` вид состоит из запроса и результатов с пометкой, что слои связей недоступны |

Успешная пустая выдача — узел запроса и строка «Ничего не найдено, порог …»; недоступность слоя графа, ошибка поиска и пустая выдача различаются явно.

## Раскладка, вход и возврат к общему виду

Раскладка с нуля из детерминированного рассева: запрос в центре, результаты по кругу в порядке `rank`, окружение около своих результатов; дальше запрос и результаты движутся по физике, как любые узлы. Длина связи не служит шкалой силы; физика, остановка по действию пользователя, reduced motion, скрытие и уничтожение панели — как в общем виде. Камера при входе вписывается один раз; последующие изменения размера и страницы не вписывают её.

- **Вход.** Завершённый поиск с главного экрана или из глобального слоя включает вид запроса во всех панелях графа (мини-граф и полный граф), панель сама не открывается и не переносится; показ результата в графе открывает или выделяет вкладку графа и выбирает узел результата. Плашка «Запрос «…»» с кнопкой «Общий вид», подсказка при входе.
- **Возврат.** «Общий вид» возвращает прежние позиции, камеру, выбор и закрепления общего вида: состояния хранятся отдельно, ключ — проект, область, проекция и идентификатор поиска. Следующий завершённый поиск снова включает вид запроса. Сброс результатов поиска, смена проекта или области выводят панель в общий вид. Возврат действует на ту панель, в которой нажата кнопка; вход, напротив, включается во всех панелях ([макет перехода](#макет-перехода-между-общим-видом-и-видом-запроса), принято автором, OQ-120).
- **Поиск идёт.** Прежний вид остаётся; поздний ответ прежнего поиска отбрасывается по поколению. Ошибка поиска вид не меняет.
- **Снимок.** Вид строится на одном снимке графа; если после поиска индекс обновился, вид помечается «изменён после поиска», а не смешивается со свежими данными.

Вид запроса не сохраняется между запусками сам по себе: он следует за сессией поиска окна.

## Макет перехода между общим видом и видом запроса

Статус 22-10-2026: макет собран на стенде 2.1.4 (`npm run graph-design --prefix ui`, параметры `query`, `qs`, `depth`, `qstate` — в [дизайне стенда](physical-graph-design.md)); правила ниже приняты автором 22-10-2026 вместе с четырьмя предложениями (OQ-120). Умолчания OQ-119 (глубина 1/2, автоматический вход, узел с причиной, шкала cosine) приняты автором раньше и здесь не пересматриваются. Стенд берёт результаты по словам названий и сочиняет оценки по месту в выдаче; он показывает вид и переходы, а не качество поиска. Проверено на стенде в Chromium и юнит-тестами правил построения: передача сессии (`chats/2026-10-22-query-transition`).

### Что видит пользователь в виде запроса

- **Панель запроса** в полном графе — полоса под панелью инструментов: квадрат запроса, текст «…», число результатов, применённый режим поиска и вид оценки («оценка rerank», «оценка — косинус (rerank не выполнялся)», «оценки нет»), переключатель «Окружение 0 · 1 · 2» и кнопка «Общий вид». В мини-графе — плашка «Запрос «…» · Общий вид» и строка состояния; глубины и «Показать ещё» в мини-графе нет, там действуют умолчания (глубина 1).
- **Узлы.** Запрос — квадрат; результат поиска — документ с кольцом цвета связи запроса; связанный источник режима «Со связями» — документ с пунктирным кольцом; результат без объекта графа — пустой пунктирный круг. Окружение результатов — обычные документы. Место результата в выдаче видно в списке и инспекторе.
- **Связи.** Связь запроса — оранжевая линия по оценке; без оценки («Отношения и пути») — пунктир одной толщины. Остальные виды рисуются как в общем виде.
- **Инспектор запроса** показывает режим поиска (при откате — и запрошенный), вид оценки, глубину, «Показано X из Y» и список всех результатов по месту: оценка с видом, статус, причина включения связанного источника, результаты вне карты. Инспектор результата — место, канал, оценка, совпавшие фрагменты; инспектор окружения — шаг от результата.
- **Предупреждения** собраны в одну жёлтую полосу: откат режима поиска, «изменён после поиска», «Граф неполон» с числом результатов без объекта графа, связанные источники вне карты. Усечение — отдельная полоса «Показано X из Y узлов · … связей. Причина: …» с кнопкой «Показать ещё»; на максимуме кнопки нет, остаётся фраза о пределе. Состояния слоёв — полоса общего вида. «Ничего не найдено» — узел запроса и строка с порогом.

### Правила перехода

| Событие | Что происходит |
|---|---|
| Завершённый поиск (главный экран или глобальный слой) | Вид запроса включается во всех панелях, в том числе после ручного «Общий вид»; панель сама не открывается. Общий вид запоминает места узлов, камеру и выбор (закрепления живут в раскладке и не теряются); раскладка строится с нуля вокруг запроса, камера вписывается один раз; всплывает подсказка с числом результатов, глубиной и режимом |
| «Общий вид» | Только эта панель возвращает прежние места, камеру, выбор и закрепления без нового расчёта и без вписывания; второй панели вид запроса остаётся. Камера пересчитывается к размеру панели, чтобы смена высоты полосы запроса не сдвигала картинку |
| После «Общего вида» | В углу карты остаётся пунктирная плашка «Запрос «…» · Показать запрос в графе» (в мини-графе «Показать»); она строит вид заново из того же поиска без запроса к воркеру. Следующий завершённый поиск включает вид сам |
| Поиск идёт | Прежний вид (общий или запроса) остаётся; полоса «Идёт поиск: показан прежний вид»; в окне результаты на время поиска обнуляются, поэтому вид снимается только когда поиск не идёт, ошибки нет и сессия поиска сброшена |
| Ошибка поиска | Вид не меняется; полоса с причиной «Граф остался прежним» |
| Смена режима связей | Перекладка с нуля без запроса к воркеру; связь запроса видна в любом режиме; узел окружения виден, если в режиме у него есть ребро |
| Смена глубины | Узлы и позиции прежние остаются, новые появляются рядом с результатом; сброс «Показать ещё» |
| «Показать ещё» | Пределы растут шагами до максимума вида (две ступени), позиции и камера сохраняются, дублей нет |
| Пустая выдача, слой недоступен | Узел запроса (и результаты) без окружения; слой помечен; «Общий вид» работает |

Клавиатура: «Общий вид» и «Показать запрос в графе» — обычные кнопки с Tab/Enter; сочетания карты (`M`, `F`, стрелки, пробел) работают в обоих видах; reduced motion — раскладка статична, вход и возврат без анимации.

### Принятые предложения

Автор принял все четыре (OQ-120): возврат только в нажавшей панели; пунктирная плашка «Показать запрос в графе»; глубина и «Показать ещё» только в полном графе; визуальный язык результатов (кольцо, пунктирное кольцо, пустой круг, нейтральный пунктир).

## Договор данных вида запроса

Внутренняя проекция окна `QueryGraphSlice` поверх `PhysicalGraphSlice` (версия метода `physical-v1`); существующие `GraphReply`, `graph_search` и MCP/CLI-контракты не меняются. Запрос среза: проект, область, снимок, описание поиска (идентификатор, текст, запрошенный и применённый режим, `score_kind`, результаты), включённые виды, `depth`, `fanout`, порог близости, бюджеты, курсор. Срез: всё содержимое `PhysicalGraphSlice` плюс узел запроса, рёбра `query_result` с `raw_score`, `score_kind`, `s_q` и совпавшими чанками; статус каждого результата (`ready`, `no_graph_object`, `changed_since_search` с причиной); состояния трёх слоёв; запрошенные и применённые бюджеты, показанные и известные счётчики, `truncated`, причины, курсор. Fingerprint включает запрос, область, режимы, глубину, `fanout`, порог, лимиты и метод; изменение любого начинает новый срез; исчезнувший снимок — `snapshot_expired`. Текст запроса используется как подпись и ключ, но граф по нему не ищет и не векторизует.

## Что реализовано в окне и чем отличается от контракта

Статус 22-10-2026 (пункт 2.2.3). Вид запроса включается после каждого завершённого поиска, в том числе из глобального слоя, во всех панелях графа, и выключается, когда результаты поиска сброшены. Код — `ui/src/lib/graph/query.ts` (построение и отбор), `PhysicalGraph.svelte` (вход, возврат, полоса запроса, инспектор), `draw.ts` (квадрат запроса, кольцо результата, оранжевая связь). Проверено тестами окна и в браузере на макетных данных; на настоящих запросах bars-project не проверялось.

**Совпадает с контрактом:** узел запроса и ребро `query_result` к каждому результату, `s_q = clamp(score, 0, 1)` без пересчёта по месту в выдаче; один узел на документ с наибольшей оценкой; вид оценки rerank/косинус подписан, при «Отношения и пути» оценки нет, связь нейтральная пунктирная; окружение `fanout` 4 по ссылкам (сначала другие результаты, затем взаимные) и по смыслу, глубина 0/1/2 (по умолчанию 1), результаты окружением не вытесняются; порядок включения при нехватке места и пределы 200 узлов / 800 рёбер до 500 / 2000 с «Показать ещё» в две ступени; режим связей и порог перекладывают раскладку с нуля без запроса к воркеру, связь запроса видна в любом режиме; раскладка — запрос в центре, результаты по кругу в порядке выдачи; «Общий вид» возвращает только нажавшую панель, плашка «Показать запрос в графе» строит вид заново, следующий поиск включает его сам; пока идёт поиск, прежний вид остаётся.

**Отличается от контракта:**
- **Построение на клиенте.** Нет Rust-проекции, `QueryGraphSlice` и команды воркера. Окружение берётся из рёбер уже загруженного среза `graph_physical`: ссылки и близость документов kNN k=5 при cosine не ниже 0,5, а не точный cosine результата со всеми документами области. Охват — документы среза (до 500); область берётся из среза.
- **Нет `related` и путей.** Связанные источники режима «Со связями» на карте не рисуются и в инспекторе запроса не перечислены; пути режима «Отношения и пути» не подсвечиваются. Нет пометки «без физической связи».
- **Нет статусов «изменён после поиска» и «удалён».** Результат, которого нет в срезе, остаётся в списке инспектора запроса с причиной «документа нет в срезе графа», а полоса вида пишет «Граф неполон» с числом таких результатов; отдельного узла-призрака на карте нет.
- **Возврат в общий вид** сохраняет закрепления, но не восстанавливает прежние места узлов, камеру и выбор: раскладка общего вида продолжается с тех мест, куда узлы сдвинуло движение.
- **Глубина** переключается только в полном графе; в мини-графе действует умолчание 1.
- **Совпавшие чанки** не рисуются ромбами; их строки и оценки видны в инспекторе результата.
- **Шкала cosine** окна 0,60–0,95 для оценки `cosine` принята автором, но на настоящих запросах не проверялась.

## Проверки проекта и критерии реализации

Скрипт проекта проверяет правила на готовых рёбрах снимка: детерминизм построения, глубину 0, порядок включения при усечении (первые соседи раньше вторых), неизменность силы после порога, независимость порядка соседей от степени узла; размеры — в таблице выше. Это проверка правил, не приёмка Т-47.

| Проверка следующего шага | Ожидаемый результат |
|---|---|
| Результаты нескольких чанков одного документа | Один узел, наибольшая оценка, все фрагменты в инспекторе |
| Ответ без реранка, с ошибкой реранка, с реранком | Вид оценки подписан по фактическому `score_kind`; шкалы не смешиваются |
| `related` и `graph` | Нет подделанной оценки; причина включения и «без физической связи» видны |
| Результат без объекта графа, слой строится/неполон/устарел/недоступен | Узел результата виден с причиной, вид помечен неполным, готовые слои работают |
| Область из модулей/файлов | Окружение только из области; нет числа исключённых; результаты в области всегда |
| Глубина 0/1/2, пределы 200/800 и максимум | Явное усечение с причиной; результаты не вытеснены; продолжение без дублей |
| Смена режима связей | Перекладка с нуля без запроса к воркеру; связь запроса видна в любом режиме |
| Вход/возврат/новый поиск/поздний ответ/смена проекта | Состояния общего вида сохранены; поздний ответ отброшен; вид не смешивает снимки |
| Stop, reduced motion, скрытие, уничтожение | Поведение как у общего вида |
| bars-project и overdrive-bots, настоящие запросы S1–S8 | Понятные основания, приемлемые время расчёта окружения (не измерено), CPU/память; обе темы/размеры |
