# Контракты инструментов GraphRAG для bars

Контракты шести операций GraphRAG и расширений поиска и статуса: реализованная схема v1 и целевой контракт полного состава. Статус фичи — [Index.md](Index.md#статус); приёмка по [GR-03](requirements.md#gr-03-новые-инструменты-и-единое-выполнение) не завершена. `schema_version` относится к GraphRAG DTO, не к версии существующей SQLite-схемы ([architecture/graph.md](../../architecture/graph.md#таблицы-графа-в-sqlite)).

## Фактический контракт v1

Worker: `graph_query` принимает `{cwd?, project?, request: GraphRequest}`. MCP выставляет шесть read-only имён из таблицы соответствия; `operation` выбирается именем инструмента, `modules/files` передаются плоско и преобразуются в `request.scope`. CLI принимает те же поля через JSON запроса. Неизвестные поля GraphRequest отклоняются.

| Операция | Реализованные входы |
|---|---|
| relations | Ровно один `query`/`entity_ref`; `predicates`, `direction`, `polarity`, `qualifiers` |
| paths | `from`, `to`: ObjectRef либо `{label, kind?, namespace?}`; `path_kind=semantic\|structural\|mixed`, `max_hops`, `max_paths` |
| impact | Непустые `roots`, обратный обход положительных зависимостей; `change_description` возвращает capability unavailable |
| context | Непустой `query`, `task_profile=implementation\|investigation\|decision`, сужающие `roles`, `token_budget`; `tokenizer_id`/`roots` возвращают capability unavailable; estimated byte budget всего DTO |
| explore | Ровно один `topic`/`whole_scope=true`; `analysis=topics\|connectivity\|coverage\|conflict_candidates`, `grouping=communities\|modules` |
| graph | `view=documents\|sections\|chunks\|entities\|mixed`, `local`, `roots`, `include_paths`, `predicates`, `direction`; depth задаётся `budgets.max_depth` |

Общие входы: `scope`, `budgets`, `limit`, `snapshot`, `cursor`. Фактические численные пределы — в [правилах реализации](implementation.md#начальные-пределы-выполнения); это инженерные ограничения, ресурсная приёмка ещё открыта. Endpoint/ObjectRef устаревшей ревизии не заменяется поиском похожего объекта.

Ответ: нормализованные `nodes`, `sources`, `assertions`, `evidence`; элементы `items` имеют дискриминатор `type`. У узла/источника поле называется `reference`, у основания — `span`, точный `quote` и extractor version. Дополнительно: `operation`, `schema_version=1`, `scope`, `snapshot`, `generations`, `layer_state/layer_states`, `coverage`, `requested/applied`, `applied_limit`, `clamped`, `truncated/limit_reasons`, `next_cursor`, `warnings`, `method`, `elapsed_ms`, `resolution/candidates`, `missing_roles`, `budget_mode`, `used_bytes`. Смысловой слой остаётся partial: полнота неизвестна. Отсутствие связи не доказывает отсутствие зависимости/проверки.

Search: без `mode` — прежний Search и прежняя форма ответа. Явный `mode=hybrid|mix|graph` вызывает `graph_search`; дополнительно принимает `graph_budgets`, в mix — `include_related` (по умолчанию true) и `related_budget` (положительный byte budget пакета; меньший из него и max_bytes). Возвращает прежний SearchOutput плюс `requested_mode`, `applied_mode`, `fallback_reason`, `related`, `graph_results`. В mix кандидаты расширяются до rerank/top-K; связанные пакеты имеют собственные основания. `include_related=false` отключает расширение/пакеты и явно применяет hybrid. При неготовом графе mix явно переходит к hybrid; graph возвращает ошибку. CLI: `search --mode mix --no-related` / `--related-budget N`; окно — переключатель добавления связанных источников.

Статус содержит необязательный `graph`. `graph_build` принимает target; `graph_cancel` — target и `job_id`. Запись доступна только окну/CLI; MCP не получает write-tools. Accepted не означает завершения. Автообновление следует за публикацией текстового индекса и использует сохранённые векторы, без переиндексации embeddings.

## Целевой контракт: незавершённые отличия

Следующие разделы сохраняют проект полного состава. Context `roots/include_related`, отдельные `edge_types/include_unresolved`, per-file progress/errors и точный tokenizer пока не реализованы; их нельзя передавать как работающие поля v1. Полная приёмка требует устранить эти отличия либо явно согласовать изменение контракта, не скрывать их фикстурами.

## Общие входы и правила области

Все шесть инструментов — чтение готовых слоёв. Natural-language query может использовать выбранные query-модели, что отражается в методе/таймингах; это не включает построение индекса. Запросы, сообщения и подписи — по НФТ-4.

| Поле | Тип и правило |
|---|---|
| `project` | Необязательный идентификатор/путь; разрешение по текущему контракту проекта сессии |
| `modules`, `files` | Необязательные списки; тот же смысл объединённой области, что у существующего поиска; неизвестные значения — ошибка |
| `snapshot` | Необязательный opaque token предыдущего ответа; без него сервер выбирает согласованный снимок |
| `budgets` | Необязательный объект с `max_depth`, `max_nodes`, `max_edges`, `max_fanout`, `max_paths`, `timeout_ms`, `max_bytes`; применяются релевантные операции ограничения |
| `limit` | Необязательный положительный предел элементов результата, не отменяет общий byte/time/graph budget |
| `cursor` | Необязательное продолжение запроса с тем же снимком, областью и параметрами; изменение связанных аргументов отклоняется |

Численные умолчания/максимумы и единицы фиксируются в P0 по GR-09; выбранные значения записываются в этот контракт до реализации. Отрицательные/нецелые счётчики, пустой обязательный query, неизвестный enum и несовместимые варианты входа — `invalid_params`. Превышение разрешённого максимума прижимается с `clamped` и фактическим значением; ноль допускается только там, где явно определён, например depth=0 для самого root.

Если операция задаёт `max_hops/max_paths` одновременно с общим пределом depth/paths, действует меньший из разрешённых пределов; ответ показывает оба запрошенных и эффективный. Ни один локальный параметр не увеличивает серверный максимум.

`ObjectRef`: `kind`, opaque `id`, `revision`. Внешний ID — не SQLite rowid и не номер строки. Разрешение текстового имени даёт один объект либо список кандидатов с неоднозначностью. Предикат, alias или ID из другого namespace не объединяется молча. Раздел, чанк и сущность имеют разные `kind`.

## Общий результат GraphRAG

| Поле | Значение |
|---|---|
| `schema_version` | Версия GraphRAG DTO; первоначальное предложение — 1 |
| `scope`, `snapshot` | Фактически использованная область и снимок |
| `generations` | Версии текста, структуры, смысла, communities и fingerprints применённых методов |
| `layer_state`, `coverage` | Состояние нужных слоёв; известные indexed/processed/failed counts, denominator и метод подсчёта |
| `requested`, `applied`, `clamped` | Запрошенные/применённые параметры и изменения пределов |
| `items` | Специфичные операции отношения/пути/узлы/пакеты/группы |
| `sources`, `assertions`, `evidence` | Нормализованные справочники только использованных и разрешённых объектов |
| `truncated`, `limit_reasons`, `next_cursor` | Усечение, причины и продолжение, только если оно действительно доступно |
| `warnings`, `method`, `timings` | Ограничения вывода, использованный метод/модели и время стадий |

`coverage` сообщает обработку корпуса, а не вероятность полноты ответа. Если denominator неизвестен — `null` и причина, а не фиктивные 100%. Размер ответа учитывает envelope и справочники; evidence не отрезается так, чтобы результат продолжал считаться полным. Cursor продолжает выдачу, но не выдаёт себя за способ обойти исчерпанный time/visit budget: причина частичности сохраняется.

`Evidence`: ref документа/ревизия, path, source ranges, quote или разрешимая ссылка на диапазон, source hash, extraction method/version. Текст может быть прочитан отдельно, но ссылка должна разрешаться в исходный снимок либо честно возвращать stale. Документированный факт, модельный кандидат и статус ручной проверки — разные поля.

## bars_relations — утверждения и карточка связей

**Назначение:** S2/S4/S5; вход в граф для остальных инструментов.

Варианты входа: ровно один из `query: string` или `entity_ref: ObjectRef`. Необязательны `predicates: string[]`, `direction: incoming|outgoing|both`, `polarity: positive|negative|any`, `qualifiers`, общие scope/budgets/limit. `qualifiers` фильтруют выбранную схему платформ/версий/условий; отсутствие квалификатора не означает совпадение с любой конкретной платформой.

Результат: разрешённые участники и aliases, assertion refs, subject/predicate/object, направление, polarity/qualifiers, происхождение/статус, evidence refs, ранг совпадения с query и `score_kind`. Вход по ID не требует нового entity-extraction; поиск естественной формулировки использует индекс отношений/алиасов и выбранную query-модель.

При неоднозначном имени — `resolution=ambiguous` и кандидаты без отношений произвольно выбранного объекта. При отсутствии matching relations — успешный пустой список с scope/coverage. При устаревшем entity_ref — `stale_ref`, не подбор похожего объекта.

## bars_paths — пути между объектами

**Назначение:** S2/S7 и объяснение результата S1/S3.

Обязательны `from`, `to`: ObjectRef либо `{label, kind?}`. Необязательны `predicates`, `path_kind: semantic|structural|mixed`, `max_hops`, `max_paths`, qualifiers и общие ограничения. Исходный проектируемый профиль — semantic; смешанный путь выбирается явно и сохраняет типы каждого перехода.

Результат каждого пути: ordered node refs, ordered assertion/edge refs, направление traversal и исходное направление предиката, evidence каждого смыслового ребра, условия, rank/score_kind, `complete`, причина ограничения. Кратчайший путь не подписывается причинным объяснением автоматически.

Для двух неоднозначных концов возвращаются кандидаты обеих сторон без комбинаторного угадывания. Пустой набор путей несёт searched scope/depth/budgets. Временной предел — partial с причиной; недоступный semantic layer — ошибка, не ответ «связи нет». Циклы не приводят к бесконечному обходу или перечислению всех простых путей.

## bars_impact — влияние изменения

**Назначение:** S1 и предметный обход для S8.

Обязателен непустой `roots: ObjectRef[]`. Необязательны профиль predicates/qualifiers, глубина и `change_description`. Описание изменения — необязательное уточнение отбора, не разрешение изменить документацию. Без него возвращаются документированные зависимости от roots.

Результат: affected object refs, роль описания/решения/проверки, direct/indirect, обосновывающие path refs, условия и причина включения. Для `A depends_on B` изменение B ведёт к A; направление проверяется отдельно для каждого предиката. Упоминания/обычные ссылки возвращаются в `related_links`, не как доказанная зависимость.

Если change_description реально использовалось модельным фильтром — ответ показывает этот метод; если не поддержано выбранным режимом, вход отклоняется с понятной причиной, а не игнорируется. Формулировки результата — «проверить описание», не «код сломан».

## bars_context — контекст задачи по ролям

**Назначение:** S3/S4/S7; использует связи S1/S2/S5.

Обязателен `query`. Необязательны `task_profile`, `roles`, `roots`, `token_budget`, `tokenizer_id`, `include_related`, scope и graph budgets. Схема ролей первоначально: requirement/decision/behavior/architecture/constraint/verification; конкретный профиль выбирает подмножество.

Результат — `role_groups`, source refs, spans, связь с query/root/path, `missing_roles`, `used_budget`, `budget_mode=exact|estimated`, tokenizer и ограничения. Роль с неизвестным основанием классификации не заполняется уверенным выдуманным статусом. Один фрагмент может покрыть несколько ролей без многократного списания токенов текста.

При малом бюджете возвращается меньший комплект с перечислением непокрытого; нельзя обрезать текст посреди необходимой оговорки и сохранить вывод как полный. Бюджет всего ответа включает метаданные и нормализованные справочники. Пакет — первоисточники и структурные метки, не сгенерированный ответ на задачу.

## bars_explore — обзор темы и аудит

**Назначение:** S5/S6/S8.

Вход: `topic` либо явный `whole_scope=true`; `analysis=topics|connectivity|coverage|conflict_candidates`, detail level, roles/predicates для выбранного анализа, общие budgets. `topic` и whole_scope одновременно не задаются. Ни один режим не запускает скрытое обогащение.

| analysis | Результат | Условие доступности |
|---|---|---|
| `topics` | Группы, представители, межгрупповые связи, coverage и продолжение | Готовая группировка выбранной области; текстовое имя группы имеет происхождение |
| `connectivity` | Изоляты, хабы, unresolved/broken links, orphan source refs | Структурный слой; неизолированность через Index отдельно от смысловых связей |
| `coverage` | Объекты без найденной роли/отношения, пути и область поиска | Достаточное покрытие соответствующего смыслового слоя либо явная partial |
| `conflict_candidates` | Пары несовместимых утверждений и evidence с условиями/статусами | Поддерживаемая семантика qualifiers/polarity; кандидат, не автоматический вердикт |

Группировка по источникам одного seed не называется обзором всего проекта. При фильтрации корпуса summaries/communities из исключённых источников не используются скрыто. Неполный extraction не даёт заключения об отсутствии проверки или противоречий.

## bars_graph — общий и локальный подграф

**Назначение:** данные графического просмотра и структурное представление результатов всех S1–S8.

Вход: `view=documents|sections|chunks|entities|mixed`, `roots?`, `local: boolean`, `depth`, `edge_types`, direction, `grouping=document|community|none`, `include_unresolved`, scope/budgets/cursor. Local требует root; depth=0 показывает сами roots. Общий граф без roots не превращается в неограниченную выгрузку.

Результат: node refs с kind/label/group refs; edges с типом/направлением/происхождением, counts и evidence refs; group members или возможность раскрытия; truncated и известные totals. В documents view агрегируются только выбранные типы; число рёбер и число evidence раздельны. Скрытый endpoint не раскрывается подписью/counter через фильтр.

Layout выполняет клиент над разрешённым результатом и не влияет на ранги поиска. Сохранённая камера/пины — пользовательское состояние, не смысловые данные. При раскрытии нужен тот же snapshot; после смены поколения клиент запрашивает новый согласованный срез.

## Расширение bars_rag_search

Новый необязательный `retrieval=hybrid|mix|graph`, исходное умолчание hybrid. Для mix: `include_related`, `related_budget` и общие graph budgets; существующие поля min_score/candidates/limit сохраняют смысл основного канала. Graph использует режим результата relations/paths; клиентам нужно знать новый DTO, а не ожидать прежний список чанков.

| Канал ответа | Состав |
|---|---|
| `results` | Основные текстовые совпадения с действующей шкалой и порогом |
| `related` | Связанные evidence bundles, пути и причины включения с собственным бюджетом; не выдаются за прошедшие старый min_score |
| `graph_results` | Для graph: отношения/пути и нормализованные источники |
| `retrieval_status` | Requested/applied mode, layer state, fallback reason, поколения, coverage и усечение |

Прежний вызов без новых параметров сохраняет прежнюю форму и семантику результата. Новая расширенная форма включается явным новым режимом; совместимость старых клиентов проверяется. Это действующий публичный MCP/CLI-контракт, поэтому переход должен быть спроектирован, а не случайно обеспечен тестами.

Отключённый/неготовый graph layer: mix → hybrid с явной причиной; graph → `graph_not_ready`. Отсутствующий нужный отдельный capability, например communities для topics, — `graph_capability_unavailable`, не пустая успешная выдача. Источник связан по структуре — отдельный reason от смыслового пути.

## Расширение статуса и явное управление заданиями

`bars_status` получает graph-секцию: enabled layers, states, поколения/fingerprints, counts/coverage, активное задание, progress и ошибки файлов. Старые поля статуса не меняют смысл. Подробные ошибки не требуют полного текста документа в логах.

Для записи проектируются общие worker-операции `GraphBuild` и `GraphCancel`: layer, scope, extractor/config fingerprint, mode incremental/rebuild; ответ — job ID/accepted либо ошибка. Accepted означает постановку задания, не готовность графа. Завершение/ошибка/отмена видны в статусе. Нужные дополнительные поля фиксируются после OQ-85, до P4.

Доступ записи — явные действия окна и CLI `graph build/cancel`; расширение write-инструментов MCP не входит в первоначальные шесть операций. Существующий `bars_reindex` не получает тайного значения «скачать extractor и построить граф». Перестройка embeddings и её согласие по Т-25 независимы.

## Ошибки и ограниченные результаты

Имена ниже — проект новых ошибок; существующие проектные/модельные ошибки сохраняются по текущему протоколу.

| Состояние | Ответ |
|---|---|
| Неверный аргумент/область | `invalid_params` с указанием поля |
| Нужный слой ещё не построен | `graph_not_ready` и layer state |
| Метод выбранного слоя недоступен | `graph_capability_unavailable` и требуемая capability |
| Ref больше не соответствует исходнику | `stale_ref`, без подмены похожим объектом |
| Снимок/курсор потерян | `snapshot_expired` / `cursor_mismatch`; требуется новый запрос |
| Имя неоднозначно | Нормальный resolution result с кандидатами, без произвольного обхода |
| Нет результата в области/пределах | Успешный пустой список, scope/coverage/limits |
| Достигнут лимит при наличии результатов | Partial, причины, только валидные evidence bundles |
| Отмена / ошибка исполнения | Явное cancelled/error, не «совпадений нет» |

## Соответствие CLI и окна

| MCP | CLI, проект синтаксиса | Действие окна |
|---|---|---|
| `bars_relations` | `relations` | Связи/карточка объекта |
| `bars_paths` | `paths` | Две вершины → путь |
| `bars_impact` | `impact` | Влияние изменения |
| `bars_context` | `context` | Собрать контекст с бюджетом |
| `bars_explore` | `explore` | Обзор темы / аудит |
| `bars_graph` | `graph show` | Общий/локальный граф и раскрытие |

CLI предлагает JSON с тем же DTO и текстовое представление без потери признаков partial/coverage. Точный набор флагов фиксируется вместе с схемой DTO до клиентской реализации. Выбранный подграф можно экспортировать в JSON; дополнительные форматы не обязательны для GR-01…GR-12.
