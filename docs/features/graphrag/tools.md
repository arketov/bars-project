# Контракты инструментов GraphRAG для bars

Контракты шести операций GraphRAG и расширений поиска и статуса: реализованная схема v1 и целевой контракт полного состава. Статус фичи — `Index.md`; приёмка по [GR-03](requirements.md#gr-03-новые-инструменты-и-единое-выполнение) не завершена. `schema_version` относится к GraphRAG DTO, не к версии существующей SQLite-схемы ([architecture/graph.md](../../architecture/graph.md#таблицы-графа-в-sqlite)).

## Фактический контракт v1

Срез 4.3.5 реализован в исходниках: общий вход `documents` для `impact`, `context` и локального `graph`, конец пути `{document}`, расширение корня-документа до его разделов и чанков, кандидаты имён и диагностика следующего шага. Ограничения обхода и области сохраняются; гиперссылки не становятся зависимостями. Финальные тесты, сборка и native не запускались по указанию автора 01-11-2026; статический разбор не заменяет приёмку исполнения.

Worker: `graph_query` принимает `{cwd?, project?, request: GraphRequest}`. MCP выставляет шесть read-only имён из таблицы соответствия только при `[mcp] graph_tools = true` в `settings.toml`: по умолчанию они скрыты от агентов до приёмки качества (OQ-162, реализовано 4.1.2; [инструменты MCP](../agent-tools/mcp-tools.md)), воркер, CLI и окно от ключа не зависят; `operation` выбирается именем инструмента, `modules/files` передаются плоско и преобразуются в `request.scope`. CLI принимает те же поля через JSON запроса. Неизвестные поля GraphRequest отклоняются.

Состояние 2.2.5: `graph_status` и `bars_status.graph` возвращают независимые `freshness=not_built|current|stale`, `completeness=complete|partial|unknown`, `availability=enabled|disabled`, `job_state=idle|queued|running|stopped|failed`. Общие признаки выводятся из включённых `layers`; прежнее `state` описывает данные, а не активное задание. У каждого слоя — те же три признака данных, generation/fingerprint, `source_revisions` и `coverage` (`unit`, `processed`, `total`, `missing`, `comparisons`, `reason`). Покрытие близости относится к чанкам, единица comparisons определяется fingerprint метода: направленные сравнения прежнего kNN или неориентированные пары точного парного прохода; покрытия разных единиц не складываются. GraphReply включает `layers` с ревизиями возвращённых источников; общий статус слоя консервативен для проекта. Совместимый устаревший снимок возвращается с предупреждением, mix переходит к обычному поиску, context проверяет текущие ревизии. `read` дополнительно возвращает `revision` — BLAKE3 исходного UTF-8 текста; окно проверяет её перед выделением строк старого графа. Подробности и ограничения — [контракт чтения прежнего снимка](implementation.md).

| Операция | Реализованные входы |
|---|---|
| relations | Ровно один `query`/`entity_ref`; `predicates`, `direction`, `polarity`, `qualifiers` |
| paths | `from`, `to`: ObjectRef, `{document}` либо `{label, kind?, namespace?}`; `path_kind=semantic\|structural\|mixed`, `max_hops`, `max_paths` |
| impact | `documents` и/или `roots`, обратный обход положительных зависимостей; `change_description` возвращает capability unavailable |
| context | Непустой `query`, необязательные `documents`/`roots` ограничивают окрестность до ранжирования; `task_profile=implementation\|investigation\|decision`, сужающие `roles`, `token_budget`; `tokenizer_id` возвращает capability unavailable; estimated byte budget всего DTO |
| explore | Ровно один `topic`/`whole_scope=true`; `analysis=topics\|connectivity\|coverage\|conflict_candidates`, `grouping=communities\|modules` |
| graph | `view=documents\|sections\|chunks\|entities\|mixed`, `local`, `roots`, `documents` только для local, `include_paths`, `predicates`, `direction`; depth задаётся `budgets.max_depth` (в MCP — полем `max_depth`) |

Общие входы: `scope`, `budgets`, `limit`, `snapshot`, `cursor`. Фактические численные пределы — в [правилах реализации](implementation.md#пределы-выполнения); ресурсная приёмка ещё открыта. Endpoint/ObjectRef устаревшей ревизии не заменяется поиском похожего объекта.

Текстовый вид ответа для агента (`format=txt`) — [контракт 4.3.2](#ответ-графа-для-агента--текст-предел-пустые-ответы). Ответ DTO: нормализованные `nodes`, `sources`, `assertions`, `evidence`; элементы `items` имеют дискриминатор `type`. У узла/источника поле называется `reference`, у основания — `span`, точный `quote` и extractor version. Дополнительно: `operation`, `schema_version=1`, `scope`, `snapshot`, `generations`, `layer_state/layer_states`, `coverage`, `requested/applied`, `applied_limit`, `clamped`, `truncated/limit_reasons`, `next_cursor`, `warnings`, `method`, `elapsed_ms`, `resolution/candidates`, `missing_roles`, `budget_mode`, `used_bytes`. Смысловой слой остаётся partial: полнота неизвестна. Отсутствие связи не доказывает отсутствие зависимости/проверки.

Search: без `mode` — прежний Search и прежняя форма ответа. Явный `mode=hybrid|mix|graph` вызывает `graph_search`; дополнительно принимает `graph_budgets`, в mix — `include_related` (по умолчанию true) и `related_budget` (положительный byte budget пакета; меньший из него и max_bytes; слишком малый — выдача без пакета с `fallback_reason`, ISS-88). Возвращает прежний SearchOutput плюс `requested_mode`, `applied_mode`, `fallback_reason`, `related`, `graph_results`. В mix кандидаты расширяются до rerank/top-K; связанные пакеты имеют собственные основания. `include_related=false` отключает расширение/пакеты и явно применяет hybrid. При неготовом графе mix явно переходит к hybrid; graph возвращает ошибку. CLI: `search --mode mix --no-related` / `--related-budget N`; окно — переключатель добавления связанных источников.

Статус содержит необязательный `graph`. `graph_build` принимает target и необязательный `layer=all|structure|semantic|similarity` (умолчание all); `graph_cancel` — target и `job_id`. Запись доступна только окну/CLI; MCP не получает write-tools. Accepted не означает завершения. Автообновление выполняется отдельным управляемым заданием после публикации текстового индекса и использует сохранённые векторы, без переиндексации embeddings. Сохранённая пауза `paused` запрещает автообновление до явного build.

**`context.roots`.** `roots` — `ObjectRef[]`, документ, раздел, чанк или сущность. Окрестность корня — объекты в пределах `budgets.max_depth` по структурным и положительным смысловым связям обоих направлений; корень-документ приводит свои чанки. Окрестность не расширяет `scope`: объекты вне области отбрасываются. Без `roots` отбор идёт по всей области, как сейчас. С `roots` и `query` оба условия работают как пересечение отбора и ранжирования: сначала окрестность, затем релевантность `query` внутри неё. Целевой контракт 4.3.7: каждый элемент несёт `via=query|root|path`, у `via=path` — ссылку на путь от корня. Устаревший корень — `stale_ref`.

**Без точного tokenizer.** Токены клиента зависят от модели клиента (Claude, Codex и другие), а tokenizer встроенной embed-модели считает по-другому; «точное» число для чужой модели вводило бы в заблуждение. Поэтому `budget_mode` всегда `estimated`, а ответ называет `tokenizer=estimate-v1`: один токен — 3 байта UTF-8, то есть бюджет `token_budget` пересчитывается в `max_bytes = token_budget × 3`. Для русского текста это консервативная оценка (в среднем один токен — заметно больше трёх байт), поэтому ответ скорее меньше бюджета, чем больше; точный коэффициент на корпусе измеряется в 4.1.7. Жёсткий предел байт действует всегда и включает envelope и справочники.

**`impact.change_description`.** Описание изменения — текст, по которому затронутые объекты ранжируются по близости цитат (FTS и существующий query-вектор, если модель уже в памяти; метод записывается в `method`). Объект без совпадения с описанием остаётся в ответе: отсутствие слов не доказывает отсутствия влияния. Ответ показывает `score_kind` и то, что описание использовалось. Скрытого запуска модели и модели-фильтра нет.

**Предикаты и `origin` в `graph`.** `edge_types` дублировал бы `predicates`: каждый тип связи — предикат (`links_to`, `similar_to`, `contains` и так далее). Происхождение связи (`structural`, `explicit_rule`, `similarity`) — отдельное свойство ребра; фильтр по нему вводится необязательным полем `origins`.

## Словарь связей

Статус: словарь принят автором 22-10-2026 (OQ-142); extraction v6 публикует `depends_on` с `kind=precondition` вместо `requires` (23-10-2026). `requires` остаётся входным фильтром для прежних клиентов. Ребро читается «`from` — предикат — `to`»; направление в хранилище совпадает с этим чтением.

| Предикат | Класс | Направление (`from → to`) | Полярность | Обход `impact` |
|---|---|---|---|---|
| `contains` | структурный | родитель → вложенный (документ → раздел) | только положительная | нет |
| `covers` | структурный | чанк → раздел, чей исходный диапазон он покрывает | только положительная | нет |
| `next_chunk` | структурный | чанк → следующий чанк того же документа | только положительная | нет |
| `links_to` | структурный | документ или раздел, где стоит ссылка → цель ссылки | только положительная | нет |
| `mentions` | упоминание | чанк → сущность | только положительная | нет |
| `depends_on` | смысловой | зависимый → то, от чего зависит | положительная и отрицательная | да: от `to` к `from` |
| `uses` | смысловой | использующий → используемое | положительная и отрицательная | да: от `to` к `from` |
| `implements` | смысловой | реализация → реализуемое (раздел → требование) | положительная и отрицательная | да: от `to` к `from` |
| `verifies` | смысловой | проверка → проверяемое | положительная и отрицательная | да: от `to` к `from` |
| `supersedes` | смысловой | новое решение → заменённое | только положительная | нет; идёт отдельным обходом «текущее решение» |
| `similar_to` | производный | симметричен, хранится один раз | только положительная | нет |
| `co_occurs` | производный | симметричен, хранится один раз | только положительная | нет |
| `member_of` | производный | участник → группа (community) | только положительная | нет |

Правила.

- **Только смысловые предикаты несут полярность и условия.** `negative` значит «в источнике сказано, что связи нет» («A не зависит от B»), а не «связи не найдено». Отрицательное ребро не участвует в обходе `impact` и `paths` по умолчанию, но попадает в `relations` и в кандидаты противоречий `explore`.
- **Производные и структурные связи не становятся смысловыми.** `similar_to`, `co_occurs`, `links_to` не используются как `depends_on` ни при каком пороге; путь `mixed` сохраняет класс каждого перехода.
- **Квалификаторы** — словарь строка → строка до 32 ключей. Ключи v1: `condition` (условный оборот, цитата с союзом: «если выбран CPU»), `platform`, `version`, `kind` (уточнение смысла предиката, например `precondition`). Ключ вне этого списка отклоняется на разборе правил, в запросе фильтр по неизвестному ключу — `invalid_params`. Отсутствие квалификатора не равно «для любой платформы».
- **Происхождение** — `structural`, `explicit_rule`, `similarity`; в ответе поле называется `origin`. Статус ручной проверки не вводится (OQ-86).
- **`requires`.** По решению автора отдельного значения в новых утверждениях нет: «требует», «запускается/выполняется только после» дают `depends_on` с `kind=precondition`. Метод `explicit-markdown-v6` инвалидирует прежнее хранилище. Входной `predicates=["requires"]` выбирает только такие предусловия, с предупреждением об устаревании; остальные `depends_on` этим фильтром не выбираются. Полярность и условия сохраняются.

## Общие входы и правила области

Все шесть инструментов — чтение готовых слоёв. Natural-language query может использовать выбранные query-модели, что отражается в методе/таймингах; это не включает построение индекса. Запросы, сообщения и подписи — по НФТ-4.

| Поле | Тип и правило |
|---|---|
| `project` | Необязательный идентификатор/путь; разрешение по текущему контракту проекта сессии |
| `modules`, `files` | Необязательные списки; тот же смысл объединённой области, что у существующего поиска; неизвестные значения — ошибка |
| `snapshot` | Необязательный opaque token предыдущего ответа; без него сервер выбирает согласованный снимок |
| `budgets` | Необязательный объект с `max_depth`, `max_nodes`, `max_edges`, `max_fanout`, `max_paths`, `timeout_ms`, `max_bytes`; применяются релевантные операции ограничения |
| `limit` | Необязательный положительный предел элементов результата, не отменяет общий byte/time/graph budget |
| `cursor` | Необязательное продолжение запроса с тем же снимком, областью и параметрами; изменение связанных аргументов отклоняется |

Численные умолчания, максимумы и единицы по GR-09 — в [правилах реализации](implementation.md#пределы-выполнения). Отрицательные/нецелые счётчики, пустой обязательный query, неизвестный enum и несовместимые варианты входа — `invalid_params`. Превышение разрешённого максимума прижимается с `clamped` и фактическим значением; ноль допускается только там, где явно определён, например depth=0 для самого root.

Если операция задаёт `max_hops/max_paths` одновременно с общим пределом depth/paths, действует меньший из разрешённых пределов; ответ показывает оба запрошенных и эффективный. Ни один локальный параметр не увеличивает серверный максимум.

`ObjectRef`: `kind`, opaque `id`, `revision`. Внешний ID — не SQLite rowid и не номер строки. Разрешение текстового имени даёт один объект либо список кандидатов с неоднозначностью. Предикат, alias или ID из другого namespace не объединяется молча. Раздел, чанк и сущность имеют разные `kind`.

## Общий результат GraphRAG

| Поле | Значение |
|---|---|
| `schema_version` | Версия GraphRAG DTO; первоначальное предложение — 1 |
| `scope`, `snapshot` | Фактически использованная область и снимок |
| `generations` | Версии текста, структуры, смысла, communities и fingerprints применённых методов |
| `layer_state`, `coverage` | Состояние нужных слоёв; известные indexed/processed/failed counts, denominator и метод подсчёта |
| `requested`, `applied`, `clamped` | Запрошенные/применённые параметры и изменения пределов |
| `items` | Специфичные операции отношения/пути/узлы/пакеты/группы |
| `sources`, `assertions`, `evidence` | Нормализованные справочники только использованных и разрешённых объектов |
| `truncated`, `limit_reasons`, `next_cursor` | Усечение, причины и продолжение, только если оно действительно доступно |
| `warnings`, `method`, `timings` | Ограничения вывода, использованный метод/модели и время стадий |

`coverage` сообщает обработку корпуса, а не вероятность полноты ответа. Если denominator неизвестен — `null` и причина, а не фиктивные 100%. Размер ответа учитывает envelope и справочники; evidence не отрезается так, чтобы результат продолжал считаться полным. Cursor продолжает выдачу, но не выдаёт себя за способ обойти исчерпанный time/visit budget: причина частичности сохраняется.

`Evidence`: ref документа/ревизия, path, source ranges, quote или разрешимая ссылка на диапазон, source hash, extraction method/version. Текст может быть прочитан отдельно, но ссылка должна разрешаться в исходный снимок либо честно возвращать stale. Документированный факт, модельный кандидат и статус ручной проверки — разные поля.

## Ответ графа для агента — текст, предел, пустые ответы

Статус: проект 28-10-2026, принят автором по OQ-219: пакет предложений [исследования формата ответов](../../knowledge/graph-answer-format.md) и таймаут MCP 5000 мс; форму входа по пути документа автор поручил проектировать агенту. Схемы операций реализованы (4.3.3), текстовый рендер — 4.3.4 (ISS-22); формы входа и диагностика реализованы в 4.3.5; качество оснований и отбора остаётся в шагах 4.3.6–4.3.9. Текстовый вид — `format=txt`; в DTO v1 добавлены входы документов и публичные пространства имён без изменения ObjectRef. Канал `structuredContent` с `outputSchema` не вводится: клиент агента читает текст.

Один текст на все клиенты: его собирают функции `bars-protocol`, общие у MCP и CLI; окно «Со связями» показывает те же факты списком (4.3.4). Служебные подписи блоков — на английском, содержимое и подсказки воркера — на языке пользователя (правило языка в `AGENTS.md`).

Реализация 4.3.4: внутренний IPC-признак `text` у `graph_query` и `graph_search` выбирает текстовый предел; при отсутствии признака действует прежний JSON-контракт. Рендер индексирует узлы, основания и источники один раз на ответ. Воркер применяет результат отбора целых элементов до возвращения ответа и пересчитывает курсор с учётом реально показанных элементов. `context` ограничивается целыми фрагментами внутри ролей; `paths` и `impact` — целыми путями без обещания продолжения, которого операция не поддерживает. Основные блоки `RESULT` в mix сохраняются; при нехватке места показываются целые блоки с явным советом сузить поиск. Входы документов и диагностика ошибок реализованы в 4.3.5; качество отбора проверяется отдельно.

Проверка рендера 4.3.4 от 01-11-2026: 11 целевых Rust-регрессий рендера, 4 теста списка окна, Svelte и production-сборка UI прошли; независимое ревью sol после исправлений не оставило замечаний к логике, производительности и сложности. Полный `scripts/check.ps1` не зелёный: fmt/clippy прошли, сборка не увидела новые API зависимостей при наличии их в исходниках. Native-проба не выполнена, установленная сборка не обновлялась. Автор прямо разрешил закрыть 4.3.4 и отправить `main` с этими ограничениями. Это подтверждение прежнего среза, не проверка входов 4.3.5 в `e633ba4`: для него нет финального прогона, независимого ревью и измерений производительности.

### Устройство текстового ответа графа

```text
=== GRAPH relations ===
resolved: «bars_text_search» (entity)
1. bars_text_search —implements→ Т-37 [positive]
   features/agent-tools/mcp-tools.md:35-37 «Основа — общий поиск «В тексте»…»
2. …
state: semantic layer partial (566 of 1766 files)
next: for an exact phrase use bars_text_search
=== END GRAPH ===
```

Порядок частей фиксирован; любая, кроме заголовка и конца, может отсутствовать:

| Часть | Когда печатается |
|---|---|
| `=== GRAPH <operation> ===` и `=== END GRAPH ===` | Всегда |
| `resolved:` | Вход был именем или путём: что именно разрешено |
| Факты | Нумерованные строки, основание под каждой |
| `state:` | Только событие: слой `partial`/`stale`, недостающие роли, срыв по времени, откат mix к hybrid |
| `truncated:` | Только при усечении |
| `next:` | Пустой ответ, усечение, неоднозначное имя, ошибка |

Постоянной оговорки «смысловой слой неполон» нет: она не сообщает нового. Предупреждения воркера — обычным предложением, без отладочного вида Rust (`Some(ComparisonLimit)`). В тексте нет 64-значных хешей, кроме готового ObjectRef корня или кандидата для повторного вызова; `null`, пустых полей и эха запроса нет.

### Строка факта и основание в тексте графа

Факт — одна строка: `<N>. <субъект> —<предикат>→ <объект>`; после неё в скобках только то, что отличает факт от обычного: `[negative]`, `[if: «условие»]`, `[platform=windows]`, `[kind=precondition]`. Узел-документ печатается путём от корня документации, раздел — `путь › заголовок`, сущность — подписью. Основание — строка под фактом с отступом: `путь:строки «цитата»`; до трёх оснований на факт, остальные — «+N ещё».

- **Цитата.** До 300 знаков, обрезка по границе предложения с `…`; полный фрагмент читается `bars_read` по `путь:строки`.
- **Структурный и производный переход.** Ссылка, содержание и близость отмечены классом: `[structural]`, `[similarity 0.81]`; цитаты у них нет, вместо неё — место ссылки `путь:строка`. Они не выдаются за смысловую зависимость.
- **Один раз.** Вложенные и совпадающие диапазоны одного документа склеиваются в один; цитата не повторяется в нескольких ролях или у нескольких фактов — остальные места ссылаются на первое номером факта.

### Текст каждой операции графа

| Операция | Что печатается | Единица усечения |
|---|---|---|
| `relations` | Разрешённые участники, затем факты «субъект — предикат → объект» с основанием; при неоднозначном имени — кандидаты без отношений | Факт с основанием |
| `paths` | Путь за путём: `path 1 (3 hops, semantic)`, цепочка узлов, затем шаги по строке с основанием каждого смыслового шага; кратчайший путь не назван причиной | Путь целиком |
| `impact` | Группы `direct` и `indirect`: документ, роль (описание, решение, проверка), через какой объект и основание; `related_links` — ссылки и упоминания отдельно, подписано «не зависимость» | Документ с основаниями |
| `context` | Группы по ролям; в группе — фрагменты `путь:строки «цитата»`, объединённые по документу; фрагмент в нескольких ролях печатается один раз, остальные роли — `also: decision`; недостающие роли — в `state:` | Фрагмент |
| `explore` | `topics`: тема с именем, числом документов и представителями со строками (`name from heading of <путь>`); `connectivity`: изоляты, узлы-хабы, битые ссылки списком путей; `coverage`: объекты без роли и где искали; `conflict_candidates`: пара утверждений с цитатами и условиями, подпись «кандидат, не вердикт» | Тема, пара |
| `graph` | Счётчики и рёбра `<от> —<предикат>→ <к> (<origin>)` без повторов; узлы названы путями от корня документации и подписями; группы со счётчиком участников | Ребро |
| `bars_rag_search` с `mode=mix` | Прежние блоки `RESULT`, затем `=== RELATED ===`: факты и пути связанных источников с причиной включения `why: query\|root\|path` | Связанный пакет |

Неизвестный тип элемента печатается строкой `item <тип>: <подпись>` с основаниями, а не JSON. Приёмка: на каждом типе из `relation`, `path`, `role_group`, `topic`, `audit`, кандидатов имён текст сохраняет все источники, которые есть в JSON того же ответа.

### Эхо параметров в тексте графа

Печатается только то, что отличается от умолчания или изменено сервером, строкой `applied:` внутри `state:` — например `applied: timeout_ms=5000 (requested 20000, clamped)`, `scope: modules=[features]`, `fallback: mix→hybrid, related_budget too small`. Параметры со значением по умолчанию не печатаются; `requested` не повторяется, если равен `applied`.

### Предел текста графа и продолжение

- **Предел.** 16 000 знаков на ответ (около 5 тыс. токенов по `estimate-v1` для английского, больше для русского), вместе с заголовком и концом. Он ниже порога предупреждения Claude Code (10 тыс. токенов) и действует только на `txt`; JSON ограничен `max_bytes` операции, как сейчас.
- **Непомещающийся первый элемент.** Сокращаются только цитаты (`quote_truncated`), шаги и пути источников сохраняются. Если одна обязательная структура с источниками сама больше предела, вызов даёт явный `invalid_params` с предложением сузить область или выбрать JSON; скрытый хвост не считается показанным, курсор для него не выдаётся.
- **Усечение целыми единицами.** Обрезку по таблице выше выполняет воркер до рендера, поэтому `next_cursor` указывает на первую непоказанную единицу и в `limit_reasons` появляется `text_limit`. Единица не режется: факт идёт вместе с основаниями. Первая единица показывается всегда; если она одна больше предела, цитаты в ней укорачиваются с пометкой `quote truncated`.
- **Строка усечения.** `truncated: shown 12 of 40 facts, 28 hidden; continue: cursor="…"`. Для `paths` и `context`, у которых нет продолжения, вместо `continue:` — `narrow:` с советом: сузить `modules`/`files`, добавить `predicates` или `roles`, уменьшить `limit`. Без этой строки агент принимает неполный список за полный (находка прогона 4.3.1, задача T08).
- **Порядок единиц** детерминирован и совпадает в тексте и JSON: сначала сильнее совпадение с запросом или ближе к корню, при равенстве — путь документа.

### Пустой ответ, ошибка и следующий шаг графа

Пустой ответ и ошибка называют причину и одно следующее действие строкой `next:`; пустота никогда не печатается как «No results.» без причины. Таблица задаёт целевой состав диагностики; фактические ограничения исходников перечислены после неё.

| Случай | Что печатается в `state:` и `next:` |
|---|---|
| `impact` без зависимостей | Сколько документов и строк покрыто смысловым слоем; отсутствие зависимости не доказано; `next:` — `bars_links` входящие ссылки документа и `bars_rag_search` по названию |
| `relations`, `explore`, `context` без результата | Область и покрытие слоя; `next:` — `bars_rag_search` по тому же вопросу или `bars_text_search` по точной фразе |
| Срыв по времени | Сколько мс ушло, что успело найтись, какие роли пусты; `next:` — сузить область или роли; увеличить `timeout_ms` можно до 5000 |
| `graph_not_ready` | Граф строится сам после обновления индекса; явно — из окна или `bars-cli graph build`; `bars_reindex` не поможет; `next:` — `bars_rag_search` без `mode` |
| `graph_capability_unavailable` | Какая возможность недоступна, что поддержано |
| Нет `documents` и `roots` | Одна из форм входа обязательна; пример `documents:["features/search/hybrid-search.md"]` |
| Неизвестный путь документа | `invalid_params`, до пяти ближайших путей; путь печатается так же, как в остальных ответах ([пути, 4.2.2](../agent-tools/mcp-tools.md)) |
| `stale_ref`, `snapshot_expired`, `cursor_mismatch` | Что потеряно и что повторить: заново вызвать операцию без `cursor` |

Ошибка остаётся ответом инструмента с признаком ошибки и текстом `Ошибка bars (<kind>): …`; `next:` добавляется второй строкой.

Фактическая детализация `e633ba4` по статическому чтению: пустой результат показывает покрытие по документам; число покрытых смысловых строк не рассчитывается. Успешный частичный ответ, остановленный по `timeout_ms`, содержит `elapsed_ms`, найденные элементы и недостающие роли. Ранний `graph_timeout`, когда ответ ещё не собран, содержит причину и совет сузить область, но не эту статистику. Полный состав таблицы и паритет каналов не подтверждены исполнением.

### Кандидаты имён в графе

При `resolution=ambiguous` или `not_found` ответ печатает до пяти кандидатов с подписью, видом и числом документов. Реализация 4.3.5 даёт готовый ObjectRef: у `paths` — `from:{kind,id,revision}` или `to:{kind,id,revision}`, у `relations` — `entity_ref:{kind,id,revision}`; значения берутся из ответа без изменений. Для `not_found` кандидаты ищутся по подстроке и префиксу; подходящих подписей может не быть. `next:` предлагает `bars_text_search` по точной фразе. Ссылка ObjectRef в тексте не печатается, кроме корней и кандидатов. Публичный `namespace` локального объекта — путь от корня документации, общих сущностей — `requirement` или `technical`; внутренний префикс проекта `//?/C:/…` не выводится (ISS-34). Конец `paths` принимает и `{"document":"<путь>"}`.

### Вход по пути документа у графовых операций

Реализовано по поручению автора (OQ-219): `bars_impact`, `bars_context` и `bars_graph` (локальный) принимают необязательное поле `documents: string[]` — пути документов, до 20. CLI принимает повторяемый `--document` либо то же поле в JSON `--input`.

- **Разбор** по двум корням, как у `bars_read`: от корня документации, затем от корня проекта; допустимы `./x.md` и абсолютный путь в сохранённом написании проекта. Реализация лексически нормализует разделители, `.` и `..`, на Windows — регистр; сравнивает только известные источники выбранной области, не читает файл и не разрешает файловые алиасы на диске. Не `.md`, неизвестный или исключённый областью документ — `invalid_params`.
- **Корни** — объединение `documents` и `roots`; хотя бы один нужен у `impact` и локального `graph`, у `context` корни необязательны. Документ-корень приводит свои разделы и чанки. `impact` дополнительно начинает обход от уже извлечённых сущностей документа: новые сущности при чтении не извлекаются. Окрестность `context` идёт по структурным и положительным смысловым связям, с общими пределами времени, глубины, узлов и рёбер; similarity не превращается в зависимость.
- **Ревизия** документа берётся из доступного снимка графа; `context` дополнительно отбрасывает источники, не подтверждённые текущим индексом. Ссылка `ObjectRef`, не совпадающая с ревизией объекта в разрешённом снимке, даёт `stale_ref` и не заменяется похожей. Чтение совместимого прежнего снимка сохраняет признаки устаревания; вход по пути не перечитывает Markdown с диска.
- **Пустой результат** при заданных `documents` печатает, что документ найден и какие слои его покрывают.

Гранулярность `context` в исходниках: перед модельным top-K выбираются документы окрестности (`context_source_files`); окончательный отбор evidence ограничен её узлами. Это не доказательство полноты ранжирования внутри отдельного раздела или чанка того же документа: такой случай и качество ролей остаются в 4.3.7. Поле `documents` не меняет схему запросов окна автоматически: окно продолжает передавать подграф как `scope.files`.

### Время выполнения графовых операций в MCP

Умолчание `timeout_ms` у MCP — 5000, и это же максимум воркера (OQ-219): раньше 1000 мс обрывали `context` с шестью пустыми ролями (ISS-24). Значение воркера по умолчанию для CLI и окна не меняется. Прижатое значение отмечается `clamped`. После загрузки набора ограниченный обход может вернуть частичный ответ с найденным и `timeout_ms`; если дедлайн истёк до сборки ответа, возвращается ошибка `graph_timeout`, а не успешная пустота.

### Схема параметров у каждой графовой операции

У каждой из шести операций MCP своя плоская схема с общими `project`, `format`, `modules`, `files`, `timeout_ms` и полями операции; чужих и неподдержанных полей нет (ISS-23). Остальные `budgets` MCP не принимает: умолчания операций из [правил реализации](implementation.md#пределы-выполнения) действуют всегда; CLI и DTO принимают их, как раньше.

| Операция | Собственные поля |
|---|---|
| `bars_relations` | `query` или `entity_ref`, `predicates`, `direction`, `polarity`, `qualifiers`, `limit`, `cursor` |
| `bars_paths` | `from`, `to`, `path_kind`, `max_hops`, `max_paths`, `predicates` |
| `bars_impact` | `documents`, `roots`, `predicates`, `max_depth`, `limit`, `cursor` |
| `bars_context` | `query`, `task_profile`, `roles`, `documents`, `roots`, `token_budget` |
| `bars_explore` | `topic` или `whole_scope`, `analysis`, `grouping`, `limit`, `cursor` |
| `bars_graph` | `view`, `local`, `roots`, `documents`, `predicates`, `direction`, `max_depth`, `include_paths`, `limit`, `cursor` |

Реализовано 28-10-2026 (4.3.3): шесть структур аргументов в `bars-mcp` с этими полями, кроме `documents`, `timeout_ms` у всех — 5000 по умолчанию; поле другой операции отклоняется ошибкой разбора. `documents` у `impact`, `context` и локального `graph`, а также `context.roots` добавлены в 4.3.5.

Поле входит в схему, когда оно работает: `change_description` — после его реализации; `include_related` и `graph.include_unresolved` — после реализации по таблице решений выше; `tokenizer_id` из схемы убран (единственное значение — `estimate-v1`, ответ его называет). Описание операции начинается с задачи, для которой её звать; описание поля — одна фраза про действие. Список шести схем — не больше 14 КБ (измерено 4.3.1: 14 199 байт у чернового набора; реализация 4.3.3 — 14 201 байт). Размер держат так: из схем `schemars` убраны `default`, `uint32`, `minimum: 0` и nullable-типы, а `format`, `predicates` и `ObjectRef` описаны в самих полях без общих определений с описаниями вариантов; новое поле или длинное описание проверяет тест списка инструментов.

### Проверки контракта ответа графа

- Размер: ответ не больше 16 000 знаков; нет 64-значных хешей, кроме ObjectRef корней и кандидатов, и `null`.
- Полнота: на каждом типе элемента текст содержит все источники JSON; усечённый ответ несёт `truncated:`.
- Пустота: каждый случай таблицы пустых ответов печатает `next:`.
- Паритет: тот же вопрос через MCP и CLI даёт одинаковый текст (4.3.10).
- Список инструментов: тест на размер и отсутствие чужих полей.

## bars_relations — утверждения и карточка связей

**Назначение:** S2/S4/S5; вход в граф для остальных инструментов.

Варианты входа: ровно один из `query: string` или `entity_ref: ObjectRef`. Необязательны `predicates: string[]`, `direction: incoming|outgoing|both`, `polarity: positive|negative|any`, `qualifiers`, общие scope/budgets/limit. `qualifiers` фильтруют выбранную схему платформ/версий/условий; отсутствие квалификатора не означает совпадение с любой конкретной платформой.

Результат: разрешённые участники и aliases, assertion refs, subject/predicate/object, направление, polarity/qualifiers, происхождение/статус, evidence refs, ранг совпадения с query и `score_kind`. Вход по ID не требует нового entity-extraction; поиск естественной формулировки использует индекс отношений/алиасов и выбранную query-модель.

При неоднозначном имени — `resolution=ambiguous` и кандидаты без отношений произвольно выбранного объекта. При отсутствии matching relations — успешный пустой список с scope/coverage. При устаревшем entity_ref — `stale_ref`, не подбор похожего объекта.

## Основания переходов — срез 4.3.6

Проект реализации 02-11-2026 по P5 и GR-02/GR-07/GR-09: каждый шаг `paths` и `impact` сохраняет исходное утверждение, направление обхода, polarity, все qualifiers и основания именно этого ребра. Цитата соседнего факта, даже на той же строке, не заменяет основание перехода. В текстовом ответе каждый шаг содержит собственные ссылки на исходные диапазоны; в окне влияние раскрывается по шагам с открытием каждого основания. Число цитат в тексте ограничено, остальные основания остаются ссылками на строки; путь сокращается только целиком.

`paths` по умолчанию исключает отрицательные смысловые рёбра; явный фильтр `polarity=negative` в DTO/CLI позволяет исследовать отрицания, но не превращает их в зависимости. `impact` всегда идёт против направления только положительных предикатов влияния. `structural` использует структурные рёбра; производная близость доступна лишь в `mixed` с собственным происхождением. Квалификаторы сохраняются по отдельным шагам: наличие пути не означает совместимость всех условий или причинное объяснение.

Обход использует индекс смежности, учитывает проверку предельной глубины в общем бюджете и ограничивает очередь числом посещений. Несколько корней `impact` делят один предел путей. Справочники ответа собираются по индексу ID рёбер; область и ревизии отсекают недоступные основания до обхода. Если одно основание исключено, другое допустимое основание того же утверждения сохраняется. Приёмка извлечения на реальном корпусе, `change_description` и общий состав P5 остаются отдельными открытыми работами.

## bars_paths — пути между объектами

**Назначение:** S2/S7 и объяснение результата S1/S3.

Обязательны `from`, `to`: ObjectRef либо `{label, kind?}`. Необязательны `predicates`, `path_kind: semantic|structural|mixed`, `max_hops`, `max_paths`, qualifiers и общие ограничения. Исходный проектируемый профиль — semantic; смешанный путь выбирается явно и сохраняет типы каждого перехода.

Результат каждого пути: ordered node refs, ordered assertion/edge refs, направление traversal и исходное направление предиката, evidence каждого смыслового ребра, условия, rank/score_kind, `complete`, причина ограничения. Кратчайший путь не подписывается причинным объяснением автоматически.

Для двух неоднозначных концов возвращаются кандидаты обеих сторон без комбинаторного угадывания. Пустой набор путей несёт searched scope/depth/budgets. Временной предел — partial с причиной; недоступный semantic layer — ошибка, не ответ «связи нет». Циклы не приводят к бесконечному обходу или перечислению всех простых путей.

## bars_impact — влияние изменения

**Назначение:** S1 и предметный обход для S8.

Обязателен хотя бы один корень: непустой `roots: ObjectRef[]` и/или `documents: string[]` — пути документов ([вход по пути](#вход-по-пути-документа-у-графовых-операций)). Необязательны профиль predicates/qualifiers, глубина и `change_description`. Описание изменения — необязательное уточнение отбора, не разрешение изменить документацию. Без него возвращаются документированные зависимости от roots.

Результат: affected object refs, роль описания/решения/проверки, direct/indirect, обосновывающие path refs, условия и причина включения. Для `A depends_on B` изменение B ведёт к A; направление проверяется отдельно для каждого предиката. Упоминания/обычные ссылки возвращаются в `related_links`, не как доказанная зависимость.

Вход v1: документ в `roots` или `documents` расширяется до его исходных объектов и уже извлечённых сущностей. Обход идёт только по положительным предикатам влияния; отсутствие извлечённой связи сохраняет пустой результат с покрытием и советом проверить входящие ссылки и поиск. Окно также может передать сущности документа корнями.

Если change_description реально использовалось модельным фильтром — ответ показывает этот метод; если не поддержано выбранным режимом, вход отклоняется с понятной причиной, а не игнорируется. Формулировки результата — «проверить описание», не «код сломан».

## bars_context — контекст задачи по ролям

**Назначение:** S3/S4/S7; использует связи S1/S2/S5.

Обязателен `query`. Необязательны `task_profile`, `roles`, `documents`, `roots`, `token_budget`, `tokenizer_id`, `include_related`, scope и graph budgets; MCP принимает подмножество — [схема у каждой операции](#схема-параметров-у-каждой-графовой-операции). Схема ролей первоначально: requirement/decision/behavior/architecture/constraint/verification; конкретный профиль выбирает подмножество.

Результат — `role_groups`, source refs, spans, связь с query/root/path, `missing_roles`, `used_budget`, `budget_mode=exact|estimated`, tokenizer и ограничения. Роль с неизвестным основанием классификации не заполняется уверенным выдуманным статусом. Один фрагмент может покрыть несколько ролей без многократного списания токенов текста.

При малом бюджете возвращается меньший комплект с перечислением непокрытого; нельзя обрезать текст посреди необходимой оговорки и сохранить вывод как полный. Бюджет всего ответа включает метаданные и нормализованные справочники. Пакет — первоисточники и структурные метки, не сгенерированный ответ на задачу.

## bars_explore — обзор темы и аудит

**Назначение:** S5/S6/S8.

Вход: `topic` либо явный `whole_scope=true`; `analysis=topics|connectivity|coverage|conflict_candidates`, detail level, roles/predicates для выбранного анализа, общие budgets. `topic` и whole_scope одновременно не задаются. Ни один режим не запускает скрытое обогащение.

| analysis | Результат | Условие доступности |
|---|---|---|
| `topics` | Группы, представители, межгрупповые связи, coverage и продолжение | Готовая группировка выбранной области; текстовое имя группы имеет происхождение |
| `connectivity` | Изоляты, хабы, unresolved/broken links, orphan source refs | Структурный слой; неизолированность через Index отдельно от смысловых связей |
| `coverage` | Объекты без найденной роли/отношения, пути и область поиска | Достаточное покрытие соответствующего смыслового слоя либо явная partial |
| `conflict_candidates` | Пары несовместимых утверждений и evidence с условиями/статусами | Поддерживаемая семантика qualifiers/polarity; кандидат, не автоматический вердикт |

Группировка по источникам одного seed не называется обзором всего проекта. При фильтрации корпуса summaries/communities из исключённых источников не используются скрыто. Неполный extraction не даёт заключения об отсутствии проверки или противоречий.

## bars_graph — общий и локальный подграф

**Назначение:** данные графического просмотра и структурное представление результатов всех S1–S8.

Вход: `view=documents|sections|chunks|entities|mixed`, `roots?`, `local: boolean`, `depth`, `edge_types`, direction, `grouping=document|community|none`, `include_unresolved`, scope/budgets/cursor. Local требует root; depth=0 показывает сами roots. Общий граф без roots не превращается в неограниченную выгрузку.

Результат: node refs с kind/label/group refs; edges с типом/направлением/происхождением, counts и evidence refs; group members или возможность раскрытия; truncated и известные totals. В documents view агрегируются только выбранные типы; число рёбер и число evidence раздельны. Скрытый endpoint не раскрывается подписью/counter через фильтр.

Layout выполняет клиент над разрешённым результатом и не влияет на ранги поиска. Сохранённая камера/пины — пользовательское состояние, не смысловые данные. При раскрытии нужен тот же snapshot; после смены поколения клиент запрашивает новый согласованный срез.

## Расширение bars_rag_search

Новый необязательный `retrieval=hybrid|mix|graph`, исходное умолчание hybrid. Для mix: `include_related`, `related_budget` и общие graph budgets; существующие поля min_score/candidates/limit сохраняют смысл основного канала. Graph использует режим результата relations/paths; клиентам нужно знать новый DTO, а не ожидать прежний список чанков.

| Канал ответа | Состав |
|---|---|
| `results` | Основные текстовые совпадения с действующей шкалой и порогом |
| `related` | Связанные evidence bundles, пути и причины включения с собственным бюджетом; не выдаются за прошедшие старый min_score |
| `graph_results` | Для graph: отношения/пути и нормализованные источники |
| `retrieval_status` | Requested/applied mode, layer state, fallback reason, поколения, coverage и усечение |

Прежний вызов без новых параметров сохраняет прежнюю форму и семантику результата. Новая расширенная форма включается явным новым режимом; совместимость старых клиентов проверяется. Это действующий публичный MCP/CLI-контракт, поэтому переход должен быть спроектирован, а не случайно обеспечен тестами.

Отключённый/неготовый graph layer: mix → hybrid с явной причиной; graph → `graph_not_ready`. Отсутствующий нужный отдельный capability, например communities для topics, — `graph_capability_unavailable`, не пустая успешная выдача. Источник связан по структуре — отдельный reason от смыслового пути.

## Расширение статуса и явное управление заданиями

`bars_status` получает graph-секцию: enabled layers, states, поколения/fingerprints, counts/coverage, активное задание, progress и ошибки файлов. Старые поля статуса не меняют смысл. Подробные ошибки не требуют полного текста документа в логах.

Реализовано 23-10-2026 (4.1.3): `graph.progress` — `phase` (`structure`, `similarity`, `publish`), `processed`, `total` (`null`, если неизвестен) и `elapsed_ms`. В structure счётчик относится к файлам, в similarity — к законченным строкам kNN. `graph.file_errors` — до 100 записей `{path, code, message}` и общий счётчик `file_errors_total`. Сообщение не содержит текста документа, только путь от корня документации, код (`unreadable`, `invalid_utf8`, `too_large`) и короткую причину. Файл с ошибкой исключается из графа и попадает в `coverage.failed` выбранной области; построение остальных продолжается, слой при этом `partial`. Ошибка целостности разбора или смена ревизии прерывает публикацию целиком. Старый согласованный набор сохраняется, пока новый не опубликован целиком.

Для записи реализованы общие worker-операции `GraphBuild` (target, layer) и `GraphCancel` (target, job_id): ответ — job ID/accepted либо ошибка. Область построения — проект; `mode` и пользовательский extractor/config fingerprint не задаются, работает текущий локальный метод. Accepted означает постановку задания, не готовность графа. Завершение/ошибка/отмена видны в статусе; продолжение — явный build.

Доступ записи — явные действия окна и CLI `graph build/cancel`; расширение write-инструментов MCP не входит в первоначальные шесть операций. Существующий `bars_reindex` не получает тайного значения «скачать extractor и построить граф». Перестройка embeddings и её согласие по Т-25 независимы.

## Ошибки и ограниченные результаты

Имена ниже — проект новых ошибок; существующие проектные/модельные ошибки сохраняются по текущему протоколу.

| Состояние | Ответ |
|---|---|
| Неверный аргумент/область | `invalid_params` с указанием поля |
| Нужный слой ещё не построен | `graph_not_ready` и layer state |
| Метод выбранного слоя недоступен | `graph_capability_unavailable` и требуемая capability |
| Ref больше не соответствует исходнику | `stale_ref`, без подмены похожим объектом |
| Снимок/курсор потерян | `snapshot_expired` / `cursor_mismatch`; требуется новый запрос |
| Имя неоднозначно | Нормальный resolution result с кандидатами, без произвольного обхода |
| Нет результата в области/пределах | Успешный пустой список, scope/coverage/limits |
| Достигнут лимит при наличии результатов | Partial, причины, только валидные evidence bundles |
| Отмена / ошибка исполнения | Явное cancelled/error, не «совпадений нет» |

## Соответствие CLI и окна

| MCP | CLI, проект синтаксиса | Действие окна |
|---|---|---|
| `bars_relations` | `relations` | Связи/карточка объекта |
| `bars_paths` | `paths` | Две вершины → путь |
| `bars_impact` | `impact` | Влияние изменения |
| `bars_context` | `context` | Собрать контекст с бюджетом |
| `bars_explore` | `explore` | Обзор темы / аудит |
| `bars_graph` | `graph show` | Общий/локальный граф и раскрытие |

CLI предлагает JSON с тем же DTO и текстовое представление без потери признаков partial/coverage. Точный набор флагов фиксируется вместе с схемой DTO до клиентской реализации. Выбранный подграф можно экспортировать в JSON; дополнительные форматы не обязательны для GR-01…GR-12.
