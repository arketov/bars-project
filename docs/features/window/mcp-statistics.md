# Статистика вызовов MCP

Статус: реализовано в рабочей копии; проверены хранилище, настоящий IPC/MCP и окно на фикстурах. Установленное приложение не обновлялось. Связанные требования: Т-19, Т-20, НФТ-4. Источник потребности — [IDEA-05](../../backlog/ideas.md).

Открыто замечание автора 18-10-2026: ISS-14 — неудовлетворительный дизайн и невозможность анализа отдельных вызовов. Разделы до «Контракт этапа 26» описывают текущую агрегатную реализацию. Функциональный контракт отдельных вызовов спроектирован 18-10-2026; [доработка данных и UX/UI](refinement-plan.md) ещё не реализована. OQ-89: автор установил максимум 7 дней подробной истории; остальные ограничения ниже — инженерные решения.

## Границы учёта MCP

Решение агента: сессия — одно соединение `bars-mcp` с воркером, а не чат клиента. Хук не передаёт идентификатор чата в MCP; связывать их по cwd нельзя при параллельных чатах. Переподключение начинает новую сессию; повтор после обрыва считается отдельной попыткой. Идентификатор включает время, PID воркера и счётчик соединений.

Учитываются шесть инструментов, дошедших до обработчика воркера: поиск, чтение, структура, проекты, состояние и переиндексация. Ошибки выполнения учитываются, ошибки разбора/допуска IPC и недоступный воркер — нет. `hello`, список инструментов MCP, CLI, хук, окно и фоновая индексация не учитываются. Успех означает успешный ответ инструмента: запуск индексации не означает успешного завершения индексации. Время — выполнение обработчика без IPC и записи статистики; первая/последняя отметки — время завершения вызовов.

Проект — зарегистрированный корень, разрешённый тем же способом, что у вызова. Ошибка разрешения и общий список проектов относятся к «Без проекта». Не сохраняются запросы, аргументы, содержимое документов и тексты ошибок.

## Хранение статистики MCP

Решение агента: `~/.bars/mcp-statistics.sqlite3`, отдельно от индексов и логов. SQLite из существующего стека, без нового пакета. Агрегаты по UTC-дню, сессии, проекту и инструменту: число вызовов, ошибок, суммарное время в миллисекундах, первый/последний вызов. Хранятся текущий и 29 предыдущих UTC-дней; максимум 100 000 агрегатов, старейшие удаляются. Очистка при записи и чтении; без обращений файл сам не изменяется. Это ограниченное окно наблюдений, не пожизненные итоги.

Запись после выполнения в blocking-задаче; сбой статистики не меняет ответ инструмента. В логе — предупреждение без аргументов. Чтение через отдельную команду окна, без нового MCP-инструмента; ошибка чтения отображается явно. `BARS_USER_HOME` изолирует файл вместе с остальными данными.

## Контракт этапа 26: анализ отдельного MCP-вызова

Потребность автора, ISS-14: установить «что вызвано, с чем, чем закончилось, сколько вернулось». Основная сущность нового экрана — отдельная попытка вызова, агрегаты — её сводка. Функциональный путь: период/проект → сессия/инструмент/исход → вызов → запрошенные и применённые значения → краткий итог либо ошибка. Сессия остаётся соединением MCP с worker, не чатом пользователя.

| Данные попытки | Обязательный смысл |
|---|---|
| ID / версия записи | Уникальный ID попытки и версия; повтор после обрыва — другой ID. Терминальная запись не перезаписывается повтором |
| Контекст | Имя инструмента, сессия, эпоха worker; запрошенный проект и канонически разрешённый проект/имя на момент вызова. Нет разрешённого проекта — отдельное «Без проекта» |
| Время | UTC-начало/конец; длительность по монотонным часам в миллисекундах, не разность настенных часов. В окне — местная дата/время |
| Вход | Разрешённые поля исходного MCP-запроса до подстановки умолчаний прокси; пропущенное, `null`, пустое и явное значение различимы |
| Применено | Реальные значения после разрешения проекта, настроек, ограничений и fallback; источник значения: явно / умолчание / ограничено. Не вычислять заново по нынешним настройкам |
| Исход | Выполняется, успех, ошибка, неизвестно. Дополнительно: пустой результат, предупреждение/fallback, постановка в очередь. Эти признаки не подменяют исход |
| Результат | Количество + единица либо «не применяется» / «неизвестно»; безопасный краткий итог без полного ответа |
| Ошибка | Стабильный код и безопасное объяснение из каталога; этап отказа. Сырой текст провайдера, стек, токены и произвольный payload не сохраняются |
| Полнота | Версия контракта, скрытые/усечённые поля, разрыв записи, отсутствие применённых значений до выполнения |

Изменение только `format` не меняет число фрагментов/строк/заголовков. Формат ответа — поле прокси, которого нет в текущем worker `Call`: этап 29 должен передать разрешённый контекст исходного MCP-вызова во внутреннем протоколе. Копирование сериализованного `Call` после подстановки значений не даст достоверного исходного входа.

## Контракт этапа 26: матрица шести MCP-инструментов

Общие поля всех инструментов: исходный `format`, фактически выбранный `txt/json`; для инструментов с целью — исходный `project`, использованный `cwd` и разрешённый проект. Для `bars_projects` проект неприменим. Список ниже — allowlist, произвольные дополнительные ключи не записываются. Поля текста/пути ограничиваются по правилам хранения; секреты и содержимое результатов не входят в allowlist.

| Инструмент | Запрошено | Применено / краткий итог | Единица результата и критерий проверки |
|---|---|---|---|
| `bars_rag_search` | `query`, `modules`, `files`, `limit`, `candidates`, `min_score` | Разрешённые область и модели; `applied.results` (верхняя граница K), `candidates`, `rerank_candidates`, `min_score`, `score_kind`, `clamped`; rerank запрошен/фактически выполнен, безопасная причина fallback, `indexing/pending` | `results.len()` **фрагментов**, не K и не документов. При K15 и 3 hits показать 3; при 0 — успешный пустой ответ |
| `bars_read` | `path` | Фактически разрешённый путь документа; диапазон — весь документ. Никакого придуманного параметра раздела/строк у `read` нет | Число **строк** исходного `ReadOutput.text` по той же функции `number_lines`; пустой файл — 0. Не число символов или чанков |
| `bars_outline` | `path`, `levels`, `under`, `under_line` | Разрешённый путь; выбранные уровни и разрешённый опорный заголовок/строка, если есть. Пустые levels означают все уровни | `headings.len()` **заголовков** после фильтра; 0 — успешный пустой ответ. Недопустимый раздел/аргумент — ошибка |
| `bars_projects` | Только общие поля формата | Снимок числа зарегистрированных проектов | `projects.len()` **проектов**; пустой реестр — успешный ответ 0 |
| `bars_status` | Цель проекта | `state`, `updated_at`, `pending`, `watching`, нужна ли переиндексация; наличие безопасного кода проблемы | Количество **не применяется**. `pending` — отдельное число документов в очереди, не объём ответа; не показывать «1 результат» |
| `bars_reindex` | Цель проекта, `full` | Фактический вид задания и ID операции; `accepted`, объединение с ожидающим заданием. `accept_model_change` от MCP не допускается | Количество **не применяется**; `accepted=true` — «Проверка/переиндексация поставлена в очередь», не завершённая индексация. Т-25 проверяется отдельно |

Если ошибка возникла до выбора настроек/открытия файла, применённые значения и количество — «неизвестно», не нули и не текущие настройки. При успешном поиске с отказом rerank исход — успех с предупреждением, шкала и параметры относятся к фактически выполненному поиску. Оценки и тексты отдельных hits не сохраняются: задача — анализ вызова, а не копия поисковой выдачи.

## Контракт этапа 26: охват, исход и измерение MCP

Инженерное решение: сохраняется нынешняя наблюдаемая граница — шесть типизированных вызовов, допущенных к MCP-обработчику worker. Перед исполнением создаётся запись «Выполняется», после — терминальная. Отказы разрешения проекта и ошибки обработчика входят; проект при неудачном разрешении — «Без проекта» с запрошенной целью. Измеряем время внутри обработчика, включая его ожидание ресурсов и gate, без транспорта, форматирования прокси и записи статистики. Оно не называется полной задержкой клиента.

| Случай | Учёт / исход | Проверка этапа 29 |
|---|---|---|
| Успешный/пустой ответ | Успех, фактическое количество | Ноль отличается от ошибки; неприменимое количество не добавляется к нулевым выдачам |
| Ошибка worker | Ошибка с кодом; количество неизвестно | Сохранён исходный ответ инструмента, безопасное объяснение не копирует upstream payload |
| Обрыв MCP после начала исполнения | Итог worker, если он доступен; доставка клиенту — неизвестна | Не приравнивать успех worker к получению ответа клиентом; повтор создаёт новую попытку |
| Падение/перезапуск worker при незавершённой записи | Неизвестно; конец и полная длительность отсутствуют | Запись предыдущей эпохи не остаётся «Выполняется» навечно и не считается ошибкой/успехом |
| Неверный JSON/MCP-аргумент, отказ допуска/десериализации IPC, недоступный worker | В подробную историю не входят; граница охвата объясняется на экране | Не обещать полноту всех клиентских попыток. `hello`, tools/list, CLI, хук, окно, фоновые задания также исключены |
| Отказ записи начала/конца | Ответ инструмента не меняется; диагностический флаг потери данных | Ошибка учёта видна в экране/логе без аргументов; незаписанный исход не придумывается |

Отказ записи не блокирует инструмент. Предлагается ограниченная очередь записи; её переполнение учитывается как потеря наблюдений, а не молчаливый успех. Живой worker держит счётчик потерь и последнюю безопасную причину вне неисправной БД; после перезапуска зафиксировать точное число утраченных событий невозможно. История прямо обозначает эту границу.

## Контракт этапа 26: хранение аргументов и срок MCP-истории

**Решение автора 18-10-2026, OQ-89:** «Историю храним за 7 дней максимум». Подробная история использует скользящие 7 × 24 часа по UTC-времени начала вызова, включая незавершённые записи. На чтении записи старше cutoff не выдаются, даже если физическая очистка ещё не прошла. Очистка при старте worker, чтении/записи и не реже одного раза в час; при выключенном bars файлы сами не меняются. Политика не обещает очистку внешних резервных копий и гарантированное стирание с накопителя.

Инженерные решения этапа 26, не отдельные слова автора:

- Локально в `~/.bars/mcp-statistics.sqlite3`, под `BARS_USER_HOME` в изолированных проверках. Разрешены полный поисковый запрос и пути из матрицы; никакой произвольной сериализации входа, документов, полных ответов и ключей. Это пользовательские данные, их не дублируют в технический лог.
- Верхние лимиты: 10 000 попыток и 32 МиБ сериализованных данных записей; срабатывает первый из срока/числа/объёма, старейшие вытесняются. 32 МиБ — бюджет данных, не обещание размера SQLite с индексами/WAL; размер файлов отдельно замерить на этапе 29, обеспечить checkpoint и повторное использование освобождённых страниц.
- Одна запись — до 32 КиБ UTF-8; одно строковое поле — до 8 КиБ, массив — до 100 элементов. Усечение только по границе UTF-8, всегда с исходной длиной/числом и явным признаком; числовые параметры, исход, ID и единицы не усекаются. Приоритет бюджета: обязательные метаданные, затем запрос, пути и фильтры. UI не выдаёт усечённый текст за полный вход.
- «Сохранять подробную историю MCP» включено по умолчанию, политика видна на экране. Отключение запрещает новые подробные записи; ранее записанные остаются до очистки/истечения срока. Нетерминальные записи при отключении получают «Сбор прекращён; исход неизвестен», без придуманного времени завершения; их последующие итоги не дописываются. Никакого скрытого накопления аргументов в агрегатах или очереди после отключения. Повторное включение начинает сбор с текущего момента, без восстановления пропущенного.
- «Очистить историю MCP» требует подтверждения области «все проекты и сессии» и удаляет подробности вместе с прежними агрегатами. Активная операция продолжает исполняться, но её очищенная запись не возвращается после завершения: поколение записи отделяет новые вызовы от очищенных. При отказе очистки показана ошибка, данные не объявляются удалёнными.

Миграция на этапе 29: версионировать схему; старые агрегаты не разворачивать в выдуманные вызовы. Сохранить их в отдельном режиме «Агрегаты прежней версии, без подробностей», отсечь до последних 7 дней при первом открытии новой версии; пограничный UTC-день с неизвестным временем отдельных вызовов удалить целиком. Новые сводки строить только по новым попыткам; старые и новые числа не складывать, поскольку возможен перекрывающийся период. Отключение подробной записи не создаёт новые прежние агрегаты. Сбой миграции не меняет ответы инструментов и не уничтожает исходную БД; экран сообщает недоступность истории.

## Контракт этапа 26: сценарии экрана анализа MCP

Новый экран использует одну совокупность фильтров и один снимок данных для сводки/списка. Период фильтруется по началу вызова, интервал `[от, до)`; по умолчанию последние 24 часа, максимум 7 дней. Совместные фильтры: проект, сессия, инструмент, исход. «Без проекта» — отдельный выбор. Смена проекта сохраняет совместимую сессию, несовместимую сбрасывает с объяснением. Старые агрегаты доступны отдельно и не маскируются под подробную историю.

| ID / сценарий | Данные / действие | Ожидаемый результат | Проверка этапов 29–30 |
|---|---|---|---|
| M-01. Найти медленный/ошибочный вызов | Выбрать период, проект, сессию, инструмент, исход; открыть строку | Общие суммы и список по тем же фильтрам; подробности входа/применённых значений/результата | По реальному вызову можно ответить на четыре вопроса автора без чтения JSON |
| M-02. Умолчания и ограничения | Пропустить K, передать чрезмерный C; затем сменить настройки | Видны «умолчание на момент вызова», ограниченное C и фактические значения | Старые подробности не меняются после сохранения новых настроек |
| M-03. Успех 0, ошибка, fallback и reindex | Открыть четыре записи | «0 фрагментов», безопасная ошибка, успех с предупреждением, «В очереди» различимы | Ни пустой успех, ни `accepted` не выглядят ошибкой/готовым индексом |
| M-04. Большая история / параллельные вызовы | Прокрутить страницы, обновить список, открыть ID | Страницы по 50, серверная фильтрация, стабильная сортировка `(started_at, ID)` по убыванию и курсор снимка | Нет загрузки всей истории, дублей/пропусков из-за вставок; выбранная запись не прыгает на чужую |
