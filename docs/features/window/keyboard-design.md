# Сочетания клавиш bars — действия, умолчания и конфликты

Статус на 21-10-2026: реестр, маршрутизатор, список действий, настройки переназначения и профиль воркера реализованы в рабочей копии по Т-45. Программный WebView2: вызов/запись/переназначение, IPC, подсказки, конфликт ревизии, обе темы на 1440/1024/760 px; UI — 224 теста. Доказательства и ограничения (`chats/2026-10-21-keyboard-implementation`). Новые умолчания — инженерный выбор реализации, не отдельное решение автора. Физическая клавиатура, установленная сборка и macOS не приняты; установка отложена OQ-113.

## Основание и границы клавиатуры

Обязательные исходные умолчания — Т-29 и Т-40 из [MAIN_IDEA](../../MAIN_IDEA.md); рамка — Т-43…Т-45 и [решения автора](workspace-decisions.md#сочетания-клавиш). [Исследование docking](../../knowledge/window-docking.md) уже проверило программную навигацию вкладок, но оставило собственный реестр команд и физическую проверку открытыми. Нового выбора библиотеки для клавиатуры не требуется.

Замечание автора о неудобном UX и отставании от референса сохранено в [требованиях окна](requirements.md#задача-пользователя-и-исходное-состояние-окна). Поэтому сочетания должны вызывать те же действия, что меню и кнопки, сохранять область поиска, фокус и документ, работать в обеих рабочих зонах. Текстовые настройки не получают отдельной системы управления. ISS-13…15 из [реестра ошибок](../../backlog/issues.md) остаются открытыми: доступ с клавиатуры к уведомлениям, отдельным вызовам MCP и меню папок нужен, но не заменяет нативную проверку этих функций.

«Глобальный» поиск доступен внутри активного окна bars. Системного перехвата вне bars, фонового открытия приложения и нового global-shortcut plugin нет. Отдельное окно документа использует тот же профиль сочетаний, но собственные активную панель и документ. Поиск в нём открывает тот же пользовательский сценарий для проекта этого окна; не переключает проект основного окна.

## Реестр действий и список команд

Единая запись: `id`, русские название/категория, допустимые виды окна, контекст, `enabled(context)` с причиной недоступности, умолчание для платформы, пользовательское назначение, `execute(context)`. Идентификатор стабилен при переименовании подписи. Кнопки, меню, список команд и клавиатура используют этот реестр; обработчик не имитирует клик по DOM.

`commands.open` открывает компактный список действий над рабочей областью: фильтр по русскому названию и категории, сочетание справа, причина недоступности. Стрелки выбирают строку, Enter выполняет доступную команду; Escape возвращает прежний фокус. Команды без умолчания вызываются из этого списка и допускают назначение в настройках. Текущие значения полей и каждый пункт длинного списка проектов не становятся отдельными командами: клавиатура входит в соответствующий контрол, дальше действуют его штатные клавиши.

Контекст фиксируется при вызове списка/меню: окно, проект, панель, вкладка, целевой документ или узел графа. Фокус фильтра списка не подменяет цель. Перед выполнением контекст проверяется заново; удалённая цель даёт сообщение и не заменяется последней открытой вкладкой. Выбор файла/папки, подтверждение удаления и согласие на переиндексацию сохраняют прежние диалоги и ограничения.

## Штатная навигация контролов

Клавиши контролов не входят в переназначаемую карту приложения. Они работают только внутри своего элемента; команда с модификатором не заменяет обычный Enter/Tab.

| Контрол | Клавиши и поведение |
|---|---|
| Поле запроса | Enter запускает поиск при допустимом запросе; IME сначала завершает композицию |
| Кнопки, чекбоксы, ссылки | Tab/Shift+Tab — фокус; Enter/Space по роли; ссылка активируется Enter |
| Вкладки | Стрелки в tablist, Home/End — первая/последняя; фокус содержимого отдельно через Tab |
| Дерево | Вверх/вниз — видимые строки, вправо — раскрыть/первый ребёнок, влево — свернуть/родитель, Home/End — край; Enter открывает документ, Space меняет галочку области |
| Цель контекстного меню | Shift+F10 / ContextMenu открывает меню у сфокусированного файла, папки, проекта или результата; выбор/галочки не меняются |
| Меню / список команд / выбор документа | Вверх/вниз, Home/End, Enter; вправо/влево для подменю; Escape закрывает верхний слой |
| Структура и список графа | Стрелки/Home/End обходят строки, Enter — переход/инспекция; Space в списке графа меняет явное выделение строки |

Для редактора Tab внутри таблицы сохраняет поведение Т-29; выход из редактора доступен F6/Shift+F6 и переназначаемыми `panel.next`/`panel.previous`. На Mac функциональные клавиши могут требовать Fn в зависимости от настройки клавиатуры. Это показывается в справке, физическая проверка обязательна.

## Приоритеты обработчиков и ввода

Один маршрутизатор на окно. Не несколько независимых `window.keydown` с конкурирующим Escape. Передача контекста явная, через адаптеры Workspace, GlobalSearch, ContextMenu и редактора; Dockview не получает вторую конкурирующую карту клавиш.

1. Системный диалог и ОС владеют своими клавишами. bars не пытается перехватить их.
2. Запись нового назначения в настройках принимает сочетание; остальные команды временно выключены. Escape отменяет запись, Tab переводит фокус на её кнопки; эти клавиши нельзя захватить как назначение.
3. Верхний модальный слой/меню владеет Escape, Tab и навигацией. Открытый диалог подтверждения блокирует команды под ним. В слое поиска допустимы `search.open` (фокус запроса) и `commands.open` (дочерний список с целью внутри поиска). Закрытие дочернего слоя не закрывает родительский.
4. Составной контрол обрабатывает своё поведение: таблица редактора, список подсказок, меню, дерево, вкладки. Уже обработанное событие (`defaultPrevented`) не выполняет команду приложения.
5. Доступное действие активного редактора/графа/документа, затем команда активной группы, затем окна. Сочетания из этих пересекающихся контекстов не допускают неоднозначных назначений.

`isComposing`, события между compositionstart/compositionend, `key=Dead`, `Process`, AltGraph пропускаются без вызова команд и без `preventDefault`. Точное равенство модификаторов: Ctrl+Shift+F не вызывает Ctrl+F. `repeat` не повторяет дискретные операции открытия/закрытия/переноса/удаления; повтор стрелок контролов сохраняется. Отмена стандартного действия только после выбора доступной команды; одно событие — одно выполнение. Нативный accelerator и DOM не вызывают команду дважды.

Обычные поля ввода сохраняют Ctrl/Cmd+A/C/X/V/Z, вставку без форматирования Mod+Shift+V, Redo, навигацию/выделение текста, удаление слов, Home/End. Оконные команды с выделенными умолчаниями (поиск, список команд, открытие документа, настройки, смена группы/вкладки, закрытие) работают и из поля. Пользовательская команда не может занять защищённые текстовые комбинации. В рендере копирование выделенного текста остаётся штатным.

Escape закрывает ровно верхний слой; без слоя не очищает запрос, не закрывает вкладку и не выходит из приложения. Фокус возвращается инициатору; если он исчез — активной вкладке прежней группы, затем ближайшей видимой группе. Для сохранения документа при закрытии используются Т-29/НФТ-5; ошибка записи оставляет вкладку открытой.

## Формат клавиш, русская раскладка и системные конфликты

Хранить `KeyboardEvent.code` и точный набор модификаторов; `Mod` разворачивается для платформы при сборке карты. Физическая KeyF работает в EN и RU независимо от `key=F/А`; интерфейс показывает «Ctrl+Shift+F (А)» для выбранного профиля RU, с пояснением про позицию клавиши. Сам текст вводится по `key`/input, не преобразуется в латиницу. Отсутствующий `code` не угадывается по кириллической букве: запись сообщает «Клавиша не распознана», событие при работе пропускается. Для пользовательской раскладки подпись физической позиции остаётся явной.

Одна комбинация на действие и платформу, без последовательностей/chords. Это исключает зависшие префиксы и таймауты при наборе текста. Допустимы Ctrl/Cmd с буквой/цифрой/пунктуацией и необязательным Shift, функциональные клавиши; Alt/Option допускается только вместе с Ctrl/Cmd после проверки AltGraph. Одиночные буквы/цифры/Space, Tab, Enter, Escape, стрелки и чистые модификаторы не назначаются действиям приложения.

| Класс конфликта | Политика |
|---|---|
| Windows: Win-сочетания, Alt+Tab, Alt+F4, Ctrl+Alt+Delete, Ctrl+Escape, Ctrl+Shift+Escape, Alt+Space, Alt+Shift, Ctrl+Shift без основной клавиши | Не назначать; системные действия/смена раскладки |
| macOS: Cmd+Tab, Cmd+Space, Cmd+Q, Cmd+H, Cmd+M, Cmd+Option+Escape, Ctrl+стрелки | Не назначать; системные действия. Реальные настройки ОС могут добавлять другие сочетания |
| Текст: Mod+A/C/X/V/Z, Mod+Shift+V, Windows Ctrl+Y/Ctrl+Shift+Z, macOS Cmd+Shift+Z; Shift+Insert, Ctrl+Insert, Shift+Delete; навигация/выделение текста | Защищены от переназначения в приложении |
| WebView: поиск страницы, reload, печать, DevTools, масштаб, история; Dockview: фокус групп и вкладок | Реестр владеет назначенными сочетаниями; браузер не выполняет параллельное действие. Reload не получает продуктового назначения |
| Две команды с одним сочетанием | Проверка пересечения контекстов, конфликт до сохранения. Окно пересекается со всеми контекстами; редактор и граф допускают одинаковую комбинацию, когда их фокус взаимоисключён |
| Сторонняя программа/персональные настройки ОС | Обнаружение всех перехватчиков невозможно; честная подсказка и проверка пользователем, без обещания автоматического обнаружения |

Для WebView2 предложено отключить browser accelerators при создании каждого окна и оставить базовое редактирование; если конкретный host не предоставляет настройку, точечно использовать AcceleratorKeyPressed. Не считать `preventDefault` достаточным без нативного прогона. Не менять debug-инструменты разработки вне release-профиля. F6 требует отдельной проверки: WebView2 различает windowed/visual hosting. macOS/WKWebView и меню приложения требуют отдельного адаптера; Windows-настройка там не применяется.

Первичные источники проверены 20-10-2026: [Microsoft — клавиатура WebView2](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/browser-features#additional-keyboard-shortcuts-information), [API browser accelerators](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2settings.arebrowseracceleratorkeysenabled), [MDN — физический code](https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/code), [MDN — isComposing](https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/isComposing). Это основания проекта; поведение собранного bars ими не доказано.

## Настройки сочетаний и сохранение

Новый раздел «Сочетания клавиш» внутри нынешних настроек. Компактная таблица: действие, контекст, сочетание, состояние; поиск по названию/клавишам, категории и фильтр «Изменённые». Отсутствие назначения показано «Не назначено». Будущая команда показывает этап/причину недоступности; назначение можно подготовить, но оно не перехватывает ввод до появления реализации.

Строка: «Назначить», «Убрать сочетание», «По умолчанию». При записи видны полученная комбинация и кнопки «Принять / Отмена». Конфликт показывает обе команды и контексты; применение заблокировано. Пользователь меняет другое назначение или явно нажимает «Переназначить сюда»: в общем черновике прежнее действие получает отсутствие сочетания. Нет скрытой замены по порядку загрузки. «Сбросить все» требует подтверждения и меняет только черновик сочетаний.

«Отменить / Сохранить» применяют целую карту. До успешной записи действует прежняя карта. Ошибка записи сохраняет черновик и текст ошибки; успешная запись обновляет подсказки меню, кнопок и `aria-keyshortcuts` без перезапуска. Если `commands.open` снят/переназначен, список действий остаётся доступен кнопкой меню рабочей области и штатной Tab-навигацией; настройки всегда достижимы без известной горячей клавиши.

Хранение — отдельный `~/.bars/keybindings.json` в пользовательском профиле (с учётом `BARS_USER_HOME`), не в проекте и не в раскладке Dockview. Формат v1: `version`, монотонная `revision`, `platforms.windows`/`platforms.macos`, словарь `actionId → {code, modifiers} | null`. Отсутствующий ключ — текущее умолчание; null — явно снятое сочетание. Сохраняются только переопределения. Виртуальный Mod в файле не используется; модификаторы нормализованы и отсортированы.

Общий воркер — единственный писатель: чтение карты и сохранение с expected revision через существующий IPC; временный файл, атомарная замена, уведомление окон после успеха. Если другое окно уже сохранило назначения — конфликт ревизии, без last-write-wins; черновик остаётся для повторного выбора. Не использовать `settings_save` целиком для этого файла и не перезаписывать настройки моделей. При недоступном воркере текущая карта продолжает работать, сохранение недоступно с причиной.

Неизвестный ID сохраняется как неактивное переопределение и показывается в настройках; не становится командой. Повреждённый файл/неподдерживаемая версия не перезаписывается автоматически: сообщение и штатные умолчания в памяти; запись поверх — только явный подтверждённый сброс. Конфликтная карта с диска отклоняется целиком с перечислением конфликтов, без случайного победителя. Обновление умолчаний не должно создавать скрытый конфликт с прежним переопределением: новая конфликтующая комбинация не активируется до разрешения в настройках, прежняя действующая пользовательская команда сохраняется.

## Реализация и критерии проверки

### Срез реализации 21-10-2026

Реализация опирается на каталог этого документа: чистая модель сочетаний, отдельный профиль воркера, адаптер Workspace, список команд и раздел настроек. Профиль обслуживают внутренние команды Tauri `keybindings_get`/`keybindings_save`; событие `bars://keybindings` сообщает окнам успешную ревизию. Хранилище сериализует запись и проверяет ожидаемую ревизию; настройки моделей не затрагиваются. Будущие действия редактора, файлов и нового графа остаются недоступными с указанием этапа. Release WebView2 отключает browser accelerators; стенд читает настройку обратно и подтверждает `false`. Результаты и оставшиеся проверки — в передаче сессии (`chats/2026-10-21-keyboard-implementation`).

Модули: `keybindings.ts` — каталог, физический `code`, допустимость, пересечения и разрешение новых конфликтных умолчаний; `keybindings.svelte.ts` — действующая карта и синхронизация; `workspace-commands.ts` — действия рабочей области и проверка закреплённой цели; `command-adapters.ts` — обработчики результатов, логов, уведомлений, MCP, индексации и карточки темы. `CommandPalette` сохраняет исходную цель, `KeybindingsPage` — собственный черновик. Контролы дерева и вкладок владеют своими стрелками; обработчики MCP/уведомлений уступают верхнему диалогу. Цель, удалённая или изменившаяся во время списка действий, не заменяется другой.

Проверены отдельные сценарии K-01…05 и K-07 в пределах имеющихся экранов; K-08 — профиль, неизвестные ID/версия, повреждение, ошибка записи и конкуренция писателей (изолированные тесты модуля Rust), IPC и конфликт ревизии (WebView2). Обновлённый профиль рассылается окнам; двухоконный физический сценарий не проверялся. Для K-06 реализованы обход/перенос/размер, но полный жестовый прогон ещё открыт. K-09 требует физических клавиш; K-10 — следующих этапов и macOS. Полный `cargo test` не выдан за пройденный: сборка его зависимости остановилась на C1083 длинного вложенного пути генератора Vulkan; тесты модуля хранения отдельно прошли через `rustc --test` с готовыми зависимостями.

Последовательность 1.3.2: чистая модель реестра/контекстов/проверки конфликтов → IPC и профиль → единый маршрутизатор и адаптеры существующих экранов → список команд и раздел настроек → нативные прогоны. Новых редактора, файловых операций и графа в этом срезе нет: их адаптеры подключаются при реализации соответствующих этапов. Нынешние обработчики Escape/Enter/Tab переносятся в согласованный порядок; старые конкурирующие пути удаляются.

| Проверка | Ожидаемое доказательство |

Чистую модель проверять unit-тестами, фокус и адаптеры — компонентными, приоритет host — физическими клавишами. Синтетический KeyboardEvent доказывает маршрутизацию, но не перехват ОС/WebView2.
