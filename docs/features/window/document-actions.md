# Документ из дерева и меню документа

[Дизайн этапа 27](refinement-design.md#меню-корня-модуля-и-папки) и связанный HTML задают меню корня, группы `.`, модуля и папки. Реализация этапа 31 добавляет эти цели в общее меню окна; макет остаётся примером на вымышленных данных. Меню самого проекта — [контекстное меню проекта](project-menu.md); удаление проекта целиком — [полное удаление](../projects/deletion.md).

Порядок пунктов, группы, недоступные пункты, подменю и таблица меню всех объектов окна — в разделе «Модель меню окна» ниже; разделы про цели и команды ОС остаются в силе.

Статус 26-10-2026: модель и меню дерева реализованы в рабочей копии; проверены компонентными тестами и программным сценарием собранного Tauri/WebView2. Другие места документа сохраняют прежнее меню до шагов 3.3.5–3.3.7. Запуск внешних программ, настоящий буфер ОС, физические жесты, установленная версия и macOS не приняты. Основание: IDEA-02, IDEA-09, OQ-74, Т-14, Т-17, Т-20; принятый макет — `mockups/context-menu-model.html`.

ISS-15 остаётся открытым для физической приёмки: программный сценарий открывает меню корня и папки в собранном окне, но не заменяет проверку пользователем. Контракт закрепления цели папки сохраняется.

## Чтение документа из дерева

Нажатие на имя файла открывает целый документ в существующей правой колонке без поискового запроса. Галочка отдельно меняет область поиска; открытие документа её не меняет. Дерево показывает документы текущего индекса, включая документы без чанков. Пути дерева относительно корня документации переводятся в исходные пути индекса; поддерживаются вложенный корень документации и `.`.

Из дерева документ открывается с начала, без подсветки найденного раздела. Из выдачи сохраняются прокрутка и подсветка строк. Вызов `read` получает явный путь от корня проекта (`./docs/x.md`), чтобы совпадение с `docs/docs/x.md` не открыло другой файл (OQ-35). Последнее открытие имеет приоритет; поздний ответ чтения после смены проекта или закрытия просмотра игнорируется. Пропавший файл показывает существующее сообщение просмотра, прочие ошибки — уведомление.

## Меню документа

По замечанию автора 20-10-2026 меню компактное: текст 12 px, отступы пункта 4×8 px, минимальная ширина 180 px. У меню папки/модуля нет верхней шапки с типом («Модуль») и абсолютным путём; команды и пояснение области проверки сохраняются. Путь доступен командой «Скопировать путь».

Правый клик по файлу дерева открывает набор из раздела «Модель меню окна» с группами и удалением последним. Карточка результата пока использует прежний список: «Открыть», «Открыть в новом окне», «Открыть в …», «Открыть в Проводнике», «Скопировать путь», «Проверить индекс». В подменю — «Программа по умолчанию», установленные VS Code, Блокнот и обнаруженные редакторы (Cursor, VSCodium, Notepad++, Sublime Text, Zed). Обнаружение по PATH и стандартным каталогам установки; это не полный реестр всех программ ОС. Недоступные редакторы не показываются. Дерево подписывает команду «Показать в Проводнике», на macOS — «Показать в Finder»; у прежних меню подпись «Открыть» сохраняется до их перевода.

Выделение текста добавляет «Копировать»; текстовые поля сохраняют прежнее меню редактирования. Меню закрывается по Escape, внешнему клику, прокрутке, потере фокуса и смене проекта. Подменю укладывается в окно; доступно с клавиатуры. Ошибка запуска/буфера/очереди показывается уведомлением, без ложного сообщения об успехе.

## Команды ОС и очередь

Инженерное решение: команды Tauri проверяют принадлежность пути списку документов зарегистрированного проекта. Открытие редактора принимает идентификатор из фиксированного каталога, а не произвольную команду. Путь передаётся отдельным аргументом без shell. Копируется абсолютный путь без номера строки; существующая кнопка «Копировать путь:строку» не меняется. Проводник выделяет файл.

«Проверить индекс» ставит `Job::files` с одним путём и приоритетом `Explicit`, без полной переиндексации и без согласия на смену модели. Сохраняется OQ-44: исполнитель сверяет проект целиком, переэмбеддит только изменившиеся документы. Очередь может объединить задание с уже ожидающей проверкой. Удалённый файл допускается к проверке по записи старого индекса. Состояния `unavailable` и `reindex_required` возвращают существующие ошибки. Уведомление подтверждает постановку в очередь, завершение видно на странице индексации.

## Приёмка документа и меню

- Открыть файл дерева без поиска; галочки неизменны, подсветки результата нет. Повторить для корня `.` и вложенного docs_root.
- Открыть результат с подсветкой; затем другой файл дерева. Быстро сменить проект/закрыть просмотр во время чтения.
- Проверить меню на дереве и карточке, выделенный текст и поля ввода, Escape/внешний клик/края окна/клавиатуру.
- Проверить абсолютный путь с пробелами и кириллицей; открыть редактор по умолчанию и найденный редактор, выделить файл в Проводнике. Ошибки не должны выглядеть успехом.
- На временном профиле изменить/удалить документ, поставить проверку, увидеть задание `files` и обновлённый индекс. Смена модели не должна обходить диалог согласия.

## Модель меню окна

Макет меню принят автором 24-10-2026. Шаг 3.3.4 переводит дерево на чистую модель `menu-model.ts`: группы, разделители, причины недоступности, опасное удаление последним, цель строки и команды реестра. Остальные места документа и диалог входящих ссылок — шаги 3.3.5–3.3.7. Основание: [опись и образцы меню](../../knowledge/context-menus.md), ISS-57 и ISS-47; реестр команд — [каталог клавиш](keyboard-design.md). Меню проекта сохраняет свою логику ([меню проекта](project-menu.md)).

### Пункт меню и группа

Пункт — запись, а не склейка списков по месту вызова. У пункта: `id` команды реестра, подпись, группа, порядок в группе, условие показа по виду объекта и месту, условие доступности с причиной, признак «опасный», подпункты (одна глубина). Для дерева меню собирает чистая функция `treeMenu` в `ui/src/lib/menu-model.ts`; `ContextMenu.svelte` рисует результат без добавления пунктов. Меню дерева, адаптер списка действий и клавиши вызывают общий `executeTreeCommand` из `tree-commands.ts`, который повторно проверяет проект, корень, существование узла и доступность команды. Подменю найденных программ сохраняет отдельный асинхронный запрос каталога; выбор программы идёт через ту же команду открытия с ID редактора.

Группы идут в одном порядке во всех меню; пустая группа не показывается, разделитель стоит только между показанными группами, не в начале и не в конце, не дважды подряд.

| № | Группа | Что в ней |
|---|---|---|
| 1 | `edit` — правка текста | Отменить, Повторить, Вырезать, Копировать, Вставить, Выделить всё — только то, что применимо к полю, редактору или выделению |
| 2 | `tab` — вкладка | Закрыть, Закрыть другие, Закрыть справа, Переместить вкладку… |
| 3 | `open` — открыть | Открыть, Открыть в новом окне, Открыть в …▸ |
| 4 | `create` — создать | Новый документ…, Новая папка…, Создать документ (для битой ссылки) |
| 5 | `modify` — изменить | Переименовать…, Переместить… |
| 6 | `path` — путь | Показать в Проводнике (на macOS «Показать в Finder»), Скопировать путь, Скопировать ссылку |
| 7 | `style` — оформление | Цвет…, Цвет и иконка… |
| 8 | `index` — проверка | Проверить индекс, Проверить индекс проекта |
| 9 | `delete` — удаление | Удалить…, Удалить проект…, Закрыть тему |

Порядок 3–9 — группы из ISS-57 («открыть · создать · переименовать и переместить · путь и Проводник · цвет · проверить индекс · удалить последним»); `edit` и `tab` стоят выше как действия над текстом и над вкладкой, на которых пользователь уже находится.

### Показ, недоступность и опасные пункты

- **Скрыт** пункт, который объекту не подходит по виду или месту: «Переименовать» у группы «Корневые документы», «Открыть» на вкладке этого же документа, «Цвет и иконка…» у папки глубже второго уровня, «Открыть в …» у папки. Скрытый пункт не оставляет разделителя.
- **Серый с причиной** пункт, который объекту подходит, но сейчас недоступен: «Проверить индекс» при `unavailable` или `reindex_required`, «Закрыть другие» без других вкладок группы, «Закрыть справа» без вкладок справа, «Переместить вкладку…», когда разделение невозможно, «Переименовать/Переместить/Удалить», пока воркер запускается. Причина — в подсказке и доступном описании через `aria-describedby`; при фокусе или наведении она также показана внизу меню. Серый пункт остаётся в обходе стрелками, Enter и клик ничего не делают. Дерево при потере связи с воркером открывает меню без запроса закрепления папки; команды, требующие воркера, недоступны. Это меняет прежний обход меню проекта «только по доступным пунктам».
- **Опасное — группа `delete`, всегда последняя**, в меню и в подменю. Признак `danger` задаёт оформление (макет — шаг 3.3.3) и требует подтверждающего диалога до действия; меню, открытое с клавиатуры, ставит фокус на первый доступный пункт, а не на опасный.

### Сочетания клавиш в пунктах

Сочетание берётся из реестра по `id` в момент открытия меню (`bindingFor`) и стоит справа от подписи; пользовательское назначение побеждает умолчание, нет назначения — нет текста. Меню не регистрирует клавиш: оно только показывает. Пункты правки текста показывают штатные системные сочетания (Mod+Z, Mod+X, Mod+C, Mod+V, Mod+A): они остаются штатным редактированием и не переназначаются ([каталог клавиш](keyboard-design.md), раздел «Каталог действий редактора»). В дереве добавлены `target.style`, `target.checkIndex`, `target.openExternal`; существующие команды создания и изменения активированы, F2 и Delete берутся из реестра. Для следующих мест остаются `tab.closeOthers`, `tab.closeRight`, `link.copy`, `link.createTarget`, `heading.goTo`, `heading.copyLink`; их добавляют вместе с реализацией.

### Подменю

Подменю — для большой группы, глубина один. Их два: «Открыть в …» (Программа по умолчанию, затем найденные редакторы — как в [меню документа](#меню-документа)) и «Документ ▸» в редакторе. Правая стрелка и Enter открывают подменю, левая стрелка и Escape закрывают его и возвращают фокус на родителя; второй Escape закрывает меню. Одиночный пункт в подменю не прячется. «Документ ▸» содержит группы меню того же документа во вкладке в том же порядке, с теми же правилами скрытия.

### Цель меню — ближайший размеченный объект

Каждый объект с меню размечает себя `data-menu-kind` (`file`, `folder`, `project`, `panel-tab`, `link`, `heading`, `topic`, `row`) и, где важно место, `data-menu-place` (`tree`, `tab`, `header`, `editor`, `render`, `card`). Цель — ближайший предок нажатого элемента со своим `data-menu-kind`; он не наследует документ раздела по `closest("[data-document-path]")`. Данные цели (путь документа, путь проекта, идентификатор панели) остаются в существующих атрибутах.

Приоритет прежний: поле ввода → ближайшая цель → обычное текстовое меню; выделенный текст добавляет сверху группу `edit` с «Копировать». Меню объекта не дописывает меню предка. Вкладка служебной панели и узел графа — цели без документа: `documentAt` для них пуст, файловых пунктов нет.

Правило единого набора: всё, что стоит за документом, — карточка выдачи, находка аудита, вхождение «В тексте», похожий отрывок, входящая ссылка в панели «Ссылки» — это объект `file` с набором документа; различаются только групповые условия места (`tab` — для вкладки и объектов внутри неё, «Открыть» скрыт там, где документ уже открыт).

### Таблица меню объектов

Состав пунктов по группам. «Док.» — набор документа: `open` (Открыть, Открыть в новом окне, Открыть в …▸) · `modify` (Переименовать…, Переместить…) · `path` (Показать в Проводнике, Скопировать путь) · `index` (Проверить индекс) · `delete` (Удалить…).

| Объект и место | Меню по группам |

| Файл в дереве | Док. и между `path` и `index` — `style` (Цвет…) |

| Выделенный текст в рендере | `edit` (Копировать) · меню рендера |
| Редактор исходника | `edit` · «Документ ▸» (меню вкладки) |
| Модуль и папка второго уровня | `create` · `modify` · `path` · `style` (Цвет и иконка…) · `index` (Проверить индекс проекта) · `delete` |
| Папка третьего уровня и глубже | то же без `style` |
| Группа «Корневые документы» (`.`) | `create` · `path` · `index` |
| Проект | `index` (Проверить индекс) · `delete` (Удалить проект…) |
| Вкладка служебной панели | `tab` |
| Ссылка в тексте, исходящая строка панели «Ссылки» | `open` (Открыть цель, Открыть в новом окне) · `path` (Скопировать ссылку) |
| Битая ссылка | `create` (Создать документ) · `path` |
| Заголовок в структуре документа | `open` (Перейти к заголовку) · `path` (Скопировать ссылку на заголовок) |
| Строка «Новых тем» | `path` (Скопировать запрос) · `delete` (Закрыть тему) |
| Строка индексации, вызова MCP, уведомления, журнала | `open` (Подробности, Повторить, если допустимо) · `path` (Копировать); состав — команды реестра `indexing.details`, `mcp.details`, `notification.details`, `logs.copy` |

| Выделенный текст вне полей | `edit` (Копировать) |

Отдельное окно документа показывает набор по месту объекта в нём: группа `tab` есть, если документ там открыт во вкладке Dockview.

### Что в модель не вошло

- «Открыть» у папки: клик по имени уже открывает файл папки ([дерево и файлы](../knowledge-base/tree-and-files.md)), в меню он был бы вторым путём к тому же.
- Слой «расширенных» пунктов за Shift, как в Проводнике: меню bars короткое, слой решал бы проблему, которой нет.
- Цвет и иконка из вкладки и карточки: Т-38 выбирает оформление в меню строки дерева.

## Контракт этапа 26: цели меню дерева документов

Реализация этапа 31: отдельные команды Tauri `folder_target` и `folder_action`. Первая закрепляет проверенную цель в памяти окна и возвращает непрозрачный ID; вторая принимает только этот ID и действие. Проверяются поколение регистрации, ревизия docs_root, подтверждённый предок документа и канонические границы пути. Папка не передаётся файловой команде. Повторное открытие меню заменяет цель; поздний ответ не открывает закрытое меню. Проверка проекта возвращает ID принятой операции.

Потребность автора, ISS-15: правый клик по папке документов открывает полезное меню. Инженерное решение — отдельный тип цели папки, не передача каталога в файловую команду `document_action`. Цель фиксируется при открытии: вид, канонический проект/поколение регистрации, актуальный docs_root/его версия, относительный путь и вычисленный абсолютный путь. Бэкенд заново проверяет цель перед действием. Имя проекта и надпись узла не являются идентификаторами.

| Цель | Как определяется | Открыть в ОС / скопировать | Проверка индекса |
|---|---|---|---|
| Корневой модуль `.` | Виртуальная группа файлов непосредственно в docs_root, не отдельный каталог | Тот же docs_root; подпись «Корневые документы» отличает группу от физической папки | Весь проект, не только файлы группы `.` |
| Модуль-папка | Первый сегмент пути под docs_root | Физический каталог модуля | Весь проект |
| Вложенная папка | Предок индексированного документа под модулем | Физический вложенный каталог | Весь проект |
| Файл дерева / результат поиска | Исходный путь документа из индекса | Существующее меню файла; Проводник выделяет файл | Существующая проверка файла `Files/Explicit`, без изменения её контракта |
| Проект | Цель в списке/переключателе проектов | Существующее меню проекта | Проверка проекта и удаление по отдельному контракту проекта |

У дерева `.` — группа только корневых файлов; при отсутствии корневых файлов группа не создаётся. Отдельной строки «Корень документации» нет: автор убрал её 19-10-2026 («Убрал»), меню корня открывает группа «Корневые документы» и она адресует тот же docs_root. Дерево по диску показывает также пустые и ещё не индексированные папки: они допускаются меню по результату обхода диска, без документа в индексе. В пустом проекте создание доступно кнопками над деревом; корень можно открыть из меню проекта.

## Контракт этапа 26: действия папки и результат

Набор папки/модуля/корня: «Открыть в Проводнике» (macOS: «Открыть в Finder»), «Скопировать путь», «Проверить индекс проекта». Рядом с последним действием/в его пояснении явно указано «Проверяется весь проект», включая вызов из вложенной папки. Минимальный набор — инженерное решение, не дословный список автора. Файловое «Открыть» в просмотрщике и подменю редакторов для папки не добавляются. Создание, переименование, перенос и удаление в меню папки и файла добавил этап 3.3.1 по Т-33: пункты и их поведение описывает [дерево по диску и операции](../knowledge-base/tree-and-files.md).

| ID / действие | Необходимые данные | Непосредственный результат | Критерий проверки этапа 31 |
|---|---|---|---|
| F-01. Правый клик по строке корня/модуля/папки | Закреплённая цель; координаты | Общее меню bars для нажатого каталога | Имя, иконка, счётчик, свободная часть строки и правый клик по галочке дают ту же цель; выбор/раскрытие/проект не меняются |
| F-02. Клавиша меню / Shift+F10 | Сфокусированная строка цели | То же меню у строки, фокус в первом доступном пункте | Стрелки, Home/End, Enter, Escape; после закрытия фокус возвращается в исходную строку |
| F-03. Открыть в ОС | Проверенный существующий каталог | ОС приняла команду открытия именно папки, не выделения папки в родителе | На временных каталогах с кириллицей/пробелами визуально открыт нужный каталог; возврат API не выдаётся за доказательство просмотра человеком |
| F-04. Скопировать путь | Проверенный абсолютный путь каталога | Путь без номера строки записан в буфер, короткое подтверждение | Проверено содержимое буфера; ошибка буфера — уведомление, без сообщения успеха |
| F-05. Проверить индекс проекта | Канонический проект; валидная привязка цели; область задания Full, приоритет Explicit | Запрос принят/объединён с ожидающим; ссылка на ID операции | Используется существующая проверка одного проекта, не `check_all`, не rebuild и не выборочная индексация папки. Сообщение только «Проверка проекта в очереди» |
| F-06. Ошибка действия | Код/безопасная причина, исходная цель | Меню закрывается, ошибка остаётся в центре уведомлений; повтор из актуального меню | Нет успеха по одному клику/неудачному вызову; другая текущая страница не подменяет цель ошибки |

Итог F-05 поступает из [контракта уведомлений](notifications.md#контракт-этапа-26-сценарии-и-состояния-уведомлений), а не из ответа очереди. Проверка допустима и для удалённой папки старого дерева, пока проект и docs_root доступны: это способ убрать устаревшие записи. `unavailable` и `reindex_required` не обходятся, автоматического согласия Т-25 нет. Если одно задание уже исполняется, дополнительная проверка следует правилам существующей очереди и получает явную связь с принятой операцией.

## Контракт этапа 26: допуск путей и меняющееся дерево

Для каталога нужен собственный допуск: зарегистрированный проект, текущий docs_root, относительный путь подтверждённого узла дерева/его предка либо сам корень. Не расширять файловый allowlist до произвольного абсолютного пути. Сегменты `..`, абсолютный путь вместо относительного, чужой диск/UNC и подмена префикса (`docs-other` вместо `docs`) запрещены; равенство/вложенность проверяются по компонентам. `.` обрабатывается как явная цель корня, не как произвольный обход.

Перед действием ОС канонизируются корень и существующий каталог; symlink/junction за пределы разрешённого корня не допускается. Копирование существующей папки использует тот же проверенный путь. Для удалённой папки копирование использует подтверждённый путь прежнего узла и канонизированный ближайший существующий предок внутри корня; если доказать принадлежность нельзя, отказ. Проверка индекса удалённой папки не открывает её путь в ОС и проверяет проект. Корень с docs_root `.` разрешён; вложенный docs_root и одинаковые сегменты `docs/docs` не обрезаются эвристикой строк.

| ID / особое состояние | Действие | Результат | Проверка |
|---|---|---|---|
| F-07. Папка удалена после построения дерева | Открыть / копировать / проверить | Открытие — «Папка не найдена»; безопасное копирование возможно с пометкой отсутствия; проверка проекта убирает устаревшие записи | Реально удалить временную папку между открытием меню и командой; ошибки различимы |
| F-08. Смена проекта/docs_root, удаление/повторная регистрация | Выполнить старое действие / получить поздний ответ | Меню закрыто; устаревшая цель отклонена, поздний ответ не перенаправляется в новый проект | Привязка проверяется и в UI, и в обработчике; обновление дерева той же цели допускает повторную валидацию |
| F-09. Проект недоступен / требуется согласие на модель | Проверить индекс проекта | Штатное объяснение и переход к проекту/согласию, без постановки задания | Нет обхода Т-25; ошибка ОС открытия не скрывает рабочую возможность проверки доступного проекта |
| F-10. Только вложенные файлы / корневые файлы есть | Открыть меню группы «Корневые документы» (если она есть) | Меню адресует docs_root; без корневых файлов группы и меню корня в дереве нет | Проверены docs_root `docs`, `manual/docs`, `.` и группа `.` без подмены области поиска |
| F-11. Junction/symlink наружу, поддельная цель | Выполнить действие | Безопасный отказ; процесс и буфер не получают недопущенный путь | Проверить пограничные префиксы, другой диск, `..`, перенос узла и смену ссылки после открытия меню |

Меню закрывается по Escape, внешнему клику, прокрутке, потере фокуса и смене проекта. Расположение ограничено окном; абсолютный путь доступен через «Скопировать путь». Текстовые поля сохраняют меню редактирования; выделение текста сохраняет «Копировать»; файл, папка и проект не получают действия друг друга. Точка приоритета: поле ввода → ближайшая цель файла/папки/проекта, с дополнительным «Копировать» выделенного текста → обычное текстовое меню. Клавиатура, обе темы и узкое окно — макеты этапа 27, регрессии и действия ОС в собранном Tauri — этап 31. Проверка нового кода в этапе 26 не заявляется.
