# Ход индексации в окне bars

Как окно показывает работу очереди индексации ([architecture/worker.md](../../architecture/worker.md), Т-10, Т-19). Мокап — [mockups/indexing.html](mockups/indexing.html), четыре сцены.

## Где виден ход индексации

- **Точка проекта** в списке: цвет акцента, мигает; в подписи — процент или «ждёт» ([main-window.md](main-window.md)).
- **Строка состояния** под деревом: «Индексация · проект N %» или «ждут N документов».
- **Страница проекта** с подробностями — открывается кнопкой «Подробнее» в баннере или нажатием на проект в индексации.
- **Иконка трея** — см. «Трей» ниже.

## Страница индексации проекта

Показывается для полной переиндексации после согласия ([reindex-consent.md](reindex-consent.md)) и для первой индексации нового проекта.

- **Баннер состояния.** Если поиск по проекту не работает, это сказано первой строкой: «Поиск по проекту пока не работает. Старый индекс заменится новым, когда переиндексация закончится». Другие проекты ищутся (Т-25).
- **Прогресс.** Крупно «обработано документов из всего»; полоса; оценка оставшегося времени. Под ней три плитки: чанков обработано, скорость (чанков в секунду), устройство (видеокарта или CPU, [features/models/local-models.md](../models/local-models.md)). Документы — единица, которую воркер считает в `pending`; число чанков — оценка по нарезке (OQ-46).
- **Сейчас.** Файл, который эмбеддится, и число файлов с ошибкой.
- **Кнопки.** «Приостановить» и «Остановить» — в протоколе таких методов нет, нужны новые (решение агента, OQ-55). Остановка оставляет старый индекс и проект в `reindex_required`: согласие нужно будет дать снова. Пауза замораживает очередь целиком.
- **Очередь.** Проекты по порядку: номер, имя, причина («полная переиндексация по согласию», «правки файлов, 3 документа», «проверка при старте»), состояние. Приоритеты — как в воркере: явная переиндексация и хук, затем слежение, затем старт и час.

Первая индексация нового проекта выглядит так же, без баннера о поиске: пока индекс пуст, поиск просто ничего не вернёт ([empty-states.md](empty-states.md)). У встроенной нескачанной модели первой стадией идёт скачивание с ходом загрузки ([error-states.md](error-states.md)).

## Обычное обновление не блокирует поиск

Правка файла, проверка при старте и часовая проверка (Т-10) работают в фоне. На главном экране над выдачей показан спокойный баннер цвета акцента: «Идёт обновление индекса · ждут N документов» с полосой и ссылкой «Подробнее». Поиск работает по тому, что уже проиндексировано; правки последних минут могут в выдаче не появиться. Блокирует поиск только переиндексация после смены модели (Т-25).

## Ошибка файла при индексации

Документ, который не удалось проиндексировать, остаётся в очереди с ошибкой, остальное индексируется дальше; уже проиндексированная версия файла не трогается ([features/models/external-models.md](../models/external-models.md)). Страница проекта показывает:

- жёлтый баннер «N документов не проиндексированы» и кнопку «Повторить»;
- список: путь, текст ошибки без ключей и что сделать — уменьшить размер чанка, проверить права, повторить;
- пояснение, что bars повторяет сам: до трёх раз при сетевой ошибке и 5xx, затем ждёт следующей проверки.

Точка проекта при этом жёлтая, в трее — «нужно внимание». Текст ошибки — то же, что `last_error` в `status` ([architecture/worker.md](../../architecture/worker.md)).

## Трей

Закрытие окна прячет его, воркер остаётся в трее (Т-1). Иконка показывает общее состояние:

| Вид | Состояние |
|---|---|
| серая или спокойная | всё актуально, воркер ждёт |
| малиновая, мигает | идёт индексация; подсказка: «проект N %, ждут M документов» |
| жёлтая | нужно внимание: переиндексация (Т-25), ошибка файла, провайдер недоступен |

Меню трея: «Открыть bars» (двойной клик по иконке — то же), строки состояния (индексация, нужна переиндексация), «Проекты», «Настройки», «Выход». Пункт состояния открывает окно на нужном проекте. Состав меню — решение агента: требования к нему в MAIN_IDEA.md есть только на «Выход» и показ окна (Т-1).
