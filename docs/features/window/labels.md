# Словарь подписей окна bars

Статус: проект 3.4.3, проверен чтением кода окна и воркера 28-10-2026; в коде не реализован (реализация — шаг 3.4.6). Названия слов в таблицах ниже — предложение агента, не решение автора; спорные места вынесены в OQ-217. Источник — проблема ISS-59 ([реестр проблем](../../backlog/issues.md)) и UX-3 из [аудита клиента 23-10-2026](../../audits/client-2026-10-23.md). Язык интерфейса — по НФТ-4 (русский).

## Правило: идентификатор только в подсказке и в отчёте

Пользователь видит слова, а не имена из протокола. Идентификатор (`mix`, `include_related`, `max_bytes`, `Some(ComparisonLimit)`, `document-centroid-v1`) допустим в двух местах и больше нигде:

- **подсказка** (`title`, раскрывающаяся строка «подробнее») — мелким моноширинным шрифтом после слов: «Со связями (`mix`)»;
- **отчёт об ошибке и копируемый текст** — полностью, как пришло от воркера ([принципы показа ошибок](error-states.md)).

Следствия:

- Подпись, кнопка, заголовок, строка состояния, уведомление и пустое состояние идентификатора не содержат. Число и единица — да: «ответ усечён: достигнут предел размера» вместо «max_bytes».
- Неизвестный идентификатор (воркер новее окна) не показывается как есть: окно пишет нейтральную фразу группы («причина не определена») и кладёт сырое значение в подсказку и отчёт.
- Свободный текст воркера на русском показывается как пришёл, если в нём нет идентификаторов. Если идентификатор внутри фразы («Связи отключены: include_related=false»), окно подменяет его по таблице, а не режет строку регулярным выражением.
- Одно понятие — одно слово на всех экранах. Парные подписи («Готов» в списке, «слой готов» в строке) берутся из одной таблицы.
- Настройки — исключение по месту, не по правилу: строка вида `rerank_candidates` остаётся в подсказке под названием поля, как сейчас.

## Модуль подписей

Все подписи значений протокола лежат в одном модуле окна, `ui/src/lib/labels.ts` (имя — предложение, подтверждается в 3.4.6). Разрозненные таблицы (`SEARCH_MODE`, `KIND_TITLE`, `stateLabels`, `STATE_TEXT`, `SCORE_LABEL`, подписи причин в `graph/query.ts`) переезжают в него, прежние имена остаются тонкими обёртками на время переноса.

- **Группы.** Режим поиска, вид оценки, состояние слоя графа, вид связи, уровень графа, причина усечения, причина отката режима, режим движения, вид узла. У каждой группы своя таблица `идентификатор → { слово, подсказка }`.
- **Один вход.** `label(группа, идентификатор)` возвращает слово и подсказку. Для группы с закрытым перечислением (TypeScript-объединение) таблица — `Record<Тип, …>`: новое значение без подписи не соберётся. Для открытых строк (`limit_reasons`, `fallback_reason`) таблица неполная по природе, поэтому есть запасная фраза группы и сырое значение в подсказке.
- **Причины усечения.** Предлагается такой словарь: `max_nodes`, `nodes` — «достигнут предел числа узлов»; `max_edges`, `edges` — «предел числа связей»; `max_bytes`, `bytes` — «предел размера ответа»; `limit`, `items` — «предел числа результатов»; `fields` — «длинные поля сокращены»; `skipped` — «часть документов пропущена». Одно слово для кода из графа и из чтения диска.
- **Без строкового поиска и среза.** Идентификатор внутри свободной фразы заменяется по таблице известных фраз воркера; режущих регулярных выражений нет.
- **Проверка правила.** Тест по таблицам: у каждого значения есть слово, оно не содержит `_`, латинских имён и `=`. Второй тест рендерит выдачу «Со связями», вкладку «Граф» и меню проекта на заглушке и ищет идентификаторы в видимом тексте без подсказок.

## Что остаётся за пределами словаря

- Тексты ошибок воркера и провайдера: их смысл — в [экранах ошибок](error-states.md); словарь решает только показ идентификаторов в них.
- Названия настроек в `<code>` под полем и клавиши: словарь их не меняет.
- Документы и ответы MCP для агентов: идентификаторы там нужны, правило относится только к окну.
- Предложение окончательных слов для таблицы «Опись» утверждает автор через OQ-217, пока в коде оно не закреплено.
