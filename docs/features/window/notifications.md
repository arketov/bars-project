# Уведомления и колокольчик bars

Статус: реализовано в рабочей копии 18-10-2026; 79 UI, 154 worker и 51 protocol тест прошли, UI check/build, app check и worker clippy успешны. Встроенный браузер: обе темы, настройки, очистка и переходы проверены на фикстурах; настоящее скачивание и Tauri-окно не проверялись, установленный bars не обновлялся. Основания: [пожелание автора](../../backlog/ideas.md#idea-04-сервис-уведомлений-и-колокольчик), Т-1, Т-20, НФТ-4. Макет: [notifications.html](mockups/notifications.html).

Открыто замечание автора 18-10-2026: ISS-13 — внешний вид, удобство и отсутствие полезного итога в карточке. Текущая реализация не означает приёмку UX/UI; [доработка и отдельный этап дизайна](refinement-plan.md). Функциональный контракт этапа 26 ниже спроектирован по исходникам; он предназначен для этапов 27–28 и ещё не реализован.

## Содержание центра уведомлений

Этот раздел и следующие два раздела описывают существующую реализацию этапа 20; целевое поведение отделено заголовком «Контракт этапа 26».

Постоянный колокольчик внизу боковой панели открывает список со всех проектов. Скачивание или загрузка модели — одна обновляемая карточка с названием, процентом файлов и прогресс-баром; 100 % файлов при действующей загрузке означает подготовку модели, а не успешную готовность. Карточки появляются и при загрузке из поиска. Прогресс берётся из кэша воркера; окно не запускает модели ради опроса.

Индексация показывает проект, обработанные документы, обход папки или паузу. Ожидающие задания показываются отдельно. Ошибки индексации ведут на существующий экран подробностей; ошибки действий окна сохраняются после исчезновения toast. Уведомления модели ведут в настройки моделей. Успешное скачивание определяется по полному комплекту файлов при завершившейся операции; исчезновение задания индексации означает только окончание наблюдаемого выполнения, поскольку API не различает успех и отмену.

## Жизненный цикл уведомлений

Инженерное решение: история хранится только в памяти окна, без отдельной базы, системных push и фоновых сообщений ОС. До 100 последних завершённых карточек плюс активные; активные не удаляются очисткой. Ошибки и начало операции дают непрочитанное уведомление; очередной процент не увеличивает счётчик. Открытый список отмечает все карточки прочитанными. Изменение результата или повторный запуск снова требует внимания. Повтор одинаковой ошибки в опросе не создаёт дублей; новая ошибка после устранения видна снова. Очистка истории удаляет завершённые карточки; сохраняющаяся проблема не появляется заново до изменения её состояния.

Опрос последовательный, раз в секунду; ошибка чтения моделей не превращается в успешное завершение загрузок. Пропадание воркера отмечается после штатных двух неудач. После восстановления опрос продолжает обновлять карточки. Короткие операции между опросами могут не попасть в историю: это центр наблюдаемых состояний, не журнал аудита. Полный журнал относится к IDEA-03.

## Проверка уведомлений

Проверки 18-10-2026: vitest включает переходы модели, ошибки при наличии весов, отсутствие дублей, повтор ошибки после восстановления, ограничение истории и очистку; компонентные тесты — прогресс, пустое состояние, Escape с возвратом фокуса, внешний клик. Проверка общего опроса подтверждает один одновременный `models_info` для настроек и уведомлений и сохранение последнего снимка при ошибке.

Worker-тест на временном home проверяет устойчивую ошибку, запрет второго одновременного скачивания, очистку ошибки при повторе, сохранение CPU и выбор builtin даже при сохранённом remote. Handler-тест проверяет 100 % полного кэша и 0 % отсутствующей модели. Фикстуры не скачивают настоящие модели.

Браузерная сцена `?scene=notifications`: загрузка 42 %, идущая индексация, очередь, ошибка. Проверены чтение, очистка без удаления активных карточек, переходы к моделям и индексации; пустая сцена и Escape. [Снимок тёмной темы](../../chats/2026-10-18-notification-center/notifications-dark.png), [светлой темы](../../chats/2026-10-18-notification-center/notifications-light.png). Это проверка интерфейса на заглушке, не скачивания по IPC. Ручное чтение изменений выполнено; новые зависимости не добавлялись.

Остаётся приёмка в настоящем приложении:

- Начать скачивание: карточка и процент меняются без дублей; уйти из настроек — прогресс остаётся доступен.
- Скачанные файлы при активной подготовке не показываются как законченная загрузка; ошибка не получает успешный статус.
- Запустить индексацию двух проектов: видны работа и очередь; пауза отражается в карточке.
- Ошибка файла открывает ход индексации; ошибка действия остаётся в списке после toast.
- Колокольчик: пустой список, непрочитанные, очистка завершённых, Escape, внешний клик, клавиатура, светлая и тёмная темы.
- Автотесты проверяют переходы, ошибки и отсутствие дублей. Настоящее скачивание и Tauri проверяются отдельно от браузерных фикстур.

## Контракт этапа 26: назначение и источник результата уведомлений

Потребность автора, ISS-13: по карточке понять, что произошло, с каким проектом/моделью, каков результат и что делать дальше. Слова «Выполнение закончено» без результата не удовлетворяют этому сценарию. Компоновка, размеры, цвета и интерактивный макет относятся к этапу 27.

Инженерное решение этапа 26: worker сообщает явный итог операции после применения результата к состоянию проекта. Источники уже существуют внутри worker: `JobResult`/`Outcome`, отчёт с `added/changed/removed/unchanged/problems`, результат подготовки модели. Их надо вывести через protocol на этапе 28. Исчезновение из `activity`, отсутствие ошибки, 100 % файлов и `accepted=true` не доказывают успеха. Центр показывает фоновые операции, их события и ошибки действий окна; это не аудит каждого MCP-вызова.

| Данные операции | Значение и источник |
|---|---|
| Идентичность | Эпоха worker + ID операции; канонический проект и поколение регистрации либо ID/вариант модели. Имя — подпись, не ключ |
| Причина и область | Проверка, rebuild, скачивание, подготовка; явный запрос/слежение/периодическая проверка; область фактического задания |
| Жизненный цикл | Создана, очередь, исполняется, пауза запрошена, пауза подтверждена, остановка запрошена, терминальный исход |
| Прогресс | Стадия; обработано/всего документов либо байтов; неизвестный знаменатель — без процента. Процент относится к стадии |
| Итог | Успех, частичный результат, отмена, ошибка; отдельно `index_applied` и сохранение старого индекса. Неизвестный исход — отсутствие достоверного итога |
| Подробности | Время начала/конца, длительность, счётчики отчёта или признак готовности файлов/сессии; безопасная причина, доступное действие |

Файловые ошибки учитываются даже при успешном обходе: обычное обновление может применить часть изменений, а неполный rebuild по OQ-80 не заменяет индекс. Неизвестное число не превращается в ноль. Операция проверки без изменений имеет результат «Индекс актуален», с фактическим числом проверенных документов, если оно известно.

## Контракт этапа 26: сценарии и состояния уведомлений

| ID / событие и данные | Действие пользователя | Результат в центре | Критерий проверки этапа 28 |
|---|---|---|---|
| N-01. Запрос принят; ID и очередь | Открыть карточку | «Проверка индекса в очереди», проект, причина, переход к заданию | `accepted` создаёт ожидание; карточка не сообщает об обновлённом индексе |
| N-02. Обход → обработка; счётчики | Посмотреть ход индексации | Одна карточка меняет стадию и прогресс; при неизвестном total — «Обход папки» | Несколько опросов не создают дублей и новых непрочитанных на каждый процент |
| N-03. Запрос паузы → подтверждённая пауза | Приостановить / продолжить на странице индексации | До подтверждения «Пауза запрошена»; затем «На паузе»; пауза всей очереди явно обозначена | Текущий документ может закончиться; карточка не показывает ложную мгновенную остановку |
| N-04. Успешно применён отчёт | Открыть подробности результата | «Индекс обновлён: добавлено A, изменено B, удалено C» либо «Индекс актуален»; время и проект | Счётчики взяты из отчёта именно этого запуска, не из следующей проверки |
| N-05. Есть ошибки файлов / rebuild не применён | Открыть ошибки, исправить, повторить | «Обновлено с ошибками: N документов» либо «Переиндексация не применена; сохранён прежний индекс» | Частичный результат отличим от успеха; повтор rebuild после смены модели проходит штатное согласие Т-25 |
| N-06. Остановка запрошена; затем итог отмены | Остановить на странице индексации | «Остановка запрошена» → «Отменено»; применённые изменения обычной проверки указаны, rebuild не объявлен применённым | Ответ команды остановки не подменяет терминальный итог; отмена очереди также имеет явный итог |
| N-07. Скачивание → проверка файлов → подготовка | Открыть настройки модели | 100 % скачивания означает «Проверка файлов»/«Подготовка», пока операция активна | Ошибка подготовки после скачивания отображается ошибкой; файлы на диске не дают зелёный результат |
| N-08. Терминальный результат модели | Посмотреть результат | Для download-only: «Файлы модели проверены и готовы»; для загрузки сессии: «Модель готова» | Скачивание без ONNX-сессии не выдаётся за готовность инференса; в карточке указаны модель и вариант |
| N-09. Ошибка операции / действия окна | Исправить причину, повторить доступное действие | Безопасная причина и конкретное действие; ID операции или ID попытки действия | Toast может исчезнуть, ошибка остаётся; повтор — новая попытка, прежний результат сохранён |
| N-10. Операция началась и закончилась между опросами | Открыть центр после следующего опроса | Карточка с явным итогом, даже если прогресс не наблюдался | Два снимка без running не теряют короткую явную операцию |
| N-11. Потеря связи / смена эпохи worker / пропуск истории | Восстановить связь, открыть подробности | Сохранён последний снимок с отметкой «Нет связи»; без доступного итога — «Исход неизвестен» | Никакого успеха по исчезновению; восстановление той же эпохи догружает события и убирает предупреждение связи |
| N-12. Несколько проектов и объединение очереди | Перейти из старой карточки после смены проекта | Открывается закреплённый проект/результат; объединённые запросы ссылаются на одно задание | Новое задание после начала старого имеет другой ID; одинаковые имена и поздние ответы не смешивают проекты |
| N-13. Удалён проект или сменилась его регистрация/модель | Открыть старые подробности / повторить | Сохранён итог; переход объясняет отсутствие цели, повтор недоступен для прежнего поколения | Карточка не открывает текущий чужой проект и не возрождает регистрацию |

Цепочка переходов: очередь → исполнение ↔ подтверждённая пауза → терминальный итог. Запрос остановки возможен из очереди/исполнения/паузы. Итог неизменен; повтор создаёт новый ID. Если подтверждённого итога нет, связь/неизвестность показываются отдельно от последнего известного состояния. Сбой операции получения данных — состояние центра, а не ошибка каждой наблюдаемой операции.

## Контракт этапа 26: доставка, внимание и очистка уведомлений

Инженерное решение: последовательные снимки active + поток завершений с монотонным курсором и эпохой worker. Worker удерживает последние 1000 терминальных событий текущего процесса; ID и последний номер события исключают дубли. Первый снимок нового окна показывает active, старые завершения не объявляются новыми. Открытое/скрытое окно продолжает опрос; после временного разрыва получает пропущенные завершения. При вытеснении событий worker явно сообщает разрыв; для затронутой операции без результата показывается неизвестность. После перезапуска worker история не восстанавливается из логов. Это ограниченная доставка за время жизни процесса, не постоянный журнал. Чтение событий не запускает модели и индексацию.

В окне остаются все активные операции и до 100 последних завершённых карточек. Начало явной операции, ошибка и изменение терминального результата дают непрочитанность; процент, очередь → выполнение и регулярная проверка без изменений — нет. Фоновая проверка без изменений не создаёт отдельную карточку; результат явной проверки показывается всегда. Повторяющаяся нерешённая проблема обновляет одну карточку; ошибка после устранения — новое событие.

| ID / действие | Данные | Результат | Проверка |
|---|---|---|---|
| N-14. Прочитать | ID карточки и версия события | Карточка становится прочитанной только при показе в видимой области панели либо явном «Прочитать все» | Открытие длинного списка не читает невидимые карточки; событие после чтения вновь непрочитано |
| N-15. Очистить завершённые | Текущий набор ID/версий и курсор | Завершённые удалены, активные остаются; очистка не останавливает работу | Повтор того же снимка не возвращает карточки; новый итог активной операции появляется |
| N-16. Перейти / повторить | Закреплённая цель и ID результата/новой попытки | Проект выбран до показа его индексации; модель открыта в настройках; повтор подтверждает только принятие | Ошибка перехода видна; поздний ответ не подменяет выбранную цель; без нужного согласия повтор не запускается |

Порядок: активные сначала; внутри группы — время последнего значимого события по убыванию. Завершённые — по времени итога; изменение процента не переставляет список. Время показывается локально с датой для прошлых дней. Повтор доступен для загрузки модели и штатной проверки/переиндексации; ошибка буфера/запуска ОС предлагает повтор исходного действия. Недоступное действие имеет объяснение. История окна не сохраняется на диск и не очищает логи/MCP-историю.
