# Внедрение панелей рабочего окна

Статус: жизненный цикл зон и миграция раскладки 3.2.4 реализованы 26-10-2026 по согласованному OQ-202; 44 целевые компонентные проверки и 17 программных проверок собранного WebView2 пройдены. Превью и маршрутизация 3.2.5–3.2.6, физические жесты и установленная сборка ещё не проверены. Основа — [требования](requirements.md), [исследование docking](../../knowledge/window-docking.md), [ADR-0003](../../adr/0003-window-docking.md). Старый макет OQ-112 не подтверждает новый жизненный цикл зон.

## Устройство переноса

Левая колонка — обычная разметка вне Dockview (OQ-117): дерево, под ним мини-граф, внизу статус индекса, уведомления, тема и настройки. Разделитель между деревом и мини-графом и разделитель ширины колонки управляются мышью и стрелками; минимальная ширина 220 px. Колонка не закрывается и не перетаскивается. Мини-граф — та же физическая панель, что во вкладке «Граф», в компактном виде; показ «Открыть связи и основания в графе» из выдачи открывает экран «Анализ связей» вкладки «Граф» (его действия переносятся этапом 2.3).

Dockview 8.6.1 с прямым lifecycle-адаптером Svelte держит рабочую область. `closeEmptyGroups: true` удаляет опустевшие группы; `WorkspaceZones` восстанавливает только пустой центр по OQ-163/OQ-202. Целевые места открытия и повторного открытия задаёт [таблица главного окна](main-window.md); полный перевод служебных экранов остаётся в 3.2.6. Состояние смонтированного компонента сохраняется при переносе и переключении вкладки; перенос не является закрытием редактора.

Перенос вкладок: `dndStrategy: "pointer"` — Dockview ведёт жест событиями указателя, а не HTML5 drag-and-drop, который в WebView2 перехватывает обработчик файлов Tauri (ISS-21). Окна bars и стенды создаются с `disable_drag_drop_handler()`; перетаскивание файлов в окно bars не используется.

По уточнениям автора: фильтр документов высотой 24 px, сброс области — иконкой рядом с ним; прежняя нижняя строка области удалена.

Текущая раскладка хранится в localStorage с версией 3 и ключом проекта `bars-workspace-v3:`; версия 2 читается из прежнего ключа для миграции, версия 1 заменяется штатной. JSON содержит дерево групп, их роли и последнюю активность, ширину справа, ширину левой колонки, высоту мини-графа и ссылки на документы, без текста документов, ключей и настроек. При восстановлении документ читается заново через существующий read; поздний ответ прежнего проекта не попадает в новый. Повреждённый формат заменяется штатной композицией с сообщением. Настройки сохраняют собственные Сохранить/Отменить; перенос не перечитывает и не стирает черновик.

Полноценный редактор, автосохранение, ревизии и отдельные окна уже реализованы; их контракт — [проект редактора](../knowledge-base/editor-design.md). Изменение размещения должно сохранить эти функции и защиту несохранённых правок.

## Жизненный цикл правой зоны

Срез 3.2.4: реализация использует явные роли групп и схему v3. Компонентные проверки охватывают закрытие последней вкладки, восстановление центра, память ширины, миграцию и защиту сброса. Нативный сценарий `crates/bars-app/examples/right_zone_probe.js` проверяет продуктовый UI с FakeProvider: создание/закрытие зоны, два перезапуска с миграцией и перечитыванием файла, размеры 760/1090/1110/1440 и возврат сохранённой ширины. Превью края и специальный жест верх/низ относятся к следующему срезу 3.2.5; маршрутизация служебных экранов — к 3.2.6.

Поведение по OQ-163: штатная раскладка — центр с «Поиском», без пустой правой группы. Открытие документа справа или сброс вкладки к правому краю создаёт правую зону. Закрытие/перенос последней вкладки группы удаляет группу; последней группы справа — всю зону. Служебная вкладка, вручную перенесённая вправо, удерживает зону так же, как документ. При разделении верх/низ удаляется только опустевшая часть, соседние вкладки сохраняются. Автоматическое заполнение центра — по правилу мест, после завершения операции, с защитой от повторного запуска обработчиков.

Реализация: `closeEmptyGroups: true` и восстановление пустого центра после завершения операции Dockview. Раскладка различает центр и правую зону явно: по сохранённым ролям групп, не по наличию вкладки «Поиск» (её можно перенести). Новая верхняя/нижняя группа наследует роль зоны; разделение по горизонтальной оси правее центра образует правую зону. Пользовательские разделения центра сохраняются. Целевое открытие новой служебной вкладки в последней активной группе центра, иначе в первой по порядку, относится к полному переводу маршрутизации в 3.2.6. Закрытая группа исключается из указателей последней активности.

Ширина правой зоны запоминается для проекта при изменении разделителя и до удаления последней группы. Размер — общая ширина зоны, а не высота верхней/нижней части. При открытии без сохранённого размера — 40 % доступной рабочей области без левой колонки. Запомненный размер ограничивается доступным местом и минимумами групп Dockview. На узком окне применяется существующая адаптация: вкладки доступны через «Поиск»/«Документы», левая колонка сохраняется; сжатие окна не затирает размер для широкого окна. Минимум группы — 220 px по ширине и 120 px по высоте; переключатели сохраняют прежнюю адаптацию на 760 px и около порога 1100 px.

### Превью переноса и деление

Согласованный контракт 3.2.5; в срез 3.2.4 не входит.

Справа у содержимого крайней группы действует полоса 48 px; вне жеста она не занимает места и не выглядит пустой панелью. Наведение перетаскиваемой вкладки показывает прямоугольник с подписью «Откроется справа». Если зоны ещё нет — размер превью равен будущей зоне: запомненная ширина либо 40 % доступной рабочей области с теми же ограничениями. После сброса приложение задаёт новой группе этот размер: штатные 50 % Dockview не должны расходиться с превью.

Над существующей правой группой её строка вкладок принимает вкладку в текущую группу. Верхняя/нижняя полоса содержимого 48 px показывает половину высоты принимающей группы и подпись «Откроется сверху» / «Откроется снизу»; сброс делит её по высоте с общей шириной. Это разделение одной правой группы, а не создание пустой зоны под всем окном. В углах приоритет у верхней/нижней полосы; при недостаточной высоте для минимумов двух групп деление недоступно, ложного превью нет. Отмена жеста снимает превью без изменения раскладки.

Адаптер использует `dropOverlayModel` для области содержимого и подпись оверлея: `dndEdges` над группой в режиме `pointer` не срабатывает. Превью и итоговый размер рассчитываются одной функцией; во время жеста обновление не сохраняет промежуточную раскладку. Физическая достижимость полос и приоритет углов требуют проверки WebView2.

### Перевод сохранённых раскладок

Текущая версия схемы — 3: дерево групп, их роли, последняя активная группа центра/правой зоны, запомненная ширина справа и существующие размеры навигации. Ключи версии 2 читаются как источник миграции; старая запись остаётся резервным источником, в том числе при ошибке записи версии 3. Повторный запуск после миграции читает только версию 3.

Версия 2: восстановить панели, удалить пустые группы; непустые группы не пересоздавать. Роль центра получает самая левая ветвь сетки, остальные ветви — правой зоны; верх/низ наследуют роль родителя. При единственной непустой группе считать её центром. Если группы пусты, создать центр с «Поиском». Для старой пустой правой ветви сохранить её ширину до удаления; для непустой — восстановленную ширину зоны. Версия 1 сохраняет прежнее поведение замены штатной раскладкой. Повреждённый JSON не блокирует запуск: штатный центр и сообщение, без удаления файлов.

Восстановление выполняется одной операцией: роль/активность/размеры нормализуются до включения обработчиков автосохранения раскладки. Документы перечитываются, фокус возвращается к существующей активной вкладке; удалённый документ показывает существующую ошибку чтения, а не исчезает молча. Миграция не меняет текст, состояние индекса и настройки. Сброс раскладки оставляет центр с «Поиском»; открытые изменённые буферы проходят защиту редактора до перестройки, отмена отменяет весь сброс.

## Проверки реализации правила мест

| Сценарий | Проверяемый результат |
|---|---|
| Первый запуск, сброс; закрытие последней вкладки справа | Нет пустой правой половины; центр доступен; отмена закрытия сохраняет раскладку и текст |
| Дерево, оба режима поиска, глобальный поиск, граф, аудит, новая тема, ссылка, `Ctrl+O` | Место по таблице; найденные строки и исходный экран сохранены |
| Тот же документ после переноса в центр; явное «Открыть справа» | Обычное открытие активирует на месте; явное переносит; один буфер без потери истории |
| Справа сверху/снизу документы и служебные вкладки | Закрытие одной части не убирает другую; последняя вкладка любого вида удаляет зону |
| Уход последней вкладки центра; поиск справа; поиск и граф справа | Центр восстанавливается по трём веткам правила, без дубликатов и цикла событий |
| Полоса края; верх/низ; отмена; угол; слишком малая группа | Подпись и размер совпадают с результатом; недоступное деление не предлагается |
| Перезапуск, другой проект, сжатие/расширение, раскладки v1/v2/v3 и повреждённая | Размеры/роли/документы восстановлены по правилам; пустые группы не возвращаются |
| Обе темы; 760 px, около 1100 px и широкое окно | Вкладки, фокус и превью читаемы; физические мышь/клавиатура в WebView2 |

Компонентные проверки маршрутизации и сериализации дополняются программным прогоном собранного окна и физическими жестами. Установка остаётся отдельно ограничена OQ-106/OQ-113; браузерная проба не считается приёмкой установленной версии.

## Оставшиеся работы

- Физические жесты docking в настоящем окне и сверка с макетом автором (ISS-21); программные DOM-действия и синтетические PointerEvent стенда их не заменяют. Прогон 3.2.4 использует `workspace_probe` с внешним `crates/bars-app/examples/right_zone_probe.js`, временный профиль и FakeProvider; это не установленное приложение и не настоящая модель. Сценарий `workspace_probe.js` по умолчанию относится к раннему каркасу: в нём ещё есть проверки v2 и постоянной пустой зоны, поэтому он не является приёмкой 3.2.4.
- Установленная сборка: трей, меню проекта, Вставить, иконки, обычный установщик, другая папка, другой пользователь, настоящий вход в систему. Рабочее приложение не останавливать; установка только по согласованию OQ-106. Отсутствующие проверки записать точно, ISS-14 по фикстуре не закрывать.
