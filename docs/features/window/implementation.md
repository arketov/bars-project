# Как устроено окно bars

Реализация дизайна из [Index.md](Index.md): оболочка Tauri в `crates/bars-app`, интерфейс в `ui/`. Решения агента, 15-10-2026; то, чего нет в мокапах, собрано в OQ-63.

## Связь окна с воркером

Окно и воркер — один процесс (Т-1), канал окну не нужен. Оболочка держит обработчик методов воркера, который `serve_with` отдаёт, как только воркер поднят, а интерфейс вызывает его одной командой Tauri `bars_call(method, params)`: она разбирает вызов тем же `Call::from_request`, что и канал, и зовёт `dispatch`. Ответы и ошибки те же, что видят агенты, поэтому в окне `kind` ошибки (`provider_error`, `reindex_required`) означает то же самое (Т-20). До готовности воркера команда отвечает «воркер ещё запускается».

Остальные команды Tauri — действия ОС, которых у воркера нет: `pick_folder` (диалог выбора папки), `open_path` («В редакторе», «Открыть папку проекта»), `bars_dir`, `restart_app` (перезапуск всего процесса, OQ-57). Окно не получает прав на файловую систему и оболочку: в `capabilities/default.json` только `core:default`, а CSP запрещает всё, кроме своих файлов и канала команд.

События идут в обратную сторону одним именем `bars://navigate` (экран и проект): им трей и второй запуск открывают нужное место. Остальное интерфейс спрашивает сам опросом раз в секунду (`activity`, `models_info` — общий снимок для настроек и [центра уведомлений](notifications.md)), а список проектов — реже, при переменах в очереди и раз в пять секунд: он открывает индексы.

## Окно, трей и один экземпляр

- **Окно** создаётся один раз при старте: видимым, а с `--background` скрытым. Закрытие его прячет, воркер остаётся в трее (Т-1). Тема и выбранный проект запоминаются в `localStorage` окна.
- **Один экземпляр.** `tauri-plugin-single-instance` передаёт второй запуск работающему экземпляру; тот показывает окно, если запуск был без `--background`, а новый процесс завершается. Канал остаётся второй защитой от двух воркеров ([architecture/ipc.md](../../architecture/ipc.md)).
- **Трей.** Иконка рисуется в коде (`icons.rs`): скруглённый квадрат цвета состояния с буквой «b», серый, малиновый (мигает) или жёлтый. Состояние и строки меню даёт `Worker::summary` ([architecture/worker.md](../../architecture/worker.md)); оболочка опрашивает его дважды в секунду и меняет иконку, только когда что-то изменилось. Меню: «Открыть bars», строка индексации и строка внимания (открывают окно), «Проекты (N)», «Настройки», «Выход». Двойной клик по иконке открывает окно; на этом экземпляре одиночный клик делает то же. «Выход» останавливает воркер (дописывает текущий документ) и завершает процесс.

## Интерфейс на Svelte

`ui/src` — Svelte 5 (руны), TypeScript, Vite, без SvelteKit ([architecture/components.md](../../architecture/components.md)). Стили — `theme.css` и `states.css`, скопированные из мокапов; пересекающиеся имена (`.card`, `.row`, `.bar`) в общем файле переименованы (`.panel`, `.hrow`, `.pbar`), остальные стили лежат в компонентах.

| Файл | Что делает |
|---|---|
| `lib/app.svelte.ts` | состояние окна: проекты, дерево, выбор, поиск, просмотр, ход индексации, опрос воркера |
| `lib/settings.svelte.ts` | экран настроек: черновик и сохранённое, модели, клиенты, ключи, ожидание диалога согласия |
| `lib/tree.ts` | дерево «модуль → папки → файлы» с галочками, область поиска (модули целиком — в `modules`, остальное — файлами), фильтр |
| `lib/markdown.ts` | Markdown документа блоками с подсветкой найденных строк; сырой HTML показывается текстом, ссылки не активны |
| `lib/format.ts`, `errors.ts`, `consent.ts`, `settings-logic.ts` | подписи, объяснение ошибок, итог диалога согласия, проверка значений настроек |
| `lib/api.ts`, `mock.ts` | вызов воркера, команды ОС; вне Tauri — заглушка воркера для просмотра в браузере |
| `Sidebar`, `SearchPane`, `ResultCard`, `Viewer`, `IndexingPage`, `SettingsPage`, `ConsentDialog`, … | экраны мокапов |

Логика без интерфейса (дерево, форматирование, Markdown, ошибки, настройки, согласие) покрыта тестами vitest, остальное проверяется в браузере на заглушке и в собранном приложении ([knowledge/build.md](../../knowledge/build.md)).

## Что окно делает сверх мокапов

- **Пустая выдача.** Мокап показывает «лучший кандидат получил 0,18», а воркер ниже порога ничего не отдаёт. Окно повторяет запрос с порогом 0 и одним результатом: воркер прижимает порог к нижнему пределу из настроек, а окно берёт из ответа лучшую оценку и этот предел для кнопки «Порог N для этого запроса». Порог не обходится: слабые результаты приходят только после нажатия кнопки и на один запрос.
- **Тема** хранится в `localStorage` окна, а не в `settings.toml`: это оформление окна, а не параметр поиска, воркеру она не нужна.
- **Устройства** embed/rerank задаются независимо. `models_info.runtime` показывает состояние сессий и CPU-fallback, плитка хода индексации — устройство embed текущего задания (OQ-62).
- **Модель не скачана.** Пока модель скачивается или грузится, воркер отвечает `model_loading` с `data.percent`; окно показывает баннер и само повторяет поиск раз в две секунды. Ошибку фоновой загрузки воркер возвращает как `provider_error` (OQ-48); при встроенной модели окно разбирает текст и показывает «не удалось скачать» или «файлы не найдены». Кнопки «Повторить» и «Скачать заново» повторяют поиск, который заново пробует скачать недостающее.
- **Клиенты.** Одобрен ли хук в Codex, bars не видит, поэтому метка «хук ждёт одобрения» стоит, пока Codex установлен. Метка «пути устарели» и кнопка «Переустановить» — для записей, указывающих на прежнее расположение `bars-mcp` и `bars-cli`.
- **Поиск.** Вкладка «Поиск» получила поля `rerank_candidates` и `max_rerank_candidates`, которых нет в мокапе, но которые есть в [features/settings/settings.md](../settings/settings.md); вкладка «Модели» — выбор устройства для встроенных моделей.
- **Размер модели** в диалоге согласия не показан: каталог размеров не хранит (OQ-63).

## Иконка приложения

Иконка exe, установщика и окна — скруглённый малиновый квадрат с белой буквой «b» (OQ-72), та же фигура, что у иконки трея в `crates/bars-app/src/icons.rs`. Файлы `crates/bars-app/icons/icon.png` (256 px) и `icon.ico` (16–256 px) получаются скриптом `scripts/make-icon.py` (нужен Pillow): поменялась фигура в `icons.rs` — поправь её и в скрипте и запусти его заново. Tauri берёт файлы из `bundle.icon` в `tauri.conf.json`: из `icon.ico` строится ресурс exe, он же идёт в установщик, а окно получает иконку по умолчанию из той же конфигурации.
