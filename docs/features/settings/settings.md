# Настройки bars — ключи settings.toml и config.toml, значения по умолчанию

Какие настройки есть у bars, где они лежат и что делает их изменение (Т-16, Т-18, Т-24). Где лежат файлы и в каком порядке берутся значения — [files.md](../../architecture/files.md). Окно правит эти же файлы через воркер (методы `settings_get` и `settings_save`, [architecture/protocol.md](../../architecture/protocol.md); как именно воркер пишет файл — [architecture/worker.md](../../architecture/worker.md)). Ручная правка допустима: значения перечитываются при обработке заданий и запросов, отдельного слежения за файлами настроек нет. Окно пишет в `settings.toml` только пользовательские ключи; `.bars/config.toml` оно правит единственным ключом `docs_root` («Выбрать другую папку документации…»). Тема окна ключом настроек не является: она хранится в самом окне ([features/window/implementation.md](../window/implementation.md)). Автозапуск при входе в систему тоже не ключ: это запись в ОС, её читает и пишет воркер ([features/distribution/autostart.md](../distribution/autostart.md)).

## Embed-модель в settings.toml

Таблица `[embed]` — модель для всех проектов (Т-16, Т-17):

| Ключ | По умолчанию | Значение |
|---|---|---|
| `source` | `builtin` | `builtin` — встроенная; `remote` — удалённый провайдер; `local-openai` — OpenAI-совместимый адрес; `ollama` — нативный embed API Ollama; `lmstudio` — OpenAI embed API LM Studio; `tei` — нативный API Text Embeddings Inference |
| `model` | `BAAI/bge-m3` | для `builtin` — модель из каталога [features/models/local-models.md](../models/local-models.md); для остальных — имя модели у провайдера |
| `base_url` | — | адрес провайдера; для `ollama` — корень, например `http://127.0.0.1:11434`, без `/api` и `/v1` |
| `api_key_name` | — | имя записи в хранилище ОС ([architecture/secrets.md](../../architecture/secrets.md)) |
| `api_key_env` | — | имя переменной окружения, которая перекрывает ключ из хранилища |
| `batch_size` | `32` | сколько чанков в одном запросе к внешнему провайдеру |

## Rerank-модель в settings.toml

Таблица `[rerank]` — те же ключи, что у `[embed]`, кроме `batch_size`, плюс `enabled`:

| Ключ | По умолчанию | Значение |
|---|---|---|
| `enabled` | `false` | включён ли реранк (Т-16) |
| `source` | `builtin` | `builtin`, `remote`, `local-openai`, `tei`; Ollama и LM Studio не поддерживают штатный rerank API |
| `model` | `BAAI/bge-reranker-v2-m3` | Т-17 |

Реранк по умолчанию выключен. [Замер IDEA-06 от 18-10-2026](../../knowledge/search-quality.md) на i7-11700KF и RTX 3090 24 ГБ подтвердил компромисс: без порога rerank чаще ставит правильный раздел первым, но полный запрос на отложенной части занимает в медиане 0,658 с против 0,126 с без него; порог 0,1 теряет часть правильных ответов. CPU-контроль тех же запросов занимает секунды. Включение остаётся выбором пользователя. Общая глубина 15 сохранена: сокращение до 8 теряет покрытие правильных разделов первого этапа, а увеличение до 30 не дало достаточного выигрыша на обучающей части.

## Параметры поиска в settings.toml

Таблица `[search]` (Т-18, Т-24):

| Ключ | По умолчанию | Значение |
|---|---|---|
| `candidates` | `30` | сколько кандидатов берёт каждый из двух поисков |
| `rerank_candidates` | `15` | сколько лучших после слияния уходит в реранк |
| `results` | `5` | результатов без реранка |
| `results_reranked` | `3` | результатов с реранком |
| `min_score_vector` | `0.0` | порог по косинусной близости без реранка |
| `min_score_rerank` | `0.1` | порог по оценке реранка |
| `agent_min_score` | `[0.0, 1.0]` | пределы, в которых агент может задать свой порог (Т-24) |
| `max_results` | `20` | больше этого числа результатов агент запросить не может |
| `max_candidates` | `100` | больше этого числа кандидатов агент запросить не может |
| `max_rerank_candidates` | `50` | больше этого числа кандидатов на реранк агент запросить не может |

Пороги оставлены после [проверки на ai-mutiplayer-bots и bars](../../knowledge/search-quality.md#отложенная-часть-и-пороги). `0.1` у rerank — компромисс отсечения ложной выдачи и потери правильных ответов; это не гарантия, что всё ниже порога нерелевантно. На большом корпусе есть релевантные разделы с низкими оценками, подтверждёнными и на CPU. Более высокие испытанные пороги теряют больше ответов. Порог косинуса по умолчанию выключен: устойчивого отсечения шума без потерь замер не показал. Заводские значения не заменяют настройки пользователя и проекта.

Обе оценки лежат в диапазоне от 0 до 1. Косинусная близость нормализованных векторов на практике не бывает отрицательной. Встроенный rerank возвращает сырой логит, поэтому bars пропускает его через сигмоиду. Внешний rerank в формате Cohere уже отдаёт `relevance_score` от 0 до 1. Поэтому у порога и его пределов один масштаб, какой бы ни была модель.

Число результатов и кандидатов из вызова агента сверх `max_results`, `max_candidates` и `max_rerank_candidates` прижимается к пределу, как и порог (Т-18, Т-24).

## Устройство для встроенных моделей в settings.toml

Независимый ключ `accelerator` в `[embed]` и `[rerank]`:

Для встроенного rerank DirectML выбирает FP16, CPU — FP32; INT8 не включён из-за обнаруженных потерь при текущем пороге. Tokenizer остаётся на CPU. Выбор precision и ограниченное уменьшение GPU-пачки при нехватке памяти описаны в [моделях](../models/local-models.md); отдельного пользовательского ключа precision нет.

Для embed FP16 выбирается отдельная модель `BAAI/bge-m3:fp16` на Windows. Окно устанавливает DirectML; CPU у этого профиля недоступен. Смена обычной bge-m3 на FP16 или обратно меняет fingerprint и требует согласия на переиндексацию по Т-25. При недоступной GPU автоматического перехода FP16 → FP32 нет; обычная bge-m3 сохраняет прежний CPU fallback и остаётся заводским выбором. Проверки FP16 embed.

| Ключ | По умолчанию | Значение |
|---|---|---|
| `accelerator` | `auto` | `auto` — видеокарта, если она есть (DirectML на Windows), иначе CPU; `cpu` — только процессор |

Видеокарта выбрана по умолчанию даже без прироста скорости: она снимает нагрузку с процессора (OQ-27). Смена устройства не меняет отпечаток индекса и не требует переиндексации (`features/models/local-models.md`). Перезагружается только соответствующая модель; текущая работа заканчивает прежний снимок настроек. Candle работает на CPU, устройство внешнего провайдера bars неизвестно. Окно отдельно показывает предпочтение и устройство загруженной сессии с причиной CPU-fallback.

Старый `[device].accelerator` читается как исходное значение обеих моделей с предупреждением; явные новые ключи имеют приоритет каждый для своей модели. При следующем сохранении общий ключ переносится в две таблицы; остальные ключи и комментарии сохраняются. Само чтение файл не меняет.

## Выгрузка встроенных моделей из памяти в settings.toml

Ключ `unload_after_minutes` в `[embed]` и `[rerank]` — через сколько минут простоя воркер выгружает встроенную модель из памяти (решение автора 19-10-2026, ISS-18). Как идёт выгрузка — [local-models.md](../models/local-models.md).

| Ключ | По умолчанию | Значение |
|---|---|---|
| `embed.unload_after_minutes` | `15` | минут простоя до выгрузки embed; `0` — не выгружать |
| `rerank.unload_after_minutes` | `5` | минут простоя до выгрузки rerank; `0` — не выгружать, пока rerank включён |

Больше 10 080 минут (неделя) — ошибка чтения: для «никогда» есть `0`. Выключенный rerank выгружается сразу при любом значении. Срок не входит в отпечаток модели и в её настройки: его смена не перезагружает модель и не трогает индекс. Внешние модели не выгружаются, ключ на них не влияет.

## Пауза перед индексацией правки в settings.toml

Таблица `[indexing]` (Т-41, [очередь документов](../indexing/document-queue.md)):

| Ключ | По умолчанию | Значение |
|---|---|---|
| `edit_pause_seconds` | `30` | сколько секунд после последней правки документа bars ждёт, прежде чем пересчитывать его; `0` — без паузы |

Больше 3600 секунд (час) — ошибка чтения: для «не ждать» есть `0`. Пауза относится к правкам из окна и событиям слежения за файлами; проверки при старте, раз в час и явные команды её не ждут. В окне — раздел «Индексация», поле «Пауза, секунд», применение кнопкой «Сохранить». Воркер подхватывает новое значение при следующей правке; уже назначенное ожидание не пересчитывается.

Умолчание 30 секунд задано Т-41. Замер на 8 тысячах правок агентов за шесть недель ([умолчания индексации](../../knowledge/indexing-defaults.md)): пауза 30 с убирает 44 % вызовов embed, 15 с — 42 %, 10 с — 40 %, 5 с — 33 %. Правка ждёт embed не дольше 50 с в 90 % случаев при 30 с и 29 с при 15 с. На число заданий индексации пауза почти не влияет. Предложение снизить умолчание до 15 с — OQ-183, до ответа автора действует 30 с.

## Почасовая проверка — не настройка

Проверка всех зарегистрированных проектов раз в час — константа `PERIODIC_INTERVAL`, ключа в `settings.toml` нет. По решению автора OQ-206 это независимая проверка `scan`: без расхождений она не создаёт задания обновления и не загружает модель. Слежение ограничено активностью MCP и открытыми окнами; правила — [обновление индекса](../indexing/updates.md). Прежние оценки стоимости 15-минутного такта относятся к реализации до этого изменения и не являются замером нынешнего пути.

## Как bars читает файлы настроек

Читает `bars-core`, модуль `settings`; домашнюю папку bars ему передаёт вызывающий. Файлы только читаются.

- **Нет файла** — заводские значения. Файл при этом не создаётся.
- **Незаданный ключ или таблица** — значение с нижнего слоя: пользовательское, а за ним заводское. Значения накладываются по ключам, а не по таблицам: `config.toml` с одним `results` меняет только `results`.
- **Ошибка в файле** — битый TOML, неверный тип или выбор (`source = "cloud"`), нулевое число кандидатов, результатов, пачки или размера чанка, оценка вне 0…1, `agent_min_score` с нижним пределом выше верхнего (OQ-32). Чтение возвращает ошибку с именем файла и ключом, файл целиком не применяется. Воркер продолжает работать на прежних настройках и показывает причину в окне. Молча подставить умолчания нельзя: так можно незаметно перестроить индекс с другой нарезкой.
- **Неизвестный ключ или таблица** — опечатка или ключ из другой версии (OQ-33). Он игнорируется, а в ответ чтения идёт предупреждение с файлом и ключом вида `search.min_char`. Так файл новой версии открывается в старой. Ключи моделей в `.bars/config.toml` тоже неизвестные: модели задаются только в `settings.toml`.
- **`min_chars` выше `max_chars`** — не ошибка: нарезка прижимает минимум к максимуму ([features/indexing/chunking.md](../indexing/chunking.md)).
- **Корень документации** при чтении не проверяется: его проверяет обход файлов ([features/indexing/updates.md](../indexing/updates.md)).
- **Поля провайдера** проверяются при чтении (решение агента, OQ-59). Ошибка чтения с файлом и ключом, если:
  - `source = "builtin"`, а `embed.model` нет во встроенном каталоге ([features/models/local-models.md](../models/local-models.md)), или `rerank.model` не `BAAI/bge-reranker-v2-m3`;
  - источник `remote` или `local-openai` без `model` (умолчание `bge-m3` провайдеру не подходит) или без `base_url`; адрес не `http://`/`https://`, без хоста, с пробелами или с логином и паролем;
  - источник `remote` без `api_key_name` и без `api_key_env`: удалённому провайдеру нужен ключ, локальному — нет;
  - `model`, `api_key_name` или `api_key_env` заданы пустыми.

  Таблица `[rerank]` проверяется, только если `enabled = true`: окно может сохранять её по шагам. Само наличие ключа в хранилище при чтении не проверяется; нет ключа — ошибка при первом запросе к провайдеру.

## Сохранение настроек из окна: версия файла и слияние по полям

Статус: реализовано 26-10-2026 по решению автора OQ-173. Полный `scripts/check.ps1` зелёный; четыре новые регрессии записи, девять регрессий сохранности UI и девять проверок собранного Tauri/WebView2 прошли. Установленная сборка и физическая клавиатура не проверены. Общий принцип и диалоги несохранённого — [editor-design.md](../knowledge-base/editor-design.md), раздел «Модель конфликтов и несохранённого».

- **Версия файла.** `settings_get` возвращает `revision` — `размер-хеш blake3` байтов `settings.toml`, как у документа ([протокол](../../architecture/protocol.md)); файла нет — `null`. Окно хранит `base` (настройки, как их прочитали) и `revision`.
- **Черновик.** Окно перечитывает файл при каждом открытии экрана настроек. Черновик, равный `base`, заменяется свежим чтением. Изменённый остаётся; версия файла сверяется при возвращении фокуса окну и при сохранении.
- **Что отправляется.** `settings_save` получает `base` — исходный снимок, `changes` — только поля, где черновик отличается от `base` (ключ вида `таблица.ключ` и значение), и `expected_revision`. Остальные ключи файла, комментарии и порядок воркер не трогает.
- **Что делает воркер.** Читает файл и считает его ревизию. Совпала с `expected_revision` — записывает `changes`. Не совпала — смотрит, какие ключи изменились снаружи относительно `base`: если среди них нет ключа из `changes` с другим значением, записывает `changes` поверх нового файла (слияние, внешняя правка другого ключа не блокирует сохранение). Иначе ничего не пишет и отвечает `conflict` со списком полей: ключ, значение в `base`, на диске, моё.
- **Конфликт.** Над формой полоса «settings.toml изменён вне окна» со списком конфликтующих полей и двумя выборами. «Взять с диска» ставит в эти поля значения с диска и обновляет `base` и `revision`; остальные правки пользователя остаются, сохранение — отдельное действие. «Оставить моё» повторяет сохранение с текущей ревизией из ответа `conflict`: перезаписать диск в обход сверки нельзя.
- **Уход с экрана.** Выход из настроек («К поиску», другой раздел) с изменённым черновиком спрашивает «Сохранить / Не сохранять / Остаться»; «Сохранить» с конфликтом оставляет пользователя на экране. Закрытие окна в трей черновик не трогает. Выход из процесса черновик настроек не проверяет: НФТ-5 говорит о правках документов.
- **После записи.** Ответ несёт новую `revision` и `settings` как они стали после слияния, окно обновляет `base` и черновик из него. Запись остаётся атомарной, итоговый текст проверяется тем же разбором, что при чтении; воркер ставит проекты на проверку, как описано ниже.

Замок воркера упорядочивает чтение и сохранение из разных окон; повторная сверка текста перед записью отказывает при новом внешнем изменении. Ручной редактор замок bars не использует: интервал между последней сверкой и атомарным переименованием не исключён. Битый TOML и ошибка доступа оставляют черновик; окно запрещает запись до успешного чтения файла.

Образец сверки ревизии — сохранение карты клавиш ([keyboard-design.md](../window/keyboard-design.md)): там профиль меняется целиком, здесь по полям, потому что в `settings.toml` пишут и вручную.

## Что происходит при изменении настроек bars

При сохранении внешнего источника имя модели записывается явно, даже если совпадает с унаследованным именем встроенной BGE. Иначе файл с новым `source`, но без обязательного `model`, не проходит собственную проверку. Это относится независимо к embed и rerank; существующий комментарий при неизменном явно записанном имени сохраняется.

| Что изменили | Что делает воркер |
|---|---|
| `[embed]` так, что изменился отпечаток модели (источник, модель, префикс документа; у внешней модели — и размерность, когда она известна) | проекты переходят в `reindex_required` (Т-25); эмбеддинг не запускается, пока человек не согласится |
| `[rerank]` | новая модель грузится при следующем реранке; индекс не трогается |
| `embed.accelerator` / `rerank.accelerator` | перезагружается только соответствующая встроенная модель; текущая работа заканчивает свой снимок настроек, индекс не трогается |
| `embed.unload_after_minutes` / `rerank.unload_after_minutes` | новый срок действует с ближайшей проверки простоя: сохранение из окна будит её сразу, ручная правка — в пределах 10 секунд; модель не перезагружается |
| `[search]` | действует со следующего поиска |
| `[chunking]` или `docs_root` | проект ставится на полную проверку: все документы режутся заново. Векторы неизменившихся чанков переиспользуются по хешу (НФТ-1); согласие не нужно, потому что модель та же |

Параметры нарезки, которыми построен индекс, записаны в `meta` индекса ([schema.md](../../architecture/schema.md)). По ним воркер и узнаёт, что нарезка изменилась, даже если файл правили при выключенном воркере.
