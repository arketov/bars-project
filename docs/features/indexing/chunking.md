# Нарезка документа на чанки

Статус 01-11-2026: реестры проверены 31 тестом чистой нарезки, сохранностью диапазонов на двух корпусах и 5 проверками собранного Tauri/WebView2 с FakeProvider; общий гейт ещё выполняется. Новый замер качества моделей и установленная сборка не проверены.

Как bars превращает Markdown-файл в чанки по требованию Т-23. Размеры по умолчанию — из Т-18: минимум 250, максимум 6000 символов. Размер считается в символах Unicode, а не в байтах. Если минимум выше максимума, минимум прижимается к максимуму.

## Разбор документа перед нарезкой

1. Файл читается как UTF-8; BOM отбрасывается. Переводы строк `CRLF` и `CR` приводятся к `LF` до любого разбора (урок 1 образца). Номера строк при этом не меняются: одна строка остаётся одной строкой.
2. Frontmatter в начале файла (`---` … `---`) отрезается. Из него читается только `title` документа (Т-11); значение в кавычках берётся без кавычек. Номера строк считаются по исходному файлу, вместе с frontmatter.
3. Заголовки — только ATX: строки `#`…`######` с пробелом после решёток и непустым текстом. Строки внутри огороженных блоков кода (```` ``` ```` и `~~~`) заголовками не считаются. Setext-заголовки (текст с подчёркиванием `===` или `---`) bars не распознаёт; `BARS_INSTRUCTION.md` просит их не использовать.

## Дерево разделов документа

Документ превращается в дерево разделов. Раздел — заголовок и текст до следующего заголовка любого уровня. Родитель раздела — ближайший заголовок выше с меньшим уровнем. Текст до первого заголовка — раздел-вступление; его цепочка заголовков — `title` документа или имя файла. Имя файла без `.md` заменяет `title` и везде, где показывается заголовок документа, если в frontmatter его нет (Т-11).

Цепочка заголовков раздела — заголовки от корня до него через `/`: `Заголовок 1/Заголовок 2/Заголовок 3.1`. Решётки в цепочку не входят, `title` документа в неё не добавляется. Раздел-вступление без текста не даёт чанка.

## Один раздел — один чанк

Каждый раздел даёт свой чанк. Текст чанка — собственный текст раздела, без подразделов и без строки самого заголовка: заголовок уже стоит в цепочке. Если у раздела есть подразделы, в конец чанка добавляется список их заголовков (только прямых детей), как в образце автора:

```text
Заголовок 1/Заголовок 2/
В этом разделе уточнение бла бла
other headers:
### Заголовок 3.1
### Заголовок 3.2
```

Список не входит в подсчёт размера чанка. У раздела, разрезанного на несколько чанков, он стоит в последнем. У чанка, который получился склейкой нескольких разделов, списка нет: заголовки склеенных разделов уже в его тексте, а остальные подразделы видны по их собственным чанкам.

Размер чанка считается в символах Unicode по тексту без списка подзаголовков.

Номер первой строки чанка — строка заголовка раздела; у раздела-вступления — первая непустая строка. У второго и следующих чанков большого раздела — первая строка их текста. Номер последней строки — последняя строка текста чанка; у раздела без текста он равен номеру строки заголовка.

## Большой раздел: дорезка по абзацам

Раздел длиннее максимума режется на несколько чанков с одной и той же цепочкой заголовков. Граница ищется в таком порядке:

1. пустая строка между абзацами;
2. конец строки;
3. жёсткий разрез по максимуму — только если одна строка длиннее максимума.

Огороженный блок кода и таблица не разрезаются посередине, если помещаются в максимум целиком. Блок длиннее максимума режется по строкам. Абзацы в одном чанке разделяются одной пустой строкой, сколько бы их ни было в файле; у раздела, который не режется, текст остаётся как в файле.

Для разделов с реестрами действует отдельное окно, описанное в разделе «Таблицы и списки реестров».

Каждая часть большого раздела, у которой есть продолжение, заканчивается точным суффиксом ` ...(truncated)`. Последняя часть и неразрезанные разделы — без суффикса. Маркер добавляется после нарезки: не входит в лимит исходного текста, не меняет номера строк и диапазоны исходника; входит в выдачу и текст для эмбеддинга.

## Таблицы и списки реестров

Контракт 6.3.2: вариант B из [бенча качества](../../knowledge/search-quality.md), OQ-159, OQ-178, OQ-179. Проверки реализации фиксируются в журнале сессии. Порог `min_score_rerank=0.1` сохраняется; окно 1500 символов — приближение для 512 токенов, а не гарантия вместимости любой пары с запросом.

Реестр — Markdown-таблица с ведущими `|`, строкой-разделителем шапки и минимум двумя строками данных либо список из минимум трёх подряд пунктов с идентификатором в начале (`Т-25`, `ISS-18`, `№48`). Допускаются маркеры `-`, `*`, нумерация `1.`, выделение `**` и чекбоксы. Отступленные продолжения остаются с пунктом. Примеры внутри огороженного кода реестрами не считаются.

Раздел с реестром режется с пределом `min(max_chars, 1500)`; шапка входит в этот предел. Таблица режется между строками, список — между пунктами, остальной текст — по абзацам. В продолжении таблицы повторяются обе строки шапки; цепочка заголовков сохраняется. Короткие разделы с реестрами сохраняются целиком. Склейка с соседями и добор до минимума не увеличивают предел реестра. Обычные разделы сохраняют прежний предел и нарезку.

Строка таблицы или пункт длиннее окна режется по строкам, затем по символам Unicode; шапка таблицы повторяется, пока в окне остаётся место хотя бы для одного символа строки. Если сама шапка занимает всё окно, таблица режется обычным способом без повторения шапки. Текст не пропадает, превышение `max_chars` не допускается. Служебные ` ...(truncated)` и `other headers:` остаются вне предела, как у обычной нарезки.

Первая часть начинается со строки заголовка раздела, продолжения — со своей первой строки данных. Повторённая шапка не расширяет диапазон продолжения к началу таблицы. Исходные диапазоны GraphRAG включают только собственные строки и символы, без копий шапки, padding и служебного текста; BOM и CRLF учитываются при переводе диапазонов в исходный файл.

## Маленький раздел: склейка

Раздел, у которого собственный текст короче минимума, склеивается со следующим разделом документа (Т-23, OQ-20). Следующий раздел приклеивается целиком, если вместе они не превышают максимум. У склеенного чанка цепочка заголовков и номер первой строки — от первого раздела, номер последней строки — от последнего склеенного, а заголовок каждого следующего раздела остаётся в тексте строкой с решётками. Склейка повторяется, пока чанк не дорастёт до минимума или не упрётся в максимум. Склеиваются только неразрезанные разделы: большой раздел, режущийся на несколько чанков, к соседу не приклеивается.

Последний маленький раздел документа приклеивается к предыдущему чанку, если вместе они не превышают максимум.

Если склеить нельзя (следующий раздел не помещается в максимум или режется на части, а предыдущего чанка для последнего раздела нет или он не вмещает), чанк добирается до минимума копией символов из текста выше: берутся последние символы текста предыдущих чанков, ровно столько, сколько не хватает до минимума, и ставятся перед текстом чанка через пустую строку. Это копия, а не перенос. Номера строк чанка при этом не меняются. Если выше текста нет (начало документа) или его не хватает, чанк остаётся короче минимума.

## Текст чанка для эмбеддинга

В эмбеддинг идёт весь чанк, кроме номера строки (Т-23, OQ-19):

```text
path: docs/test/test_file.md
Заголовок 1/Заголовок 2/Заголовок 3.1
<текст чанка>
```

Префикс документа модели, если он есть, добавляется перед этим текстом ([features/models/local-models.md](../models/local-models.md)). Номер первой и последней строки чанка хранится рядом как метаданные и показывается в выдаче.

Из этого следует: правка внутри раздела меняет только его чанки; вставка строк выше сдвигает номера строк, но не текст для эмбеддинга, поэтому векторы переиспользуются (НФТ-1). Переименование файла меняет `path:` и требует нового эмбеддинга чанков этого файла.
