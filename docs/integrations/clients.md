# Подключение bars к агентским клиентам

Что делает установка в клиент (Т-21). Её запускают `bars-cli install`, пункт «Установить» в окне или сам агент по текстовой инструкции.

## Что прописывается в клиенте

Две записи с именем `bars`:

- **MCP-сервер** — команда `bars-mcp` по абсолютному пути, транспорт stdio;
- **хук начала сессии** — команда `bars-cli hook session-start` по абсолютному пути ([agent-tools/cli.md](../agent-tools/cli.md)).

## Claude Code

| Запись | Файл |
|---|---|
| MCP-сервер | `~/.claude.json`, раздел `mcpServers.bars` (уровень пользователя) |
| Хук | `~/.claude/settings.json`, `hooks.SessionStart`, срабатывает на `startup` и `resume` |

## Codex

| Запись | Файл |
|---|---|
| MCP-сервер | `~/.codex/config.toml`, таблица `[mcp_servers.bars]` |
| Хук | `~/.codex/hooks.json`, событие `SessionStart`, срабатывает на `startup` и `resume`; формат записи тот же, что у Claude Code |

Codex не запускает новый или изменённый хук, пока пользователь не одобрит его командой `/hooks` в Codex; одобрение привязано к хешу записи. Поэтому после установки в Codex и после каждого её обновления bars сообщает пользователю (в окне и в выводе `bars-cli install`), что хук нужно одобрить. Пока хук не одобрен, MCP работает, а проект регистрируется окном или CLI.

Проектный `.codex/` bars не использует: Codex грузит его только для доверенных проектов.

## Другие MCP-клиенты

Любой клиент, который умеет запускать stdio-MCP (например, чат Claude Desktop через `claude_desktop_config.json`), подключает `bars-mcp` вручную по текстовой инструкции. Хука у таких клиентов нет: проект регистрируется в окне или через CLI, а актуальность держит воркер (Т-10).

## Как bars правит чужие конфиги

- Перед правкой bars сохраняет копию файла рядом: `<файл>.bars-backup`.
- Меняются только записи с именем `bars`; остальное содержимое и порядок ключей сохраняются.
- Повторная установка обновляет пути в своих записях и не создаёт дублей.
- Абсолютные пути к `bars-mcp` и `bars-cli` bars строит от расположения своего exe: оно зависит от установщика (MSI, NSIS, `.app`). Если приложение переехало, воркер при старте замечает, что пути в записях устарели, и предлагает переустановить.
- `~/.claude.json` одновременно пишет сам Claude Code, поэтому bars перечитывает его прямо перед записью и пишет атомарно, через временный файл и переименование.
- Чем правятся файлы: `toml_edit` для `config.toml` Codex, `jsonc-parser` для `settings.json` и `hooks.json` (форматирование сохраняется), `serde_json` с сохранением порядка ключей для `~/.claude.json` ([architecture/stack.md](../architecture/stack.md)).
- Удаление убирает только записи `bars` (Т-21).
- Если файл не разбирается как JSON или TOML, bars ничего не пишет и сообщает об ошибке.

## Текстовая инструкция по установке

Окно показывает, а `bars-cli install --print-instruction` выводит короткий текст для агента: где лежат `bars-mcp` и `bars-cli` и какой командой подключиться (`bars-cli install --client …`). Агент выполняет её сам (Т-21). Текст также запрещает агенту самому передавать `bars-cli reindex --accept-model-change`: это согласие пользователя (Т-25).
