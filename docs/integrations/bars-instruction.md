# BARS_INSTRUCTION.md

Файл, который bars кладёт в корень документации проекта (Т-8). Он адресован моделям, которые пишут документы, и объясняет, как писать, чтобы bars хорошо их индексировал.

## Как файл живёт в проекте

- Текст зашит в bars и меняется вместе с версией bars.
- При регистрации и при каждой проверке актуальности bars сравнивает хеш файла с хешем своей версии; если не совпадает или файла нет — записывает свою версию (Т-8). Правки пользователя в этом файле не сохраняются.
- Сам файл в индекс не попадает ([indexing/updates.md](../indexing/updates.md)).

## О чём инструкция

Каждое правило следует из того, как bars режет документы ([indexing/chunking.md](../indexing/chunking.md)):

- **Модуль — подпапка первого уровня** под корнем документации; всё глубже принадлежит модулю (Т-7). Документы одной темы кладите в один модуль.
- **`title` во frontmatter** каждого документа: он показывается в выдаче (Т-11).
- **Только ATX-заголовки** `#`…`######`. Подчёркнутые заголовки (`===`, `---`) bars не видит.
- **Раздел понятен сам по себе.** Каждый раздел попадает в выдачу без соседей, только с цепочкой заголовков. Не пишите «см. выше», «как сказано ранее»; называйте предмет в заголовке.
- **Заголовки говорят, о чём раздел.** Цепочка заголовков входит в текст для эмбеддинга: «Настройка порта воркера» найдётся, «Настройка» — хуже.
- **Разумный размер разделов.** Очень длинный раздел режется на несколько чанков с одной цепочкой заголовков; совсем короткий склеивается с соседом. Лучше несколько средних разделов, чем один огромный.
- **Документ описывает текущее состояние.** Устаревшее правьте или удаляйте: bars ищет по всему, что лежит в документации.
- **Никаких секретов** в документации: ключей, токенов, паролей.
