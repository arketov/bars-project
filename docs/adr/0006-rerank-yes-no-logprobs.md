# ADR-0006 — rerank через Ollama и LM Studio по logprobs yes/no

Статус: **accepted**, 28-10-2026. Решение автора по исследованиям [Ollama](../knowledge/ollama.md) и [LM Studio](../knowledge/lmstudio.md). Реализации и проверки на reranker-модели пока нет.

## Контекст

Embed через Ollama и LM Studio подключён (Т-17), а штатного API rerank нет ни у одного из них. Включённый rerank с этими источниками сейчас отклоняется. Прежние документы прямо исключали генеративную оценку: «генерация оценки чат-моделью не вводится». Пользователь хочет получить через эти серверы и rerank.

## Решение

Ответы автора 28-10-2026 на вопросы OQ-227…OQ-230:

- способ — «Да, согласовать» рекомендацию: оценка yes/no по logprobs первого токена. Ollama — `POST /api/generate` с `raw: true` и промптом Qwen3-Reranker. LM Studio — `POST /v1/responses` с `include: ["message.output_text.logprobs"]` и `reasoning.effort: none`. Оценка `p(yes)` лежит в 0…1, порог rerank не меняется;
- модели — «Любая, Qwen3-Reranker основная»: чат-модели допускаются с пометкой «качество не проверено»;
- LM Studio — «Да, через /v1/responses»: шаблон чата и штраф повторов сервера остаются оговоркой;
- сбой части запросов или истечение общего дедлайна — «Без реранка целиком»;
- параллельных запросов по умолчанию — «4», значение настраивается.

Источник получения весов для аппаратной проверки остаётся открытым (OQ-231).

## Обоснование и альтернативы

Qwen3-Reranker обучен именно на ответ yes/no, его эталонная оценка — двухклассовый softmax по этим логитам. Значит, способ воспроизводит настоящий cross-encoder, а не подменяет его. У Ollama logprobs есть в `/api/generate`. У LM Studio 0.4.26 проба нашла их только в `/v1/responses`: `/v1/completions` и `/v1/chat/completions` отдают `null`.

Отвергнуты:
- число в тексте ответа — нет калибровки, ошибки разбора;
- ранжирование всего списка одним запросом — нет оценки каждого документа;
- embed от GGUF reranker — вектор не является оценкой пары;
- ожидание штатного API — запросы upstream открыты с 2024 и 2026 годов без срока.

## Последствия

Включённый rerank с источниками `ollama` и `lmstudio` перестаёт отклоняться. Поиск делает N запросов на кандидатов в пуле из 4 потоков под общим дедлайном 60 с. Выдача без rerank с пометкой — как при любом сбое rerank. Нужно проверить на RTX 3090:
- генерацию из GGUF Qwen3-Reranker, сконвертированных под rank-pooling;
- совпадение с llama-server `--reranking`;
- рендер шаблона и влияние штрафа повторов в LM Studio;
- усечение длинного документа;
- задержку при 15 и 50 кандидатах.

Если сверка с эталоном не сходится, решение пересматривается.

## Где применено

Контракт описан в [внешних моделях](../features/models/external-models.md) как согласованный, без реализации.
