# ADR-0002 — Qwen3 через встроенный llama.cpp

Статус: accepted (архитектура по OQ-60); продуктовая приёмка открыта. Дата: 18-10-2026.

## Контекст GGUF

Candle загружает Qwen в FP32 на CPU, 4B требует около 16 ГБ для весов. Автор выбрал встроенный llama.cpp и Q4_K_M в OQ-60, 16-10-2026; это расширение Т-3. Windows-спайк подтвердил сборку вместе с ORT и реальное исполнение Qwen 0.6B на CPU/Vulkan. [Результаты и ограничения](../knowledge/gguf-models.md); полное качество и 4B ещё принимаются. Успешная сборка не закрывает эту приёмку.

## Решение GGUF

Использовать закреплённый `llama-cpp-2` 0.1.160 для встроенных Qwen 0.6B/4B Q4_K_M. Существующие идентификаторы настроек сохраняются, отпечаток индекса меняется: backend, квант, ревизия, инструкция и предел входа влияют на совместимость. Переиндексация только по Т-25. bge-m3 остаётся умолчанием на fastembed/ORT; rerank не меняется этим решением.

На Windows `Auto` предпочитает Vulkan; `Cpu` запрещает GPU offload. Ошибка GPU даёт CPU fallback с явной причиной. Общая инициализация llama.cpp — одна на процесс; модель и её контекст владеют памятью до штатной выгрузки. `self_cell` обеспечивает безопасное владение контекстом, ссылающимся на модель; самодельное продление lifetime и утечки модели не допускаются.

Nomic v2 MoE сохраняется на candle: Т-17 требует доступность модели, а одно наличие официального GGUF не подтверждает правильные encoder/pooling, качество и жизненный цикл. Удаление поддержки Nomic или перенос без опыта не оправданы. Старый candle-путь Qwen удаляется при внедрении; fallback между различными весами/квантами не допускается.

## Последствия GGUF

Скачивание закреплённых repo/revision/file, проверка длины и SHA-256 до создания сессии. Готовность кэша — проверенная метка с сигнатурой файла; опрос окна не хеширует гигабайты. Штатная очередь загрузки, прогресс и ошибки сохраняются. Новый backend и фактический Vulkan показываются окном. Для сборки Windows нужен Vulkan SDK; пользователю готового приложения SDK не требуется, нужен поддерживаемый драйвер либо CPU fallback.

Официального Q4_K_M у 0.6B нет; выбранная сторонняя конверсия явно названа в каталоге артефактов и исследовании, закреплена ревизией и хешем. При недостатке памяти или отсутствии полного бенча этап не объявляется завершённым. macOS/Metal и другие GPU требуют отдельной приёмки.

## Отклонённые варианты GGUF

Отдельный llama-server — не соответствует решению о встроенном воркере. Сохранение Qwen candle как скрытого fallback смешало бы векторы и вернуло FP32-расход памяти. Смена bge по умолчанию не поручена. Перенос Nomic без проверки нарушил бы доступность Т-17.
