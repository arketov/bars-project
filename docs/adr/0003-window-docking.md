# ADR-0003 — кандидат docking и отдельные окна документа

Статус: accepted — инженерный выбор реализации 1.1.4 по поручению автора 20-10-2026; это не утверждение о физической приёмке макета или отдельном выборе библиотеки автором. Дата: 20-10-2026.

## Контекст панелей bars

Т-40/Т-43/Т-45 и [проект окна](../features/window/requirements.md) требуют проверить docking для нынешнего Svelte/WebView2. Уточнение автора 20-10-2026: «Главное чтоб она была примерно как сейчас»; отдельное окно: «Каждый документ можно открыть в новом окне через правую кнопку мыши и там редактировать». Стороны закреплены OQ-111. Выбор библиотеки автор этим не задавал. [Исследование, числа и границы](../knowledge/window-docking.md).

## Предлагаемый выбор для каркаса

Рекомендованы `dockview-core@8.6.1` с прямым lifecycle-адаптером Svelte 5 и CSS из `dockview@8.6.1`. Проба использует настоящие компоненты bars; дополнительные framework wrappers не нужны. Состояние документа, поиска и графа хранится вне layout JSON. Раскладка получает собственную версию приложения, область проекта/роль окна и восстановление при повреждении; закрытие вкладки подчиняется сохранению редактора.

Отдельное окно документа создаётся через Tauri WebviewWindowBuilder и вызывает тот же Shared/WorkerHandler. Браузерный popout библиотеки не используется как доказательство Т-40. Окно документа не создаёт второй воркер/модели и не управляет основной раскладкой. Контроль ревизий и сохранение нескольких редакторов проектируются отдельно.

## Обоснование и альтернативы

Dockview поддерживает нужные структуры и API сохранения, прямой адаптер и round-trip прошли программную пробу WebView2; есть ARIA/messages/keymap. Стоимость полного API выше Golden Layout: 97413 против 32542 байт gzip JS, плюс CSS. Для локального bars это приемлемый кандидат; итоговый bundle и отзывчивость проверяются на реальном каркасе.

Golden Layout 2.6.0 остаётся запасным кандидатом: меньший JS и virtual binding, но полное управление панелями с клавиатуры потребует отдельной проверки и адаптации; npm-публикация существенно старше. dock-spawn-ts 4.4.0 требует решения обнаруженной проблемы CSS imports в Vite. Собственный docking engine означает поддержку drag, split, ARIA и сериализации в проекте; необходимость такого объёма своим кодом не установлена.

## Последствия и условия внедрения

В репозитории кандидат пока devDependency стенда; основной App.svelte не изменён. Макет обеих тем/узкой ширины, русские команды и доступная альтернатива мыши обязательны перед продуктовой приёмкой. Нынешний глобальный app.viewer не станет многодокументным от подключения библиотеки. Редактор, синхронизация правок и полный перенос экранов — отдельные работы. Если макет или физическая проверка выявит неприемлемый риск, рекомендация пересматривается до внедрения.
