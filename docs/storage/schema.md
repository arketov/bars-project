# Схема индекса проекта

Индекс проекта — один файл SQLite `.bars/index.sqlite` (Т-5). Полнотекстовый поиск — FTS5, векторный — sqlite-vec.

## Таблицы индекса

| Таблица | Что хранит |
|---|---|
| `meta` | версия схемы, версия bars, отпечаток модели ([models/local-models.md](../models/local-models.md)), время последнего обновления |
| `documents` | путь от корня проекта, модуль, `title`, размер, время изменения, sha256 содержимого |
| `chunks` | документ, порядковый номер, строки начала и конца, цепочка заголовков, текст чанка, хеш текста для эмбеддинга |
| `chunks_fts` | FTS5 по цепочке заголовков и тексту чанка; токенайзер `unicode61` с `remove_diacritics 2` |
| `vectors` | sqlite-vec `vec0`: хеш текста для эмбеддинга → вектор `float[размерность]` |

Связь чанка с вектором идёт через хеш текста для эмбеддинга. Поэтому одинаковые чанки (например, повторённый в двух файлах раздел) хранят один вектор, а неизменившийся чанк после правки соседнего раздела находит свой старый вектор (НФТ-1).

## Версия схемы индекса

Схема индекса имеет номер версии в `meta`. Новая версия bars, встретив старую схему, переводит её миграцией, если это возможно без нового эмбеддинга. Если невозможно, индекс получает состояние «нужна переиндексация», и действует то же правило, что при смене модели: предупреждение и переиндексация по согласию (Т-25).
