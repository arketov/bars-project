# Handoff: проект схемы баллов

Продолжение темы: [токенизация](../2026-11-03-tokenization-research/handoff.md), [бенч](../2026-11-03-search-bench/handoff.md). Результат — раздел «Проект схемы баллов» в [hybrid-search.md](../../features/search/hybrid-search.md), опыты — [search-scores.md](../../knowledge/search-scores.md), данные — [search-scores-2026-11-03](../../knowledge/search-scores-2026-11-03/Index.md). Ничего не собиралось и не запускалось, кроме `node`; `bars-cli` не вызывался (использованы сохранённые выдачи `cli-full.json`).

## Сделано

- Проект схемы: `S = a + w_c·c + w_f·f + w_p·p + w_l·l`, где опора `a` — rerank, а без него косинус (абсолютная шкала, на ней порог); `f` — составной bm25 с четырьмя колонками, поделённый на максимум списка; `p` — точное совпадение (идентификаторы, фраза, пары слов подряд); `l` — связи по индексу ссылок, вес 0 до бенча. Недоступный сигнал выпадает, опора определяет шкалу и порог. Порог — по опоре, не по сумме. Операторы `"фраза"`, `-слово`, `path:`/`папка:`; свёртка кусков раздела — лучший кусок, бонус 0; формат результата для MCP и окна; стартовые веса и правило подбора в 2.3.4.
- Опыты на node (копии индексов, 168 запросов, выдачи CLI): сумма отдельно нормированных полей хуже одного составного bm25 (57 % против 60 % первым; ранговое нормирование 51 %); покрытие слов запроса не помогает; фраза +0,006 MRR (шум); RRF rerank+FTS хуже (58 % против 63 %), сумма `rerank + 0,1·FTS` лучше на 2 п.п. первым при том же Hit@3 (65 % / 88 % / 0,760 против 63 % / 88 % / 0,753), но строгую приёмку не проходит (11 запросов потеряно, 15 выиграно); абсолютная шкала bm25 правильный первый от неправильного не отделяет; порог 0,1 по rerank не отсекает ничего, 0,2 — 13 % лишнего и 3 правильных куска; свёртка раздела качество не меняет, бонус за остальные куски вредит (`bp-09`, `tm-13`), 10 кусков → 7,4 раздела.
- Вопросы автору OQ-265…OQ-269.

## Не сделано

- Косинус как сигнал, замена RRF порядком `S0`, режим без rerank, связи — не измерены: вектор запроса даёт только модель, сборка запрещена (OQ-267, OQ-268).
- Операторы и запросы без ответа в бенче не представлены (0 из 168), порог выше 0,1 не обоснован (OQ-269).
- Свёртка до rerank и склейка хвоста раздела не проверялись.
- Не правились: MAIN_IDEA, ADR-0007, PLAN.md, код, описания текущего поведения (настройки, MCP, руководство). Когда автор согласует проект, при реализации придётся поправить: [settings.md](../../features/settings/settings.md) (порог), [mcp-tools.md](../../features/agent-tools/mcp-tools.md) и [cli.md](../../features/agent-tools/cli.md) (операторы, результат-раздел), [protocol.md](../../architecture/protocol.md) (поля ответа), [manual/search.md](../../manual/search.md), [global-search-design.md](../../features/window/global-search-design.md), [text-search.md](../../features/search/text-search.md), раздел «Где применено» ADR-0007.
