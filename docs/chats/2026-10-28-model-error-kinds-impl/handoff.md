# Виды ошибок встроенной модели в воркере и окне — итог 3.4.5

Предыдущая сессия: [handoff 3.4.4](../2026-10-28-model-error-kinds/handoff.md)

## Сделано

- Воркер по [экранам ошибок](../../features/window/error-states.md) (раздел «Виды ошибок встроенной модели») задаёт вид ошибки: `ModelErrorKind` и `ModelFailure` в `bars-core`, типы `EmbedError::Network` и `EmbedError::Files` там, где вызов принадлежит bars (hf-hub, проверка размера и хеша GGUF и ONNX), общий список признаков нехватки памяти (`is_out_of_memory`) для вида ошибки и для уменьшения пачки rerank.
- Ошибка загрузки хранится парой «вид и сообщение» (`Loads`, `Readiness::Failed`, `download_errors`); поиск отдаёт `provider_error` с `data.reason`, `models_info` — `download_error_reason` (у rerank его нет, OQ-218). Контракт — [протокол](../../architecture/protocol.md).
- Окно: `errors.ts` выбирает экран по `data.reason` (неизвестное — `runtime`), `SearchError.svelte` даёт кнопки по виду: «Скачать снова/заново» запускает `model_download`, «Открыть папку моделей», «Выбрать устройство», «Скопировать подробности»; под заголовком виден текст ошибки и `reason`.
- Поправлены руководство «Неполадки», `window/implementation.md`, статус ISS-36 в `backlog/issues.md`.
- Тесты: вид по типу и тексту (`failure.rs`), хранение и безопасный текст скачивания, `data.reason` в ответе поиска, экраны по каждому виду (`errors.test.ts`).

## Не сделано

- Проверка в собранном окне и в установленной сборке не выполнялась (установка — по согласованию с автором).
- Вид ошибки у сбоя поиска загруженной модели не задаётся: окно читает его как `runtime`.

## Сложности

- Рабочая копия общая с параллельной сессией 5.2.1: те же `methods.rs`, `SearchError.svelte`, `app.svelte.ts`, из-за чего полная сборка какое-то время не проходила по чужим правкам. Основной код этого шага (`bars-core`, воркер, окно) попал в коммит `847d01c` сессии 5.2.1, у которой общие файлы были в рабочей копии; отдельный коммит содержит остальное — примеры, тест ответа поиска, документы, план.
- `scripts/check.ps1`: форматирование, clippy и сборка зелёные, UI 707 тестов и svelte-check зелёные; в `cargo test -p bars-worker` при параллельных запусках и работающем `bars.exe` падают тесты канала (`AlreadyRunning`, DACL именованного канала) — изолированно проходят.
- fastembed скачивает файлы внутри создания сессии, поэтому для вида `network` на первой загрузке bge-m3 файлы теперь получает `download_onnx_artifacts` до создания сессии.
