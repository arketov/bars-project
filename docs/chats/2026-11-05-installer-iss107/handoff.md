# Передача — установщик не оставляет старую версию (шаг 1.2.1, ISS-107)

## Сделано

Код и документы написаны; сборки, тесты и установщик не запускались (запрет автора на ноутбуке).

- **Метка обновления.** `crates/bars-protocol/src/launch.rs`: `UPDATE_MARKER` (`update.lock` рядом с exe), `UPDATE_MARKER_TTL` (10 минут), `update_in_progress`; `spawn_worker` отказывается запускать воркер при свежей метке (`WouldBlock`, «идёт обновление bars: повторите запрос через минуту»). Проверка внутри `spawn_worker` покрывает `bars-mcp` и `bars-cli` без правок их кода (`crates/bars-mcp/src/lib.rs` не менялся). Пять тестов написаны, не запускались.
- **Хуки установщика.** `crates/bars-app/installer-hooks.nsh` переписан (UTF-8 с BOM для русских сообщений): метка → `bars.exe` стирается или переименовывается в `.old*` (до остановки воркера: прокси прежней версии метку не знают, но запускать им нечего) → `--quit` из переименованного файла → ожидание 15 с → завершение процесса по пути к файлу (Restart Manager шаблона переименованный файл уже не видит) → перенос `bars-mcp.exe` и `bars-cli.exe`. Имена `.old`, `.old1` … `.old9`: занятые файлы прошлых обновлений не мешают. Перед копированием проверка «файл освобождён», после — «файл записан»; иначе окно/консоль и `Abort` (код 2). Метка стирается в `POSTINSTALL` и при ошибке; деинсталлятор делает то же без жёстких ошибок.
- **Документы.** `features/distribution/installer.md` (порядок обновления, прокси прежних версий), `architecture/ipc.md`, `features/window/error-states.md`, `manual/install.md`, `knowledge/installer.md`, ISS-107 в `backlog/issues.md` (остаётся открытым).

## Не сделано

- Ничего не собиралось и не устанавливалось; NSIS-скрипт не компилировался (`makensis` не запускался). Возможные места ошибок: `${For}`/`${ExitFor}` в `BarsSetAside`, обработка BOM в `!include`, кавычки PowerShell в `nsExec`, пробег Abort в тихом режиме (код 2).
- Прокси версий до этого шага метку игнорируют: на первом обновлении до версии с меткой они могут запустить новый `bars.exe` между копированием и снятием метки.

## Дальше

При первой сборке автор проверяет по порядку: (1) `scripts/build-installer.ps1` собирает установщик без ошибок NSIS; (2) установка поверх работающих `bars` и нескольких сессий агентов даёт новую версию (дата `bars.exe`, окно показывает новую сборку), в папке остаются `bars*.exe.old*`; (3) агент во время установки получает «идёт обновление», после — работает; (4) искусственная ошибка (занять `bars.exe` без права переименования невозможно, проще — удалить `bars-mcp.exe` из установщика) даёт сообщение и код 2 в тихом режиме; (5) настоящее удаление чистит метку и `*.old*`; (6) `cargo test -p bars-protocol launch` зелёный.
