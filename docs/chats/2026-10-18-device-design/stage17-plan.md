# Этап 17 — раздельные устройства моделей и устойчивость индексации

Статус: согласованный план реализован 18-10-2026; целевые тесты и две аппаратные сессии пройдены. [Проверки и ограничения](../2026-10-18-stage17-implementation/device-verification.md), [доказательства](../2026-10-18-stage17-implementation/device-evidence.json). Повторная интерактивная проверка Save после исправления dev-заглушки недоступна из-за разрыва CUA; компонентная регрессия и настоящий Save/Get воркера пройдены. Погружение — MCP bars и Serena Rust LSP; после разрыва Serena — точечные патчи.

## Результат для пользователя

Основание — [IDEA-01](../../backlog/ideas.md#закрытые-пожелания), OQ-62 и OQ-80 в [реестре вопросов](../../../QUESTIONS.md), Т-3, Т-16, Т-17, Т-25 и НФТ-1. Человек оставляет embed на GPU и переводит rerank на CPU независимо; окно сообщает выбранную политику и устройство загруженной модели. Ошибка одного документа не прекращает обработку остальных; серия ошибок останавливает задание с понятной причиной и списком файлов.

Смена устройства не меняет модель индекса и не требует согласия на переиндексацию. Оптимизация precision, новые EP, выбор номера GPU и выгрузка по таймеру относятся к отдельным этапам исследования скорости и памяти.

## Настройки и переход с общего устройства

Канонический формат `settings.toml`:

```toml
[embed]
accelerator = "auto"

[rerank]
accelerator = "cpu"
```

Значения обоих ключей — `auto` и `cpu`; заводское значение обоих — `auto`. Auto сохраняет текущую политику ускорителя с CPU при невозможности загрузки. Слова «GPU обязательно» в UI нет. Для `remote` и `local-openai` устройство сервера неизвестно bars: переключатель скрыт, сохранённый выбор встроенного устройства не теряется. Для candle выбор недоступен с пояснением «Только CPU». Выключенный rerank сохраняет настройку, но не загружается ради показа устройства.

Технический переход нужен из-за существующего пользовательского файла `[device]` — это наблюдаемый контракт настроек, а не второй постоянный способ конфигурации:

1. На чтении каждый новый ключ имеет приоритет над старым общим; отсутствующий наследует `[device].accelerator`, затем `auto`. Частично мигрированный файл не меняет выбор второй модели.
2. Старый ключ валидируется и даёт предупреждение о миграции; незнакомые ключи по-прежнему дают штатные warnings. Неверное значение известного ключа не превращается молча в Auto.
3. Чтение файл не переписывает. При следующем успешном `settings_save` материализовать оба разрешённых значения в новых таблицах и удалить только старый `device.accelerator`; посторонние ключи и комментарии сохранить. Пустую старую таблицу удалить. Запись — через существующий атомарный путь `settings_io`, с проверкой полученного TOML перед заменой.
4. Общий accelerator убрать из разрешённой структуры Settings и SettingsDoc, UI и текущих ключей слотов. Старый формат остаётся только во входном адаптере миграции. Старое окно не получает новый DTO: окно и воркер поставляются одним бинарником.

Индексный fingerprint не содержит accelerator. `needsReindex` в UI уже сравнивает source/model: это свойство сохранить тестом. При изменении устройства новая работа получает новый слот соответствующей модели; уже начатая работа завершает свой снимок настроек. Старый слот живёт, пока его держат текущие запросы. Параллельные смены не должны позволять завершившемуся старому loader перезаписать сведения нового слота. Во внешнем backend смена неиспользуемого accelerator не должна перезагружать провайдера.

## Устройство загруженной модели: общий контракт

Добавить в общий интерфейс embed/rerank снимок исполнения: источник, backend, фактическое устройство сессии и безопасная причина fallback. ONNX отдаёт CPU/DirectML, candle — CPU, HTTP — `external` без догадок о железе сервера. Значение DirectML означает выбранный EP сессии; это не профиль размещения каждого оператора на GPU. CoreML не добавлять декларативно без реализации.

В `models_info` добавить независимые сведения `runtime.embed` и `runtime.rerank`: `model`, `source`, `requested`, `state`, `actual`, `fallback_reason`. `state`: `unloaded`, `loading`, `ready`, `failed`; `actual` отсутствует до успешной загрузки и у внешнего сервера. Ошибка загрузки не выдается за успешный CPU fallback. Для Auto/candle CPU — ограничение backend, не ошибка GPU. Существующий список каталога и прогресс скачивания сохранить.

Снимок принадлежит слоту/поколению настроек. Публикуется при загрузке, сбрасывается при замене; `models_info` читает коротко защищённую копию, не берёт mutex инференса и ничего не загружает. Не выдавать устройство ранее загруженной модели за текущее. Получение состояния остаётся дешёвым во время долгого Run.

В прогресс задания добавить снимок устройства именно его embed-слота. После Save текущее задание может продолжать работу на старом устройстве: плитка показывает устройство задания, блок настроек — состояние нового выбора. Для отображения rerank использовать `models_info`, не запускать его при индексации.

## Ошибка документа и бюджет повторов

Согласованная политика: первая попытка плюс **три повтора** документа, паузы 1/2/4 с; предел **три последовательно неудачных документа с вызовом embed**. Это внутренние константы с инъекцией ожидания для тестов, без новых пользовательских настроек. Окно выводит «attempt 2/4».

Единственный владелец повторов индексации — индексатор перед записью документа. HTTP-вызов embed для индексации делает одну попытку на пачку; внутренний `post_with_retries` не умножает её. Повторяется получение недостающих векторов документа; уже существующие векторы переиспользуются. Успешные пачки не записываются отдельно от документа. Для документа из N пачек верхняя граница — 4N HTTP-запросов; тест счётчика использует одну пачку и ожидает максимум четыре запроса. Поиск сохраняет прежнюю HTTP-политику через отдельный путь `embed_query`, rerank — без повторов.

Классификацию ошибок сохранять типом, не разбирать тексты:

- Сеть, 429, 5xx и обычная ошибка вычисления встроенного embed — повторяемые ошибки документа; после исчерпания бюджета файл пропускается.
- Отказ HTTP 4xx, кроме 429, — ошибка документа без повторов, как в текущем HTTP-контракте; серия таких документов тоже достигает порога. Не повторять неправильный ключ четыре раза.
- Невозможность загрузки модели, неверные настройки, отсутствие ключа, SQLite/диск, неверное число/размерность/нечисловые векторы — ошибка задания сразу. Пропуск документов не скрывает нарушение целостности или невозможность подготовить провайдера.
- Остановка пользователем — отдельный исход, без повторов. Проверять pause/cancel перед попыткой и во время ожидания паузы; не держать слот модели во время backoff. Текущий блокирующий Run/HTTP-запрос заканчивается в пределах действующего timeout; обещания мгновенной отмены нет.

Счётчик серии увеличивается один раз на окончательно неудачный документ, не на попытку и не на чанк. Успешный вызов embed для следующего документа сбрасывает серию. Неизменённый файл, чтение без embed или ошибка обхода не доказывают восстановление провайдера и не сбрасывают серию. На третьем таком отказе остановить проверку до следующего файла. Для неизвестной размерности внешнего embed `prepare` остаётся подготовкой модели с отдельным прежним HTTP-бюджетом: сбой до начала обхода — ошибка задания, не фиктивная ошибка документа. Повторы подготовки не оборачиваются повторами документа.

## Целостность индекса и повторная проверка

Обычное обновление: прежние chunks, векторы, hash, stat неудачного документа остаются нетронутыми; у нового документа запись не появляется. При следующей проверке он снова требует embed. Счётчики added/changed/chunks увеличиваются только после успешной транзакции. Пропавшие на диске файлы удаляются штатно, с действующей защитой ошибок обхода.

При смене chunking/docs_root неполный проход с embed-ошибкой не записывает новый layout. Иначе следующий запуск может принять необработанные документы за построенные новыми параметрами. `updated_at` может означать завершение проверки с проблемами, но интерфейс не называет индекс полностью актуальным. Отчёт различает `complete`, `completed_with_problems`, `aborted`.

**Решение автора, OQ-80, 18-10-2026:** при полной переиндексации остальные документы обрабатываются, но хотя бы один пропуск из-за embed запрещает swap. Достигнут порог серии — обход останавливается раньше. В обоих случаях старый индекс остаётся целым, временный файл штатно очищается, отчёт ошибок сохраняется в памяти воркера. Старые векторы в новый индекс не переносятся. После смены модели проект остаётся `reindex_required`; для той же модели старый индекс доступен. Повтор — явная полная переиндексация после устранения причины; новый цикл rebuild автоматически не запускается.

Правило OQ-80 касается ошибок embed. Действующую обработку unreadable/не-UTF-8 не расширять молча: это отдельная политика обхода. Обычные повторные проверки по событиям и таймеру сохраняются. Результаты текущих ошибок заменяются последним полным отчётом; история ошибок на диск относится к будущим логам, IDEA-03.

## Отчёт и окно

Добавить типизированную проблему embed: путь, безопасная причина, число попыток, стадия, наличие прежней версии документа. До завершения задания публиковать проблему через `IndexObserver`; `JobCell` хранит список текущих проблем и номер попытки. `worker::problems` объединяет текущий снимок с последним отчётом без дублей, а после завершения показывает последний отчёт. При `Failed`, `Cancelled` и запрете swap не терять уже накопленные проблемы: изменить payload исходов `indexer → job → apply`.

Окно получает различие: «обновлено с ошибками», «остановлено после серии ошибок», «полная переиндексация не применена». Не показывать «индекс актуален» только потому, что задание исчезло из очереди. Для остановленного rebuild показывать отчёт и действие повторной полной переиндексации; после смены модели использовать существующий путь согласия. Никакого автоматического согласия Т-25.

Мокап: [device-settings.html](../../features/window/mockups/device-settings.html). На карточках моделей независимые Auto/CPU, отдельно сохранённая политика и устройство загруженной сессии. При fallback — короткое пояснение CPU. Плитка индексации подписана «Устройство embed · текущее задание». Сцены: смешанный выбор, загрузка, fallback, внешний провайдер, candle, одиночная ошибка, серия ошибок, неприменённый rebuild. Язык подписей — по НФТ-4; ISS-11 исправляет английские подписи, а не разрешает их добавлять.

Матрица регрессии индексатора: единичный отказ с успехом на попытках 2 и 4; четыре отказа → пропуск; плохой/хороший/плохой документ сбрасывает серию; плохой/неизменённый/плохой/плохой достигает порога; 401 без повтора; 429 с четырьмя запросами; отмена в backoff; ошибка на последней пачке многочанкового документа; отсутствие частичной записи; сохранение ошибок после abort/cancel; следующий проход повторяет файл с прежним stat; неполная смена layout; запрет swap при первой/сменённой/той же модели, в том числе ошибка последнего документа. Существующие тесты UTF-8, обхода и смены fingerprint остаются регрессией.

Процессные сессии: отдельный `BARS_USER_HOME` внутри разрешённого стенда проекта, временный тестовый проект и текущий Rust fake-provider; установленный профиль не править. Для настоящих моделей использовать существующий кэш только для чтения либо явный изолированный кэш; тяжёлые запуски последовательно, с учётом соседних опытов этапов 11/13. Проверить auto/cpu и cpu/auto через фактический worker-путь: загрузка, индексация, поиск с rerank, Save и повтор. Устройство не доказывать одним TOML или mock JSON. CPU-fallback воспроизводить детерминированной ошибкой загрузчика; аппаратную недоступность GPU не имитировать изменением драйвера.

Tauri single-instance не изолируется одним BARS_USER_HOME: отдельная UI-сборка с уникальным identifier либо согласованная проверка обновлённого приложения. До UI-приёмки старый установленный bars не считать новой реализацией. Работа macOS остаётся отдельно непроверенными.
