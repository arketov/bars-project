# Проверка этапа 29 — история отдельных MCP-вызовов

Статус 18-10-2026: сбор данных, хранилище и API реализованы и проверены в рабочей копии. Экран этапа 30 и нативная приёмка этапа 32 не выполнялись; ISS-14 остаётся открытым. Установленный bars не закрывался и не обновлялся.

## Проверенные сценарии истории MCP

| Проверка | Результат |
|---|---|
| Настоящий MCP → локальный IPC → worker, все шесть инструментов | В истории есть формат, исходный вход, применённые значения, сессия, проект, времена и собственные единицы. Для reindex — ID/вид задания и слияние; accepted не считается завершённым индексом |
| Missing / null / явное значение | Различимы после прокси; неизвестные поля отбрасываются. Контекст не ломает предельный размер допустимого IPC-запроса |
| Поиск: настройки 2→4, чрезмерные limit/candidates | Старый вызов сохраняет K=2, новый K=4; запрос 999/99999 ограничен до 5/10 с признаком и причиной |
| Успех с нулём, ошибка и неприменимое количество | Проверены пустые projects/read/outline/search; ошибки поиска/файла/проекта и согласия reindex. Ноль не заменяет ошибку; status/reindex имеют null и `not_applicable` |
| Два проекта/соединения, одновременные вызовы и повтор | Раздельные сессии/проекты, уникальные ID. Очистка и отключение не меняют ответ инструмента; после включения пишутся новые попытки |
| Прерванный настоящий IPC, перезапуск worker и повтор | Сервер теста прерван во время поиска, ожидающего gate. Новая эпоха восстанавливает неизвестный исход без выдуманного конца/длительности; повтор имеет новый ID/эпоху/сессию |
| Миграция и хранение | Прежние агрегаты отдельно; новые попытки не выдумываются. Проверены срок, row/byte caps, пагинация и сводка, новые вставки между страницами, несовместимый курсор, очистка при активной записи |
| Отказ хранения | Занятый writer, повреждённая/будущая БД и исчерпание восьми permits видны в диагностике. Исходная БД не заменяется. Успешный IPC-ответ остаётся успешным при отказе записи |
| Размер/содержимое записи | UTF-8, control characters/JSON escaping, длинные массивы, предел 32 КиБ и явное усечение. Документы, hits, произвольные ключи и сырые ошибки не сохраняются |

Реальный сбор означает настоящий код MCP, IPC, worker и SQLite. Модель в интеграционных сценариях — FakeProvider, документы/профили — временные; качество модели этим не доказывается. Обычный worker-прогон также выполнил существующий тест bge-m3, но это не отдельная приёмка моделей.

## Команды и результаты этапа 29

Windows, Rust 1.99.0; MSVC 17.14.42 из `C:/BuildTools`, Ninja, Vulkan SDK 1.4.363.0, release target `C:/bg22`. Тесты используют временные home/config/client profiles; настоящие профили не изменялись.

- Worker: общий последовательный прогон — 187 passed, один `provider_knows_every_builtin_model...` отфильтрован широким `--skip builtin_model`; этот тест отдельно passed. После финальных правок — 19 профильных `mcp_` passed, включая новый тест перезапуска и 9 тестов хранилища.
- `cargo test --release -p bars-mcp --test mcp -- --test-threads=1` — 11 passed.
- `cargo test -p bars-protocol --lib` — 53 passed, включая передачу исходного контекста и сохранение допустимости большого запроса.
- UI: `npm test -- --maxWorkers=1 src/lib/McpStatisticsPage.test.ts src/lib/mcp-statistics.test.ts` — 4 passed; `npm run check` — 0 ошибок/предупреждений, `npm run build` — passed.
- `cargo check --release -p bars-app` — passed. Нативные Tauri-команды скомпилированы; клики по новому API пока отсутствуют, экран — этап 30.
- Строгий clippy worker/MCP lib, `--no-deps -D warnings` — passed. Worker/MCP/protocol lib вместе, `--no-deps -D warnings -A clippy::large_enum_variant` — passed. Строгий вариант с protocol без исключения упирается в размер `Call::GraphQuery` параллельного GraphRAG; это не исправлялось в этапе 29.
- Ручное ревью: allowlist на двух границах, безопасные ошибки, отсутствие upsert после очистки, фиксация применённых настроек внутри выполнения, монотонное время, SQL-фильтры/курсор и пределы. `git diff --check` затронутых исходников — passed. Чужие изменения сохранены; коммит/push не выполнялись.

Ранний параллельный прогон имел `table meta already exists` в существующем IPC-тесте; последовательный общий и финальный профильный прогоны прошли. Новый параллельный тест сначала выявил потерю записи из-за SQLite read→write upgrade; исправление IMMEDIATE и однократного DDL проверено повторно. Начальный UI check поймал отсутствующий импорт SearchOutput в параллельном GraphRAG; к моменту повторной проверки импорт уже добавлен параллельной работой, повтор зелёный.

## Измерение задержки и размера истории

[Данные замера](measurements.json): 200 коротких поисковых записей в временной SQLite, по два синхронных commit на попытку; без модели и IPC. p50 **28,938 мс**, p95 **37,596 мс**; данные записей **87 492 байта**, файл после checkpoint **151 552 байта**, потери **0**. Это добавленная стоимость begin+finish на этой машине, не задержка MCP целиком и не оценка на предельных 10 000 записях. Верхняя граница 32 МиБ относится к сериализованным данным, не сумме файлов SQLite/WAL. Бюджет приемлемой задержки автором отдельно не установлен.
