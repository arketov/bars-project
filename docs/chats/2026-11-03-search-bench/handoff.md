# Handoff: бенч настоящих запросов

Продолжение темы: [search-pivot](../2026-11-03-search-pivot/handoff.md) и раздел «Аудит 03-11-2026» в [search-quality.md](../../knowledge/search-quality.md).

## Сделано

- Набор из **168 запросов** с эталонами по пяти проектам: bars-project 42, overdrive-bots 40, RoleGPT 32, agaugu 30, tmc-opovechenie 24; 13 групп (вопросы обычным языком 63, идентификаторы 12, «где описано» 11, синонимы 11, номера и даты 9, длинный набор слов 7, термины 5, опечатки 5, словоформы 5, смешанные ru/en 6, два куска раздела 6, настоящие запросы агентов 14, руководство среди журналов 14). Эталон — путь, цепочка заголовков и дословная опора из чтения документов; `build.mjs` проверяет, что опора есть ровно в одном чанке.
- Настоящие запросы агентов: 14 дословных из `mcp-statistics.sqlite3` (копия, только чтение), по открытым проектам; firetech-tmc-mcp не использовался.
- Точка отсчёта: полный конвейер через `bars-cli --json search` по одному запросу подряд (rerank был загружен во всех 168, отказов нет) и три FTS-варианта на копиях индексов (как сейчас, заголовок ×5, `AND`). Полный конвейер: первым 63 %, Hit@3 88 %, MRR@10 0,747, nDCG@10 0,788, не найден 8 %. FTS как сейчас: 52 % / 75 % / 0,653 / 0,710. FTS ×5: 55 % / 79 % / 0,674 / 0,724. `AND`: 22 % / 27 %. Журналы в топ-3 — 4 %, повтор раздела в топ-5 — 4 %, повтор документа — 72 %.
- Разделы по группам и проектам, правило приёмки (не хуже на 1 п.п. ни в одной группе и проекте, подбор — нечётные номера, проверка — чётные), запуск и ограничения — в разделе «Бенч настоящих запросов» документа `search-quality.md`. Данные и скрипты — [search-bench-2026-11-03](../../knowledge/search-bench-2026-11-03/Index.md).
- Закрытые данные (копии индексов пяти проектов ≈510 МБ, эталоны с опорами, сырая выдача CLI) — `%USERPROFILE%\.bars\bench\`; в репозитории только запросы, метрики, скрипты и эталон bars-project.
- Ничего не собиралось, `cargo`, `scripts/check.ps1`, serena и `npm` не запускались; скрипты — `node` `.mjs`. Во время работы у другой сессии шёл `cargo.exe`: не мой, не трогал.

## Не сделано

- «Только векторы» и «без rerank»: из `bars-cli` без правки настроек и без сборки их не получить. Описаны как будущий прогон (`bench_quality` IDEA-06 на этом наборе или параметр rerank на вызов).
- Нет нетехнического корпуса среди зарегистрированных проектов и запросов без ответа (ложная непустая выдача).
- Группы по 5–14 запросов: чтобы правило «1 п.п. в группе» что-то значило, нужно ≥30 в группе (≈400 запросов).
- Время запроса не измерено: median 8,4 с и p95 21 с при параллельной нагрузке других сессий — не задержка поиска.
- Эталон неполон там, где тему описывают несколько документов (bars-project, RoleGPT): числа — нижняя граница.

## Сложности

- Стемминг FTS в копиях индекса — Snowball ru/en; npm-пакета нет, собственная копия русского стеммера плюс выученные пары «слово → основа» из индекса (95,9–99,9 % совпадения с индексом по русским словам корпуса). Английские слова вне корпуса стеммятся грубо.
- `bars-cli search` учитывается в статистике MCP и «Новых темах» как обычный вызов: 168 запросов бенча попали туда.
- Документы bars-project правились во время прогона; при смене границ чанка опора может оказаться в соседнем чанке.

## Дальше

- Решение автора: расширять ли набор до ~400 запросов и добавлять нетехнический корпус до проектирования баллов.
- Отдельная сессия с разрешением собирать: прогон «только векторы» и «без rerank» на этом наборе, затем баллы сигналов ADR-0007 на варианте проверки по правилу приёмки.
- Недостаточно сильные группы для расширения в первую очередь: настоящие запросы агентов (14 %), синонимы (45 %), идентификаторы (42 %), опечатки.
