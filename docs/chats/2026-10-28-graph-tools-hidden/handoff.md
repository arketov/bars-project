# Итог сессии 4.1.2 — графовые инструменты MCP скрыты по умолчанию

## Сделано

Шаг плана 4.1.2, решение автора по OQ-162 (23-10-2026): шесть графовых инструментов скрыты, включаются настройкой. Контракт — [инструменты MCP](../../features/agent-tools/mcp-tools.md), ключ — [настройки](../../features/settings/settings.md).

- **Ключ `[mcp] graph_tools`** в `~/.bars/settings.toml`, по умолчанию `false`. Ядро (`bars-core/src/settings`), `McpDoc` в `SettingsDoc` протокола, запись из окна в `bars-worker/src/settings_io.rs` по общему механизму слияния полей.
- **Прокси сам читает файл** при создании сессии (`crates/bars-mcp/src/settings.rs`, `Env::bars_home`): список инструментов отдаётся без воркера и без `bars-core` (НФТ-3), поэтому спросить воркера нельзя. В `tools/list` остаются десять инструментов, скрытый вызов клиент получает как неизвестный. Нет файла, ошибка разбора или не логическое значение — скрыты.
- **Инструкция `initialize`** — `instructions(graph_tools)`: строка о графовых инструментах только при включённом ключе.
- **Окно:** переключатель «Графовые инструменты» во вкладке «Клиенты», пишется по «Сохранить» ([экран настроек](../../features/window/settings-window.md)).
- Документы: `manual/settings.md`, `architecture/files.md`, `features/graphrag/tools.md`, `features/agent-tools/Index.md`, `CHANGELOG.md`.
- Тесты: ядро (умолчание, значение, неизвестный ключ, неверный тип), воркер (круг записи без пустой таблицы), прокси (скрыто/показано/`bars_home: None`, вызов скрытого инструмента не доходит до воркера, настоящий exe с подменой `BARS_USER_HOME` отдаёт 10 инструментов), окно (фикстуры).

## Не сделано

- Установленная сборка и настоящие клиенты не проверялись: новые списки дойдут до агентов после установки (4.4.3).
- `bars_rag_search` с `mode=mix|graph` от ключа не зависит: решение OQ-162 касается шести инструментов. Если mix тоже нужно скрыть, это отдельное решение автора.
- Тексты skills и обеих копий `BARS_INSTRUCTION` упоминают графовые инструменты — они в 4.1.3 (ISS-29, ISS-30).

Чужой `git pull --rebase --autostash` откатил моё рабочее дерево после зелёной проверки; правки вернул из висячего autostash-коммита, общие `types.ts` и `mock.ts` собрал заново от `HEAD`. Способ и ловушка — [сборка и проверки](../../knowledge/build.md), раздел «Коммит при чужих правках в рабочем дереве».
