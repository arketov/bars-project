# Проверка этапа 30 — экран анализа MCP

18-10-2026, Windows. Реализован экран в рабочей копии; ISS-14 остаётся открытым до нативной приёмки этапа 32. Установка, публикация, коммит и push не выполнялись. Параллельные изменения сохранены.

## Что реализовано и проверено

| Сценарий | Доказательство |
|---|---|
| M-01: четыре вопроса автора | Продуктовый Svelte-компонент показывает инструмент, проект/соединение, локальное время, вход, применённые параметры, исход, длительность и количество с единицей без раскрытия JSON |
| M-02: умолчания и ограничения | Таблица разделяет запрошенное и применённое; limit/candidates/min_score используют сохранённые sources. Missing, null, пустая строка/массив, неизвестное и неприменимое различимы. Текущие настройки не подставляются; при отсутствии исходного контекста typed-снимок помечен явно |
| M-03: разные итоги | Нулевой успех, ошибка с безопасной причиной, выполняется, неизвестно, fallback и принятая очередь имеют разные подписи. Последнее не объявляется готовым индексом |
| M-04: большой список | UI-тест: 10 000 в summary, первая страница 50, продолжение с точным курсором без дублей. Браузер: 240 записей, 50 → 100, затем исход error → 40; сводка после серверной фильтрации |
| M-05: выбор/пустота | Фильтр закрывает подробности; обновление сохраняет ID, в том числе вне первой страницы. Вытеснение объясняется. Закрытие возвращает фокус строке либо заголовку списка, если строки нет на обновлённой странице |
| M-06: сбои | Ошибка чтения не становится пустотой; повтор восстанавливает список. Диагностика читается отдельно. Поздний ответ старого фильтра не меняет новый список/выбор; результаты подсказок также инвалидируются |
| M-07: хранение | Очистка требует подтверждения всех проектов/сессий и прежних агрегатов, начальный фокус на отмене. Ошибка сохранения остаётся ошибкой; переключатель ждёт подтверждения сервера. Старые суммы доступны отдельно |
| Подсказки | SQL ищет метаданные во всей истории периода, не только первой странице: часть пути/ID с учётом регистра, сессии выбранного проекта, максимум 200 + признак ограничения. Rust-тест: 205 сессий и отдельная сессия другого проекта |

## Настоящая запись и границы проверки

Новый Rust-тест `handler::tests::history::mcp_history_ui_real_ipc_record_has_readable_input_and_result`: временные home/проект, настоящий локальный IPC, протокольный клиент с `ClientKind::Mcp` и исходным контекстом, настоящий обработчик/SQLite. `bars_read`, `path=guide.md`, `format=json` → успех, **18 строк**, применённый абсолютный путь и `range=whole_document`. Индексация тестового корпуса использует FakeProvider; инференс/качество моделей не проверяются. Публичный stdio-прокси этим новым тестом не запускается.

Сериализованная страница получена из stdout теста (`MCP_UI_EVIDENCE`), временный корень обезличен до `C:/temporary-bars-project`. Остальные поля сохранены: [фикстура реальной записи](../../../ui/src/lib/fixtures/mcp-history-ipc.json). Эта страница проверена компонентным тестом и в браузере в обеих темах. Нулевая длительность — реально сохранённые 0 мс короткого чтения, не подстановка неизвестного.

Браузерный стенд [ui/preview/mcp-history.html](../../../ui/preview/mcp-history.html) монтирует настоящий компонент с изолированным адаптером в памяти. `scene=ipc` — полученная запись, остальные сцены вымышленные; команды управления не затрагивают установленный профиль. Запуск: `npm --prefix ui run dev`, затем `/preview/mcp-history.html?scene=ipc&theme=light`. Снимок записи датирован 18-10-2026; позже стандартный фильтр последних суток может его исключить.

Настоящие Tauri invoke проверены на уровне привязок/имён аргументов с mock invoke и компиляцией приложения. Клики в собранном WebView, системная интеграция, macOS и закрытие ISS-14 остаются этапу 32. Предельная нагрузка с одновременной записью 10 000 попыток этим этапом не измерялась.
