# Handoff: токенизация по языкам

Продолжение темы: [search-bench](../2026-11-03-search-bench/handoff.md), раздел «Аудит 03-11-2026» в [search-quality.md](../../knowledge/search-quality.md). Результат — [tokenization.md](../../knowledge/tokenization.md), данные — [tokenization-2026-11-03](../../knowledge/tokenization-2026-11-03/Index.md).

## Сделано

- Опыты на node по копиям индексов и 168 запросам бенча, только FTS: стемминг (Snowball, правила для ПРОПИСНЫХ, коротких слов и цифр, префиксы, лемма OpenCorpora через `az`), поля и точная форма, веса, стоп-слова, идентификаторы, camelCase, множитель покрытия, trigram, исправление опечаток по словарю индекса.
- Главное: **четыре колонки** (название и имя файла, заголовки, текст, точная форма с малым весом) дают +9 п.п. первым и +0,05 MRR к Snowball в две колонки (60 % / 77 % / 0,691 против 51 % / 73 % / 0,637), на проверочной части не хуже, чем на подборе; исправление опечаток по словарю возвращает Hit@3 65 → 76 % на синтетических опечатках; лемма, префиксы, стоп-слова, camelCase, множитель покрытия, trigram как основной сигнал не помогают или вредят.
- Определение языка: по письменности точнее и дешевле n-грамм (одно слово 19/21 против 10–11/21); язык — свойство слова. CJK: `unicode61` не находит ничего (0/18), биграммы 18/18, trigram 16/18, ICU 17/18, jieba 7/18 (синтетический корпус).
- Оценка tantivy и Rust-крейтов по документации; рекомендация — остаться на FTS5 с подготовкой токенов до индекса.
- Новые вопросы OQ-261…OQ-264 в `QUESTIONS.md`; строки в индексах `knowledge/`, `chats/`; ссылки из `stack-research.md` и `search-quality.md`.
- Ничего не собиралось, `cargo`, `scripts/check.ps1` и сборки не запускались; npm-пакеты ставились только в папку scratchpad.

## Не сделано

- tantivy и Rust-токенизаторы не запускались (OQ-262).
- Нет метрик по языкам кроме ru/en; CJK — синтетика (OQ-261, OQ-264).
- Строгое правило приёмки не выполнено у лучшего варианта: 16 запросов ухудшились (список в документе), разбор — в 2.3.4.
- Время запроса и исправления опечаток на большом словаре, мягкое покрытие слов запроса — не измерены.

## Сложности

- `queries.json` в копиях закрытых проектов не содержит `split`; деление на подбор и проверку взято по чётности номера запроса.
