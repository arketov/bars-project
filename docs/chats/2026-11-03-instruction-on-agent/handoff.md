# Handoff — BARS_INSTRUCTION.md только при работе агента (шаг 3.1.3)

## Сделано

- Документы сначала: [как файл живёт в проекте](../../features/docs-convention/bars-instruction.md), [доставка](../../features/docs-convention/delivery.md), [порядок проверки](../../features/indexing/updates.md), [реестр проектов](../../features/projects/projects.md), [файлы на диске](../../architecture/files.md), требования базы знаний, руководство (`manual/projects.md`, `manual/agents.md`).
- Решение: отметка «агент работал с проектом» — сам файл `BARS_INSTRUCTION.md`, флага в `.bars/config.toml` нет. Файл есть — хеш сверяется при каждой проверке, как раньше; файла нет — проверка его не создаёт. Проекты, где файл уже лежит, ведут себя прежне.
- Файл кладёт `Worker::observe_mcp` при первом вызове после истечения аренды: через него идут и хук сессии (`session_start`, оба пути), и каждый вызов MCP по проекту. Окно, создание проекта (Т-35, и так не клало), CLI-регистрация — файл не кладут; CLI работает как окно.
- Код (не собирался, не запускался, не закоммичен): `crates/bars-core/src/instruction.rs` (`sync` не создаёт, новая `place` создаёт), `crates/bars-worker/src/worker/activity.rs` (`place` при первом `observe_mcp`).
- Тесты (написаны, не запускались): `instruction.rs` (sync не создаёт / place создаёт / правка по хешу), `worker/tests/activity.rs` (окно без агента — файла нет; MCP и хук — есть; существующий файл сверяется), `worker/tests/deletion.rs` (вызов `observe_mcp` для файла), комментарий в `bars-cli/tests/cli.rs`.
- Файл по-прежнему не индексируется и не показывается в дереве (код `walk.rs`, `tree_io.rs` не менялся).

## Не сделано

- Сборка, тесты, `scripts/check.ps1` — по запрету автора. Код не коммитится до общего прогона.
- Комментарии в `worker/job.rs` и `worker/scan.rs` («Т-8: инструкция сверяется после каждой проверки») остались; поведение верное, слова неточные.
- Скрипты `scripts/*` и UI-тексты не проверялись на ожидание файла сразу после регистрации в окне.

## Сложности

- Нет явного признака «команда от агента» у CLI: считается агентом только путь через MCP или хук. Агент, вызвавший CLI в терминале, получит файл при первом MCP-вызове.
- Файл, удалённый человеком, вернётся при следующей работе агента.
