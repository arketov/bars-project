## Критерии выбора документа в AI-сессиях

Обе стандартные сессии записывают воспроизводимый баг, неутверждённую идею, ограниченный замер A/B, принятое решение SQLite, требования export с приёмкой, короткий log и handoff. Проверяются пути, ссылки, frontmatter/title/H1, оглавления, сохранение статуса идеи и исследования, отсутствие расширения общего SPEC подробностями фичи. Ссылка на принятый ADR из описания устройства допустима вместо копирования решения.

Обе сессии override получают собственные правила: корень `manual/`, баги в `tickets.md`, замер в `perf.md`, передача в `next.md`. Они должны обновить эти документы и не создавать `docs/`, `backlog/`, `knowledge/` или `chats/`. Это проверка рекомендательного характера таблицы на реально выполняющей задания модели.

Это проверка доступности рекомендаций, не общий бенч качества; параметры живого поиска менялись параллельной работой, поэтому оценки между вызовами не сравниваются.

## Найденные ограничения и изменения после опытов

- Длинная таблица плохо находилась по вопросу о багах: нужные строки выделены в самостоятельный раздел. Повтор того же вопроса с обычным порогом вернул этот раздел первым.
- Первоначальная формулировка тестового проекта «требования только SPEC» запрещала отдельный документ требований фичи. Стенд уточнён: в SPEC только общие требования.
- После исправления стенда одна сессия всё ещё расширила SPEC деталями export. В инструкцию и bars-docs добавлена явная граница между общими требованиями и требованиями фичи; проверка неизменности SPEC усилена. Четыре приёмочные сессии на окончательном asset прошли; все последующие проверки доставки используют те же тексты.
- Процессный опыт со встроенной моделью начал скачивание в изолированную папку и не уложился в таймаут. Для проверки документации он заменён FakeProvider за `test-support`; запрос fake-модели без этой сборки завершается ошибкой до запуска воркера. Процессы стендов завершаются штатно либо по своему PID.
- Общий `cargo fmt --check` затронул незавершённые параллельные файлы. Проверка rustfmt ограничена изменёнными Rust-файлами этого этапа; чужие файлы не форматируются.
