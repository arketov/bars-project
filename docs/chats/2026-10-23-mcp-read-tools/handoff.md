# MCP после редактора — реализация и границы приёмки

## Сделано 23-10-2026

По OQ-146 реализованы два инструмента чтения поверх общих модулей: `bars_text_search` и `bars_links`. Строгие ревизии/курсоры, независимая отмена, ограниченные страницы и ошибки чтения, TXT/JSON и история без содержимого ответа. Оконные методы не открыты агенту. Контракт — [инструменты MCP](../../features/agent-tools/mcp-tools.md); инструкции, два skill, доставка и руководство актуализированы.

Пройдены проверки протокола (55), ссылок (10; один замер ignored), поиска (6), IPC (10), MCP (5 unit + 14 integration), инструкции (3), клиентов (18), таблицы Т-37 и YAML skills. `check.txt`, `protocol.txt`, `links.txt`, `text.txt`, `ipc.txt`, `static.json`; итоговые логи Cargo сохранены рядом. Настоящий stdio-процесс: `stdio.json`; обновление клиентов в шести изолированных сессиях: `client-refresh.json`; регистрация/доставка: `docs-delivery.json`. Реальные профили не изменены.

Установщик собран штатным скриптом без переустановки зависимостей. Путь, дата, SHA-256 и PE — `artifact.json`, сборка — `installer-build.txt`. Установщик содержит текущее совместное рабочее дерево; проверки этой сессии относятся к MCP, не ко всем параллельным изменениям.

## Не сделано и ограничения

Общий пункт 4.4.2 открыт. Автор 23-10-2026 подтвердил OQ-113: «Сохранить запрет на установку». Рабочий bars не закрыт и не обновлён. Нет приёмки доставки установленной сборкой, ручного доверия `/hooks`, настоящей сессии Claude Code и IPC под другим пользователем Windows. CLI Claude не найден в PATH и проверенных стандартных местах. Проверки DACL под текущим пользователем не заменяют второй аккаунт.

Настоящий Codex 0.163.0-alpha.11.1 дождался единственного вызова за 65005 мс без настройки tool timeout (`codex-timing.json`). Это не воспроизведение прежнего `Transport closed`; причина старого сбоя не доказана, таймауты продукта не изменены.

## Сложности и дальше

Serena недоступна в инструментах сессии; выполнена ручная навигация и проверка изменений. У процессного стенда обнаружены две причины ложных отказов: asset изменился во время сборки; старый стенд читал stderr вместо штатного worker.jsonl. Исправлены logger примера, выбор событий своего PID и ожидание точных четырёх skill-файлов; последующий прогон успешен. Параллельные изменения сохранены; ветка не менялась, push не выполнялся.

После отдельного разрешения: штатное обновление и новое initialize реальных клиентов, доверие хуку самим пользователем, сессия Claude Code и проверка другого аккаунта Windows. До этих проверок закрывать весь 4.4.2 нельзя.
