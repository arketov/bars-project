# Чтения без записи и восстановление файлов индекса 5.1.2 — передача

Предыдущая сессия: [handoff](../2026-10-28-worker-index-rules/handoff.md)

## Сделано

- Правила из [воркер bars](../../architecture/worker.md) реализованы: `similar`, `duplicates`, список модулей, дерево и два аудита открывают индекс через `Index::open_read_only`; `Inner::activate` файлов индекса больше не трогает (ISS-67, ISS-68).
- `recover_index_files` (`bars-core/src/indexing/indexer.rs`) — таблица `index.sqlite` / `.old`, `.new` удаляется всегда; воркер зовёт её в `Worker::start` до очереди и в начале `job::run` под замком задания (ISS-67, ISS-76).
- `IndexingError::Swap { cause, rollback }`: неудачный откат подмены виден; воркер пишет обе причины в лог уровнем `error` и ставит `last_error` (ISS-76).
- scan сверяет `stem_version` (`Index::stem_outdated`) и ставит задание обновления, которое перестраивает FTS.
- Тесты: восстановление и откат в `indexer/tests.rs`, три теста воркера (старт возвращает `.old`, задание возвращает `.old`, проверка из таймера не трогает `.new`).
- Правки: worker.md, hybrid-search.md, статусы ISS-67, ISS-68, ISS-76 в `backlog/issues.md`, отметка в плане.

## Не сделано

- 5.1.3 (выход на границе документа, ISS-66, OQ-168).
- Не проверено на живом воркере: полная переиндексация, у которой отказывает подмена.

## Сложности

- В рабочем дереве шли чужие правки (виды ошибок модели, `ModelFailure`): целиком `scripts/check.ps1` не прошёл — падали `cargo fmt` и сборка в чужих файлах (`gate.rs`, `query.rs`, `bars-protocol`, тесты каталога моделей). Свои крейты проверены отдельно, итог — в коммите; коммит собран только из своих хунков.
- Чтение без записи меняет ответ для проекта без файла индекса: `similar`, `duplicates` и аудиты теперь отвечают ошибкой открытия, а не создают пустой индекс.
