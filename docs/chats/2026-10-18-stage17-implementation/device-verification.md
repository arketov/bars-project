# Этап 17 — проверка устройств моделей и ошибок индексации

Статус: реализация и целевая приёмка на Windows выполнены 18-10-2026. Протокол — [stage17-plan.md](../2026-10-18-device-design/stage17-plan.md), компактные доказательства и SHA-256 — [device-evidence.json](device-evidence.json). Рабочая копия содержит независимые параллельные изменения; манифест фиксирует хеши реально проверенных исходников, не объявляет чистым весь checkout.

Коммит реализации: `327bfbd`.

## Проверенный продуктовый результат

- `embed.accelerator` и `rerank.accelerator` независимы. Старый общий ключ читается без потери CPU-выбора и переносится при Save. Неиспользуемое устройство HTTP-провайдера не заменяет его слот.
- `models_info.runtime` сообщает состояния unloaded/loading/ready/failed, устройство сессии и причину CPU-fallback. Чтение не берёт mutex инференса. Старый loader не перезаписывает сведения нового слота; действующий запрос сохраняет старую модель.
- Индексация делает первую попытку и три повтора с паузами 1/2/4 с. После отказа документ пропускается; три неудачных документа с вызовом embed подряд останавливают проверку. Успешный embed сбрасывает серию, неизменённые файлы — нет.
- Старый документ и layout сохраняются при отказе. По OQ-80 полный rebuild с пропусками embed не подменяет старый индекс; отчёт ошибок остаётся доступен и при abort/cancel. Окно показывает ошибки во время работы, номер попытки, устройство задания и итог; sidebar не называет неполную проверку актуальным индексом.

## Проверки кода и регрессии

| Проверка | Результат |
|---|---|
| `cargo test -p bars-core -p bars-worker -p bars-protocol --lib --locked --quiet -- --test-threads=1` | core 193, protocol 50, worker 132 — пройдены |
| `cargo test -p bars-cli -p bars-mcp --locked --quiet -- --test-threads=1` | CLI 8, MCP 9 — пройдены |
| `cargo clippy -p bars-core -p bars-worker -p bars-protocol --lib --tests --locked -- -D warnings` | пройдено |
| `cargo check -p bars-app --locked` | нативный Tauri-крейт проверен компилятором |
| `npm test`, `npm run check`, `npm run build` в `ui/` | 55 тестов; 0 ошибок/предупреждений Svelte; production build готов |

Регрессии включают четыре сочетания настроек; приоритет миграции по ключам и сохранение комментариев; независимость слотов, активного читателя и старого loader; чтение runtime при занятом model mutex; успех после одного/трёх повторов, одиночный отказ, серию отказов, восстановление провайдера, неизменённый файл между отказами; повтор файла после сохранения старого hash/stat, защиту layout и бинарную неизменность старого индекса после неудачного rebuild. Loopback HTTP считает ровно четыре запроса при 429/503 и один при 401 — вложенного бюджета нет. Инъекция отказа GPU проверяет CPU-fallback с причиной и ошибку, если CPU тоже не загружается.

Проверки watcher и CLI уточнены: начальный отчёт может быть заменён фоновой проверкой, а кратковременное indexing допустимо после успешного поиска. Проверяется содержимое индекса и ограниченное ожидание готовности, без отключения слежения.

`clippy --all-targets` встретил независимое предупреждение `needless_range_loop` в параллельном `examples/inference_worker/mod.rs`; чужой стенд не менялся. Расширенный прогон интеграционных тестов core выполнил проверки bge/CPU/DirectML и rerank, но остановлен на дорогой повторной индексации всего текущего `docs/` на CPU (`search_corpus`). Этот прогон не объявляется полностью пройденным; полный бенч качества этапов 9/11 не повторялся.

## Аппаратные сессии настоящего воркера

Стенд — `crates/bars-worker/examples/verify_devices.rs`: отдельные каталоги home/fixture в `spikes/stage17/`, `Worker` и штатные обработчики SettingsGet/Save, ModelsInfo, Search. Канал MCP здесь не используется; MCP проверен отдельно. Веса берутся из существующего кэша без скачивания; пользовательские настройки, проекты и установленное приложение не менялись. Каталог моделей DTO смотрит в изолированный home, провайдер явно получает общий кэш: его downloaded-флаги не используются как доказательство загрузки.

Обе сессии выполнены последовательно на i7-11700KF / RTX 3090, драйвер 32.0.16.1692. Устройство — EP сессии, не профиль размещения всех операторов.

| Стартовый выбор | Подтверждено после загрузки | Проверка изменения через Save |
|---|---|---|
| embed Auto, rerank CPU | embed DirectML, rerank CPU | rerank переведён в Auto → DirectML; устройство embed сохранено |
| embed CPU, rerank Auto | embed CPU, rerank DirectML | rerank переведён в CPU; устройство embed сохранено |

В каждой сессии: два документа проиндексированы; поиск и повторный поиск дали две оценки rerank без fallback; Settings Save/Get сохранил выбор. После смены только rerank его runtime стал unloaded, embed сохранил устройство; следующий поиск успешно загрузил новый rerank, отпечаток индекса остался совместимым. JSON содержит результаты до и после Save. Первый исследовательский запуск стенда преждевременно принял fallback при загрузке за готовность; он не засчитан. Финальный стенд требует `score_kind=rerank` и отсутствие `rerank_error`.

Воспроизведение: собрать `cargo build -p bars-worker --example verify_devices --locked`, затем запустить `target/debug/examples/verify_devices.exe <новый-home> <кэш-моделей> auto cpu` и аналогично `cpu auto`. Home должен быть новым; путь к кэшу указан явно. Источники, параметры и бинарник сверять с манифестом, тяжёлые сессии выполнять последовательно.

## Проверка окна и границы доказательств

Через браузер открыт настоящий Svelte UI dev-сервера; проверены два независимых переключателя и сохранение выбора второй модели при изменении первой. При Save найден дефект dev-заглушки `structuredClone(proxy)`: исправлен существующим JSON-clone и покрыт отдельным тестом с Proxy. Компонентные тесты проверяют fallback и отсутствие GPU-кнопок для HTTP/candle. После исправления CUA закрыл соединение (`Transport closed`), включая попытку reset: повторная интерактивная проверка Save и скриншот не выполнены. Реальный Save/Get и последующая смена устройства подтверждены обработчиками воркера в аппаратных сессиях; это отдельно от браузерной заглушки.

Tauri/webview и установщик в этой сессии не переустанавливались. macOS не проверена.
