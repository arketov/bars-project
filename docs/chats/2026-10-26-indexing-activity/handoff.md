# Активность проектов и очередь индексации

## Сделано

- Реализовано уточнение Т-10 / OQ-206: часовая проверка, MCP-наблюдение от последнего вызова, открытые проекты UI. Контракт — [обновление индекса](../../features/indexing/updates.md).
- Неактивные проекты без notify; фоновые и хвостовые scan добавляют обновление только при расхождениях. Сохранены приоритет явной проверки, отмена, ошибки настроек, ручная остановка графа и обновление BARS_INSTRUCTION.md без задания индексации.
- Независимые привязки окон; Tauri использует ID настоящего окна, закрытие в трей снимает наблюдение, скрытый WebView его не восстанавливает.
- Полный `scripts/check.ps1 -Jobs 2` зелёный: fmt, clippy, build, Rust, Svelte 0/0, 522 теста UI. Воркер: 305 passed, 2 штатных ignored. Локальный лог — `check-final-5.txt`; воспроизведение окружения — `check.ps1 -Mode all`.
- Изолированный WebView2: [результат пяти проверок](native/result.json). Стенд завершается, рабочий bars и его профиль не затрагиваются. Дифф проверен вручную.
- Обновлены требования, архитектура, руководство и changelog. Параллельные изменения сохраняются отдельно от коммита задачи.

## Не сделано

- Установленная сборка не обновлялась; её приёмка не заявляется.

## Сложности

- Начальный переход на scan возобновлял остановленный граф; фон теперь использует запуск без resume. Подготовка MCP-теста новых тем ждёт начальную проверку, сохраняя запрет сбора при неготовом индексе.
- Общий кэш C:/bt/bars задерживал параллельные сборки. Красный общий прогон также поймал изоляционный тест MCP из параллельной работы; текущий исходник с уникальными каналами прошёл общий повтор. Отрицательные логи сохранены локально.
- Rust example потребовал штатный Windows manifest; рабочее приложение и системные DLL не менялись.
