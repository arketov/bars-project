# Поиск без rerank на 5 000 чанках, CPU и Worker/IPC (шаг 6.2.1) — итог сессии

## Сделано

- Полный индекс естественных 5000 чанков и по две серии из 100 поисков без rerank на CPU — в ядре и через настоящий воркер и IPC, ноутбук Core Ultra 5 125H (OQ-195…OQ-197). [Исследование скорости](../../knowledge/inference-speed.md), раздел «Естественные 5 000 чанков», записывает, что из прогона верно: индекс, стабильность выдачи, совпадение воркера с ядром.
- Автор признал замер грязным: серии шли, пока он работал, и пункты 6.2.1 и 6.2.2 вычеркнуты из плана (OQ-198). Задержки и сравнения серий сняты как результат; НФТ-2 не подтверждено. Сырые данные — [прогон под нагрузкой](../../knowledge/search-cpu-2026-10-25/Index.md).
- Стенд `crates/bars-worker/examples/bench_worker_search_cpu.rs` (новый); в `crates/bars-core/examples/bench_search_cpu.rs` — запасная подготовка на CPU. Правлены hybrid-search.md, traceability.md, `knowledge/Index.md`, QUESTIONS.md, PLAN.md. Коммиты `f1d1b20`, `1a0bbfc`, `f092ffa` и итоговый коммит этой правки.

## Не сделано

- Честного замера НФТ-2 нет: нужна серия без работы на машине с записью загрузки CPU рядом с каждым ответом. Пункта плана для неё нет.

## Сложности

- Замер под нагрузкой. Стенд следил только за свободной памятью, не за CPU, поэтому серии в разное время несравнимы. Решение автора — вычеркнуть пункт (OQ-198); граница записана в исследовании.
- Подготовка на DirectML встроенной Arc шла 34 ч и была остановлена Monitor; частичный индекс взят в кэш, остаток посчитан на CPU (OQ-196). Медленнее ли DirectML сам по себе, не доказано.
- Воркер один раз не стартовал без 4 ГиБ свободной RAM и один раз остановился без записанной причины; стенд теперь ждёт запаса памяти и пишет подробную ошибку.
- Сверка выдачи по хешу ломалась на f32, перечитанных как f64; стенд сравнивает разобранный JSON.
- Serena и semble не подключились; код читался через `git show`. Параллельная сессия закоммитила часть правок и перенумеровала вопросы.
