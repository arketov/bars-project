# Поиск без rerank на 5 000 чанках, CPU и Worker/IPC (шаг 6.2.1) — итог сессии

## Сделано

- [Исследование скорости](../../knowledge/inference-speed.md), раздел «Естественные 5 000 чанков»: полный индекс естественных 5000 чанков и по две серии из 100 поисков без rerank на CPU — в ядре и через настоящий воркер и IPC. Ноутбук Core Ultra 5 125H, общая нагрузка (OQ-195…OQ-197).
- Главное: через воркер 200 из 200 ответов быстрее 1 с, медиана 0,12 с, максимум 0,55 с; выдача совпала с ядром. Прямой `search` в ядре — медиана 0,31 с при свободной памяти и 0,58 с при её нехватке (тогда 5 из 100 дольше 1 с).
- [Доказательства](../../knowledge/search-cpu-2026-10-25/Index.md): сводки, все наблюдения, журналы Monitor, хеши.
- Стенд `crates/bars-worker/examples/bench_worker_search_cpu.rs` (новый); в `crates/bars-core/examples/bench_search_cpu.rs` — запасная подготовка на CPU. Правлены hybrid-search.md, traceability.md, `knowledge/Index.md`, QUESTIONS.md (OQ-195…OQ-197).

## Не сделано

- Статус НФТ-2 в MAIN_IDEA.md («требует подтверждения») не менялся: правка требования — решение автора с записью в журнал раундов.
- Причина разницы ядро/воркер (0,27 против 0,08 с вне embed) не установлена; нужен профиль.
- Окно, MCP, одновременные запросы, холодный кэш ОС и другие машины не мерились.

## Сложности

- DirectML на встроенной Arc при нехватке RAM считал около 2,3 мин на чанк; через 34 ч Monitor его остановил. Остаток досчитан на CPU за 8 минут, частичный индекс пошёл в кэш.
- Воркер один раз отказался стартовать (свободно 0,49 ГБ RAM) и один раз остановился на втором запросе без записанной причины; после этого стенд ждёт запаса памяти и пишет подробную ошибку, две серии прошли подряд.
- Сверка выдачи в первой серии воркера давала 92 из 100 из-за f32/f64 в хеше; побайтово 100 из 100, сверка исправлена.
- Serena и semble не подключились; код читался через `git show`. Параллельная сессия закоммитила часть моих правок и перенумеровала вопросы.
