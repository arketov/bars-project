# Модели в bars — встроенные и внешние, видеокарта и смена модели

Статус: пересказ простыми словами на 19-10-2026, сверен со [встроенными моделями](../features/models/local-models.md), [внешними моделями](../features/models/external-models.md) и [согласием на переиндексацию](../features/window/reindex-consent.md). Работа на Mac и слабых видеокартах не проверялась.

## Зачем bars модели

bars использует две модели:

- **embed-модель** превращает текст в вектор, чтобы искать по смыслу. Без неё поиск по смыслу не работает. Одна на все проекты.
- **rerank-модель** перепроверяет лучших кандидатов и уточняет порядок. Необязательна, по умолчанию выключена.

Модели только ищут и оценивают. Текст ответа они не пишут.

## Какие встроенные модели есть в bars

Встроенные модели работают прямо на вашем компьютере, без интернета (кроме первого скачивания).

| Модель | Что о ней знать |
|---|---|
| `BAAI/bge-m3` | **по умолчанию.** Хорошо понимает русский и английский, длинные куски не обрезает |
| `BAAI/bge-m3:fp16` | та же bge-m3 в облегчённом виде для видеокарты на Windows. Только видеокарта, процессор не поддерживается. Проверена не полностью |
| `Qwen/Qwen3-Embedding-0.6B` | на выбор; файл около 400 МБ |
| `Qwen/Qwen3-Embedding-4B` | на выбор; файл около 2,5 ГБ, на процессоре медленная |
| `nomic-ai/nomic-embed-text-v2-moe` | на выбор; только процессор; видит только начало длинного куска (примерно 1500 символов) |

Rerank встроенный один: `BAAI/bge-reranker-v2-m3`.

Если не знаете, что выбрать, — оставьте `bge-m3`.

## Как bars скачивает модель

Модель скачивается **при первом использовании** — когда вы добавили первый проект или впервые ищете. Можно скачать заранее: «Настройки» → «Модели» → кнопка «Скачать» у модели.

- Пока модель качается, окно показывает «Модель грузится, N %». Поиск в это время отвечает «модель загружается, повторите позже»; окно само повторяет запрос.
- При 100 % модель ещё загружается в память — это пара секунд.
- Окно можно закрыть: скачивание продолжится в фоне.
- Скачанные модели лежат в `~/.bars/models/` и общие для всех проектов.
- Если интернет оборвался, скачанная часть сохранится; нажмите «Повторить».

## Почему первый поиск после перерыва дольше

При смене модели текущий запрос заканчивает работу с прежней сессией. Освобождение её памяти выполняется отдельно и не задерживает короткие обращения к воркеру; следующая загрузка ждёт окончания освобождения.

Чтобы не занимать память, bars выгружает модели, когда они не нужны: rerank — через 5 минут простоя, embed — через 15 минут. Следующий запрос загрузит модель заново из файлов на диске: это несколько секунд, иногда с сообщением «модель загружается». Агент этого сообщения не видит: bars сам ждёт загрузку до минуты. Ничего не теряется и не скачивается заново.

Срок можно поменять для каждой модели: «Настройки → Модели → Выгрузка из памяти», минуты простоя. `0` — не выгружать совсем: первый поиск после перерыва станет быстрым, но модель всё время будет занимать память (у bge-m3 это гигабайты).

## Видеокарта или процессор для моделей bars

По умолчанию bars считает на **видеокарте, если она есть**, иначе на процессоре. На Windows подходит любая видеокарта с DirectX 12, включая встроенную Intel. Видеокарта выбрана даже когда она не быстрее: она разгружает процессор.

Выбор отдельно для embed и для rerank: «Настройки» → «Модели» → «Устройства моделей» → «GPU, если доступен» или «Только CPU». Применяется по «Сохранить».

- Переиндексация после смены устройства **не нужна**: результаты одинаковые.
- Если видеокарта не запустилась, bars сам переходит на процессор и пишет причину в настройках и в журнале.
- Текущая работа доделывается на прежнем устройстве.

## Как подключить внешнюю модель через API

Вместо встроенной модели можно взять чужую:

- **Удалённый провайдер** — облачный сервис с OpenAI-совместимым API (для embed) или API в формате Cohere (для rerank). Нужны адрес, имя модели и ключ.
- **Локальный адрес** — свой сервер на этом же компьютере или в сети (например, llama-server). Ключ не нужен.
- **Ollama** — отдельный вариант для embed. Сначала установите модель в Ollama, затем укажите корень сервера, например `http://127.0.0.1:11434`, и точное имя модели (`qwen3-embedding:0.6b`, `:4b` или `:8b`). Видеокартой управляет Ollama. bars запрещает тихое обрезание длинного входа. Для Qwen3 инструкция к запросу добавляется автоматически. Штатного rerank в Ollama нет: выберите его независимо, например встроенный. После замены весов под тем же именем выполните полную переиндексацию. Подробности подключения — [внешние модели](../features/models/external-models.md).

Где: «Настройки» → «Модели» → переключатель способа подключения.

**TEI (Text Embeddings Inference).** Отдельная кнопка для embed и rerank. Запустите по серверу TEI на каждую модель и укажите корни адресов без `/v1` (например, `http://127.0.0.1:8080` и `http://127.0.0.1:8081`). Имя в bars должно совпадать с загруженной моделью: TEI не переключает модель по запросу. Длинные тексты отклоняются без обрезания; уменьшите размер куска, если сервер сообщает о превышении контекста. Ключ при необходимости задаётся в тех же полях. Для Qwen3-Embedding сохраняйте имя `Qwen/Qwen3-Embedding-…` и не добавляйте ещё одну инструкцию на сервере.

**llama.cpp и Infinity.** Выберите «Локальный адрес» независимо для двух моделей. У llama-server запустите отдельные процессы: embedding с `--embedding`, rerank с `--reranking` и поддерживаемой reranker-моделью. У Infinity настройте префикс API `/v1`; точные имена моделей видны на его сервере. Для локальных Qwen3-Embedding с именами `Qwen/Qwen3-Embedding-…` или `Qwen3-Embedding-…` инструкция запроса добавляется автоматически; произвольный alias семейство скрывает. GPU, контекст, точность и расход памяти определяет внешний сервер. Сравнительного улучшения качества эти настройки сами по себе не гарантируют.

**LM Studio.** Запустите его локальный сервер, выберите «LM Studio» для embed и укажите адрес (обычно `http://127.0.0.1:1234`) и точный идентификатор embedding-модели. Например, `text-embedding-qwen3-embedding-0.6b`; для Qwen3 сохраняйте имя семейства в ID, чтобы bars добавлял инструкцию к запросу. GPU, контекст и выгрузку задаёт LM Studio. Он может без ошибки обрезать длинный текст: уменьшайте размер чанка и проверяйте журнал сервера. Символы чанка и токены контекста не равны. Штатного rerank API нет — выберите встроенный rerank или другой сервер. Модель и её квантизацию меняйте с полной переиндексацией. bars не скачивает модели LM Studio.

**Ключ.** Задаётся кнопкой и сохраняется в защищённом хранилище Windows, а не в файле настроек. В поле видно только имя записи. Ключ можно подменить переменной окружения. Исправленный ключ начинает действовать сразу, без перезапуска.

**Что уходит провайдеру.** При индексации — текст всех кусков документации; при поиске — ваш запрос. Если документация секретная — используйте встроенную модель или локальный адрес.

**Ошибки провайдера.** При индексации bars повторяет запрос до трёх раз с паузами. Если документ так и не обработался, он пропускается до следующей проверки, а старая версия в индексе остаётся. Если не отвечает только rerank, поиск идёт без него.

**Слишком длинный кусок.** bars не обрезает текст для внешнего провайдера. Если провайдер жалуется на длину, уменьшите максимальный размер куска («Настройки» → «Нарезка») или смените модель.

## Что будет, если сменить embed-модель

Векторы разных моделей несовместимы. Поэтому после смены embed-модели (или её облегчённого варианта, или внешнего провайдера):

1. Перед сохранением окно предупредит, что понадобится переиндексация.
2. После «Сохранить» откроется **диалог согласия**: слева модель индекса, справа новая; таблица проектов с числом документов и оценкой времени. Для внешнего провайдера — красное предупреждение, что все тексты уйдут ему и время и стоимость определяет он.
3. Кнопки:
   - **«Переиндексировать (N)»** — начать для отмеченных проектов. Можно отметить не все.
   - **«Позже»** — настройки сохранены, но проекты ждут. **Поиск по ним не работает**, пока вы не согласитесь.
   - **«Вернуть прежнюю модель»** — откатить настройку, всё снова работает без переиндексации.

Пока проект ждёт согласия, у него жёлтая точка, поле запроса недоступно, а над ним баннер с кнопкой «Переиндексировать…». Другие проекты ищутся как обычно.

Во время переиндексации старый индекс остаётся, а новый строится рядом. Нужно временно больше места на диске. Если переиндексация прервалась или часть документов не обработалась, старый индекс **не** заменяется неполным новым.

**Нюанс.** Агент через MCP не может дать согласие и запустить такую переиндексацию: это решение человека. Из терминала согласие даётся так: `bars-cli reindex --accept-model-change`.

**Смена rerank-модели** переиндексации не требует: новая модель просто загрузится при следующем поиске.

## Сколько памяти и времени занимают модели

Ориентиры с машины автора:

- bge-m3 на процессоре — около полсекунды на кусок при индексации. Проект на 5 000 кусков в первый раз — около 40 минут. Дальше — только изменения.
- Превратить запрос в вектор — около 50 мс.
- Поиск с rerank на мощной видеокарте — около 0,4–0,7 с; на процессоре — секунды.

На вашем компьютере цифры будут другими. Локальные модели занимают память не только весами: рабочие буферы могут вырасти после длинного текста и сохраняться до выгрузки модели. В проверенных сериях индексации с поиском bge-m3 FP32 достигала около 4,9 ГиБ private commit без rerank и 6,84 ГиБ с ним; облегчённый FP16-вариант — около 3,2–3,3 и 5,0 ГиБ. Это результаты одной машины и корпуса, не минимальные требования. Private commit не равен занятой физической RAM. Метод и границы — [исследование памяти](../knowledge/memory.md).

Для меньшего расхода на Windows можно явно выбрать `BAAI/bge-m3:fp16` при работающем DirectML; потребуется согласие на переиндексацию, как при любой смене embed-модели. При ошибке DirectML этот профиль не переходит на CPU автоматически. Заводская модель прежняя; разные precision не смешиваются в одном индексе.

Если обычная bge-m3 уже работает на DirectML, в «Настройки» → «Модели» есть предложение **«Выбрать FP16»**. Оно меняет только несохранённый выбор: проверьте его и нажмите «Сохранить». Затем отдельно подтвердите переиндексацию нужных проектов; до согласия новый индекс не строится. «Отменить» возвращает прежний выбор без записи.

В «Настройки» → «Модели» задайте сроки выгрузки: по умолчанию embed — 15 минут простоя, rerank — 5. Следующий запрос загрузит модель снова. Значение 0 оставляет модель в памяти постоянно. Выгрузка уменьшает расход после простоя, но не пик активной индексации; отключение ненужного rerank освобождает его сессию после текущего вызова.

## Файл подкачки и нехватка памяти

Файл подкачки увеличивает доступный Windows предел commit и может помочь приложениям продолжить работу при нехватке физической RAM. Он не делает модель меньше и не гарантирует прежнюю скорость: чтение вытесненных страниц добавляет задержку. В диспетчере задач смотрите не только свободную RAM, но и «Выделено» — текущее значение и предел. Свободный запас commit уже учитывает подкачку; сжатие памяти Windows не отменяет этот предел.

bars не меняет подкачку и настройки ОС. Проверенного размера файла подкачки и бюджета для машин с 8/16/32 ГиБ у проекта пока нет; правило «RAM × 1,5» из замеров не следует. При недостатке памяти можно отключить ненужный rerank, включить выгрузку по простою либо выбрать другую модель с подтверждением переиндексации. Число кандидатов и длина текста автоматически ради памяти не сокращаются.
