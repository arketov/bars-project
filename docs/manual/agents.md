# bars и агенты — подключение Claude Code, Codex и других клиентов

Статус: пересказ простыми словами на 19-10-2026, сверен с [подключением клиентов](../features/clients/clients.md) и [инструментами MCP](../features/agent-tools/mcp-tools.md). Установка проверялась на временных копиях профилей; на настоящем Claude Code проверка не делалась.

## Зачем подключать bars к агенту

Агент (Claude Code, Codex) без bars ищет в документации грепом по словам или читает файлы подряд — это долго и дорого по токенам. С bars агент задаёт вопрос своими словами и сразу получает нужные разделы с путями и строками. Это тот же поиск, что в окне, по тому же индексу.

## Как подключить bars к Claude Code, Codex или Kimi Code

**В окне:** «Настройки» → «Клиенты» → «Установить» в строке нужного клиента.

**В терминале:**

```powershell
bars-cli install --client claude-code
bars-cli install --client codex
bars-cli install --client kimi-code
```

Что делает установка:

- добавляет в клиент **MCP-сервер** `bars` — через него агент вызывает поиск;
- добавляет **хук начала сессии** — при старте сессии он сообщает bars, в какой папке работает агент; bars регистрирует проект (если там есть `docs/` с документацией или уже настроенный проект `.bars/`) и проверяет его индекс;
- кладёт три **skills**: `bars-docs` (как искать и читать документацию через bars), `bars-session-log` (как вести журнал сессии) и `bars-end` (завершение сессии). Правила оформления документов дублирует `BARS_INSTRUCTION.md` в корне документации проекта — bars кладёт его сам при первой работе агента с проектом.

После установки **перезапустите клиент**, чтобы он увидел bars.

## Завершение сессии командой bars-end

В конце работы напишите агенту `/bars-end` (в Codex — `$bars-end`). Агент перенесёт в документацию проекта всё, что узнал и сделал: поправит описания фич и руководство, запишет исследования, баги и пожелания, исправит устаревшие места и напишет итог сессии. Требования, решения, план и правила для агентов он только предложит — их правка ждёт вашего «да». Коммит агент не делает, пока вы не попросите. Сам агент эту команду не запускает. Подробности — [завершение сессии](../features/docs-convention/session-end.md).

## Подключение Ouroboros

В «Настройки → Клиенты» выберите Ouroboros и нажмите «Установить». Поддерживается `razzant/ouroboros` с обычной локальной папкой `~/Ouroboros/data/`. Через CLI: `bars-cli install --client ouroboros`; удаление — `bars-cli uninstall --client ouroboros`. Если настройки в этот момент сохраняет Ouroboros, повторите установку после завершения записи.

bars добавляет свой MCP-сервер в `settings.json` и включает MCP. Перед изменением сохраняет `.bars-backup`; другие серверы и настройки сохраняются. Хук и skills в Ouroboros не устанавливаются: добавьте проект в окне bars или командой `bars-cli register <папка>`. Общий MCP и выключенная запись не включаются повторно фоновым обновлением. Нестандартные пути `OUROBOROS_*`, удалённые и контейнерные установки пока не поддерживаются; путь к локальному `bars-mcp` должен быть доступен Ouroboros. Формат описан в [контракте подключения клиентов](../features/clients/clients.md).

## Подключение iterion

Клиент `iterion` реализован без проверки сборкой. «Настройки» → «Клиенты» → iterion → «Установить» или `bars-cli install --client iterion` (удаление — `bars-cli uninstall --client iterion`).

bars положит в папку `plugins/bars/` в `~/.iterion` (или в `ITERION_HOME`) плагин: он подключает MCP-сервер `bars` и skill `bars-docs`. Общий `plugins.yaml` bars не трогает. Другие два skills (`bars-session-log`, `bars-end`) в iterion не ставятся. Плагин нужен потому, что iterion запускает Claude Code только со своим списком MCP-серверов и записи из `~/.claude.json` не видит. Работает с узлами `claude_code`, `claw` и `pi`; узлы `codex`, `kimi` и `grok` плагины не видят.

Нюансы:

- **Только без песочницы.** Если iterion запускает workflow в Docker или Podman (`sandbox: auto` и они установлены), `bars-mcp` внутри контейнера недоступен. Отключите песочницу (`sandbox: none`) для workflow, которым нужен bars.
- **Хука нет.** Проект добавьте в окне bars или `bars-cli register <папка>`.
- **Рабочая копия запуска.** iterion работает в отдельной копии репозитория вне него; bars берёт проект основного checkout. Правки документов, сделанные внутри запуска, поиск не увидит, пока они не влиты в основной checkout.

Формат — в [контракте подключения клиентов](../features/clients/clients.md).

## Одобрение хука в Codex

Codex не запускает новый или изменённый хук, пока вы его не одобрите. После установки выполните в Codex команду `/hooks` и одобрите хук `bars`. Пока хук не одобрен, поиск у агента работает, но проекты надо добавлять самому — окном или `bars-cli register`.

bars напомнит про `/hooks` только когда хук действительно изменился.

## Какие файлы клиента меняет bars

| Клиент | MCP-сервер | Хук | Skills |
|---|---|---|---|
| Claude Code | `~/.claude.json` | `~/.claude/settings.json` | `~/.claude/skills/` |
| Codex | `~/.codex/config.toml` | `~/.codex/hooks.json` | `~/.agents/skills/` |
| Kimi Code | `~/.kimi-code/mcp.json` | `~/.kimi-code/config.toml` | `~/.kimi-code/skills/` |
| Ouroboros | `~/Ouroboros/data/settings.json` | Не устанавливается | Не устанавливаются |
| iterion (проект) | `~/.iterion/plugins/bars/plugin.yaml` (или в `ITERION_HOME`) | Не устанавливается | Только `bars-docs`, в `plugins/bars/` |

bars аккуратен с чужими файлами:

- перед правкой делает копию `<файл>.bars-backup`;
- меняет только записи с именем `bars`, остальное не трогает;
- повторная установка не создаёт дублей;
- если файл повреждён, ничего не пишет и сообщает об ошибке.

**Нюанс.** При каждом запуске bars сам проверяет и чинит уже установленные интеграции: например, после переезда в другую папку. Ваши правки текстов skills `bars-docs`, `bars-session-log` и `bars-end` при этом перезапишутся — они встроены в bars.

## Как убрать bars из клиента

«Настройки» → «Клиенты» → «Удалить» или `bars-cli uninstall --client claude-code` (или `codex`, `kimi-code`, `ouroboros`; `iterion` — когда клиент будет реализован). Уберутся только записи и установленные skills bars. При удалении самой программы bars это делается автоматически.

## Как подключить bars к другому MCP-клиенту

Любая программа, которая умеет запускать MCP-сервер через stdio (например, Claude Desktop), подключается вручную: «Настройки» → «Клиенты» → «Копировать конфиг» и вставьте его в настройки этой программы. Хука у таких клиентов нет: проекты добавляйте окном или `bars-cli register`.

## Инструкция для агента: пусть агент подключится сам

«Настройки» → «Клиенты» → блок «Инструкция для агента» → «Копировать», или `bars-cli install --print-instruction`. Вставьте текст агенту — он сам выполнит нужную команду установки. Текст на английском: он для агента, а не для человека.

## Какие инструменты bars получает агент

| Инструмент | Что делает |
|---|---|
| `bars_search` | один поиск тремя способами: по вопросу; по образцу (`like="путь:строки"` — похожие разделы других документов и ссылки на исходный); все вхождения строки (`occurrences`, узкое регулярное выражение — `/…/`); область — пути-префиксы `in` |
| `bars_read` | прочитать документ целиком или часть через `lines` / `under` (достаточно конца цепочки заголовков), с исходными номерами строк; `view=outline` — оглавление, `view=links` — входящие и исходящие ссылки; длинный документ без уточнений возвращается оглавлением с подсказкой; путь папки (без `.md`) — как `ls`: подпапки с числом документов и документы с названиями, один уровень, `order=desc` — обратный порядок (последние сессии журнала первыми), продолжение через `cursor` |
| `bars_status` | одна сводка: проект и модули, состояние индекса, версии прокси и воркера, состояние аудитов, число новых тем, граф; `refresh=true` запускает проверку индекса, `all=true` показывает все проекты |
| `bars_audit` | аудиты ссылок, дублей и противоречий плюс сохранённые вопросы («новые темы»): состояния, находки, сводка чисел, запуск и остановка; у новых тем — карточка и проверка без нового спроса |
| `bars_relations`, `bars_paths`, `bars_impact`, `bars_context`, `bars_explore`, `bars_graph` | работа с графом связей, см. [граф](graph.md); по умолчанию скрыты, включаются настройкой «Графовые инструменты MCP» |

До обновления 10-11-2026 инструментов было семнадцать; старые имена (`bars_rag_search`, `bars_text_search`, `bars_outline`, `bars_links`, `bars_get_similar`, `bars_projects`, `bars_reindex`, инструменты аудитов и новых тем) удалены без псевдонимов — сессия со старым подключением получит «неизвестный инструмент» до перезапуска клиента. Проверку индекса, которую раньше запускал `bars_reindex`, теперь запускает `bars_status` с `refresh=true`; полная переиндексация остаётся у окна и `bars-cli reindex`.

Агент **не может**: убрать или удалить проект, включить автозапуск, менять настройки, дать согласие на переиндексацию после смены модели. Это решения человека.

## Свежие правки и ссылки

Новые инструменты доступны после обновления сборки и перезапуска клиента. Точный поиск и ссылки читают диск, поэтому видят сохранённые изменения до embed; несохранённый текст редактора агенту недоступен. Смысловой поиск может ещё ждать паузы или очереди. Ради обычного ожидания переиндексацию запускать не нужно.

Если документ изменился между порциями точного поиска, агент получает `stale_revision`; если изменился снимок ссылок — `stale_cursor`. Нужно начать чтение заново. При усечении списка документов агент сужает область поиска. Полный исходник длинной ссылки можно прочитать через `bars_read`.

## Как агент выбирает проект

По умолчанию — проект той папки, где работает агент: ближайший зарегистрированный вверх по дереву; в git worktree — проект, чей репозиторий его создал, и по умолчанию вид этого worktree со своими правками (параметр `wt`, `wt="."` — основной checkout; ещё не реализовано, [worktree](projects.md)). Другой проект агент указывает явно, именем, путём или составным именем подпроекта `главный/путь`; искать проекты по части имени помогает `bars_status(filter=...)` (ещё не реализовано, [подпроекты](projects.md)). Поиск никогда не смешивает проекты.

Это же правило действует у сводки `bars_status`: без параметров она показывает проект сессии. Другой проект выбирается через `project`, полный список — через `all=true`. Назначения модулей берутся из их оглавлений; если оглавления нет в индексе, назначение не угадывается. Если проект сессии не зарегистрирован, агент получает ошибку с подсказкой, а не список чужих проектов.

Если модель загружается, нужно дождаться загрузки. Если не готов граф, пока доступны обычный поиск и чтение; граф обновляется после индекса, вручную — из окна или командой `bars-cli graph build`. Переиндексация эти ожидания не заменяет. Пометка `partial` говорит о неполном покрытии графа; сама по себе она не означает устаревшие данные.

## Как агент выбирает область поиска

При подключении bars сообщает агенту модули текущего проекта и число документов; назначение из оглавлений модулей печатается в конце стартовой инструкции и в части PROJECT сводки `bars_status`. Если воркер не ответил за три секунды, клиент продолжает работу с общей инструкцией. Новый модуль не запрещается схемой инструмента.

Агент выбирает область по виду знания среди настоящих папок вашего проекта — какие они, bars не предписывает: у кода это, например, описание поведения, решения и журнал сессий, у менеджера по продажам — инструкции, скрипты и архив сделок. Область задаётся путями-префиксами `in`: папка любой глубины или файл, несколько путей объединяются. Если нужно текущее состояние, агент не берёт журналы и архивы; нужна история — берёт её папку. Когда нужно несколько видов или место неясно, доступен весь проект; слабую или пустую выдачу стоит расширить. Обязательной частоты фильтрации нет. Ответ показывает область в шапке, а числа кандидатов и результатов по модулям — когда ответ пуст или результаты из нескольких папок. Эти числа объясняют состав выдачи, но не подтверждают полноту базы. Установленным клиентам изменения приходят с обновлённой сборкой; контракт — [модули для агента](../features/agent-tools/module-scope.md).

## Что такое BARS_INSTRUCTION.md

Когда агент начинает работать с проектом (хук сессии или первый вызов MCP), bars кладёт в папку документации этого проекта файл `BARS_INSTRUCTION.md` — короткую инструкцию для агентов на английском: как оформлять документы, чтобы bars хорошо их находил. bars сам обновляет этот файл и не включает его в поиск. Править его руками бесполезно: bars вернёт свою версию. Подробности — [инструкция bars](../features/docs-convention/bars-instruction.md).
