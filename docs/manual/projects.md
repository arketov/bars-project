# Проекты в bars — как добавить, убрать, перенести и удалить

Статус: пересказ простыми словами на 19-10-2026, сверен с [реестром проектов](../features/projects/projects.md) и [полным удалением](../features/projects/deletion.md). Что окно показывает, если проект пропал, — [экраны ошибок](../features/window/error-states.md#проект-пропал); если что-то пошло не так, смотрите [неполадки](troubleshooting.md). Меню проекта и удаление реализованы, но ручная проверка в установленном окне ещё не сделана.

## Что bars считает проектом

Проект — любая папка, где лежат ваши Markdown-тексты: репозиторий с кодом, заметки, рабочие инструкции, руководства. bars ищет только по файлам `.md`; код, картинки, PDF и HTML не индексируются.

При добавлении вы выбираете, где bars искать:

- **«Вся папка»** — все `.md` внутри папки. Подходит для заметок, инструкций и руководств.
- **«Папка `docs/`»** — только `docs/` внутри папки. Подходит для репозитория кода, где документация лежит отдельно.

Если в папке есть `docs/`, bars предложит её, иначе — всю папку. Выбранная папка — **корень документации**.

Подпапки первого уровня внутри корня документации bars называет **модулями**: например, `clients/`, `scripts/` или `docs/features/`. Файлы прямо в корне попадают в модуль «(корень)». По модулям удобно сужать поиск.

Каждый проект ищется отдельно: поиск никогда не смешивает два проекта.

## Как добавить проект в bars

**В окне.** Нажмите кнопку проекта вверху слева → последний пункт «Добавить проект…» → выберите папку → в окне «Что считать документацией?» оставьте предложенный вариант или выберите другой («Вся папка» или «Папка `docs/`») → «Добавить».

**В терминале** из папки проекта:

```powershell
bars-cli register .
bars-cli register . --root all
bars-cli register . --root docs
bars-cli status
```

Без `--root` bars берёт предложенный вариант: `docs/`, если она есть, иначе всю папку. `--root all` — вся папка, `--root docs` — папка `docs/`. Параметр действует, только пока у папки нет `.bars/config.toml`; у настроенного проекта корень меняется в настройках.

**Через агента.** Если bars подключён к Claude Code или Codex, проект добавится сам при старте сессии агента в этой папке, — но только если в папке уже есть `docs/` (с хотя бы одним `.md`) или `.bars/` проекта. Папку заметок без `docs/` агент сам не добавляет: добавьте её в окне или командой `bars-cli register`, выбрав «Вся папка».

Уже добавленные проекты при этом не меняются: у них остаётся прежний корень.

После добавления bars ставит проект в очередь и начинает индексацию. В первый раз bars может ещё скачивать модель: это видно по проценту в окне.

## Сколько ждать первую индексацию проекта

Первая индексация идёт в фоне. Время зависит от размера документации и компьютера: ориентир — около полсекунды на кусок текста на процессоре, то есть проект на 5 000 кусков может индексироваться около 40 минут. На видеокарте обычно быстрее. Пока индексация идёт, поиск работает по тому, что уже успело попасть в индекс. Следующие обновления быстрые: bars пересчитывает только изменённые разделы.

Ход виден в окне: мигающая точка у проекта, строка под деревом документов, кнопка «Подробнее» → страница проекта с процентом, скоростью и оставшимся временем.

## Что значит цвет точки у проекта

| Точка | Что значит | Что делать |
|---|---|---|
| зелёная | индекс актуален, рядом число документов | ничего |
| малиновая, мигает | идёт индексация | можно искать, но свежие правки могут ещё не найтись |
| жёлтая | нужна переиндексация после смены модели или есть ошибка файла | открыть проект и прочитать баннер |
| серая | папка проекта не найдена на диске | см. «Проект пропал» ниже |

## Если нужно сменить корень документации

Если в корне документации нет ни одного `.md`, bars покажет экран «документации не найдено» (жёлтая точка) с кнопкой «Выбрать другую папку документации…». Ту же кнопку можно использовать, чтобы сменить выбор позже. Можно выбрать любую папку внутри проекта, в том числе всю папку. Выйти за пределы проекта (`..`) нельзя. После смены папки bars перепроверит все документы сам, согласие не нужно; уже посчитанные куски переиспользуются.

Технически это ключ `docs_root` в файле `<проект>/.bars/config.toml`.

## Что лежит в папке .bars внутри проекта

После добавления в корне проекта появляется папка `.bars/`:

- `index.sqlite` — индекс проекта (тексты кусков, векторы, служебные данные);
- `config.toml` — настройки этого проекта, если вы их меняли.

Когда с проектом начинает работать агент (его хук сессии или первый запрос через MCP), bars кладёт в папку документации файл `BARS_INSTRUCTION.md` — инструкцию для агентов, как оформлять документы. Если вы добавили папку в окне и агентов не используете, файла в вашей папке не будет. Сам этот файл в поиск не попадает, а если он уже есть, bars обновляет его сам.

Если выбрана «Вся папка», `.bars/` и все папки, имя которых начинается с точки (`.git` и подобные), не индексируются и в дереве не показываются. Папки вроде `node_modules` или `target` bars сам не пропускает: у репозитория кода выбирайте «Папка `docs/`».

`.bars/` можно добавить в `.gitignore`: индекс у каждого свой и пересобирается.

## Как проверить индекс проекта вручную

bars следит за файлами открытого в окне проекта и час после последнего обращения MCP. Все проекты дополнительно проверяются раз в час; без изменений задания индексации не создаются. Если хочется проверить прямо сейчас:

- правый клик по проекту → «Проверить проект»;
- или кнопка «Проверить сейчас» на странице проекта;
- или `bars-cli reindex`.

Проверка файлов выполняется сразу, даже когда другой проект индексируется. Итог — в колокольчике: сколько изменений найдено или что различий нет. Пересчёт найденных изменений выполняется отдельно, в очереди; до него поиск видит прежний индекс. Пауза очереди не мешает самой проверке. Полная перестройка с нуля — `bars-cli reindex --full`; обычно она не нужна.

## Проект пропал: серая точка

Если папки проекта нет на месте, bars помечает его серым и перестаёт индексировать, но **ничего не удаляет**. Частые причины: проект перенесли, диск отключён, папка OneDrive выгружена в облако.

На экране проекта есть кнопки:

- «Проверить сейчас» — если папка уже вернулась;
- «Добавить проект на новом месте…» — если вы её перенесли;
- «Убрать из bars» — если проект больше не нужен.

Когда папка вернётся, bars сам продолжит работу при ближайшей проверке.

## Как перенести проект в другую папку

Перенесите папку проекта целиком, вместе с `.bars/`. Затем добавьте проект на новом месте («Добавить проект…» или `bars-cli register`). bars подхватит старый индекс без пересчёта, если модель в настройках та же. Старая запись станет серой — уберите её кнопкой «Убрать из bars».

## Убрать проект из bars или удалить его полностью

Есть два разных действия:

| Действие | Где | Что делает |
|---|---|---|
| **Убрать из bars** | кнопка у пропавшего проекта; `bars-cli unregister` | bars забывает проект. Папка `.bars/` с индексом остаётся: при повторном добавлении индекс подхватится |
| **Удалить проект** | правый клик по проекту → «Удалить проект» | забывает проект **и** стирает его индекс и настройки в `.bars/`. Есть окно подтверждения, по умолчанию выбрано «Отмена» |

Ваша документация и `BARS_INSTRUCTION.md` не удаляются ни в одном случае. Свои файлы, которые вы сами положили в `.bars/`, тоже остаются. Общие модели, настройки bars и другие проекты не затрагиваются.

**Нюанс.** После полного удаления агент может снова добавить проект при старте сессии в этой папке. Запрета на повторную регистрацию нет.

**Нюанс.** Агент через MCP не может ни убрать, ни удалить проект: это делает только человек.

## Вложенные проекты

Проект может лежать внутри другого. Агент и `bars-cli` выбирают ближайший зарегистрированный проект вверх от текущей папки.

Документы вложенного проекта живут в его собственном индексе: внешний проект их не индексирует и не ищет в них. Это относится к папке документации вложенного проекта; его файлы вне неё (например, `README.md` в корне) остаются у внешнего. Когда вы добавляете или снимаете вложенный проект, внешний сам пересчитывается: документы уходят из его индекса или возвращаются, без полной пересборки. Если вложенный проект пропал с диска, он остаётся исключённым, пока вы не уберёте его запись.

- **В дереве внешнего проекта** такая папка серая, с пометкой «вложенный проект», без галочки и с действием «Открыть проект».
- **В диалоге добавления папки** внутри проекта написано, сколько её файлов уйдёт из индекса внешнего; в диалоге внешнего проекта — какие вложенные проекты исключены.
- **Агент**, спросивший `bars_status` или поиск, видит строку «исключены вложенные проекты: …» с именем для параметра `project`.
- **Хранилище без проекта** (например, `gramax/`) целиком входит в индекс внешнего с корнем «вся папка»; чтобы вынести его, добавьте эту папку отдельным проектом.

Ещё не проверено сборкой и на реальных проектах: шаг написан без запуска тестов.

Работа в worktree (`.worktree/<имя>`, `.claude/worktrees/<имя>`) ищет по основному проекту: worktree лежит внутри него. Так же работает git worktree вне проекта (например, рабочая копия запуска iterion): по файлу `.git` bars находит основной checkout, и если он зарегистрирован, сессия ищет по нему, а хук начала сессии такую копию отдельным проектом не регистрирует. Правки документов, сделанные только в рабочей копии, в выдачу попадут после слияния в основной checkout. Ещё не проверено сборкой.

## Два проекта с одинаковым именем

По умолчанию имя проекта совпадает с именем папки. Чтобы задать своё, нажмите правой кнопкой на проект в переключателе и выберите «Переименовать…». Введите имя и нажмите «Сохранить». Папка и путь останутся прежними. Новое имя сохраняется после перезапуска и показывается также в MCP и CLI; агент может выбирать проект по нему. Старое имя папки больше не используется для выбора, абсолютный путь работает всегда. Если имена совпадают, окно показывает их с путём, а в командах и у агента такой проект нужно указывать путём.
