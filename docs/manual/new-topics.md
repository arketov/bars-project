# Новые темы в bars

При проверке через агента используется `bars_audit` с `kind="new_topics"` и `action="check"`: она сохраняет результат проверки, но не увеличивает число обращений и не закрывает тему за вас. Для сравнения поисковых формулировок агент указывает `diagnostic=true` в `bars_search`; служебные прогоны тогда не попадают в «Новые темы». Накопленные ранее записи автоматически не удаляются.

Статус на 19-10-2026: экран и сбор сделаны и проверены тестами и на заглушке воркера; **настоящая модель и собранное окно ещё не проверены** ([план проверки](../features/new-topics/plan.md)). Пересказ описания фичи, [устройства экрана](../features/new-topics/design.md#экран-в-окне) и [требований](../features/new-topics/requirements.md).

## Что такое «Новые темы» в bars

Первая строка в дереве документов слева, выше всех папок, — «Новые темы» со значком листа с искрой. Нажатие открывает список вкладкой в центре; документы из результатов проверки открываются справа, сохраняя список. Это список вопросов, на которые документация не ответила: поиск в окне или агент через MCP ничего не нашёл. По списку видно, какие знания стоит дописать. Список свой у каждого проекта. По вашему поручению агент читает его через `bars_audit` с `kind="new_topics"` (список, карточка `action=get`), чтобы дополнить документацию. bars не ищет по этому списку как по документам; закрытие и удаление темы остаются в окне.

Справа от названия — число активных тем (незакрытых). Прочерк вместо числа значит, что список не удалось прочитать; это не «ноль тем».

## Как вопрос попадает в список

- **Сам, если поиск ничего не вернул.** Пустой поиск в окне или у агента при готовом индексе становится темой. Пока идёт индексация, грузится модель или индекс устарел, тема не создаётся: это не отсутствие знаний.
- **Вручную, если выдача была, но ответа в ней нет.** Над карточками результатов справа есть «Не хватило знаний». Нажатие запоминает вопрос именно той выдачи, что на экране, даже если вы уже поправили поле запроса.
- Похожие вопросы объединяются в одну тему, формулировки сохраняются. Для bge-m3 порог сходства — 0,68; дополнительно проверяются смысловые отличия по числам, идентификаторам и известным противоположностям. Смена порога действует на новые обращения: уже созданные отдельные темы сама по себе не объединяет. Счётчик «обращений» считает отдельные поиски, а не людей и не задачи.
- Похожие вопросы объединяются в одну тему, формулировки сохраняются. Для bge-m3 порог сходства — 0,68, для проверенной встроенной Qwen3 4B Q4_K_M — 0,75; дополнительно проверяются числа, идентификаторы и известные противоположности. Автогруппировка может пропустить перефраз или объединить разные вопросы; для других моделей она включается после отдельного замера. Смена порога действует на новые обращения: уже созданные темы сама по себе не объединяет. Счётчик «обращений» считает отдельные поиски, а не людей и не задачи.
- Накопленные дубли объединяются в карточке: раскройте «Объединить с…», выберите другую тему и нажмите «Объединить темы». Название текущей темы сохраняется, формулировки и обращения выбранной переходят в неё. Это работает и после смены модели. Тему нужно проверить заново; прежние проверки отмечены устаревшими. Если темы успели измениться, список обновится без объединения. При сумме больше 50 формулировок операция отклоняется без потери данных.
- Проверка темы, диагностика пустой выдачи и повторы при загрузке модели спрос не увеличивают.

## Как пользоваться списком и карточкой

1. Нажмите «Новые темы». В центре откроется вкладка со списком; выбранная тема открывается в ней же, назад к списку — «К списку» (в широкой панели список и карточка стоят рядом). Закрыть вкладку — крестик. Запрос, выдача и область поиска при этом не сбрасываются; открытые документы справа сохраняются.
2. Фильтры: «Активные», «Найдены совпадения», «Закрытые». Есть поиск по тексту и сортировка по последнему обращению или по числу обращений.
3. Выберите тему. В карточке — формулировки с областями поиска, причины, даты и последняя проверка.
4. Допишите документацию и нажмите «Проверить знания»: bars заново ищет по каждой формулировке в её исходной области. Найденные фрагменты показаны с путём и строками, «Открыть документ» ведёт к тексту.
5. Решаете вы: «Знаний достаточно» закрывает тему, «Всё ещё не хватает» оставляет её открытой. Сами совпадения тему не закрывают.
6. «Проверить все» проверяет активные темы по одной (видно «Проверяется N из M») и останавливается кнопкой «Остановить».

Если у темы была область (модуль или файлы), «Проверить по всему проекту» расширяет поиск на весь проект: только по вашему нажатию, и итог подписан как расширенный.

Правой кнопкой по теме откройте меню из двух пунктов. «Скопировать» копирует полный исходный запрос, даже если тему переименовали. «Закрыть» означает, что данных достаточно: сразу удаляет тему и её формулировки без подтверждения, а не переносит в «Закрытые». Следующий самостоятельный пустой поиск может добавить её снова. Открывать карточку предварительно не нужно. С клавиатуры меню вызывается Shift+F10 на строке темы.

## Что значит неполная проверка

Проверка знаний всегда использует rerank, даже если он выключен для обычного поиска. Загрузка или ошибка rerank прерывает проверку с понятной причиной; выдача cosine её не заменяет.

«Найдены совпадения» означает, что поиск вернул фрагменты, а не подтвердил наличие ответа. В карточке видны параметры исходного поиска и проверки. Если исходный поиск использовал rerank, а проверка — cosine, проверка считается неполной: оценки несопоставимы. Ошибка или загрузка включённого rerank тоже показывается как неполная проверка с причиной, даже если фрагменты нашлись.

Пустой результат при загрузке модели, индексации или пропавшей области — это «проверка неполная», а не «материалов нет». Тема остаётся как была, область молча не расширяется. Вывод «материалы не найдены» bars делает, только если все формулировки проверены без ошибок по одному и тому же состоянию индекса. Если тему меняли после проверки, рядом стоит пометка об устаревшем итоге.

## Удаление, очистка и выключение сбора

- **Удалить…** убирает тему и её формулировки. Новый пустой поиск с тем же вопросом создаст её снова; закрытая тема при новом обращении открывается заново.
- Под списком раскрывается «Управление списком»: переключатель «Собирать новые темы этого проекта», место хранения и «Очистить список…» с подтверждением. Выключение останавливает новые записи и оставляет старые; очистка сбор не выключает.
- Хранится всё в `.bars/new-topics.sqlite3` проекта. Тексты вопросов могут быть чувствительными, а bars не меняет `.gitignore`: если `.bars` попадает в git, исключите этот файл сами. Полная переиндексация, смена модели и очистка истории MCP список не стирают; удаление проекта из bars его удаляет.

## Чего пока нет

- Ручного объединения и разъединения тем (OQ-102): слияние идёт только автоматически, по строгим правилам. Отрицания и противоположности («можно» и «нельзя») сходством не различаются, такие вопросы иногда сливаются; тему можно удалить и завести заново (OQ-100).
- Подключения внешнего чата: собираются только поиск окна и MCP.
