# Обновление индекса

Как воркер держит индекс проекта актуальным (Т-9, Т-10, Т-22).

## Какие файлы индексируются

Все `**/*.md` под корнем документации проекта (Т-7). Модуль файла — его подпапка первого уровня. Файлы прямо в корне документации (например, `docs/Index.md`) индексируются в модуль «(корень)». Файл `BARS_INSTRUCTION.md` в корне документации не индексируется.

## Когда запускается проверка актуальности

| Источник | Что проверяется |
|---|---|
| Слежение за файлами (крейт `notify`) | изменённые файлы; события копятся 500 мс, потом обрабатываются пачкой |
| Старт воркера | все зарегистрированные проекты |
| Хук начала сессии агента | проект сессии |
| Раз в час | все зарегистрированные проекты |
| Команда переиндексации (окно, MCP, CLI) | проект целиком |

Одновременно индексируется один проект; остальные ждут в очереди. Поиск во время индексации работает по тому, что уже в индексе ([architecture/ipc.md](../architecture/ipc.md)).

## Порядок проверки проекта

1. **Отпечаток модели.** Если отпечаток в настройках не совпадает с индексом, проект получает состояние «нужна переиндексация», и дальше ничего не делается (Т-25). Эмбеддинг не вызывается.
2. **`BARS_INSTRUCTION.md`.** Хеш файла сверяется с хешем версии, зашитой в bars; не совпадает или файла нет — файл записывается заново (Т-8).
3. **Обход файлов.** Для каждого `.md` сравниваются размер и время изменения с индексом. Только если они отличаются, считается sha256 содержимого. Совпал хеш — файл не тронут.
4. **Изменённые и новые файлы** режутся на чанки ([chunking.md](chunking.md)). Для каждого чанка считается хеш текста для эмбеддинга. Вектор с таким хешем уже есть в индексе — используется он; нет — чанк уходит в эмбеддинг. Так правка одного раздела эмбеддит только его чанки (НФТ-1).
5. **Пропавшие файлы** удаляются из индекса вместе с чанками (Т-22). Отдельной защиты от массового удаления нет: индекс следует за диском.
6. **Уборка.** Векторы, на которые больше не ссылается ни один чанк, удаляются.

Каждый документ записывается в индекс одной транзакцией: поиск видит либо старую версию документа, либо новую.

## Полная переиндексация

Полная переиндексация (по согласию после смены модели или по явной команде) строит индекс заново во временном файле рядом со старым и подменяет его в конце. Если она прервалась, старый индекс остаётся целым.
