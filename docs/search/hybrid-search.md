# Гибридный поиск

Как воркер отвечает на поисковый запрос (Т-12…Т-15, Т-18, Т-24, Т-25). Все числа ниже — значения по умолчанию из Т-18; их меняют настройки и вызов агента.

## Область поиска

1. **Проект.** Явно заданный проект или проект сессии: ближайшая к cwd агента папка, которая зарегистрирована в bars (Т-15). Поиск никогда не выходит за один проект (урок 9 образца).
2. **Отбор внутри проекта.** Список модулей и/или файлов (Т-14). Модуль задаётся именем подпапки, корневой модуль — `.`; файл — путём относительно корня документации. Неизвестный модуль или файл — ошибка `invalid_params`. Пустой список — весь проект.
3. **Состояние проекта.** Если проекту нужна переиндексация из-за смены модели, поиск возвращает ошибку «нужна переиндексация» и ничего не ищет (Т-25).

## Кандидаты из двух поисков

- **Полнотекстовый:** FTS5 по цепочке заголовков и тексту чанков, ранжирование `bm25`, первые 30. У FTS5 нет русской морфологии, поэтому текст чанков при индексации и слова запроса при поиске проходят один и тот же стемминг Snowball для русского и английского (`rust-stemmers`): «настройки» и «настройка» дают одну основу. Слова, которые стеммер не меняет (идентификаторы, числа, латиница в коде), ищутся как есть. Слова запроса соединяются через `OR`: `bm25` сам поднимает чанки, где совпало больше слов. На корпусе bars стемминг ставил нужный раздел первым чаще префиксного поиска ([knowledge/spike-search.md](../knowledge/spike-search.md)).
- **Векторный:** запрос эмбеддится моделью проекта (с префиксом запроса, если он у модели есть); точный перебор по косинусной близости, первые 30 ([architecture/vector-search.md](../architecture/vector-search.md)).

Оба списка сливаются через Reciprocal Rank Fusion: оценка кандидата — сумма `1 / (60 + место)` по спискам, где он есть. Точное совпадение идентификатора поднимается полнотекстовым поиском, смысловое — векторным (Т-12).

## Реранк кандидатов

Если rerank включён, лучшие слитые кандидаты (`rerank_candidates`, по умолчанию 15) переоцениваются rerank-моделью, и выдача упорядочивается по её оценке. По умолчанию возвращается 3 результата. Без реранка — 5 по RRF.

## Оценка результата и порог

Порог применяется к оценке, у которой есть абсолютный смысл. Оценка RRF его не имеет:

- **С реранком** — оценка реранка, порог `min_score_rerank`.
- **Без реранка** — косинусная близость чанка к запросу, порог `min_score_vector`. Близость считается для всех кандидатов, включая найденных только полнотекстовым поиском.

Обе оценки лежат в диапазоне от 0 до 1 ([storage/settings.md](../storage/settings.md)). Порог задаёт пользователь в настройках, там же — пределы, в которых его может менять агент (Т-24). Порог агента вне пределов прижимается к ближайшей границе, и в ответе сказано, какой порог применён. Так же прижимаются число результатов и кандидатов сверх `max_results` и `max_candidates`.

## Состав результата

Каждый результат (Т-13): путь, модуль, `title` документа, цепочка заголовков, строки начала и конца, текст чанка, оценка и её вид (`rerank` или `cosine`). Ответ в целом несёт применённые параметры, флаг «идёт индексация» и число документов в очереди. Текста, сгенерированного LLM, в ответе нет.
