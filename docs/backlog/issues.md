# Известные проблемы bars

Баги, найденные автором при использовании и аудитами по его поручению (источник указан в записи). Открытые описаны отдельными разделами; исправленные сведены в таблицу «Исправленные проблемы» в конце: причина, проверки и коммит остаются в документах фич, `docs/chats/` и git. Проблема считается исправленной, когда реализация и автоматические проверки готовы, даже если осталась только приёмка в установленной сборке. Новые записи дописываются с номером ISS-NN подряд.

## ISS-99. Тест полной пересборки воркера использует фиксированное имя канала
- **Источник:** полная проверка сессии 4.1.2, 28-10-2026, первый прогон; параллельно шёл `scripts/check.ps1` другой сессии.
- **Шаги:** запустить `scripts/check.ps1` одновременно в двух сессиях одного checkout.
- **Фактически:** `handler::tests::concurrency::full_rebuild_keeps_status_window_controls_and_full_ipc_search_responsive` падает на `ipc::bind(&endpoint).unwrap()` с `AlreadyRunning`: в `crates/bars-worker/src/handler/tests/concurrency.rs` канал называется `Endpoint::named("iss16-concurrency")`, без суффикса временного профиля.
- **Ожидается:** как у тестовых Harness CLI, MCP и worker — имя канала включает уникальное имя временного профиля, и параллельные прогоны не пересекаются ([сборка и проверки](../knowledge/build.md), раздел «Одновременные IPC-тесты из разных процессов»).
- **Статус:** открыт. Повторный прогон без параллельной проверки прошёл; это не исправление.

## ISS-96. Нестабильный отказ FTS в тесте локальной OpenAI-модели

- **Источник:** полные проверки 25–26-10-2026; в сессии исследования 2.3.2 — `check.log`, `worker-retry.log`, `check-repeat.log` в `docs/chats/2026-10-26-graph-rerank/`.
- **Шаги:** запустить `scripts/check.ps1 -Jobs 2` в штатной Windows/MSVC/Vulkan-среде; сбой наблюдался при `RUST_TEST_THREADS=1`. Надёжная последовательность воспроизведения не установлена.
- **Фактически:** `handler::tests::external_models::local_openai_address_works_without_a_key` падает при поиске с `vtable constructor failed: chunks_fts`.
- **Ожидается:** поиск по созданному тестом индексу успешно завершается; временный отказ не маскируется пропуском проверки.
- **Статус:** открыт, причина не установлена. Отдельный повтор того же бинарника и следующий полный check прошли; это не доказательство исправления. Связь с нагрузкой или изменением кода не установлена. Наблюдения и способ проверки — [сборка и проверки](../knowledge/build.md), раздел «Повторяющийся отказ SQLite в worker-тесте». Причина ISS-94 этим сбоем не объясняется.

## ISS-94. Полный поиск многократно перечитывает страницы таблицы векторов

- **Источник:** жалоба автора на дисковую нагрузку 25-10-2026; контрольный поиск и отдельный read-only замер SQLite.
- **Причина:** полный перебор начинался с чанков и делал случайный поиск большого BLOB для каждого чанка. Проверка ключей векторов для графа имела тот же дефект.
- **Исправление:** последовательный проход таблицы векторов для полного поиска и проверки ключей; запросы в выбранных файлах и модулях сохраняют предварительный отбор. Механизм, численные результаты и ограничения — [векторный поиск](../architecture/vector-search.md).
- **Статус:** реализация и регрессия готовы, 336 тестов ядра зелёные. Финальный общий check: форматирование, clippy и сборка зелёные; `bars-worker` красный на аудите (`partial` вместо `complete`) и локальном OpenAI endpoint (`vtable constructor failed: chunks_fts`). Установщик не собран, установленное приложение пока использует прежний код.

## ISS-22. Графовые операции MCP и поиск mix отвечают сырым JSON на десятки килобайт

- **Источник:** аудит работы агентов 23-10-2026 по поручению автора ([agent-usage-2026-10-23.md](../audits/agent-usage-2026-10-23.md), находка А-1). Установленная сборка, Claude Code.
- **Симптом:** в формате `txt` по умолчанию `bars_relations`, `bars_paths`, `bars_impact`, `bars_context`, `bars_explore`, `bars_graph` и `bars_rag_search` с `mode=mix` печатают JSON воркера одной строкой внутри блока `=== GRAPH … ===`. В каждом ответе — эхо всех ~35 полей запроса, большинство `null`; доказательства даны 64-значными хешами, которые агент сам сопоставляет с массивом `evidence`. В тексте предупреждений виден отладочный вид Rust: «Граф близости частичный: Some(ComparisonLimit)».
- **Шаги:** 1) `bars_rag_search({query:"Как bars обновляет ссылки при переименовании документа?", mode:"mix", limit:3})`; 2) `bars_context({query:"Поменять формат текстовой выдачи поиска MCP", task_profile:"implementation", budgets:{timeout_ms:15000}})`.
- **Фактически:** шаг 1 — 58,8 тыс. знаков, из них 54 тыс. в `related`, при этом источников всего два документа; Claude Code отказался вставить ответ в контекст и сохранил его в файл. Шаг 2 — 51 тыс. знаков, из них 39 тыс. — массив `evidence`.
- **Ожидается:** текстовый ответ, который агент читает без разбора JSON: по строке на факт с видом связи, путём документа и строками, заголовком и короткой цитатой доказательства; эхо только изменённых параметров; объём txt-ответа ограничен по умолчанию с явным признаком усечения и продолжением. Предупреждения — обычным текстом.
- **Статус:** открыт. Причина — вывод JSON воркера без текстового рендера. Контракт текста принят 28-10-2026 (шаг 4.3.2, OQ-219) — [ответ графа для агента](../features/graphrag/tools.md); реализация — 4.3.4.

## ISS-23. У шести графовых операций одна общая схема параметров с чужими и неработающими полями

- **Источник:** аудит работы агентов 23-10-2026 ([agent-usage-2026-10-23.md](../audits/agent-usage-2026-10-23.md), А-2); журнал сессии `2026-10-20-window-foundation`: «change_description не поддержан».
- **Симптом:** все шесть графовых инструментов MCP принимают одну структуру `GraphArgs` (`crates/bars-mcp/src/lib.rs`, строки 218–268): около 35 параметров у каждого, включая поля других операций (`analysis` и `grouping` у `bars_relations`, `from`/`to` у `bars_context`). Параметр `change_description` есть в схеме, но не поддержан. Шесть копий схемы — порядка 30 тыс. знаков описаний в контексте каждой сессии агента, даже если граф не нужен.
- **Шаги:** запросить `tools/list` у `bars-mcp` и сравнить схемы шести графовых инструментов; вызвать `bars_impact` с `change_description`.
- **Ожидается:** у каждой операции только свои параметры с описанием умолчаний; неподдержанных полей в схеме нет.
- **Статус:** исправлен 28-10-2026 (шаг 4.3.3): у каждой из шести операций своя структура аргументов, без чужих полей и `change_description`; `timeout_ms` по умолчанию 5000; шесть схем — 14 201 байт. Поле `documents` добавит 4.3.5. Проверка: тест `every_graph_tool_lists_only_its_own_parameters`; [итог сессии](../chats/2026-10-28-graph-schemas/handoff.md); контракт — [схема у каждой операции](../features/graphrag/tools.md).

## ISS-24. Графовые операции возвращают пустой ответ без подсказки следующего шага

- **Источник:** аудит работы агентов 23-10-2026 ([agent-usage-2026-10-23.md](../audits/agent-usage-2026-10-23.md), А-3, задачи З2, З11, З12); журнал сессии `2026-10-20-window-foundation`: «impact по roots не дал зависимостей». Журнал MCP 19–23-10-2026: настоящие агенты вызвали графовые операции 5 раз, из них 3 — ошибка `graph_not_ready`.
- **Симптом:**
  - `bars_impact({query:…})` — ошибка «impact: нужны roots» без указания, где взять `roots`. `roots` — объектные ссылки из двух 64-значных хешей, которые есть только в ответах других графовых операций.
  - `bars_impact` с `roots` документа `features/knowledge-base/link-index.md` возвращает пустой список, хотя на документ ссылаются mcp-tools.md и другие: гиперссылки не считаются зависимостью, а смысловой слой частичный (566 из 1766 строк).
  - `bars_context` с умолчаниями прерывается по `timeout_ms` 1000 мс и отдаёт все шесть ролей в `missing_roles`; с явным 15 000 воркер прижимает значение до 5000 и тогда отвечает. Найденные источники не о теме: требования новых тем, ADR рендера графа, без hybrid-search.md и раздела формата ответа в mcp-tools.md.
  - `bars_relations` и `bars_explore` (`analysis: conflict_candidates`) по предметным запросам — пустой результат с `resolution: resolved`.
- **Ожидается:** пустой ответ называет причину (частичный слой, таймаут) и предлагает следующий шаг (`bars_rag_search`, входящие ссылки `bars_links`); ошибка про `roots` объясняет, откуда их взять, или `impact`/`context` принимают путь документа; умолчание таймаута для MCP позволяет `context` ответить.
- **Статус:** открыт. Полнота смыслового слоя — отдельный вопрос качества GraphRAG; здесь записан опыт агента. Принято 28-10-2026 (шаг 4.3.2, OQ-219): поле `documents` у `impact` и `context`, умолчание MCP 5000 мс, `next:` у пустых ответов — [контракт](../features/graphrag/tools.md); реализация — 4.3.5.

## ISS-25. Путь из выдачи поиска не принимается в files, ошибки области не подсказывают исправление

- **Источник:** аудит работы агентов 23-10-2026 ([agent-usage-2026-10-23.md](../audits/agent-usage-2026-10-23.md), А-4, задача З7); случай C09 [исследования 18-10](../knowledge/agent-tool-usage-2026-10-18.md); журнал MCP: `modules:["models"]` дважды, путь с `docs/` в `files` один раз.
- **Симптом:** выдача `bars_rag_search` печатает `path: docs/features/…` (от корня проекта), а `files` принимает только путь от корня документации. `bars_read`/`bars_outline` принимают оба вида, `bars_links` и продолжение `bars_text_search` — путь от корня проекта. Скопированный из выдачи путь даёт ошибку без подсказки.
- **Шаги:** 1) `bars_rag_search({query:"Пути в files указываются от корня документации", files:["docs/features/agent-tools/mcp-tools.md"]})`; 2) тот же запрос с `modules:["models"]`.
- **Фактически:** 1) «Ошибка bars (invalid_params): неизвестный файл `docs/features/agent-tools/mcp-tools.md`»; 2) «неизвестный модуль `models`».
- **Ожидается:** `files` принимает путь из выдачи (с префиксом корня документации, когда без префикса он есть в индексе), либо ошибка показывает исправленный путь; ошибка о модуле перечисляет существующие модули (уже предложено в [проекте выбора модулей](../features/agent-tools/module-scope.md)); выдача поиска печатает и путь от корня документации.
- **Статус:** исправлен частично 28-10-2026 (шаг 4.2.3): `files` принимает путь из выдачи, ошибка файла показывает до трёх кандидатов, ошибка модуля — список модулей и подсказку про подпапку. Открыто: выдача по-прежнему печатает путь от корня проекта, `doc_path` в JSON нет. Проверка: тест `unknown_scope_errors_say_how_to_fix_them`.

## ISS-26. bars_get_similar возвращает разделы того же документа

- **Источник:** аудит работы агентов 23-10-2026 ([agent-usage-2026-10-23.md](../audits/agent-usage-2026-10-23.md), А-9, задачи З5–З6). В журнале MCP за неделю настоящие агенты не вызвали `bars_get_similar` и `bars_get_duplicates` ни разу.
- **Симптом:** на вопрос «где ещё описано это правило» `bars_get_similar` отвечает соседними разделами исходного документа; другие документы с тем же правилом не попадают. `bars_get_duplicates` не принимает тему, а для смысловых пар не показывает отрывков; строки «negation words» у смысловых пар ничего не дают.
- **Шаги:** найти раздел «Базовые параметры поиска» mcp-tools.md поиском (`id: 7915-4c584657` на 23-10-2026), затем `bars_get_similar({chunk_id:"7915-4c584657", limit:5})`.
- **Фактически:** 5 из 5 результатов — разделы того же mcp-tools.md; раздел delivery.md «Выбор операции и области агентом», который поиск поставил вторым, не возвращён.
- **Ожидается:** по умолчанию разделы исходного документа исключены или сгруппированы, чтобы в выдачу попадали другие документы; смысловые пары дублей показывают по строке отрывка.
- **Статус:** открыт.

## ISS-27. Ошибки в описаниях инструментов MCP

- **Источник:** аудит работы агентов 23-10-2026 ([agent-usage-2026-10-23.md](../audits/agent-usage-2026-10-23.md), А-10).
- **Симптом:**
  - описание `bars_get_similar` содержит серии по 24 пробела (`crates/bars-mcp/src/lib.rs`, строка 507: перенос строки без `\`), модель видит их как есть;

  - описания графовых инструментов объясняют устройство («поколения и scope фиксированы; курсор только того же запроса»), но не говорят, когда операцию вызывать.

Тест списка инструментов не пускает двойные пробелы в описания и схемы. Установленная сборка не проверена; [итог сессии](../chats/2026-10-28-mcp-quick-fixes/handoff.md).

Поле `heading` показывает только заголовок первого уровня, а текст чанка содержит приклеенный раздел второго уровня.

Число результатов по умолчанию не менялось. Проверка: тесты рендера и воркера; [итог сессии](../chats/2026-10-28-mcp-quick-fixes/handoff.md).

## ISS-29. Гейт чтения документации отклоняет поиск *.md вне docs; в bars-project два гейта и неверная подсказка

- **Источник:** аудит работы агентов 23-10-2026 ([agent-usage-2026-10-23.md](../audits/agent-usage-2026-10-23.md), А-12), чтение `crates/bars-cli/src/gate.rs` и `.claude/hooks/require_tools.py`.
- **Симптом:**
  - гейт bars (`reads_docs`) отклоняет Glob и Grep с шаблоном `*.md` в любой папке, даже вне документации: условие `norm(glob).ends_with(".md")` не проверяет путь. Grep по всему репозиторию без шаблона при этом пропускается;
  - в bars-project одновременно действуют собственный хук проекта (`.claude/settings.json` → `require_tools.py`) и гейт bars (`.claude/settings.local.json` → `bars-cli hook pre-tool-use`); агент получает текст проектного хука;
  - текст проектного хука утверждает: «The bars tool schemas are deferred: load them with ToolSearch» — неверно, когда схемы уже загружены (так было в сессии аудита); у гейта bars — верное «may be deferred»;
  - блок снимает любой вызов bars, включая `bars_status` и `bars_projects`.
- **Шаги:** в новой сессии Claude Code без вызовов bars вызвать Glob с шаблоном `crates/**/*.md`; затем `cat docs/knowledge/x.md` через Bash.
- **Ожидается:** шаблон `*.md` с путём вне документации не отклоняется; в bars-project проверку документации делает один гейт; подсказка не утверждает того, чего нет.
- **Статус:** исправлен 28-10-2026 (шаг 4.1.3): гейт пропускает Glob и Grep с `*.md`, если `path` или папка в шаблоне вне документации (без них поиск идёт от корня проекта и по-прежнему отклоняется); проектный хук `require_tools.py` не проверяет документацию, так в bars-project один гейт; подсказка хука говорит «may be deferred» и показывается один раз за сессию, чтобы не требовать недоступных semble и serena. Не менялось: любой вызов bars снимает блок, включая `bars_status`. Проверка: тесты `gate.rs`, синтетический ввод хука; [итог сессии](../chats/2026-10-28-skills-gate-fixes/handoff.md).

## ISS-92. Файл, удалённый снаружи или в корзину, превращает открытый документ в пустой молча

- **Источник:** матрица сохранности 24-10-2026 ([data-safety-matrix-2026-10-24.md](../knowledge/data-safety-matrix-2026-10-24.md), M-05, M-15).
- **Симптом:** `document_read` отсутствующего файла отдаёт пустой документ с `revision = null`. Чистый буфер при проверке диска перечитывается этим ответом: текст пропадает, подпись «Обновлено с диска». Вкладка документа, удалённого в корзину из дерева bars, не закрывается, потому что `moved.accept` вызывается только при переносе.
- **Шаги:** 1) открыть документ и не менять; 2) удалить файл в Проводнике или в дереве bars; 3) вернуть фокус окну; 4) набрать символ.
- **Фактически:** по пробе над `EditorBuffer`: текст пуст, статус «чисто», сообщения об удалении нет; набранный символ создаёт файл заново с `base_revision = null`.
- **Ожидается:** документ называет «Файл удалён с диска» и для чистого буфера; текст не стирается до решения пользователя; вкладка удалённого через bars документа закрывается или помечается.
- **Статус:** исправлен 28-10-2026 (шаг 3.1.3 решил, 3.1.6 реализовал). Проверка диска и чтение отличают «файла нет» от «файл изменился»: буфер переходит в «файл удалён», текст остаётся, автосохранение стоит, полоса предлагает «Записать заново» и «Закрыть вкладку» (при правках — «Отбросить правки»). Удаление в корзину bars закрывает вкладки чистых документов и помечает изменённые. Проверено тестами `editors.test.ts`; живой сценарий в WebView2 не проводился. Описание — [модель конфликтов](../features/knowledge-base/editor-design.md).

## ISS-93. Выход процесса не ждёт запись дольше 3 секунд и теряет правку без вопроса

- **Источник:** матрица сохранности 24-10-2026 ([data-safety-matrix-2026-10-24.md](../knowledge/data-safety-matrix-2026-10-24.md), M-20).
- **Симптом:** `flush::request` ждёт первого ответа окна 3 секунды (`QUICK`); молчание без «asking» считается «можно выходить». Окно отвечает «clean» только после `editors.flush()`, то есть после завершения записи.
- **Шаги:** 1) открыть документ на медленном диске или в OneDrive, внести правку; 2) сразу выбрать «Выход» в трее, когда запись идёт дольше 3 секунд.
- **Фактически:** по коду процесс завершается до ответа окна, запись прерывается, файл остаётся прежним, вопроса нет.
- **Ожидается:** пока окно не ответило и запись идёт, выход ждёт; предел 3 секунд относится к окну, которого нет или которое не загружено.
- **Статус:** исправлен 28-10-2026 (решение OQ-174, шаг 3.1.6). Окно с изменённым или записывающимся документом сразу отвечает процессу «writing», процесс ждёт «clean» до 60 с, затем отменяет выход сообщением «Документ ещё записывается». Проверено тестами `flush.rs` и `move-flush.test.ts`; медленная запись в WebView2 не проверялась. Описание — [выход из процесса](../features/knowledge-base/editor-design.md).

## ISS-99. Возврат к запросу после другой глубины может повторно обращаться к воркеру

- **Источник:** сверка 2.4.2 при `$bars-end`, 26-10-2026; `ui/src/lib/graph/PhysicalGraph.svelte`, функции `enterQuery` и `requestQuery`. Вывод по коду; отдельная нативная проверка этого сочетания не выполнена.
- **Шаги для проверки:** завершить поиск → выбрать окружение 2 и дождаться среза → «Общий вид» → «Показать запрос в графе». Аналогично проверить возврат после «Показать ещё».
- **Фактически по коду:** `enterQuery` сбрасывает глубину и пределы, а кэш хранит один последний ключ. Несовпадение ключа вызывает новый `graph_query_slice`; при совпадении сохранённый срез применяется без IPC.
- **Ожидается:** переход OQ-120 в [контракте вида запроса](../features/graphrag/query-graph.md) обещает возврат из той же выдачи без нового запроса к воркеру. Позиции и камера общего вида — отдельный реализованный контракт.
- **Статус:** открыт. В этой документационной сверке код не менялся. Поведение при исчезнувшем снимке в данном сценарии также не проверено.
