# Известные проблемы bars

Баги, найденные автором при использовании и аудитами по его поручению (источник указан в записи). Открытые описаны отдельными разделами; исправленные сведены в таблицу «Исправленные проблемы» в конце: причина, проверки и коммит остаются в документах фич, `docs/chats/` и git. Проблема считается исправленной, когда реализация и автоматические проверки готовы, даже если осталась только приёмка в установленной сборке. Новые записи дописываются с номером ISS-NN подряд.

## ISS-22. Графовые операции MCP и поиск mix отвечают сырым JSON на десятки килобайт

- **Источник:** аудит работы агентов 23-10-2026 по поручению автора ([agent-usage-2026-10-23.md](../audits/agent-usage-2026-10-23.md), находка А-1). Установленная сборка, Claude Code.
- **Симптом:** в формате `txt` по умолчанию `bars_relations`, `bars_paths`, `bars_impact`, `bars_context`, `bars_explore`, `bars_graph` и `bars_rag_search` с `mode=mix` печатают JSON воркера одной строкой внутри блока `=== GRAPH … ===`. В каждом ответе — эхо всех ~35 полей запроса, большинство `null`; доказательства даны 64-значными хешами, которые агент сам сопоставляет с массивом `evidence`. В тексте предупреждений виден отладочный вид Rust: «Граф близости частичный: Some(ComparisonLimit)».
- **Шаги:** 1) `bars_rag_search({query:"Как bars обновляет ссылки при переименовании документа?", mode:"mix", limit:3})`; 2) `bars_context({query:"Поменять формат текстовой выдачи поиска MCP", task_profile:"implementation", budgets:{timeout_ms:15000}})`.
- **Фактически:** шаг 1 — 58,8 тыс. знаков, из них 54 тыс. в `related`, при этом источников всего два документа; Claude Code отказался вставить ответ в контекст и сохранил его в файл. Шаг 2 — 51 тыс. знаков, из них 39 тыс. — массив `evidence`.
- **Ожидается:** текстовый ответ, который агент читает без разбора JSON: по строке на факт с видом связи, путём документа и строками, заголовком и короткой цитатой доказательства; эхо только изменённых параметров; объём txt-ответа ограничен по умолчанию с явным признаком усечения и продолжением. Предупреждения — обычным текстом.
- **Статус:** открыт; причина не исследовалась.

## ISS-23. У шести графовых операций одна общая схема параметров с чужими и неработающими полями

- **Источник:** аудит работы агентов 23-10-2026 ([agent-usage-2026-10-23.md](../audits/agent-usage-2026-10-23.md), А-2); журнал сессии `2026-10-20-window-foundation`: «change_description не поддержан».
- **Симптом:** все шесть графовых инструментов MCP принимают одну структуру `GraphArgs` (`crates/bars-mcp/src/lib.rs`, строки 218–268): около 35 параметров у каждого, включая поля других операций (`analysis` и `grouping` у `bars_relations`, `from`/`to` у `bars_context`). Параметр `change_description` есть в схеме, но не поддержан. Шесть копий схемы — порядка 30 тыс. знаков описаний в контексте каждой сессии агента, даже если граф не нужен.
- **Шаги:** запросить `tools/list` у `bars-mcp` и сравнить схемы шести графовых инструментов; вызвать `bars_impact` с `change_description`.
- **Ожидается:** у каждой операции только свои параметры с описанием умолчаний; неподдержанных полей в схеме нет.
- **Статус:** открыт.

## ISS-24. Графовые операции возвращают пустой ответ без подсказки следующего шага

- **Источник:** аудит работы агентов 23-10-2026 ([agent-usage-2026-10-23.md](../audits/agent-usage-2026-10-23.md), А-3, задачи З2, З11, З12); журнал сессии `2026-10-20-window-foundation`: «impact по roots не дал зависимостей». Журнал MCP 19–23-10-2026: настоящие агенты вызвали графовые операции 5 раз, из них 3 — ошибка `graph_not_ready`.
- **Симптом:**
  - `bars_impact({query:…})` — ошибка «impact: нужны roots» без указания, где взять `roots`. `roots` — объектные ссылки из двух 64-значных хешей, которые есть только в ответах других графовых операций.
  - `bars_impact` с `roots` документа `features/knowledge-base/link-index.md` возвращает пустой список, хотя на документ ссылаются mcp-tools.md и другие: гиперссылки не считаются зависимостью, а смысловой слой частичный (566 из 1766 строк).
  - `bars_context` с умолчаниями прерывается по `timeout_ms` 1000 мс и отдаёт все шесть ролей в `missing_roles`; с явным 15 000 воркер прижимает значение до 5000 и тогда отвечает. Найденные источники не о теме: требования новых тем, ADR рендера графа, без hybrid-search.md и раздела формата ответа в mcp-tools.md.
  - `bars_relations` и `bars_explore` (`analysis: conflict_candidates`) по предметным запросам — пустой результат с `resolution: resolved`.
- **Ожидается:** пустой ответ называет причину (частичный слой, таймаут) и предлагает следующий шаг (`bars_rag_search`, входящие ссылки `bars_links`); ошибка про `roots` объясняет, откуда их взять, или `impact`/`context` принимают путь документа; умолчание таймаута для MCP позволяет `context` ответить.
- **Статус:** открыт. Полнота смыслового слоя — отдельный вопрос качества GraphRAG; здесь записан опыт агента.

## ISS-25. Путь из выдачи поиска не принимается в files, ошибки области не подсказывают исправление

- **Источник:** аудит работы агентов 23-10-2026 ([agent-usage-2026-10-23.md](../audits/agent-usage-2026-10-23.md), А-4, задача З7); случай C09 [исследования 18-10](../knowledge/agent-tool-usage-2026-10-18.md); журнал MCP: `modules:["models"]` дважды, путь с `docs/` в `files` один раз.
- **Симптом:** выдача `bars_rag_search` печатает `path: docs/features/…` (от корня проекта), а `files` принимает только путь от корня документации. `bars_read`/`bars_outline` принимают оба вида, `bars_links` и продолжение `bars_text_search` — путь от корня проекта. Скопированный из выдачи путь даёт ошибку без подсказки.
- **Шаги:** 1) `bars_rag_search({query:"Пути в files указываются от корня документации", files:["docs/features/agent-tools/mcp-tools.md"]})`; 2) тот же запрос с `modules:["models"]`.
- **Фактически:** 1) «Ошибка bars (invalid_params): неизвестный файл `docs/features/agent-tools/mcp-tools.md`»; 2) «неизвестный модуль `models`».
- **Ожидается:** `files` принимает путь из выдачи (с префиксом корня документации, когда без префикса он есть в индексе), либо ошибка показывает исправленный путь; ошибка о модуле перечисляет существующие модули (уже предложено в [проекте выбора модулей](../features/agent-tools/module-scope.md)); выдача поиска печатает и путь от корня документации.
- **Статус:** открыт.

## ISS-26. bars_get_similar возвращает разделы того же документа

- **Источник:** аудит работы агентов 23-10-2026 ([agent-usage-2026-10-23.md](../audits/agent-usage-2026-10-23.md), А-9, задачи З5–З6). В журнале MCP за неделю настоящие агенты не вызвали `bars_get_similar` и `bars_get_duplicates` ни разу.
- **Симптом:** на вопрос «где ещё описано это правило» `bars_get_similar` отвечает соседними разделами исходного документа; другие документы с тем же правилом не попадают. `bars_get_duplicates` не принимает тему, а для смысловых пар не показывает отрывков; строки «negation words» у смысловых пар ничего не дают.
- **Шаги:** найти раздел «Базовые параметры поиска» mcp-tools.md поиском (`id: 7915-4c584657` на 23-10-2026), затем `bars_get_similar({chunk_id:"7915-4c584657", limit:5})`.
- **Фактически:** 5 из 5 результатов — разделы того же mcp-tools.md; раздел delivery.md «Выбор операции и области агентом», который поиск поставил вторым, не возвращён.
- **Ожидается:** по умолчанию разделы исходного документа исключены или сгруппированы, чтобы в выдачу попадали другие документы; смысловые пары дублей показывают по строке отрывка.
- **Статус:** открыт.

## ISS-27. Ошибки в описаниях инструментов MCP

- **Источник:** аудит работы агентов 23-10-2026 ([agent-usage-2026-10-23.md](../audits/agent-usage-2026-10-23.md), А-10).
- **Симптом:**
  - описание `bars_get_similar` содержит серии по 24 пробела (`crates/bars-mcp/src/lib.rs`, строка 507: перенос строки без `\`), модель видит их как есть;
  - поле `mode` у `bars_rag_search`: «Без поля — прежний поиск и прежняя форма ответа» — «прежний» понятно только тому, кто знает историю изменений;
  - поле `include_related`: «отключить расширение и пакеты оснований; без поля включено» — у булева поля с именем include неясно, что значит true;
  - описания графовых инструментов объясняют устройство («поколения и scope фиксированы; курсор только того же запроса»), но не говорят, когда операцию вызывать.
- **Ожидается:** тексты без лишних пробелов, описание режима и поля через их действие, у графовых операций — задача, для которой их звать. Предлагаемые тексты — в документе аудита, раздел «Предлагаемые тексты описаний инструментов MCP».
- **Статус:** открыт.

## ISS-28. Выдача поиска: лишние слабые результаты и сбивающие поля

- **Источник:** аудит работы агентов 23-10-2026 ([agent-usage-2026-10-23.md](../audits/agent-usage-2026-10-23.md), А-11, задача З1); журнал MCP: `limit` задан агентами в 220 из 240 поисков.
- **Симптом:** без `limit` — 7 результатов, около 12 тыс. знаков, два последних со score 0,22 и 0,17. Заголовок `SEARCH: results 7` и строка `results: 8` в `APPLIED PARAMETERS` называют одним словом разное (найдено и предел). Поле `heading` показывает только заголовок первого уровня, а текст чанка содержит приклеенный раздел второго уровня.

- **Ожидается:** в `APPLIED PARAMETERS` — `limit:` и отдельное число выданного; заголовки всех разделов, вошедших в чанк, видны в результате. Пересмотр числа результатов по умолчанию — вопрос настроек, не этой записи.
- **Статус:** открыт.

## ISS-29. Гейт чтения документации отклоняет поиск *.md вне docs; в bars-project два гейта и неверная подсказка

- **Источник:** аудит работы агентов 23-10-2026 ([agent-usage-2026-10-23.md](../audits/agent-usage-2026-10-23.md), А-12), чтение `crates/bars-cli/src/gate.rs` и `.claude/hooks/require_tools.py`.
- **Симптом:**
  - гейт bars (`reads_docs`) отклоняет Glob и Grep с шаблоном `*.md` в любой папке, даже вне документации: условие `norm(glob).ends_with(".md")` не проверяет путь. Grep по всему репозиторию без шаблона при этом пропускается;
  - в bars-project одновременно действуют собственный хук проекта (`.claude/settings.json` → `require_tools.py`) и гейт bars (`.claude/settings.local.json` → `bars-cli hook pre-tool-use`); агент получает текст проектного хука;
  - текст проектного хука утверждает: «The bars tool schemas are deferred: load them with ToolSearch» — неверно, когда схемы уже загружены (так было в сессии аудита); у гейта bars — верное «may be deferred»;
  - блок снимает любой вызов bars, включая `bars_status` и `bars_projects`.
- **Шаги:** в новой сессии Claude Code без вызовов bars вызвать Glob с шаблоном `crates/**/*.md`; затем `cat docs/knowledge/x.md` через Bash.
- **Ожидается:** шаблон `*.md` с путём вне документации не отклоняется; в bars-project проверку документации делает один гейт; подсказка не утверждает того, чего нет.
- **Статус:** открыт.

## ISS-35. «В тексте» печатает строку с несколькими вхождениями несколько раз

- **Источник:** аудит клиентского поведения 23-10-2026 по поручению автора ([client-2026-10-23.md](../audits/client-2026-10-23.md), находка К-01).
- **Симптом:** в разделе «В тексте» строка, где запрос встречается дважды, показана дважды подряд. Причина — `ui/src/lib/TextResults.svelte:21`: цикл по `hit.ranges` на каждое вхождение выводит весь префикс строки, отметку и весь хвост.
- **Шаги:** найти слово, которое встречается в одной строке документа два раза (или регулярное выражение с двумя совпадениями в строке).
- **Фактически:** строка «порог и снова порог» с диапазонами `[0,5]` и `[14,19]` выводится как «порог и снова порогпорог и снова порог» (проверено в браузере на dev-сервере подстановкой ответа `text_search`).
- **Ожидается:** строка один раз, оба вхождения отмечены.
- **Статус:** открыт; причина найдена.

## ISS-36. Ошибка встроенной модели прячет причину, а «Скачать заново» только повторяет поиск

- **Источник:** аудит клиента 23-10-2026 ([client-2026-10-23.md](../audits/client-2026-10-23.md), К-02).
- **Симптом:** любая `provider_error` встроенной модели без слов о сети и скачивании показывается экраном «Файлы модели не найдены или повреждены» (`ui/src/lib/errors.ts:36-49`): сюда попадают сбой ORT, нехватка памяти GPU, ошибка DirectML. Текст ошибки воркера не выводится, виден только код. Кнопка «Скачать заново» (`SearchError.svelte:22`) вызывает `app.search()`.
- **Шаги:** встроенная модель отвечает на поиск ошибкой, не связанной с файлами; посмотреть экран и нажать «Скачать заново».
- **Фактически:** заголовок о повреждённых файлах, причина скрыта, кнопка повторяет поиск и ничего не скачивает.
- **Ожидается:** текст причины от воркера под подсказкой; «Файлы не найдены» — только по явному признаку воркера; кнопка скачивания запускает `model_download` или называется «Повторить».
- **Статус:** открыт.

## ISS-37. «Результатов» до первого поиска не из настроек, предел — 20 вместо max_results

- **Статус:** открыт.

## ISS-38. Отдельное окно документа опрашивает воркер каждую секунду, как главное

- **Источник:** аудит клиента 23-10-2026 ([client-2026-10-23.md](../audits/client-2026-10-23.md), К-04).
- **Симптом:** `ui/src/App.svelte:29` вызывает `app.start()` в любом окне. Окно документа (Т-40) раз в секунду зовёт `activity`, `operation_events`, `models_info`, `status`, `tree`/`tree_read`, раз в 5 с — `projects` и «Новые темы», раз в 15 с — аудиты. Если проект пропал из реестра, `loadProjects` в окне документа вызывает `select()` и перезаписывает запомненный проект главного окна.
- **Шаги:** открыть два-три документа «В новом окне» и посмотреть журнал вызовов воркера.
- **Фактически:** по коду — каждый новый документ в отдельном окне добавляет полный цикл опроса.
- **Ожидается:** окно документа без общего опроса; дерево для `[[` читается один раз и обновляется по событиям `entry-moved` и `document-saved`.
- **Статус:** открыт; подтверждено чтением кода, прогон в собранном окне не выполнялся.

- **Шаги:** правый щелчок по папке, файлу дерева, вкладке документа, тексту в редакторе, карточке выдачи.
- **Фактически:** составы меню проверены в браузере; списки — в документе аудита.
- **Ожидается:** одни группы во всех местах (открыть · создать · переименовать и переместить · путь и Проводник · цвет · проверить индекс · удалить последним); на вкладке — закрытие; в редакторе — сначала правка текста, затем подменю документа.
- **Статус:** открыт.

## ISS-58. Граф непонятен: нет входа от объекта и действий словами

- **Источник:** замечания автора 23-10-2026 («как работает граф и как им пользоваться вообще не понятно», «не понятно, как граф помогает в поиске»); разбор и предложение — аудит клиента ([client-2026-10-23.md](../audits/client-2026-10-23.md), А-3, А-5).
- **Симптом:** вкладка «Граф» открывается облаком всего проекта; десять значков без подписей; инспектор «Выберите узел или связь» со служебными строками («Снимок графа», «слой готов», «19 из 72»); первое действие не подсказано. Режим «Со связями» подан как способ искать лучше, хотя по замеру ([исследование GraphRAG](../knowledge/graph-research.md)) он нашёл 17 из 28 оснований против 16 у обычного поиска и 18 у обычного с большей глубиной.
- **Шаги:** открыть вкладку «Граф» без подготовки.
- **Фактически:** пользователь не понимает, что делать и зачем.
- **Ожидается (предложение агента):** граф открывается на активном документе или последнем запросе; над картой — действия словами («Что рядом», «Кто ссылается», «Что затронет правка», «Путь до…»); служебное — в настройки графа; из выдачи — «В графе» и «Искать в подграфе» (OQ-141). Не меняет решений OQ-141 и OQ-144.
- **Статус:** открыт; нужен дизайн и согласование с автором.

## ISS-59. Внутренние слова в интерфейсе окна

- **Источник:** аудит клиента 23-10-2026, UX-аудит ([client-2026-10-23.md](../audits/client-2026-10-23.md), UX-3).
- **Симптом:** пользователь видит идентификаторы протокола и отладки: «mix», «hybrid», `include_related=false`, «слой готов», «Снимок графа …», `limit, max_bytes`, «бюджет bytes», `Some(ComparisonLimit)`, «Проверить индекс проекта — Проверяется весь проект».
- **Шаги:** выдача «Со связями», вкладка «Граф» и её старый экран анализа, меню папки.
- **Фактически:** строки выше на экране (браузер и скриншоты автора).
- **Ожидается:** словарь подписей для пользователя; идентификаторы — только в подсказке и в отчёте об ошибке.
- **Статус:** открыт.

## ISS-60. Карточка запроса перегружена редкими настройками

- **Источник:** аудит клиента 23-10-2026, UX-аудит ([client-2026-10-23.md](../audits/client-2026-10-23.md), UX-10).
- **Симптом:** в одной карточке — область, режим, «Результатов», `Aa`, `.*`, фильтр пути, подсказка Enter и «Найти»; область «Искать во всём пр…» обрезана даже при ширине 1400 px; пустой раздел «В тексте: 0 док. · 0 вх. · 0 мс» стоит над выдачей по смыслу.
- **Шаги:** открыть окно и выполнить поиск, который не находит вхождений в тексте.
- **Фактически:** проверено в браузере.
- **Ожидается:** редкие настройки (`Aa`, `.*`, путь, режим) в раскрывающихся «Параметрах»; пустой «В тексте» — одной строкой под выдачей по смыслу. После согласования макета с автором.
- **Статус:** открыт.
