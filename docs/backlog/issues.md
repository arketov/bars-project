## ISS-02: Без rerank результаты идут не по убыванию шкалы релевантности

- [x] Исправлено — `3c6200c`
- Источник: автор, 16-10-2026

Если rerank не используется, образцы выдаются в порядке, не совпадающем со шкалой процентов («71% частично»): порядок выглядит случайным.

Замер 16-10-2026 (24 вопроса по docs/): у каждого запроса 2–6 пар соседей, где оценка растёт вниз по списку. Порядок задаёт слияние RRF, а показывается косинус, поэтому шкала с порядком не согласована.

18-10-2026 реализован выбранный автором вариант OQ-77: порядок сохранён; полоска и проценты подписаны `Cosine similarity`/`Rerank score`, неподтверждённые категории «частично/хорошо подходит» убраны, гибридный порядок объяснён над выдачей. 50/50 UI-тестов, check и build пройдены. По отдельному разрешению автора во встроенном браузере визуально проверены обычный поиск, rerank и ошибка rerank на тестовых ответах. Это проверка отображения, не реального инференса/IPC. Снимки — в [решении и проверках](../features/search/plan.md). Установленное приложение не обновлялось.

Диагностика добавлена 16-10-2026; этап 19 переносит устройство rerank, файлы модели и сырые логиты в [журнал воркера](../features/window/logs.md). Для полного набора — уровень «Отладка и выше». Нужен лог с той машины; причина ISS-03 остаётся открытой.

## ISS-06: Автообновление не подхватывает изменения документов

- [x] Исправлено
- Источник: автор, 16-10-2026

Документы меняются на диске, но в bars изменений не видно: индекс не обновляется сам. Нужно воспроизвести: слежение за корнем документации, очередь проверки (Т-10), время обновления индекса в `bars_status`.

Причина (OQ-70): `notify` на Windows теряет события при переполнении буфера, а на неизвестной ошибке слежение снимается молча. Исправлено 16-10-2026: проверка целиком через 5 секунд после пачки событий, полная проверка по `Rescan` и по событию без путей, перезапуск слежения, которое молчит при находках периодической проверки; периодическая проверка — раз в 15 минут. Описание — `features/indexing/updates.md`. Проверено тестами на сотнях файлов; на реальном `overdrive-bots` не проверялось.

## ISS-12: Тесты подменяют пользовательские пути MCP и хука

- [x] Исправлено
- Источник: автор, 18-10-2026

Запуск тестового воркера переписал Codex MCP и SessionStart на `target/debug/deps`, хотя bars установлен отдельно. Причина: `WorkerConfig::new` автоматически определял настоящий профиль клиента; временный `bars_home` не изолировал фоновый refresh.

Исправление: библиотечный конструктор запрещает изменение клиентских конфигов по умолчанию; приложение включает его явно, стенд установки задаёт временный профиль. Контракт — [clients.md](../features/clients/clients.md). Регрессии — `serve::tests::default_worker_does_not_enable_client_profile_writes`, MCP fixture и `scripts/test-client-profile-isolation.ps1`: хеши, время записи и наличие конфигов, резервных копий и skills до/после тестов. Проверено: worker 132, CLI 8, MCP 9; профиль неизменен, шесть изолированных сессий установки прошли. [Проверки и границы](../features/clients/verification.md). Пути Codex MCP и хука восстановлены на установленный bars; уже открытое окно Codex со старой командой требует перезагрузки конфигурации, его обновление не подтверждено.
