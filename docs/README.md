# Документация

Документация пишется до кода и остаётся источником правды: сначала требования, потом спецификация, потом реализация.

Требования живут в одном месте — [MAIN_IDEA.md](../MAIN_IDEA.md) в корне. Документы здесь раскрывают их по модулям и ссылаются на номера Т-N, текст требований не копируют.

## Структура

Раскладка повторяет конвенцию, по которой bars будет индексировать чужие проекты (Т-7): модуль — подпапка первого уровня под `docs/`. Этот репозиторий — первый тестовый корпус bars.

```text
docs/
├── README.md              этот файл
├── vision/
│   └── glossary.md        термины
├── architecture/
│   ├── overview.md        компоненты и потоки
│   └── stack.md           стек и внешние зависимости
└── <module>/
    ├── README.md          назначение, покрытые Т-N, границы, вопросы
    ├── spec.md            спецификация — появляется после проектирования
    └── impl_YYYY-MM-DD.md лог реализации — появляется при реализации
```

Модули:

| Модуль | Что это |
|---|---|
| [worker](worker/README.md) | Общий процесс: реестр проектов, жизненный цикл, планировщик проверок |
| [mcp-proxy](mcp-proxy/README.md) | `bars-mcp` — stdio-MCP для агентов |
| [cli](cli/README.md) | Команды для терминала и хуков |
| [indexer](indexer/README.md) | Обнаружение изменений, нарезка, эмбеддинг, инкрементальность |
| [search](search/README.md) | Гибридный поиск, слияние, реранк, фильтр по модулям |
| [models](models/README.md) | Embed и rerank: удалённые, встроенные, локальные OpenAI-совместимые |
| [storage](storage/README.md) | `.bars/`: настройки проекта и SQLite-индекс |
| [integrations](integrations/README.md) | Установка в Claude Code и Codex, хуки, `BARS_INSTRUCTION.md` |
| [ui](ui/README.md) | Окно и трей |

Вопросы живут не в `docs/`, а в одном общем файле в корне — [QUESTIONS.md](../QUESTIONS.md).

## Метки происхождения

| Метка | Значит |
|---|---|
| `[требование Т-N]` | требование из MAIN_IDEA.md |
| `[ответ ДАТА]` | ответ автора на вопрос OQ-NN |
| `[предложение]` | появилось при проработке, автор ещё не согласовал |
| `[утверждено ДАТА]` | предложение, которое автор принял |

Предложение не становится решением, пока автор его не утвердил.

## Статусы модуля

`требования` → `проектирование` → `спека утверждена` → `в работе` → `готово`

## Правила письма

- У каждого файла есть frontmatter `title` (Т-11).
- Разделы должны быть понятны сами по себе: bars режет документы по заголовкам, и раздел попадёт в выдачу без соседей.
- Никаких ключей, токенов и личных данных.
