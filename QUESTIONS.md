# Вопросы

Общий реестр вопросов по bars. Автор отвечает здесь, агент переносит решения в документацию.

Вопросы раундов 1–9 (В-1…В-29) закрыты, ответы на них — в [MAIN_IDEA.md](MAIN_IDEA.md), «Журнал раундов». Здесь лежат вопросы следующего этапа — прохода проектирования. Нумерация новая: `OQ-NN`.

## Как отвечать

- Впиши ответ после **Ответ:**. Можно коротко: «да», «вариант 2», «своё: …».
- Порядок любой, отвечать можно понемногу. Начни с высокого приоритета.
- Можно ответить в чате по номеру («OQ-03 — пайп»), тогда агент сам впишет ответ сюда.

## Что происходит после ответа

1. Ответ остаётся в вопросе с датой.
2. Если ответ меняет требование, правится MAIN_IDEA.md и пишется запись в журнал раундов. Если это решение по устройству, оно попадает в документацию `docs/`, когда её время придёт.
3. Вопрос переезжает в раздел «Закрытые», в сводке меняется статус.

## Правила ведения

- Любой вопрос — заданный в обсуждении или найденный агентом — сначала записывается сюда.
- Номер `OQ-NN` сквозной и не переиспользуется.
- Статусы: **открыт** · **отложен** (ждёт другого решения или прототипа) · **закрыт**. Приоритет — насколько ответ влияет на остальное: **высокий** · **средний** · **низкий**.
- «Варианты» — заготовка агента для брейншторма, а не рекомендация. Рекомендация, если она есть, помечена отдельно.

### OQ-02. Раскладка Cargo workspace

Нужно разбить код на крейты так, чтобы прокси остался маленьким (НФТ-3) и не тянул за собой ONNX, SQLite и Tauri.

Варианты:
1. `bars-core` (индекс, поиск, модели) + `bars-protocol` (сообщения IPC) + `bars` (Tauri, воркер, CLI) + `bars-mcp` (прокси, зависит только от `bars-protocol`).
2. То же, но CLI — отдельный крейт `bars-cli` (зависит от OQ-04).
3. Один крейт с фичами — проще, но прокси легко случайно потянет тяжёлые зависимости.

### OQ-03. Локальный канал прокси/CLI → воркер

Т-2: прокси пересылает вызовы в общий воркер. В «Решении» канал оставлен на проектирование: именованный канал или localhost.

Варианты:
1. Именованный канал на Windows, Unix-сокет на macOS (через крейт `interprocess`). Порт не нужен, доступ ограничен пользователем ОС.
2. HTTP на `127.0.0.1` со случайным портом, порт и токен записаны в файл в профиле пользователя. Проще отлаживать, но любой локальный процесс может достучаться без токена.

Ещё нужно решить: как прокси понимает, что воркер «готов», и что происходит с вызовом, пока идёт первая индексация.

**Ответ:**

### OQ-04. CLI — отдельный exe или режим `bars`

Т-20 требует CLI, «Решение» оставляет выбор проектированию. Хук начала сессии вызывает CLI на каждом старте агента, поэтому время запуска важно.

Варианты:
1. Режим `bars <команда>`: один exe, но запуск тянет Tauri и WebView-зависимости.
2. Отдельный `bars-cli`: лёгкий, как прокси, говорит с воркером по каналу из OQ-03.
3. CLI-команды живут в `bars-mcp` (`bars-mcp register`, `bars-mcp status`): два exe вместо трёх.

**Ответ:**

### OQ-05. Что из `.bars/` предназначено для git

Т-5: настройки и SQLite-индекс лежат в `<проект>/.bars/`, `.gitignore` bars не трогает (В-21). В «Решении» отмечен риск: `.bars`, закоммиченный с другой моделью, переиндексируется у каждого.

Варианты:
1. Разделить: `.bars/config.*` — для git, `.bars/index/` — локальный. В `.bars/` лежит свой `.gitignore`, который исключает только `index/`. Корневой `.gitignore` проекта при этом не меняется.
2. Всё в `.bars/` локальное, решает пользователь (как сейчас в требованиях).
3. Индекс тоже для git — команда получает готовый индекс без эмбеддинга. Тогда нужно правило о совпадении моделей (OQ-06).

**Ответ:**

### OQ-06. Смена embed-модели и переиндексация

Решено по умолчанию в MAIN_IDEA: модель записана в индексе, при несовпадении проект переиндексируется целиком (урок 4). Риск: при удалённом провайдере это платно.

Что решить:
- переиндексировать сразу или ждать подтверждения в окне и CLI;

- нужна ли оценка стоимости перед переиндексацией через удалённого провайдера.

### OQ-07. Хранение ключей провайдеров

Решено по умолчанию: ключи — в настройках приложения, не в `.bars`. Способ хранения оставлен проектированию из-за урока 12 (токен открытым текстом рядом с exe).

Варианты:
1. Хранилище ОС: Windows Credential Manager / macOS Keychain (крейт `keyring`). В конфиге лежит только ссылка.
2. Переменные окружения, на которые ссылается конфиг (`api_key_env = "OPENROUTER_API_KEY"`).
3. Оба: хранилище ОС по умолчанию, переменная окружения как переопределение.
