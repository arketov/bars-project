# Вопросы

Общий реестр вопросов по bars. Автор отвечает здесь, агент переносит решения в документацию.

Вопросы раундов 1–9 (В-1…В-29) закрыты, ответы на них — в [MAIN_IDEA.md](docs/MAIN_IDEA.md), «Журнал раундов». Здесь лежат вопросы следующего этапа — прохода проектирования. Нумерация новая: `OQ-NN`.

## Как отвечать

- Впиши ответ после **Ответ:**. Можно коротко: «да», «вариант 2», «своё: …».
- Порядок любой, отвечать можно понемногу. Начни с высокого приоритета.
- Можно ответить в чате по номеру («OQ-03 — пайп»), тогда агент сам впишет ответ сюда.

## Что происходит после ответа

1. Ответ остаётся в вопросе с датой.
2. Если ответ меняет требование, правится MAIN_IDEA.md и пишется запись в журнал раундов. Решение по устройству попадает в документацию `docs/`.
3. Вопрос переезжает в раздел «Закрытые», в сводке меняется статус.

## Правила ведения

- Любой вопрос — заданный в обсуждении или найденный агентом — сначала записывается сюда.
- Номер `OQ-NN` сквозной и не переиспользуется.
- Статусы: **открыт** · **отложен** (ждёт другого решения или прототипа) · **закрыт**. Приоритет — насколько ответ влияет на остальное: **высокий** · **средний** · **низкий**.
- «Варианты» — заготовка агента для брейншторма. Рекомендация агента, если она есть, помечена отдельно.

### OQ-95. Какой сигнал создаёт новую тему

Пустая выдача зависит от порога и выбранных файлов; непустая выдача не доказывает наличия ответа. Ошибка модели не является пробелом документации.

**Вопрос:** автоматически складывать успешные пустые поиски как кандидатов с объяснением причины, оставляя ручное подтверждение; либо показывать только подтверждённые человеком пробелы? Найдено 18-10-2026 при проектировании этапа 13. У установленного bars Private Bytes около 8,46 ГиБ, Working Set около 203 МиБ. [Причинный опыт](docs/knowledge/memory.md): две ONNX/DirectML-сессии после длинной embed-пачки удерживают 8,51 ГиБ; drop rerank освобождает около 3,25 ГиБ, после обеих моделей остаётся 249 МиБ. Отдельный rerank освобождает 1,71 ГиБ на CPU и 3,42 ГиБ на DirectML; все оценки после reload совпали. Точный вход старого завершённого процесса неизвестен; core4 превышает ограничение пачки воркера, поэтому этот результат не является точной атрибуцией прежнего воркера. [Проект опытов](docs/features/models/memory-plan.md).

Исходный bounded FP32-контроль выполнен один раз: обе модели 6,87 ГиБ, drop rerank освобождает 3,29 ГиБ, оценки после reload совпали. Второй процесс прерван preflight, ещё три серии повторов не получили стартовый запас памяти. Остаются новые FP16-процессы, отдельная атрибуция весов/arena/драйвера и цена повторной загрузки. Выгрузка после каждого запроса на CPU стоила около 10–11 с на этом входе. Политика 300/900 с реализована и проверена unit/integration-тестами; память настоящего FP16-пути ещё принимается. Не считать эти числа решением автора или оптимумом его реального трафика. Для продолжения технических опытов нового ответа автора не требуется.

- **Понижение версии запрещено** (код выхода 2 у тихого установщика).
- **Автозапуск — свой модуль воркера** (значение `bars` в `HKCU\...\Run`, команда `bars.exe --background`), а не `tauri-plugin-autostart`; методы `autostart_get`/`autostart_set` и команда `bars-cli autostart` доступны и CLI, не только окну; вкладка «Запуск» в настройках, которой нет в мокапе.
- **Самообновления нет** (`tauri-plugin-updater` не подключён): новую версию ставит запуск установщика.

Варианты:
- **А.** Как сделано.
- **Б.** Удаление не трогает записи клиентов (пользователь сам запускает `bars-cli uninstall` до удаления).
- **В.** Автозапуск только из окна, без методов для CLI.

**Ответ (16-10-2026):** вариант А — как сделано; решения агента по умолчанию приняты автором.
