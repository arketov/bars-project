# AGENTS.md

Правила для любого агента в этом репозитории: Claude Code, Codex и других.

## Что это за проект

bars — локальный RAG по Markdown-документации проектов для людей и агентов. Подробно — [README.md](README.md) и [MAIN_IDEA.md](docs/MAIN_IDEA.md).

## Стадия

Требования зафиксированы (MAIN_IDEA, 14-10-2026). Идёт реализация по срезам. Требования всего проекта — `docs/MAIN_IDEA.md`, ТЗ по фичам — `docs/features/`.

Код не запрещён, но пишется только тогда, когда есть проектный документ, на который он опирается. Выбрасываемые спайки для проверки технических рисков допустимы раньше; их результаты записываются в `docs/knowledge/`.

## План

[PLAN.md](PLAN.md) — план, по которому идёт работа. Прочитай его перед любой работой и обновляй по ходу: отмечай сделанное, добавляй следующие шаги, убирай неактуальное. Он меняется постоянно.

Ссылка на PLAN.md есть только здесь. Не ссылайся на него из других файлов: README, docs, QUESTIONS, TASKS и так далее.

## Язык

Интерфейс, сообщения поиска, документация и общение — на языке пользователя; в этом проекте — по-русски. Поисковые запросы агентов тоже на языке пользователя, без автоматического перевода на английский. Только документы с инструкциями для агентов (BARS_INSTRUCTION.md, skills) — на английском; это не задаёт язык создаваемых ими документов, запросов или интерфейса. Имена файлов, идентификаторы и термины вроде `chunk`, `rerank`, `MCP` пишутся как есть. ISS-11 не разрешает перевод интерфейса или поиска на английский.

Служебное оформление текстовых результатов MCP (границы блоков, подписи и пояснения рендерера) — на английском, по уточнению автора 18-10-2026. Содержимое документов и сообщения воркера сохраняют исходный язык.

## Вопросы

Все вопросы — и заданные автору, и найденные тобой — записываются в [QUESTIONS.md](QUESTIONS.md) под сквозным номером `OQ-NN`. В чате вопрос упоминается номером и одной строкой. Вопрос, которого нет в файле, считается потерянным. Как закрывать вопрос — написано в самом файле.

## Документация

`docs/` разложена по совету самого bars ([docs/features/docs-convention/layout.md](docs/features/docs-convention/layout.md)), заодно это проверка совета на себе (ADR-0001):

- **`docs/MAIN_IDEA.md`** — требования всего проекта (см. «Источник правды»).
- **`docs/features/<name>/`** — фича: `Index.md` коротко объясняет её и ведёт на остальные файлы; `requirements.md` — требования фичи, если появятся; `plan.md` — пока фичу делают. Дизайн окна — `docs/features/window/`, HTML-мокапы в `mockups/` не индексируются (bars берёт только `.md`), но перечисляются в `Index.md`.
- **`docs/architecture/`** — общее устройство, на которое опираются фичи.
- **`docs/adr/`** — решение с обоснованием, одно в файле `NNNN-<тема>.md`. ADR не переписывается под текущее состояние: новое решение — новый ADR, у старого меняется только статус.
- **`docs/knowledge/`** — внутренняя база знаний разработки: исследования, сравнения библиотек, замеры спайков, соглашения по коду.
- **`docs/chats/`** — журнал сессий, правила ниже.

Не в `docs/`: вопросы (QUESTIONS.md), план (см. «План»), заготовки на будущее.

Как вести:
- **Пиши документ, когда есть что документировать** — принятое решение или сделанная часть. Пустые папки, заглушки и шаблоны «на потом» не создавай.
- **Модуль — подпапка первого уровня** `docs/<module>/`, внутри любая вложенность (Т-7). Новый модуль заводи, когда появляется первый документ о нём.
- **В каждой папке `docs/`, кроме папок сессий в `chats/`, лежит `Index.md`** — оглавление этой папки: каждый файл и подпапка ссылкой с одной строкой описания. Добавил, переименовал или удалил файл — поправь `Index.md` своей папки в том же изменении. Корень — [docs/Index.md](docs/Index.md).
- **Регистр имени `Index.md` не важен**: `index.md` тоже годится. Но не держи в одной папке два файла, которые отличаются только регистром: на Windows и macOS это один файл.
- **У каждого файла есть frontmatter `title`** (Т-11).
- **Раздел понятен сам по себе.** bars режет документы по заголовкам, и раздел попадает в выдачу без соседей: не пиши «см. выше», называй предмет в заголовке.
- **Документ описывает текущее состояние**, а не историю (кроме `adr/` и `chats/`). Устарело — правь или удаляй, не дописывай поправки в конец.
- **Сначала найди документ темы и правь его.** Перепроверка, аудит или продолжение исследования исправляют исходный файл, а не создают рядом `*-audit.md` / `*-verification.md`. Итог работы над фичей — правка `features/<name>/`, а не только новый файл в `knowledge/`. Поведение и контракты продукта живут в `features/`, общее устройство — в `architecture/`; в `knowledge/` — только вопрос, метод, данные и выводы.
- **Отчёт о завершённом этапе** (план, проверки, доказательства) переносится в папку своей сессии `docs/chats/`, а действующие контракты из него — в документ фичи. В `features/` остаются только планы открытых этапов.
- **На требования ссылайся номером Т-N**, текст из MAIN_IDEA.md не копируй.
- **Сначала меняется документ, потом код.**
- Никогда не клади в репозиторий ключи провайдеров, токены и личные данные (урок 12).

## Журнал сессии

Сессия, с которой говорит пользователь, ведёт `docs/chats/<YYYY-MM-DD>-<тема>/` по [session-log.md](docs/features/docs-convention/session-log.md). Субагенты журнал не ведут. Коротко:

- `log.md` — только по поводу: неочевидная находка, подход не сработал, план меняется, перед рискованным шагом. До трёх строк, дописывай в конец без чтения файла. Не пиши ход работы, код и то, что видно в диффе.
- `handoff.md` — в конце сессии: сделано, не сделано, сложности, дальше. Новая сессия читает последний handoff по своей теме, а не все логи.
