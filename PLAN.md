## Порядок реализации

Каждый срез заканчивается работающей вещью, которую можно потрогать, и закрывает свои критерии приёмки из MAIN_IDEA. Следующий срез строится на предыдущем.

Поправка к исходному порядку «`bars-core` + `bars-cli` → воркер»: `bars-cli` не зависит от ядра и работает только через воркер ([components.md](docs/architecture/components.md)). Поэтому CLI появляется вместе с воркером, а ядро проверяется тестами.

### Срез 0. Каркас и сборка на двух ОС

- Cargo workspace по `docs/architecture/components.md`: `bars-core`, `bars-protocol`, `bars-app`, `bars-mcp`, `bars-cli`; `rust-toolchain.toml`.
- CI на GitHub Actions: сборка и тесты на Windows и macOS с первого дня — это заодно закрывает непроверенную сборку на macOS. Минуты macOS-раннеров в приватном репозитории платные, это связано с OQ-18.
- `cargo clippy`, `cargo fmt`, `cargo audit` в CI.
- Приёмка: Т-3; Т-4 — частично (сборка).

### Срез 1. Ядро: нарезка, индекс, поиск

`bars-core` как библиотека, проверяется тестами на корпусе `docs/` bars и на синтетике.

- нарезка (`indexing/chunking.md`), frontmatter, обход файлов;
- индекс SQLite (`storage/schema.md`), инкрементальная индексация по хешам, удаление пропавших (`indexing/updates.md`);
- встроенная bge-m3 на CPU и DirectML;
- гибридный поиск со стеммингом, RRF, пороги и пределы (`search/hybrid-search.md`);
- настройки (`storage/settings.md`);
- структура документа `outline`.

Приёмка: Т-7, Т-9, Т-11, Т-12, Т-13, Т-14 (отбор модулей и файлов), Т-18, Т-22, Т-23, Т-24, Т-26 (ядро), НФТ-1, НФТ-2.

### Срез 2. Воркер, канал и bars-cli

- воркер без окна: канал с DACL, протокол, запуск по требованию, один экземпляр (`architecture/ipc.md`, `protocol.md`, `worker.md`);
- очередь индексации, слежение за файлами, часовая проверка, реестр проектов (`architecture/projects.md`);
- `bars-cli`: search, outline, read, projects, status, reindex, register, unregister;
- согласие на переиндексацию через `--accept-model-change`.

Приёмка: Т-1 (один процесс), Т-5, Т-6 (через CLI), Т-10, Т-15, Т-20 (без install), Т-25 (через CLI).

### Срез 3. bars-mcp

- `rmcp`: шесть инструментов; ответ на `initialize` без ожидания воркера; запуск воркера при первом вызове.

Приёмка: Т-2, Т-19, Т-15 (через MCP), НФТ-3. После этого среза bars уже можно использовать из Claude Code, подключив `bars-mcp` вручную.

### Срез 4. Установка в клиенты и хук

- `install` / `uninstall` для Claude Code и Codex с бэкапом и атомарной записью (`integrations/clients.md`);
- `bars-cli hook session-start` с поиском корня проекта;
- `BARS_INSTRUCTION.md` и текстовая инструкция по установке.

Приёмка: Т-6 (хук), Т-8, Т-20 (install), Т-21 (CLI и текстовая инструкция).

### Срез 5. Окно и трей

- Tauri + Svelte по мокапам `docs/design/`: трей, главный экран с деревом и выдачей, просмотр документа, настройки, установка в клиенты;
- диалог согласия на переиндексацию и ход индексации — дорисовать в дизайне до начала среза (шаг 3 плана).

Приёмка: Т-1 (окно и трей), Т-6 (окно), Т-14 (дерево с галочками), Т-16, Т-21 (кнопка «Установить»), Т-25 (диалог).

### Срез 6. Модели сверх bge-m3

- внешние embed и rerank по HTTP, ключи в хранилище ОС (`models/external-models.md`, `architecture/secrets.md`);
- встроенный rerank;
- Qwen3-Embedding 0.6B и 4B, Nomic Embed v2 MoE с предупреждениями о скорости и длине входа.

Приёмка: Т-16 и Т-17 (три способа подключения, переключение rerank).

### Срез 7. Дистрибуция

- установщики Windows и macOS, подпись и нотаризация, обновление (OQ-17);
- автозапуск (OQ-16), лицензия (OQ-18);
- проверка всех критериев на macOS.

Приёмка: Т-4 полностью — Т-1, Т-2, Т-14 на обеих ОС.
